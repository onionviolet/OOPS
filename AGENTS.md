# Agent instructions

OOPS is Weibao's fork of Yet Another Idle RPG. Use [PROJECT.md](PROJECT.md) for
current focus and owner links. Follow the guidance for the work you touch.

## Standing direction and consistency gates

Weibao is the creative director. His latest direction and the relevant
[accepted decisions](docs/RULES_INDEX.md) govern changes. Open the
[vision digest](docs/VISION_DIGEST.md) for design or scope decisions. Use the
[consistency gates](docs/gm/AGENT_WORKFLOWS.md#standing-direction-and-consistency-gates)
for substantive system or UI work. UI targets desktop/laptop first. An attached reference picture is the visual floor: match its look, then improve on it deliberately ([UR177](docs/UI_RULES.md)).

For each touched code area, find the relevant rule with
`node scripts/rule_routes.mjs --for <path>`. Claude also loads matching path
rules. Use the [rules index](docs/RULES_INDEX.md) for design-rule changes and
the [area guide](docs/AREA_GUIDE.md) to find existing seams.

## Verification

Docs use relevant doc checks. For runtime work use focused tests or
`npm run test:changed` while editing. Apply
[AD36](docs/RULES_INDEX.md#efficient-rule-verification-ad36) and the
[verification procedure](docs/gm/AGENT_WORKFLOWS.md#verification) for
completion and push. The existing preflight card applies to task records
and lane briefs. Capture verbose commands to a log and report their actual
exit status and a bounded excerpt.

Gameplay completion requires rebuilt browser proof on a fresh test origin.
Persistence changes also exercise save, reload, export and import. Record
the candidate and receipts against the [AD43 floor](docs/RULES_INDEX.md#definition-of-done-the-floor-ad43).

## Safety

Preserve upstream attribution, LICENSE, private saves and unrelated work.
Persistence changes need a migration or an explicit compatibility decision.
Run work in the background. Native computer control requires Weibao's say-so.
Use the [scratch and cleanup procedure](docs/gm/AGENT_WORKFLOWS.md#safety) for
runs and merges.

## Sealed secrets

Seal world truths in play. Use IDs in reports and chat for concealed
developments unless the development question needs the truth or Weibao asks.
Read the [sealing rules](docs/gm/AGENT_WORKFLOWS.md#sealed-secrets) before working
with secrets. LOTM canon is open in development.

## Multi-agent work

Default to the primary checkout with one writer per area. For overlapping
work, integrations and shared changes, follow
[shared worktree practice](docs/gm/SHARED_WORKTREE_PRACTICE.md) and the
[coordination procedure](docs/gm/AGENT_WORKFLOWS.md#multi-agent-work).
Push waits for Weibao's yes.

## Other workflows

Use [design framing](docs/gm/AGENT_WORKFLOWS.md#design-framing) for design
decisions, [source acquisition](docs/gm/AGENT_WORKFLOWS.md#source-acquisition-tools)
for source work, and [Game MCP](docs/gm/AGENT_WORKFLOWS.md#game-mcp) for headless
play. Report what changed, the check evidence and any remaining gate.
