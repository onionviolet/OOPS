# Opening rules

Proposed 2026-11-06 (AD32); run authorized by Weibao, lines not yet accepted
([direction](USER_VISION.md#five-quality-deep-dives-on-the-prose-model-2026-11-06)).
Each line is a default, a dial and a reason, never never/always/only (AD5, AD38).

An opening is the first screen of a start and its first dozen presses. These rules add what
nobody checked: what a new player meets there. They do not restate the owners:
[PRS1-PRS3](PROSE_RULES.md) (start-screen voice and spoilers), [UR70-UR75](UI_RULES.md)
(plain terms, refusals, explained comparisons), [WER3](WORLD_ENTRY_RULES.md) (what an entry shows
before commitment) and [PACING_RULES](PACING_RULES.md) (payoff timing in minutes).

## Rules

| Code | Rule | Default, dial, reason |
| --- | --- | --- |
| OPN1 | **The first screen offers a way in.** | Default: at least one enabled scene action, and any "Next step" pointer names it. Dial: a scene that must wait (a lesson that starts at nine) says what it waits for and when. Reason: a first screen with nothing to press reads as a broken start. Flags: `no-action`. |
| OPN2 | **Words before the first press fit a budget.** | Default: about 300 words of scene prose and no block over 60 words; rules, timetables and bookkeeping fold into a "Details" disclosure (PRS3). Dial: a start chosen for its setup may run longer when the player opened the premise on purpose. Reason: the 2026-11-06 sweep found a book start with 750 words on screen before the first press. Flags: `prose-wall`, `long-block`. |
| OPN3 | **A control uses words the screen has already given.** | Default: a capitalised term in a control label appears in text above or beside it, and controls that look alike name their difference (the destination, the person, the task). Dial: a world term the player chose the start for (a spell, a Pathway) counts as given after the confirm step. Reason: UR75; "Walk · 2 min" three times says nothing about where. Flags: `unexplained-term`, `same-label`. |
| OPN4 | **A refusal says why, in player words.** | Default: a disabled scene action carries one reason naming the missing thing; engine fallback text is hidden (UR73, UR82). Dial: an action that is part of a later step may stay hidden instead. Reason: "why can't I" is the first question a locked button raises. Flags: `refusal-no-reason`, `engine-reason`, `trace-refusal-no-reason`. |
| OPN5 | **The first real action lands fast.** | Default: within about six presses of a curious reader something visible changes, and the first payoff comes within about twenty. Dial: a slow start (a trial, a cultivation) may raise it and name why; minutes are PAC's measure. Reason: the opening teaches the loop. Flags: `first-action-late`, `first-payoff-late`. |
| OPN6 | **A scene choice changes something you can see.** | Default: a number, a line, an item or the clock the player can read moves. Otherwise it is a link and looks like one. Dial: a look-around choice may only add text when the text is new. Reason: a choice that changes nothing teaches players to stop choosing. Flag: `no-effect-choice`. |
| OPN7 | **No long dead stretch.** | Default: no run of six presses where nothing visible changes. Dial: waiting is allowed when the scene says what for (a shift, a lesson). Reason: a stretch with nothing to read or earn is where a new player leaves. Flag: `dead-stretch`. |
| OPN8 | **Entry clears the last world's guidance.** | Default: the "Next step" pointer and refusal reasons name this start's places and people, not the Village's. Dial: a visit that really returns to the Village may say so. Reason: carried-over guidance sends a new player to someone who is not there. Flags: `stale-pointer`, `foreign-place`. |
| OPN9 | **A check keeps these honest, run on demand.** | Default: `node scripts/check_openings.mjs` boots each start once and reads the pacing check's cached trace; flags are a ratchet in `scripts/openings_baseline.json` (a new flag or a worse value fails, a fixed one retires). Not part of `check:rules`. Dial: trace measures are policy-limited because the curious bot presses what it has not pressed; they never lead the backlog. Reason: same as PRS5. |

## Backlog and workflow

[Openings backlog](openings/OPENINGS_BACKLOG.md), regenerated by
`node scripts/check_openings.mjs --backlog`, ranked by what most players see first (the Village, then
Tingen, then book starts). After a content fix: rerun, then `--update-baseline` retires the entry.
A trace that errored is read as pending, never as zero.
