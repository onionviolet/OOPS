# Idle RPG references: discovery, ordinary adventure and economical depth

Research date: 2026-09-30, America/New_York. Research and proposals only; creative acceptance and integration belong to the parent chat.

**Recommendation:** first build an ordinary expedition that turns a clue into a useful technique or route. Make equipment, preparation and exploration offer different solutions to that expedition. Then add bounded automation that remembers the player's plan. Cultivation can be an earned optional path later; it should not become the universal XP amplifier.

## Six detailed reference cases

### 1. Proto23: make knowledge an object in the world

**Code:** `item.skl1a` is the Bladesman Manual. Completion consumes the manual, awards 3,250 Sword Mastery XP, increases its XP modifier by 0.15 and supplies a generic book. Home furniture has give/remove and activation hooks; beds and tableware have distinct fields/effects. These are implemented objects, not only flavor strings. [Pinned HTML](https://github.com/23html/23html.github.io/blob/e93a8cd617932fb698ff889b968a32f9a20d48f3/index.html).

**Inference:** knowledge can have provenance, acquisition and a place to live. The manual's verified reward is still XP efficiency, not evidence of a new sword action. YAIRPG should preserve the tangible acquisition while improving the consequence: a newly usable stance, crafting operation or route condition.

**Proposal:** distinguish found, understood and usable. A recovered blade lesson can be interpreted by a mentor or restored using Literacy plus a craft task. Practice opens a stamina-costed stance; using it against an appropriate obstacle supplies the mastery evidence. Home later organizes these lessons or provides one preparation service instead of multiplying every stat.

**Cost:** lengthy reading without a decision is waiting; every book having a bespoke progression bar becomes clutter. Reuse reading/task completion and a small journal. Exact Proto23 combat/offline balance remains outside this source sample.

### 2. The Climb: choose what becomes part of the character's history

**Code:** heirlooms preserve selected equipment state across rebirth within a power limit. Enchanting consumes an item into a slot; awakening can change slot capacity. These state changes appear in executable actions, not just descriptions. [Pinned published bundle](https://github.com/tomlipo/the-climb/blob/b3a9510f34f210cb3f731932316efe9f100f04f2/assets/index-B-sH2ct2.js).

**Inference:** permanence is more expressive when it preserves a chosen object or capability. Limited capacity gives crafting and combat discoveries competing destinations. This provides a closer model for optional legacy than another global XP exponent.

**Proposal:** later let the player retain familiarity with one technique, a restored tool blueprint, or an expedition contact. Keep these as alternative capabilities with visible reset consequences. Do not add another reset layer now: Jade Hollow already contains the prototype's single legacy choice.

**Cost:** a retained defensive item can become an obvious pick; the reference's own text recommends defense for first-rebirth efficiency. Alternative legacies must open different opportunities, not be balanced only through multipliers. Full awakening acquisition and reset loss paths were not exercised.

### 3. Idle Loops: permanent information changes the next plan

**Code:** Wander adds town progress; it expands the pot/lock pools. Pick Locks becomes visible before it is unlocked. Pots yield mana through a regular discovery routine, while locks yield gold; Buy Mana converts gold into run budget. Restart resets run resources/stats and restarts town/action execution. Saving persists talent/skill progress and town information. [Action definitions](https://github.com/omsi6/omsi6.github.io/blob/fa21477d424f3aa1f1bf6deb9f6f83c2569770ab/loops/actionList.js), [restart/offline driver](https://github.com/omsi6/omsi6.github.io/blob/fa21477d424f3aa1f1bf6deb9f6f83c2569770ab/loops/driver.js), [saving](https://github.com/omsi6/omsi6.github.io/blob/fa21477d424f3aa1f1bf6deb9f6f83c2569770ab/loops/saving.js).

**Inference:** an unsuccessful route can still improve the plan by revealing where resources or useful actions exist. Discovery and efficiency can cooperate without requiring a new power realm.

**Proposal:** a three-step expedition plan, “gather supplies → climb known route → investigate clue,” remembers route knowledge. First-time discoveries pause for a choice; subsequent known tasks can repeat up to a target. Routes remain available after learning them, with no need to re-find the same entrance every visit.

**Cost:** rearranging dozens of actions can become programming homework. Show required inputs, where the queue stopped and one repair action. Keep the first slice to a few authored task types. No action prediction accuracy or endgame queue was tested.

### 4. Arcanum: progression is permission plus tradeoffs

**Code:** apprenticeship Smith requires crafting; Herbalist and Scribe connect jobs to different skills. Ending apprenticeship normally costs research and gold, while a dark route has different cost/result/modifiers. A “mystic savant” data condition excludes characters who already used Study. Inn housing drains gold; camp reduces lore/research rates but improves nature capacity; a shop provides income while penalizing other rates. [Class data](https://gitlab.com/mathiashjelm/arcanum/-/blob/a2632d2edf3e07e9168fff81167b11f2792e9197/data/classes.json), [home data](https://gitlab.com/mathiashjelm/arcanum/-/blob/a2632d2edf3e07e9168fff81167b11f2792e9197/data/homes.json).

**Inference:** a job, mentor and home can change how a character progresses. A hidden “never did X” gate also illustrates the cost of retrospective prerequisites. Data inspection establishes predicates; it does not prove every lock is explained or enforced correctly in deployed UI.

**Community:** some players praise the depth and others report unclear class requirements and direction. These are anecdotes, not a measured failure rate. [Discussion](https://www.reddit.com/r/incremental_games/comments/1kz5rdj/).

**Proposal:** faction access should say “demonstrate a restored tool OR defeat the guard,” and offer a reversible first specialization. A workshop/camp choice can affect one preparation operation. Reveal commitment conditions before they become irreversible; do not penalize normal exploration retroactively.

### 5. Your Chronicle: story gates should expose useful systems

**Developer:** actions advance story/abilities; automated dungeon battles use summoned monsters with skills and equipment. Routine upgrades, action/dungeon automation, offline reproduction and choice-dependent endings are stated features. [Official listing](https://store.steampowered.com/app/1546320/Your_Chronicle/).

**Inference:** story becomes mechanical when a relationship or event opens a new resource use, party option or automation service. Companions can express build identity, but exact monster roles and summon acquisition probabilities were not established by the listing.

**Proposal:** first use one mentor as an interpreter and optional one expedition assistant as a logistics choice. A scout reveals safe routes; an artisan restores expedition equipment. Treat these as alternatives and authored actions before implementing a permanent combat party. Do not model every relationship as another daily currency.

**Cost:** thousands of story actions can produce menu sprawl. Keep the current objective, its two next leads and already-completed discoveries separate in the UI. Choice-dependent endings require understandable consequences and branching content investment; they do not belong in the first ordinary expedition.

### 6. Melvor: professions feed play rather than decorate it

**Developer:** skills interact, combat has melee/ranged/magic approaches, and offline progression/bank functionality are advertised. Developer comments on the historical mastery rework confirm a shared mastery pool bonus and XP expenditure, including the cost of migration into a new system. [Official listing](https://store.steampowered.com/app/1267910/Melvor_Idle/), [developer discussion, v0.17](https://www.reddit.com/r/MelvorIdle/comments/jbe8fr/update_melvor_idle_alpha_v017_lets_try_this_again/).

**Community supplement:** the official wiki's beginner guide describes mining → smithing → equipment and fishing → cooking → food. Its FAQ describes offline death/resource depletion and save overwrite mistakes. Those pages are community-maintained, so exact current caps/loss formulas remain outside this dossier's primary-source claims. [Beginner guide](https://wiki.melvoridle.com/index.php?title=Beginners_Guide), [FAQ](https://wiki.melvoridle.com/index.php/FAQ). Direct mastery/offline-page fetches returned 403.

**Inference:** recipes make existing skills matter when their products solve a specific adventure problem. Pool-based mastery also adds a spend-versus-threshold decision, but another permanent XP bank is not necessary here.

**Proposal:** one material supports expedition repair, protective equipment and trade. Let buying supplies substitute for crafting at a visible money cost. Neither route should require maxing every skill. Show remaining inputs, expected output and the reason the activity stopped.

**Cost:** craft chains become compulsory all-skill grinding if every combat obstacle requires every profession. Save migration and offline depletion need explicit checks; descriptive UI alone does not establish safe unattended combat.

### Minimal playable example: the flooded watchpost

**Original proposal; not a reference-game mechanic or approved world.** One ordinary expedition, no new realm, prestige currency or power bar. Two main rules and one retention rule:

1. **An obstacle has a visible risk that can be countered through skill/stance, an item or a known route.** The armored sentry threatens the recovered ledger; the ledge has a footing risk. Choose one approach at each task; extra counters do not stack into free rewards.
2. **Existing supplies have competing uses.** Cloth can make a ledger wrap or be sold to pay a guide; wood can repair a brace or contribute to a shield. Supplies are consumed at committed task execution, never during visibility checks.
3. **Successful discoveries persist.** The dry route and recovered lesson remain known; re-entry does not re-grant their completion rewards. Failure spends only the shown committed cost and reveals the next preparation lead.

| Approach | Observable action sequence | Cost and payoff |
|---|---|---|
| Martial | Interpret the sentry clue; use a learned heavy stance against armor; brace the ledger before the risk resolves. | Combat/stamina and purchased or crafted wrap; practical stance training. Must remain viable without leveling several craft skills. |
| Craft | Restore a damaged winch/brace through one authored crafting action; use it to secure the ledger during the slower encounter. | Materials and preparation time; wins through protection rather than higher DPS. Items can be bought if craft mastery is absent. |
| Exploration | Follow a journal/map clue, prepare rope, establish a safe route and retrieve the ledger through a tool/skill task. | Rope/supplies and exploration time; avoids the sentry without receiving its combat loot. Route remains a useful shortcut. |

All reach the same foundational lesson through mentor interpretation or restoration, then practice it into an actual action/stance. Weather can later modify ledge cost with a permanent sheltered alternative; the first slice should not require waiting for a random weather window. Choose a modest skill threshold from baseline pacing tests rather than inventing a huge grind target in research.

**Implementation cost:** medium. Reuse quests/dialogues/actions/items/reading/conditions/rewards and existing travel/combat. Add a small versioned discovery record, risk preview and idempotent completion. A general tag engine, tactical grid, party system or offline combat makes this high cost and is excluded from the example.

**Acceptance:** three fresh test saves demonstrate different choices and costs, acquire/apply the lesson, fail/recover once without an RNG lockout, and reload mid-task and after discovery without duplicated rewards. Two counters must outperform each other on different authored situations. A player can explain the next lead, cost and expected consequence from visible text. Actual playtesting remains pending.

## Coverage checks, costs and open gates

**Discovery:** strongest verified leads are manuals, story actions, route information and authored quest access. Foundational access should have deterministic alternatives; rare loot can reward speed or variety. MR2's exact storyline RNG is unknown, so it does not justify random entry gates here.

**Skills/builds:** use-based mastery is well aligned with YAIRPG. Distinguish a useful specialization from a mandatory checklist. A global XP multiplier can shorten testing but does not create a martial/craft/exploration identity. The chosen first technique needs an actual target or action.

**Craft/world dependencies:** existing skills should support materials, tools, routes and combat preparation. Evolve supports studying differing world economics; detailed world modifier effects still need deeper source tracing. Avoid universal compatibility: later imported techniques should retain a stated cost/limit.

**Narrative/factions/companions/home:** Arcanum supports role/home tradeoffs; YC supports story/party systems; Proto23 supports home objects. Exact companion acquisition, upkeep, quests and faction relationship depth remain under-audited. First implement one mentor and a functional camp/workshop service; no roster or base-management empire is implied.

**Pacing/UI/accessibility/recovery:** no completion-time or balance measurements were made. Use time-to-next-decision and repeated-click count, not raw content size, in later playtests. Opaque gates need visible next leads; unlock summaries need search/filtering as content grows. Hover-only requirements, color-only risks and per-tick reactions are inappropriate acceptance shortcuts. Trimps' dedicated screen-reader source is a reference, not a verified accessibility score. Failure must state what was spent, what persists and how to try again. Automation should stop at danger/input exhaustion, not send players into an infinite death/rest loop.

**Offline/save policy:** local Jade Hollow currently has no closed-browser progress according to PROJECT.md; source-only research did not revalidate the whole loader. Keep that compatibility decision while adding content. Offline simulation is a separate engineering milestone, with deterministic safe-task accounting, clock changes, resource depletion, task completion, duplicate rewards, defeat and multi-tab behavior to verify. Do not quietly simulate first-time plot choices or resets.

**Reuse:** this dossier proposes design inspiration, no copied runtime/content. Concrete future code candidates are Schoko's quest ordering/recovery handling and GauTech's spell/stance unlocks. Both are YAIRPG-derived and need file-specific license/attribution checks, base-version comparison, save migration and rebuild/browser tests before reuse. Proto23 and The Climb GitHub metadata did not identify a license in this pass; public visibility is not permission to copy their code/assets. A full license audit is unnecessary unless concrete reuse is selected.

**Related dossiers:** REFERENCE_RESEARCH.md owns the upstream/fork baseline. RESEARCH_PROGRESSION_MAGIC.md was available and inspected; its knowledge/control/execution distinction complements the lesson chain. Consult RESEARCH_CULTIVATION_PATHS.md, RESEARCH_LITRPG_SYSTEMS.md and RESEARCH_ALTERNATIVE_POWER.md through RESEARCH_COORDINATION.md when delivered.
