## Schema evolution and legacy safety

Introduce pack metadata as optional before requiring a new reader. Do not change the meaning of expansion5–11 or simulation1–5 in place. A new save schema is needed when ratio/absence/operation state changes semantics; an actual implementation chooses its number after inspecting the current owners. Do not pre-reserve a guessed expansion12 while other lanes are active.

On load, validate old envelope, apply existing foundation/v0.6 migrations, map known legacy namespaces to pinned pack baselines without creating new rewards, and record which domains are legacy. Unknown retired state remains opaque. New-format import must decode, validate structure, resolve required pack/adapters, perform domain migrations and isolated loader preflight before the single publication point. Compatible absence can be dormant; active unresolved dependencies are paused, not discarded.

For database adoption, leave the original localStorage save untouched during the first migration. Copy into a new generation, read/validate it, then record the authoritative backend. On future load, use generation validity and explicit backend selection rather than whichever timestamp appears newer. If database access fails, offer the old saved generation as a clearly dated recovery choice, not automatic play from stale state. Cross-backend dual writes are not atomic. New compressed exports keep versioned decoding of current `YAIR-UTF8-1` and old base64 imports; older builds should reject newer required semantics clearly.

## Performance model and numerical limits

**F1. The current cap is boundaries, not actors or milliseconds.** `src/expansion_engine.js:advanceSimulation` processes up to512 scheduled boundaries, returns remaining time and `budgetExhausted`, and stops at blocking opportunities, waiting choices or sessions. Within one boundary, `src/simulation.js:advanceSimulationBoundary` scans jobs, conditions, people, events, event checks, pursuits, controllers and routines. Full state is cloned and validated; multiple controllers can act at one timestamp. 512 is no upper bound on total commands or CPU time.

**F2. Minute decisions do not scale to many long lives.** At one boundary/minute,512 covers512 game minutes =8h32m. One360-day year is518,400 minutes, needing at least1,013 calls at that cadence. At five-minute boundaries, a year still needs at least203 calls. At one boundary/day it fits in360 boundaries; one boundary/year makes a century100 boundaries, but exact jobs/events may add more. These are arithmetic scenarios, not measured gameplay throughput. Fifty controllers on the same cadence may share boundaries yet perform50 admission checks at each tick; staggered controllers can add distinct boundaries.

**F3. Some callers currently drain synchronously.** `src/main.js:advanceChroniclePlan` loops while budget is exhausted and time remains; the512-call budget does not by itself yield the browser main thread. Audit all callers before adding banked decades. An idle native timer path also has its own activation policy. A new scheduler must preserve every returned remainder instead of silently paying skipped time.

| Work class | Policy | Must preserve |
|---|---|---|
| Current body/combat/contact, exact material production, funded accepted jobs, expiring source/route/mandatory choice | Exact common-clock boundaries; visible decisions stop advancement | Inputs/health/stock/custody, participant occupancy, frozen outcomes, completion support, deadlines and cancellation |
| Named off-screen person with an exact commitment, pursuit or unique claim | Exact scheduled deadlines without periodic idle decision polling | Cause and real means; promote to active detail when player arrives |
| Named person without exact commitments | Deterministic lazy seasonal/yearly policy with bounded changes | Age, known goals, relationships, funds, presence; summaries are actual model outcomes, not invented history |
| Population, economy and distant faction branch | Aggregate counts/resource-flow policy, with conservation constraints and explicit event thresholds | No arbitrary free stock; no simultaneous exact and aggregate ownership of the same person/material |
| Unvisited instance | No mutable state unless a global event actually affects it; deterministic baseline plus materialized delta on first visit | Historical entry date/era and relevant global consequences |
| Closed game/offline bank | Separate selected production cap and subjective-aging policy | North star proposes no closed-game aging; current code does not establish that generic service |

Proposed initial performance targets, unmeasured: one active world,32 detailed nearby people,200 tracked coarse named people per materialized region and population cohorts for the rest;8ms work slices and a256-work-item sub-budget within the512-boundary ceiling. These are profiling fixtures/targets, not gameplay limits or timing guarantees. If one boundary exceeds the time target, splitting it requires an internal staged cursor; do not publish a half-settled causal instant. Build event-time indices before moving heavy pure calculations into a worker. A worker returns a plan at a sequence/revision; the main writer validates and commits it.

Lazy randomness must be stable across “one100-year jump” and “100one-year jumps.” Store per-world/person policy streams and the last processed epoch; bounded transitions/counters replace polling. A special first-clear, birth, death, unique-seat race or global war has a durable event/cause if later mechanics depend on it. A report can compress many ordinary changes, but cannot claim no noteworthy occurrence merely because its log was pruned.

## Risks and limits

| Code | Risk | Design response and acceptance limit |
|---|---|---|
| R1 | Layer order masks multiverse effects; personal exceptions erase other absolutes | Typed operators, targeted patches, declared collision domains; show actual exception consumer before claiming a guarantee. |
| R2 | Card format flattens distinct growth worlds | Shared cost/time/ownership compiler, family-specific signals. Concept insight, acting digestion, living Gu upkeep and blueprint manufacture remain different daily decisions. |
| R3 | Restore/retain duplicates goods or corrupts debts/jobs | Domain closure, epoch-specific reward scopes, exact reconciliation and one atomic generation. Full arbitrary historical causality remains unsupported until every affected owner has a restorer. |
| R4 | Missing private pack strands player or loses state | Preserve opaque namespace; pause unresolved active dependencies; restore/export with no silent relocation. Save-only loading is not code/pack installation. |
| R5 | Compaction erases meaningful facts or makes farming accidental | Separate narrative and authority, retain identity/claim/debt/observer state and chosen reset policy. Fully exact unlimited history is outside bounded browser storage. |
| R6 | Coarse world creates impossible unpaid labor or reveals private acts | Conservation-aware aggregates, exact paid deadlines, attributed reports and knowledge projection. Do not simulate rivals as omniscient. |
| R7 | Async persistence publishes early or races native autosave | One awaited command/save queue and writer owner; publish after transaction completion, fault/second-tab checks. |
| R8 | Browser quota/eviction breaks long-life recovery | Conservative budget, bounded generations, failed-write recovery and portable export. IndexedDB offers more room, not guaranteed indefinite retention. |
| R9 | Every idea interpreted as runtime-complete | Architecture homes are not implemented mechanics. New behavior families need handlers, pack requirements, connected consumers and playable proofs. |
| R10 | Infinite/open invention or impossible cheat collision | Authored templates first; unrestricted invention requires validated authoring/generated proposals. Contradictory absolutes need a selected resolution, not generic winner-by-JSON-order. |

The wider north star has an architecture home: body replacement/aptitude in person/body/operation owners; skill evolution/fusion/Concepts in family progression and research; shops/careers/romance/charters in funded offers, relationships and faction duties; hub returns and world barriers in edges/time policies; rivals/ancient plans/world wills in actors, situations and event causes; hidden stats/amnesia in knowledge and selective memory retention; cities/world ownership/mergers in instance graphs and scoped rules; deeds/legacy/rewards in claims plus operation epochs. This mapping preserves the ideas without asserting their mechanics already work.

Browser engines can provide deterministic authored text play and bounded local simulation. They cannot guarantee exact unlimited individual simulation, recover deleted device data without another copy, enforce tamper-proof local ironman, or invent coherent mechanics solely from unrestricted player prose. None requires abandoning YAIR's current UI for this milestone.

**P11. Cosmological scale is represented scope.** Add a cluster/layer graph and sparse materialized instances. An “infinite worlds” setting stores a generator definition and seeds for visited worlds; it does not allocate infinite instances. Existing finite-number checks in `expansion_engine.js` and `simulation_contracts.js` reject nonfinite values and numbers above Number.MAX_SAFE_INTEGER. Keep time/sequence/custody counts as safe integers. If exact huge quantities become playable requirements, use an explicitly versioned decimal/scientific representation and arithmetic adapter, with units and bounded precision. Infinity levels can be symbolic cosmology IDs/relations, not JavaScript Infinity or a universal combat multiplier. Cross-world feats remain attributed evidence, not automatic conversion of local ranks. This is a later selected numerical migration with its own rebuild/browser/save/reload/import gate.

**P12. Viewpoint and body are separate owners.** Leave the current player perspective unchanged. If soul or guide mode is selected, give controller/soul/life/body distinct IDs and scoped knowledge views; guide notes cannot grant a body's missing method or agency. Operations state which identity and memory layer they retain. Pronouns/presentation belong to identity; body capacities belong to body; local social eligibility belongs to faction/world rules. Pregnancy/childbirth or body-specific methods require explicitly authored timed bodily effects and voluntary enrollment, not a global stat modifier or demographics shortcut. Prove one body/knowledge change and actual action consequence with rebuild/browser/save/reload/import before generalizing.

**P13. Craft families share transactions, not identical products.** Extend native item identity/instance provenance deliberately for maker marks and meaningful item histories; stackable-item grouping must not merge distinct provenance or duplicate named artifacts. Repairs/reforging/disassembly resolve input ownership, loss and recipe knowledge atomically. Formation arrays own sites, living Gu own life/upkeep, machines own fuel/control, manuals own text/license, and clones own bodies. Assistants contribute paid real resources/capacity; mass production aggregates repeat work only with conservation. Use existing D1 alloy or manual production as the first selected proof, preserving its separate acceptance owner. Any changed item key/stack/persistence format needs migration plus actual crafting/consumer/save/reload/import evidence. These additions do not expand P1's first playable slice.
