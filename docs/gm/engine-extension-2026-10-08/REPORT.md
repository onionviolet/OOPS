# Engine extension study, 2026-10-08

Design proposal only. Read from the live dirty checkout; no implementation, build, gameplay test or accepted design decision is implied. [Assignment](../dispatch/engine-extension-2026-10-08/ASSIGNMENT.md) defines this lane. Start here, then read the [component inventory](COMPONENTS.md), [format proposal](SCHEMA.md) and [migration plan](MIGRATION.md). [Checkpoint](CHECKPOINT.md) preserves the result.

**The browser engine can support this direction. Extend its existing transaction, clock and ownership services, then compile world content into them. Do not replace the engine or promise that every future mechanic needs only a card.** Shared shapes make variants cheap after someone implements their actual behavior. A novel power interaction, a different body or a rewind still needs a handler with real consumers.

**F1. Much of the framework exists.** Definitions already become validated registries; actions stage costs and outcomes; the host writes the save before publishing native changes. There are world definitions, instances, visits, cargo contracts, attributed knowledge, powers, techniques, people, jobs, events and controllers. The static inventory finds **59 `*_host.js` files**, not 55. Many repeat command admission and presentation, but others connect real native combat, physical stock, local clocks or story consequences. Retain those adapters until equivalent behavior has been demonstrated.

**F2. The sketch understates existing behavior and overstates generic support.** The save already has a conservative **4 MiB shared-origin guard**. The biography already retains 64 recent moments and 200 annual summaries. Events already support chance, saved draws and `guaranteeAfter`. Conversely, `portableCarrierPolicy` is prose in the book roster, not an executable carrier interface. World-instance clocks currently require played minutes and frozen absence; ratios and autonomous yearly worlds are new semantics. The heir-save builder exists, but this source snapshot has no production caller. A generic `replay` transition is not historical rewind.

**F3. Use cards to describe contracts, not to invent guarantees.** Add typed rule resolution, pack manifests and a compiler over existing registries. Keep definition revision, live instance, player knowledge and display separate. Declare which rules override, combine or grant scoped exceptions. A cheat can be absolute and cost-free if selected; its guarantee must name its domain and collisions. A private pack disappearing must preserve its state, including jobs and claims. If the player is inside it, pause mutation and offer restoration/export, rather than silently teleporting them home.

**P1. Start with one visible home-world rule.** First wrap the existing Frontier definitions as a manifest with identical IDs and defaults. Then show one learned place rule in the existing Notebook and make it alter one opt-in preparation action's actual cost. Leave the vanilla opening and native combat semantics intact. This is a proposed first implementation packet, not authorization to build. Each later packet has its own rebuild/browser/save/reload/import gate.

**R1. Long lives need bounded state and bounded work.** Preserve authoritative claims, relationships, debts, custody, RNG and unfinished work; compact narrative presentation separately. Move persistence to asynchronous IndexedDB only after the durable publisher can await commit. Split visited-world state into revision-pinned deltas, and compress storage/export behind a versioned codec. Do not simulate a century through minute controllers: 512 one-minute boundaries cover only 8 hours 32 minutes, while a 360-day year contains 518,400 minutes. Use lazy aggregates where individual events are not promised, and exact scheduled deadlines where they are.

No browser limitation rules out authored text worlds, factions, long lives, strong cheats or bounded rewinds. Exact simulation of unlimited people and unbounded history is infeasible; arbitrary free-form invention needs an authoring or generation service. Local ironman cannot prevent someone editing their own storage. These limits need explicit product choices, not a different graphics engine.
