# REPORT: game cheats and cosmology gaps

Section G is complete as a documentation proposal. The appended catalogue has **56 rows across 32 games**, with **33 in-fiction** and **23 player-layer** rows. It covers the requested breadth without treating every acquired mechanic as a supernatural cheat. Source reading was a targeted sweep of our derived dossiers, not a new whole-game audit or playthrough.

**F1 external holders:** the framework can describe character powers, but it does not identify the carrier of a save snapshot, account unlock, run seed or player-held design library. Calling every external facility Concept or meta would invent fictional authority that these sources do not demonstrate.

**F2 activation is separate:** an item or body can arrive without the correct user, fuel, target, permission or place. Spirit Ashes need a monument; bionic skill grants need an installed module; remnant-soul restoration needs support. Backing alone cannot determine Works. This agrees with Section M F2.

**F3 composites need boundaries:** a trigger, an effect and a lasting consequence can have different backings. Noita's body status triggers a world conversion; losing that status is not shown to reverse the conversion. Resets preserve different field sets. This agrees with Section M F6.

All classifications, foreign-world predictions and adaptations below are proposals (I). No gameplay, accepted decision, cosmology rule, build, commit or private save was changed. CHEAT_COSMOLOGY.md remains untouched by Section G.

## Evidence and scope

The catalogue's Source column gives repository paths and exact line locators. JSON ID lines select the associated finding, not merely the identifier as proof. Shown means the dossier records inspected code/data; it does not mean this session ran the game. Stated means testimony, manual, tool description or source documentation. The dossiers' edition and unresolved-execution qualifications still apply.

Player-layer means the player/profile/session holds the facility. It can have fictional framing without being a transferable character skill. Increlution calls its replay a loop; Rogue Legacy uses heirs and an Architect; Sunless uses successor captains. None of those statements proves that the new character holds every old memory or that every local NPC receives the same facility. Planescape revival is in-fiction, while loading a save would be a separate player-layer operation.

The RimWorld director row is a boundary candidate: scheduling occurs outside the pawn. The inspected incident path is shown, but a player's ability to arbitrarily choose events was not traced. It is not counted as a pawn's personal power. Auto-eat and wizard-supported Permacast are interpreted as world actions with support, rather than supernatural time powers. These classifications can change with stronger fiction evidence.

The ONI snapshot row records actual save/load structure, not a diegetic regression ability. Disco's debug override row records code presence, not a demonstrated retail menu or a detective's free choice of dice. Neither row treats source access as fictional omnipotence.

Only the Factorio blueprint row uses (G). The existing dossier proves supply/network constraints but does not trace blueprint-library ownership or inter-save access. Its citation records that local evidence boundary, not independent proof of the G claim. The general layout-library claim is deliberately bounded; no blueprint export, source recovery or gameplay test was added. No other missing mechanic was filled from general franchise memory.

The required comparison is local and finite: games fit differently. No source in this pass demonstrates these exact powers crossing into another game's world. Every such portability prediction below is inferred, including predictions that a carried physical part would work.

### Predictions that fail or remain undefined

**F4 world-law origin versus lasting product:** Noita's shift script has no Lua reversal and its cooldown is not expiry. This contradicts treating it as a temporary personal perk. It does not prove cross-world mutation. A card needs separate body trigger, world effect, affected matter and persistence policy. Source: `docs/research/noita/PERKS_FINDINGS.md`, K1/K4 and the catalogue's corresponding rows.

**F5 item transport versus function:** Elden Ring's Bell/Ash support does not supply a monument. ONI's skill module can be removed, and the studied ungrant path does not prove preservation of separately learned mastery. Kenshi's powered prosthetic can require a destination maintenance ecosystem. These are concrete tests of the claim that carried items work: the carrier may survive while activation stays Blocked or Weakened. Sources: catalogue Spirit summons, Installed skill grant and Specialized prosthetic rows.

**F6 knowledge versus truth:** Noita's recipe reconstruction is a community tool, not recovered binary equivalence. A remembered seed recipe from a different algorithm version can fail. Disco's voices can disagree, and serialized thought effects differ from older descriptive item text. Knowledge backing predicts a record's carrier, not a correct answer. Sources: catalogue Seed foreknowledge, Inner faculties and Thought Cabinet rows.

**F7 continuity versus reload:** Rogue Legacy preserves purchases but clears run flags; its Architect reuses a map with selected content resets. Sunless Sea chooses a chart, Skies copies a supplied latest saved world, and Increlution deletes possessions/buildings while retaining specific ledgers. A generic Soul or save label cannot settle which entity persists. Sources: catalogue lineage, Architect, legacy and instinct rows.

**F8 offline time is not one power:** Bitburner estimates from prior activity, Melvor runs catch-up ticks, and Upload Labs banks acceleration. Increlution's catch-up can spend life. Closed-tab progress can be a simulation policy, paid time reserve or diegetic auto-cultivation. None entails universal offline safety. Sources: the five corresponding catalogue rows and `docs/research/open-idle-games-2026-10-09/REPORT.md`, F4.

### Compatibility modes still fit, if scoped per function

| Mode | Concrete proposed test (I) | What the label cannot decide |
|---|---|---|
| Works | A fitted prosthetic with compatible mechanics and maintenance performs its declared function. | Destination feasibility is untested; transport alone is insufficient. |
| Reread | A destination reads a retained instinct bonus as local practiced speed, or reads a boon under a local stat name. | Relabeling does not grant memory, executable mastery or target eligibility. |
| Rechannel | Local power feeds a supported booster, or local materials sustain an imported wand function. | Conversion needs an authored interface, efficiency and cost; names alone do not establish equivalence. |
| Weakened | A supported caster has insufficient mana production for sustained Permacast; the supported effect becomes intermittent. | Limits can be rate, range or eligible targets, not just a blanket damage multiplier. |
| Blocked | Spirit summon without monument, missing module slot, or unavailable external snapshot access. | Blocked activation does not require erasing the carried item, record or already-made bodily change. |

No new compatibility mode is required by these examples. An optional state **unknown/unresolved** is useful for incomplete evidence, but it is a review state, not a sixth fictional mode. Record transport and each executable effect separately. A dormant function can retain identity and custody.

Verse equalization can map fuel, targets or output units only when the scenario supplies that converter. Level sync does not import an account library, grant archive permissions or restore deleted history. None of the ordinary game rows proves treaty rates, a universal scale or automatic home-world supremacy. Optional converters stay possible under the accepted world-specific rulebook.

## Proposed new backings or card fields

The smallest option is to keep the eight backing names and add a substrate/access record. Adding more backing names is also possible. Both are proposals, not new global requirements.

| Option | Candidate backing/substrate | Needed distinction | Cost |
|---|---|---|---|
| O1 | External player memory or record | Player identity differs from character identity; notebook/library can be lost, copied or become stale. | Author must decide when information enters the character's knowledge and who can observe it. |
| O2 | Save snapshot or branch anchor | Save loading restores a recorded domain; regression needs a fictional actor, trigger and carry map. | Requires explicit snapshot/event order and identity mappings; not a new persistence implementation. |
| O3 | Run seed plus generator version | Seed is an address/parameter, not fuel or universal fate authority. Resolved recipe/map and RNG stream are different. | Preserve version and resolved result, and state when foreknowledge stops predicting. |
| O4 | Profile/run ledger, including meta currency | Source-Files, completion flags, multipliers and spendable currency are different fields; a balance is not by itself authority to reset. | Record owner, earning/spending consumer, reset boundary and access scope. |
| O5 | Infrastructure/network/place | Bell monument, gene machine, wand interpreter, wizard support and body maintenance can be dependencies of Soul/Body/Item powers. | More component-level preconditions instead of one short label; infrastructure need not be a ninth metaphysical category. |

Extend the existing placement card rather than replacing it:

| Existing field | Optional addition | Why games expose the gap |
|---|---|---|
| Identity | Game/build/mode, Kind, fiction holder, player/profile holder, provenance. | MR2 and Achra evidence is demo-only; Progress Knight Quest differs from original. |
| Mechanism | Activation, eligibility, contact, support and actual downstream consumer. | A learned spell, granted skill and equipped source are different. This is Section M O1/F2 data. |
| Backing | Carrier, authority, fuel and anchor for each component; dependencies marked AND/OR, not just comma-separated names. | A module AND body slot is unlike item OR spell access to a shared ray effect. This is Section M O4/F6 data. |
| Feats and limits | shown/stated/inferred/G plus edition and source key; retain anti-feats. | A tool algorithm or manual rule is not launched behavior. No global source ranking follows. |

| Meetings | Ordered effects and result ownership, including effect lifetime after source removal. | Shift conversion, removal of booster and corpse possession have different aftermath. |

| Absorption | Fictional acquisition/observer/NPC policy, original public variant and exact promise test. | External save controls do not become enemy regression powers until a fictional mechanism is authored. |

These are also likely registry data if an engine implementation is later authorized. This pass authors no schema or migration. More fields cost authoring time; minimal records can leave named unknowns rather than inventing answers.

Enemy use follows the same fictional card after adaptation, with its own access and tells. An NPC Echo Anchor holder may remember a fight; an ordinary NPC does not gain the player's actual filesystem or save menu. A blueprint enemy still needs builders and stock unless its selected cheat genuinely supplies them. This preserves the library's same-card approach without treating every UI affordance as an actor feat.

## Disputes and unresolved findings

No existing rule or row was rewritten. Existing backing claims such as item portability and Knowledge's always-travels wording are incomplete without carrier, support and eligibility. Section M already identifies the A.I. Chip's Item/Soul example mismatch; Section G does not silently repair it or use it to infer a general item rule.

The game's own counterexamples stay intact: Disco contains competing assessments; Planescape distinguishes historical memory-loss testimony from current retained memories; Increlution clears buildings; Theory of Magic preserves characters instead of forcing rebirth. Fictional framing is not evidence of universality. The 56 game rows are not a proposed final roster or an implementation queue.

Open: blueprint ownership/source trace, exact diegetic status of marginal UI mechanics, full patron terms, unreviewed native effect internals, foreign-world support maps, reset/temporal identity maps and human acceptance of adaptations. These are evidence/design gaps, not incomplete requested documentation.
