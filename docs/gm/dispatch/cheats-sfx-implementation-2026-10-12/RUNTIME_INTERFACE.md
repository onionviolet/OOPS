## State and calls

Exports `createWorkLedger(actorId='player')`, `validateWorkLedger(state)` (true or throws), `migrateWorkLedger(raw,actorId='player')` (missing data creates schema 1, valid existing data cloned, malformed/future schema or actor mismatch throws), `transitionWorkLedger(state,command,context)`, `observeWorkLedgerCraft(state,evidence,context)`, `modifyWorkLedgerChance(state,baseChance,context)`, `modifyWorkLedgerQuality(state,baseQuality,context)`, `workLedgerPresentation(state,context)`.

Transitions/observer return `{state,events}`; input state remains unchanged. Root alone assigns the returned state after native settlement. Invalid or stale calls throw. Modifiers return `{value,event:null}`; application events are published by observer only after successful native inventory/material settlement. Context `{actorId,locationId,alive,busy}` requires exact saved actor, `alive:true`, `busy:false`; commands need `locationId:'Village'`. Native consumer modifiers work at other supported native stations. Commissions only complete at Village while connected.

State fields: `schema:1`, `actorId`, `sequence` (nonnegative safe integer), `connection:'offered'|'refused'|'connected'|'disconnected'`, `points` (0, 2, or 4 in this finite two-commission proposal), `precisionKnown`, `assistUnlocked`, `commissions:{meal,hilt}` each `{status:'available'|'accepted'|'completed'|'claimed',acceptedSequence:null|positive integer}`, `settings:{effects:'full'|'reduced'|'off',sound:boolean,presentation:'inline'|'margin'}`, `receipts:[]`. Defaults reduced motion, no sound, inline. Native schema remains unchanged; add optional saved Work Ledger state and explicitly test missing-property import. No extra gameplay clock, resource, inventory or command dispatch exists in this module.

Command `{action,sequence}` uses exactly `state.sequence+1`. Actions: `accept`, `refuse`, `disconnect`, `reconnect`, `accept-meal`, `accept-hilt`, `claim-meal`, `claim-hilt`, `learn-precision`, `unlock-assist`, `settings`. Settings command adds `payload` (or `settings`) with all three fields. Refusal keeps later opt-in available. Each commission requires separate acceptance, completion and one claim; claim yields 2 points. Permanent precision method costs 2 after meal claim. Assist lease costs 2 after hilt claim. Commission success alone grants no points/power. Disconnect/reconnect changes lease availability; taught method remains.

Receipts are plain `{id,type,motif:'seal'|'guidance'|'closing',actorId,sequence,text}` with optional numeric `before,after` on applications. `events` contains only newly committed receipts; UI should animate these after settlement. Retained application entries replace the prior same-type entry. History keeps last 40 entries solely for bounded save/presentation storage, never to limit benefit use. No names, secret truths or hidden NPC intent are projected. Presentation provides `{state,available,canWrite,reason,commissions:[{id,title,recipe,requirement,status}],benefits:{precision,assist},actions:[{action,label,enabled}],settings}`.

## Exact native consumers and evidence

- Meal: `cooking/items/Roasted rat meat`, existing `src/crafting_recipes.js` recipe requiring 2 `Rat meat chunks`, output 1, native chance 0.7 to 1. `src/main.js:use_recipe` items branch owns availability, random outcome, materials, inventory and XP. Capture native base chance; replace local `success_chance` with `modifyWorkLedgerChance(...,{...context,category,subcategory}).value` before stochastic result/XP estimation. Method adds 0.15 probability, up to native certainty 1, for native item recipes only.
- Hilt: `woodworking/components/Short hilt`, existing component recipe accepts one `Processed rough wood` (or other recipe-supported wood) and produces actual hilt. Different category from meal. In components branch capture each rolled quality then `modifyWorkLedgerQuality(...,{...context,category,subcategory,qualityCap:selected_recipe.get_quality_cap()}).value` before `crafted_items`, `all_crafted`, rarity XP and inventory-key construction. Lease adds 10 quality points up to this native recipe's component cap, only woodworking/components while connected. This affects actual output and its existing equipment consumer, not merely a display stat.
- Observer receives `{sequence,category,subcategory,recipeId,attempts,successes,outputs}` directly from the local native branch after inventory addition and material consumption. Capture sequence before native work as `state.sequence+1`, and do not derive commission evidence from `game_stats.total_crafting_successes`. Item evidence uses attempted/successful counts and final count. Component evidence uses actual craft count and summed published output. Zero attempts should skip observation; failures may observe with zero successes/outputs but never complete. Prior/pre-acceptance/replayed evidence cannot complete a commission.
- For successful native applications add item `{chanceBefore,chanceAfter}` or component `{qualityBefore,qualityAfter,qualityCap}` from actual used local values. Observer independently matches the module's bonus formula and only publishes application guidance when output and successes are positive and the modifier strictly improved its value. For multi-component batches choose a concrete improved output's before/after tuple. Repeated supported crafts after commissions are claimed still receive application guidance. At recipe certainty/cap no bonus event is emitted. The modifier creates no resources or alternative crafting routes.
