# Common rules for the skill-growth Codex runs (2026-10-10)

Prepared by Claude Code at Weibao's request: "There are types of levels
and more? ... we can also run new audits accordingly, and also audit the
RR stuff with the polite downloaders ... Send out codex accordingly."

Read first: AGENTS.md, PROJECT.md, `docs/SKILLS_AND_TALENTS.md` (the
sections "Ways to grow, and what a level means" and "Level scales"), and
`docs/research/skill-growth-2026-10-10/READ_HISTORY_AUDIT.md` and
`UNREAD_AUDIT.md`. Use the codes there: growth models G1 to G40, level
meanings L1 to L23, scale shapes S1 to S14. Propose new codes as
G41+, L24+, S15+ with your run's prefix in the name (for example
"G41 (C1)") so runs don't collide; Claude will merge.

Rules:
- **Unbiased lens.** Report sources as they are, contradictions included.
  Label every claim READ (you read the text this run), STATED (blurb,
  wiki, synopsis) or MEMORY (recall). Don't invent general rules from one
  source.
- **Considerations, not specs.** Findings are proposals. No code changes,
  no build, no commits, no edits to any file outside your own output
  paths. Don't touch `docs/research/novels/royal-road-2026-10-10/` (another
  session's harvest) or user saves.
- **Sealed secrets.** If a YAIRPG world has sealed secrets
  (`docs/worlds/WORLD_SECRETS_AND_DISCOVERY.md`), refer to them by ID and
  status only in your report.
- **Copyright.** Raw downloads stay in gitignored
  `docs/research/novels/skill-growth-2026-10-10/`. Reports paraphrase;
  at most one short quote per source.
- **Polite client.** Follow "Be a polite client" in
  `docs/research/novels/SUBAGENT_RUN_RULES.md`. Stop a host for the run
  on the first 403, 429, Cloudflare or CAPTCHA. No logins.
- **Save early.** Write your report file after the first few sources and
  extend it; keep a CHECKPOINT section at the bottom listing done,
  in progress and remaining, so a resumed run can continue.
- Style: plain short sentences, no em dashes, tables where they help.
