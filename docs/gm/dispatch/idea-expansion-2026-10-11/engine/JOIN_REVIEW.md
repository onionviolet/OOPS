## C1. Correct conservation scope

G5-08 revision 1 could read as a global conservation rule. Revision 2 narrows it
to ordinary transfers, reservations and incidental replay defects. Explicit
source/world/cheat creation, destruction, duplication and restoration must execute
their promised effect, including free or inexhaustible effects where actually
supported. This reconciles G4-10/11 and G3-012's infinite-production case; G2's
precise creation/duplication mechanism is still pending.

A transformation manifest declares original and resulting item/actor identity,
owner/holder, state domains, provenance, cause, repetition allowance, external
exports and claim scope. A legitimate copy may have a distinct identity or
selected shared link. Generic once-only suppression cannot nullify a promised
repeatable copy. Conversely, failed publication must not create half a copy or
spend only part of its actual declared inputs. Ordinary trade and inheritance
retain their own transfer rules unless an explicit exceptional mechanism changes
them. No global scarce-energy debit, duplication ceiling or donor damage is
invented by this join.

### Selected runtime-card owner, not arbitrary source properties

G2-029 identifies a genuine schema seam: acquisition records have inspected
fixed provenance meaning. Charge/anchor/ruleset/lineage/selected result/runtime
claim state belongs in a validated optional owner or explicitly selected schema
extension. Reuse an existing owner when it already represents that state. Add only
the selected card's missing typed fields/consumer and corresponding migration;
this does not require an all-cheat engine before the first functional packet.
Unknown or unsupported data preserves original state and grants nothing.

A packet should first pass the source → caller → native consumer → persistence
→ rebuilt runtime proof ladder in C2. For example, one perfect-crafting function
can patch its exact native recipe/output consumer and durable product receipt;
it does not require generalized conceptual-law infrastructure. A future-sight
packet demanding native crafting outcomes, conversely, must bind those exact
native random draws rather than extrapolate from expansion simulation alone.

One concrete interface correction: G2-008's engine description names
`remainingMinutes`; inspected `advanceSimulation` currently returns `remaining`,
`stoppedAtChoice` and `budgetExhausted`. Treat the card's wording as proposed runner
contract, not an existing export shape. A future runner adapter must quote and
convert the current result explicitly. No runtime source was changed here.
