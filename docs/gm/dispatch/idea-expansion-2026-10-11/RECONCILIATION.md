## Two audit passes, then selected implementation

Design expansion preserves known variants and asks what a feature should let a
person do, combine, learn or change. Implementation audit examines definition,
actual caller/effect owner, native UI, saved fields/publication and finally
behavior. This wave supplies source/planning evidence and named future cases.
It runs no runtime, build, browser or save checks. Existing external wave
evidence remains qualified to that wave's exact revision and scope.

G8's [implementation audit](micro/REPORT.md) retains native titles rather than
acting on a stale absence claim. It distinguishes native lifetime titles from
issued simulation titles, earned skill XP from effective bonuses, growth branches
from bookkeeping, and equipment/status contribution from actual body/source
functions. The XP-cap `typeof ... === Number` guard is source-inspected
unreachable. Active-effect rejection/expiry and bulk milestone ordering are
specific consumer hypotheses with reproduction gates, not blanket runtime
failure claims. None was repaired by this planning wave.

The proposed queue separates world/source qualification, actual identity/native
bindings, suspenseful starts, micro-progression, lived-material journeys, real
exceptional functions, prior VFX, causal clocks, parallel histories/archives,
alternate lives and revision completion. Independent ready content can proceed
while a different adapter is unresolved. No requirement to build a universal
engine or every possible body before qualifying a conventional start.
