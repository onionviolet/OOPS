# World-specific drama and player control

2026-10-14. **PROPOSAL ONLY.** [P5 D9](../p5/D9_STORYTELLER.md), [P11 context E/W/Q/K](../p11/CONTEXT.md), [P9/P10 profiles](../p9/PROFILE_RULES.md), [P15](../p15/CHECKPOINT.md) and [E7](../../../../emergent/E7_OBSERVATION_AND_MYSTERY.md) retain eligibility, pacing, laws and wording. P16 adds player-facing control over generated content and explicit separation of presentation, consequence and source premise.

## T1: difficulty, tone and intensity are separate axes

| Axis | Reachable settings / effect | What it does not silently change |
|---|---|---|
| Prose tone | Cozy, humorous, solemn, eerie, grim, terse, neutral; local voice | Actual wounds, law, facts, certainty or hidden truths |
| Drama frequency | Quiet residence, frequent social contact, adventurous, volatile; world-local pacing | Pending occurrence/draw, hard eligibility or calendar semantics |
| Mechanical difficulty | Counter complexity, planning horizon, affordances, assistance, competent opposition | Arbitrary NPC scaling, obligatory cost on a strong benefit |
| Consequence policy | Recovery, reversible setbacks, severe local loss, explicitly selected terminal stakes | Ordinary defeat becomes death without a selected supported threat/policy |
| Canon/premise | Source-faithful, changed relationships, peaceful AU, divergent institutions | A different premise presented as unaltered canon |
| Participation/autonomy | Observe, manual response, player-defined delegation/standing orders | Authorizing payment, deletion or irreversible choices from a text preference |

Compose them: grim prose with gentle consequences, cozy retirement in a dangerous canon world, mechanically difficult diplomacy with no combat, a generous high-powered world with complex research, or bleak AU with strong accessibility. Defaults belong to each selected world/branch. None is a forced good/bad binary or a fixed once-use policy.

**First slice T1-A:** optional Village future-card preference for quiet/social and one presentation-intensity filter using P3's integrated eligible-selection seam and D9 where selected. Hard content veto remains zero after weighting. Store settings/cause and apply only to future admissions; retain already committed card/terms. Cost medium; dependencies: integrated P3/P1, public content tags reviewed by P15/P13, explicit owner for pending decisions. Broader mechanical difficulty is a later consumer, not proved by different wording.

Source-respecting controls can soften a description without changing a source event. If the player wants a world without that event, offer an explicitly authored AU or omission policy with a real state transition. Do not require rejecting all canon play to use a comfortable interface.

## T2: skip, veto, favorite and replay mean different operations

| Control | Proposal meaning and first bounded proof |
|---|---|
| Skip prose / compact | Hide expansion text while preserving known choices, costs and actual consequences; keyboard control returns focus to the next action |
| Veto future content | Exclude tagged families before selection using a safe declared setting, with a fitting quiet/alternate outcome; no secret-derived tag list or existence leaks |
| Decline current offer | Execute the owner's actual refusal/expiry choice; hiding a card alone does not settle it |
| Favorite | Pin a known account/person/motif for access; optional future preference weighting is distinct and explicitly labelled |
| Replay reading | Render the same saved account/performance record without new rewards, effects or draws |
| Replay simulation | Create an explicitly isolated replay/fork under timeline owners; declare retained/lost domains before commitment |
| Revise authorship | New edition or clearly editable metadata; preserve earlier performed/received versions |

**First slice T2-A:** one known event's expand/compact, favorite and read replay controls, with safe persistent metadata and an existing decline route left visible. Cost low/medium; dependencies: actual admitted account, UI/knowledge owner and optional metadata schema. Future veto uses T1's selection integration, not a cosmetic hide. An intentional new attempt/reset remains reachable through L1/T5, distinct from read replay.

## T3: accessibility does not require fictional disability

Plain-language or short descriptions; font/spacing and screen-width use; keyboard navigation with stable focus; screen-reader labels and optional announcement batching; no color-only confidence; reduced motion/effects-off; pausable/untimed reading; recap and names/relationship reminders; alternative sensory description; explicit cost/commitment wording; optional content-intensity controls. Preferences can be per player, world and branch with visible precedence. A strong player access preference wins over a fictional narrator's elaborate style.

**First slice:** I1's return bundle exposes brief/full views with semantic headings/buttons, selectable text and predictable unread announcements. No mandatory timer to read or sudden focus steal. Cost low/medium; dependencies: I1, current UI settings/panel owner. Future navigation/reading proof at 1366x768 and 1600x1000; mobile deferred. Never encode secret truth in aria-labels, titles, hidden DOM, category counts or debugging reasons.

## T4: surprise is opt-in depth, not a permission maze

Support targeted spoilers, spoiler-safe names, preference-filtered surprise, deliberate seed replay and player-selected stronger drama where the world supports it. Keep the input small: show a short default and optional advanced controls rather than demanding setup before ordinary play. Player-layer notes may record a prior revelation while a new character still lacks the in-world route. Favorite/veto settings are not evidence that this character knows hidden canon.

**First slice:** known content receives a plain selection explanation using public predicates and the player's setting; hidden candidate details remain absent. Cost medium; dependencies: T1, KnownContext, P15 text. Sealed content disclosure requires its authorized route or an explicit unseal request for that secret/world, not a generic debug button.

Current feed provides semantic controls/focus preservation, not the new preference/replay suite ([audit F7](LIVE_AUDIT.md)). Proposed controls do not authorize deleting or archiving any live save.

All future gates OPEN: hard veto actually prevents admission; filters expose no hidden facts; no draw from preview/preferences; pending truth stable; replay pays nothing; refusal/skip distinct; favorite pins do not drop live references; exact metadata and next draws through save/import; source/branch/settings precedence; real keyboard/screen-reader/desktop acceptance. A storage/queue bound must aggregate or pause safely, not impose a global content-repetition limit.
