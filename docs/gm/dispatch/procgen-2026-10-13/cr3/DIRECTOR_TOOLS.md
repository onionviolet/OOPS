# CR3 director and developer tools

Status: PROPOSAL ONLY, 2026-10-14. Extends root TL1–TL4. Tools run only in an explicit developer entry point with synthetic fixtures and disposable storage. They are excluded from normal play. P2 read-only source audit is in [REPORT](REPORT.md); P18's story QA remains a related owner, not a chemistry implementation dependency.

## TL1.a: recipe sandbox with reproducible snapshots

Create a separate local developer page/CLI that imports the resolver's pure law modules and validated synthetic fixture packs. Its entry point has no native character, save storage, live inventory, autosave, import/export-save or production command bridge. A normal build must exclude this entry point and its developer fixture/trace modules. A hidden button, URL query parameter, CSS visibility or a player cheat is not the separation boundary.

The sandbox edits inputs/quantities, ordered supported process, station/context, maker control, route and a fixture observer. Compute resolves on a clone. Display accounted allocations, retained catalysts, product/byproducts, dose/consumer, typed cause trace, rule conflicts, unresolved fields and known-versus-truth projections. Show unsupported operations as unsupported rather than approximating them with P2's oral law. P2 preview can support the first four-ingredient fixture; broader operations require their actual adapters.

At 1366x768 the developer workspace has fixture/input editor on the left, ordered procedure and context in the center, selected result/trace on the right; bottom pins baseline and current diff. At 1600x1000 compare two results side by side. No mockup image required. Each result records fixture seed, retained generated truth revision, law/pack/resolver versions, normalized intent and committed-draw fixture refs. Recompute same snapshot gives same result. A separate New fixture action may generate a new synthetic world, never reroll a retained fixture on preview.

Sandbox truth display is for permitted original test fixtures. Sealed packs default to ID/route/status-only traces even here. Debugging access to sealed files does not authorize disclosure to Weibao in this tool or a report. Unsealed fixture truth may be displayed; actual sealed truth requires his specific unseal request. Raw sealed keys, seeds, source phrases, exact target counts and cause-trace payloads do not enter public screenshots or downloadable reports. Automated leak cases can compare protected values internally and output assertion ID/pass/fail only.

No Load my save affordance. A director can reproduce an issue through a hand-authored minimal fixture or sanitized permitted replay package, without inspecting a private save. Pack selection is an explicit local developer action. Sandbox output never creates player stock, discovery, XP, orders or a new normal-play save.

## TL2.a: reachable products, dead properties and feasibility

Coverage manifest declares exact world/law/pack revisions, allowed quantities, process depth, station/capability context, available supply routes, initial resources, time/fuel bounds and any authorized exceptions. Distinguish **resolver-legal**, **acquisition-reachable**, **consumer-useful** and **observer-discoverable** products. These counts answer different questions. A legal combination with no ingredient route is not presently reachable; a paid route with insufficient starting funds may have a lawful earning path, which must be part of its witness.

P2 permits bounded whole packs and two processes; even that space should be scanned deliberately, rather than every tick. Enumerate bounded domains exhaustively when practical. Else use declared stratified/boundary sampling, property classes or constrained search, and label counts as lower bounds with exact coverage. No claim of “all products” from pairwise combinations or random sampling. Exact canonical identity and equal-effect equivalence are separate metrics; P2 proportional scaling changes identity despite equal normalized payload. Approximate grouping is a report option and never rewrites player stacks.

Required report rows:

| Code | Metric / actionable output |
|---|---|
| DC1 reachability | Count within the declared domain, witness acquisition/process/consumer path and status for each unsealed class. Sealed recipes give ID/status only and no publicly revealing aggregate changes. Cyclic acquisition gates without a starter route are flagged, not silently populated. |
| DC2 dead properties | Declaration → selectors/transforms → product projection → executable consumer dependency graph. Distinguish never read, read only for appearance, read only on excluded route, and read but never able to influence a result in this domain. A logged field is not a mechanical consumer. |
| DC3 ingredients | Ingredients with no reachable use, redundant supported role or a dominated known outcome under declared objectives. Include price/acquisition/context/exact-identity and rare exceptions. “Never worth using” needs all those domains; sampled Pareto dominance is a suggestion, not a universal conclusion. |
| DC4 interaction gaps | Exercised quantity/ratio boundaries, exact/profile slots, traces, process order, scale, route/body, context, generation revision and contradictory-rule cases. Pairwise coverage does not prove higher-order interactions. |
| DC5 output health | Useful product classes, no-response products, unresolved model cases, missing consumer adapters, conservation failures and saved-revision/reference failures. A legitimate inert result is not a defective generator merely because it lacks a buff. |

For generative species/worlds, scan a declared seed corpus and keep witness seed IDs in restricted machine evidence. The counts describe that corpus, not every possible save. A promised discoverable recipe needs a feasible saved witness and an allowed observation path. Large/open spaces remain reachable through supported laws without forcing a finite completion checklist.

## TL3.a: conservation and exploit fuzzing

Use generated state-machine command sequences over synthetic holders/jobs. Operations include supported acquire/mix/use/reserve/cancel/settle/transfer/split/dilute/separate/reprocess/pack-change/save/reload/import. Today P2 split/dilute helpers can be source probes only; they are not real UI operations or complete transformed-product records. Generated separation, catalyst handling, alternate routes and multi-stage cancellation wait for their actual operators.

An independent ledger oracle checks each conserved domain: constituent amounts and trace remainders; unique identities; charge/source energy; currency and paid obligations; object/catalyst custody and capacity. Record lawful sources/sinks, transformed destinations and emissions. Pattern information may copy under its law without duplicating the material carrier. Declared creation/duplication cheats are explicit oracle exceptions with their own payer/limit adjective; lawful powerful behavior is not automatically an exploit.

Search loops with positive unaccounted mass/charge/currency/identities or duplicated catalyst custody. A retained catalyst remains a real token unavailable to simultaneous jobs; washing/returning it cannot also create a sold copy. Legitimate trade profit is not a conservation failure. Check separately for double payouts, repricing/rounding loops, unbacked sale demand and unsupported arbitrage amplification. Distinguish economic tuning from a reproduced accounting defect.

Adversarial cases: almost-zero traces, exact rational splits/rejoins, maximum supported quantities, same-ratio scale, competing rules, scarce catalysts, full receivers, two orders sharing stock, stale context, writes failing before publication, post-write render failure, duplicate settlement/cancel, future revisions, missing source products and exposure after source consumption. Compare equivalent legal clock chunkings when the scheduler claims equivalence. Repeated preview/view switching must not consume IDs/draws or identify a product. Product truth stays fixed across observer changes.

Minimize a failure to the smallest fixture and command sequence. Output defect ID, operation boundary, conservation-domain delta, affected revision and reproducible command refs. Public findings contain no sealed payload. One witness demonstrates a defect; a passing bounded corpus proves only its tested domain. Persist the failing seed/trace in restricted fixture storage, not personal saves. Add a regression for each confirmed defect after authorized implementation.

## TL4.a: versioned ingredient packs

Pack manifest: stable pack ID/version, world/continuity, source/evidence refs, original versus adapted classification, compatible law/resolver/consumer revisions, typed ingredient/role/process/property declarations, public knowledge projection and sealed-resource reference policy. Public source uses original names and permitted attribution; private direct adaptations remain in their existing private pack route. No raw novel text or private note quotation in authored data.

Lint before activation: typed units/bases, fractions and transformations accounted, valid references, executable consumers, exact/conserved identities, supported process operators, coherent generated families, feasible acquisition, contradictions, projection leaks and revision retention. Agent-authored packs include the same cards and locators as human-authored packs; authorship does not grant truth or execution authority. Pure data cannot run arbitrary JavaScript or read files/network/saves.

Switching a pack affects future admissions under an explicit enrollment policy. Existing ingredient truth, products, learned methods, jobs and exposures pin their revisions. Retain the needed old interpreter/definitions, or choose an explicit migration or dormant preservation route. Removing a pack never silently recomputes saved chemistry, discards stock, gives identification or turns an unsupported job into a free refund. A dormant job retains escrow and a safe recovery route; reinstall restores supported access without duplicated settlement. Invalid pack/unknown meaningful revision rejects before live publication.

Sandbox fixture switching is independent of normal gameplay pack installation. These documents do not authorize installing or switching a live pack. Root integration selects the eventual optional owner/schema and serialization contract; CR3 reserves none.

## Developer-only acceptance, all OPEN

DT1: Normal-build graph/artifact scan contains no developer entry, fixture truth browser, trace export or save-mutating bridge. Normal player UI has no director route; existing authorized appraisal remains its own observation consumer.

DT2: Sandbox works using disposable in-memory/explicit temporary fixtures. Storage spies confirm zero reads/writes against native save keys, local personal save paths or authenticated player state. Invalid fixtures/operations fail without creating state. Repeat snapshot and observer filtering pass.

DT3: Coverage result records domain, enumeration/sampling method, identity/effect counts, witness status and dead-property classifications. Independently check small exact domains against hand-worked fixtures; do not test a report only against its own enumeration function.

DT4: Fuzzer detects seeded accounting defects and respects deliberately authored sources/sinks/cheats. Minimal traces reproduce; failed writes and replayed settlements create no resources. Passing results name corpus/operation bounds.

DT5: Pack activation/removal/update and retained-revision synthetic save roundtrips preserve products, pending escrow and consumed-source exposures. Sealed leak scans output ID/status only. Developer utility and Weibao's normal play acceptance remain distinct; developer tooling is not a new mandatory gate for every gameplay slice.
