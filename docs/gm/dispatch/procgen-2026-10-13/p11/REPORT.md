# P11 report: shared context and further domains

Date: 2026-10-14. Status: **PROPOSAL PACKET**. All P11 designs and slice rankings are proposals. Source inspection and static document checks are evidence only. No runtime edit, build, gameplay attempt, save access, commit, integration or human acceptance occurred in this lane.

## Outcome and context contract

[CONTEXT](CONTEXT.md) proposes one read-only logical snapshot over existing owners, plus a separate observer-limited projection. Each generator declares its inputs and applies them through four channels: eligibility, weights, functional quality and knowledge exposure. Location/region, seasons/weather/time/calendar, laws/era/control, reputation/skills/knowledge/body/possessions/relationships, P3/D8 history, D9 tension and cheats all have explicit roles. A draw freezes resolved facts, relevant input refs/revisions and cause/draw receipts in the same transaction as real costs. Rendering, reentry, skill growth, grammar updates and reload never reroll saved truth.

**F1 shown/SOURCE:** live main code exposes much of the input data, with file:line evidence in CONTEXT F1-F19, but through several adapters. P11 does not claim a shared contract is implemented. Native calendar and expansion clock need explicit mappings; region/control/occasion/source-phase adapters still need owners.

**F2 stated / separately inspected:** P1-P4 branch reports describe local implementations and checks. P2/P3/P4 use independent saved-state seams; P4's person store is not a simulation actor registry. Root must reconcile streams, cast references and the actual merged build. P11 reuses these owners and does not add their test counts to its own evidence.

**F3 inferred / proposal:** the smallest useful context reader can wrap one ordinary funded need-based interaction. The wider domains below should consume that contract, without requiring every field, a full calendar network, a universal director or a multiverse at once.

Contradictions R1-R7 in CONTEXT explicitly preserve dated main/branch status differences, clock differences, legacy once metadata, 20:00/21:00 slot/light definitions, home rain passed to remote contexts, split person stores and P5 overlap. Existing source behavior remains evidence even where it conflicts with future design direction. P11 cannot update PROJECT/USER_VISION/PLAN/STATUS under its write boundary; root owns any canonical reconciliation.
