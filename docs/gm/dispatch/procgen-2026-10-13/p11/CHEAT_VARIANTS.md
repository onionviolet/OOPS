# Generated cheat and system-interface variants

Status: PROPOSAL N14, 2026-10-14. No cheat granted, UI generated, simulator implemented or source-world rule selected. Original examples. Use [CONTEXT](CONTEXT.md), [SIMULATORS](../../../../SIMULATORS_AND_CHEAT_IMPLEMENTATION.md#the-simulator-as-one-idea-many-forms-2026-10-10), [CHEAT_LIBRARY](../../../../CHEAT_LIBRARY.md), [P5 D3](../p5/D3_TALENT_ROLL.md), [P9](../P9.md), [P10](../P10.md) and [REPORT gates](REPORT.md#future-gates).

**Value:** two holders can have different supported functions, acquisition routes, growth and presentation without treating every status panel as the same power. The world baseline decides whether a function is ordinary law or a holder-specific exception.

**Cost:** medium for a few validated functional packages and known UI variations; high for arbitrary system composition or live predictive runs. Dependencies: P1 saved draws, actual body/power/capability/cheat owner, world baseline/exception definitions, optional D3 talent/choice admission, simulator engine only for variants that simulate. Existing panel/customization owner controls presentation. Interface colors or wording alone do not prove functional power variety.

## V1: logical variant record

Separate `mechanism`, `holderReach`, `worldCompatibility`, `acquisition`, `dormancy`, `knowledgeFidelity`, `price`, `refill`, `growth`, `retention`, `communicationVoice` and `knownInterface`. A generated variant selects only validated combinations of supported handlers. A name such as oracle cannot silently add an unimplemented future predictor. Interface fields are projections of owned and known capabilities, not a catalogue that reveals undiscovered powers. Privacy and actual detection means apply on both sides.

The simulator owner's SA axes remain its axis catalogue; P11 supplies context binding, not copied book rules. Generation examples can combine a subject, horizon, control, fidelity, carry and recharge only if that engine supports the combination. No simulation-as-text reward, omniscient exactness or raw private-source content is introduced here. Stated simulator proposals are not runtime proof. Preserving generous, free, costed, rare, common and unusual variants keeps reasonable options reachable; no universal daily/once/lifespan tax is imposed.

## V2: first slice

An existing supported observation function receives two original holder packages: local careful appraisal and supported evidence comparison. Both use the same actual knowledge/basis infrastructure with distinct reachable consumers. The appraisal package improves one declared observation resolution; comparison retains two known accounts with their provenance. The safe interface shows only unlocked controls and evidence, styled through existing preferences. Draw/freeze package at a real acquisition cause; optional start, dormant awakening, research, teaching, finding, buying and inheritance remain possible routes according to world profile.

If no current consumer supports a package, first implement that consumer in its own authorized slice before showing a generated power as usable. Cosmetic voice variants can ship separately but must be labelled presentation-only. World-standard status displays belong to baseline law; a special panel grants a cheat only when its holder has an actual exceptional means.

## V3: future gates

Validate compatible mechanic/world/body/fuel packages and exact revision refs; show two different functional actions, not two color themes; no preview/acquisition reroll of a committed package; failed write grants no power/UI; old absent owner stays absent. Save/reload/import both dormant and active states and next draw. A body/world transition either preserves, suspends or translates a declared supported function with a compatibility decision; never silently reroll it. Public UI/voice/alt text reveals no future unlock, secret truth or hidden variant counts. Strong foresight additionally needs the simulator's fidelity, branch isolation, changed-cause and retention gates. Human fiction, interface taste and power balance remain unaccepted.

## V4: further reachable options

Interfaces can be textual, sensed, spoken, embodied, companion-mediated or entirely hidden; advanced detail can remain optional while usable simple controls stay clear. Rival systems, lost systems, cooperative holders, hostile interfaces, evolving voices, externalized devices, tradeable fragments and retrofitted acquired systems are further proposals. The interface can lie only through a declared in-world unreliable source with reachable evidence, never deceptive save/runtime behavior. A settings choice is not an in-world capacity cost.
