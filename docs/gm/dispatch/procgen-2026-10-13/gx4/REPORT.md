## Guard against new unseeded randomness

T1 proposed first guard: `tests/generation_randomness_guard.test.js`, picked up by existing `node --test tests/*.test.js`. Walk `src/**/*.js`, inventory each direct `Math.random` reference and compare a committed exact-expression/multiplicity manifest, ignoring line-number movement. Existing 27-site source baseline has explicit owner and category. Any additional site, increased multiplicity or changed allowed expression fails, even if another disappears. No whole-file exceptions, no automatic baseline regeneration. Existing defaults/range helper are debt exceptions with named retirement ports, not allowed for new code.

The first test can be a conservative literal scanner with explicit acknowledgement that it is not an AST/call-graph proof. Extend it to flag bracket/computed/global Math access, random aliases/destructuring and new non-root crypto entropy; only the fresh-save initializer may use getRandomValues. A future AST lint should resolve imports/aliases and forbidden Date.now/performance.now/timers/DOM/localeCompare dependencies in registered pure generators; existing package has no JS parser dependency, so select one explicitly rather than claiming esbuild provides an AST. Retain v1 order exceptions until a semantic revision is chosen.

The proposed ratchet core is small; `scanReferences` returns normalized source-expression fingerprints plus multiplicity, with line numbers for diagnostics only. Baseline entries also name owner, category and allowed retirement. No accepted count may increase.

```js
const actual = scanReferences('src');
for (const site of actual) {
  const allowed = baseline.find(row => row.fingerprint === site.fingerprint);
  assert.ok(allowed, `Unregistered randomness at ${site.path}:${site.line}`);
  assert.ok(site.count <= allowed.count, 'Randomness reference count increased');
}
assert.deepEqual(scanForbiddenAliasesAndEntropy('src'), baselineAliasExceptions);
// Deletions pass; new/changed expressions require a reviewed owner decision.
// In the mutation test, delete an old cosmetic call and add a gameplay call:
// the new fingerprint must still fail despite unchanged total count.
```

T2 proposed companion runtime test: registered generate/project/peek invoked under deterministic owners with Math.random and entropy/time globals throwing, plus deep before/after state comparison. Existing P1 replay already forbids Math.random for lineup/loot/trader/combat; extend through one real P4 generation and P2 resolver/context, not fake generators. Native craft path needs a meaningful adapter test through commit; original recipe fallback is independently tracked. Cosmetic presentation uses stub boundaries; its RNG must never affect authoritative state or replay receipt hashes.

T3 proposed mutation checks: direct Math.random call, alias, bracket access and seeded provider omitted all fail; legitimate particle callback remains accepted; a removed call cannot offset an added gameplay call; peek initializes/logs/counters or stale failed commit changes stream must fail. A baseline ratchet alone cannot catch copied PRNG, undeclared shared-cursor interference, unseen-path randomness or biased distributions.
