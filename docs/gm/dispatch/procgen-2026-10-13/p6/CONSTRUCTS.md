## Product law and axes

| Axis | Proposed contract |
|---|---|
| Logic | L2 frame/limb/sensor assembly; L3 control/command channels; L1 frame material/fuel; L4 identity/bond when living or soul-bound. Familiar recruitment/bond is a living relationship variant, not ordinary assembly from scrap. |
| Inputs | Actual parts, controller blueprint, compatible power source, work site and maker means. Familiar route adds an actual creature/body and supported pact/rearing conditions; a generated name is neither body nor allegiance. |
| Process | Build frame → install controller → provision/test → assign supported task. Familiar: rear/contact → establish supported bond → train task. Remote control, autonomy and true creature agency are distinct product capabilities. |
| Skill | Assembly precision, programming/control, channeling or husbandry competence as applicable; knowledge and power-source access cannot substitute for each other. |
| Knowledge | Tested task repertoire, command interpretation and observed limits. Controller's sealed truth is projected only through its discovery route; player knows actual charge and task status needed for control. |

Generated: frame/interface choice, task-controller graph, local supported performance and identity. Authored: valid joints/sensors/operators, creature/bond laws, bounded task list and energy/capacity. Real consumer: one construct performs actual offcut sorting or rack tending, reserving real stock/site and producing counted usable material. It does not fabricate wages, grants or unrelated personal skill mastery. Familiars can reveal supported observations or aid a specific task, with their own capability and knowledge records.

## Idle and persistence

Assigned work can run while the player does another supported activity. Worker, site, tool, energy and material reservations prevent two jobs using the same means. Pause on no fuel/stock/space; return actual output. Initial played-time operation, bounded task completion, no universal offline agent. One apparatus may support one task simultaneously as a capacity fact, never a universal once rule.

Save assembled part custody, control graph, actual body/actor ID where needed, source/charge, task progress, maintenance if locally selected, observations and familiar bond/lineage. Distinguish item-like dormant frame from deployed actor to prevent simultaneous inventory and worker copies. Restore state without respawning/recharging; unsupported controller revision rejects Import before overwrite. Legacy NPC/device state is unchanged.

## Book laws

- K6, MoL ch43/ch46/ch48: treated frame, stabilization, battery and remote relay have different roles; relay's cited limit excludes casting through it.
- K9, TTKS rune fragments: a partial controller can have supported limited functions but still needs carrier and fuel. Missing functions cannot be assumed from a nearly complete percentage.
- K10, Shadow Slave ch695-701/ch2048: source-dependent weaving and compatibility do not arise from mundane fabrication alone. Use an original construct first; no generic Memory/soul/creature equivalence.

[Locators](CANON_LOCATORS.md). Familiar-specific magical bond canon remains a source-selection gate; the above laws support construct proposals, not certification of every familiar mechanic.

## First playable slice S10-A: one powered sorting jig

Build one original frame and a two-port sorting controller at an existing workshop. Two valid settings sort actual compatible offcuts into declared repair feedstock at different energy/time costs. Assign a batch, perform unrelated player work, collect real output and use it in S5 repair. Lose power or detach controller and the task stops. This proves a created worker apparatus; S10-B golem locomotion/body and S10-C familiar training are separate later slices.

Acceptance, all OPEN: SOURCE proves stock/fuel conservation, exclusive deployment, controller compatibility, eligible-time equality and exactly-once settlement. NATIVE proves paid build → parallel task → actual collected stock → repair consumer, plus exhaustion/part removal stop. Save mid-task, then reload/Export/literal-file Import with frame/actor/charge/task/custody exact. Common gates apply. No claim of natural AI, locomotion, bonded animal or general autonomous economy until separately exercised.
