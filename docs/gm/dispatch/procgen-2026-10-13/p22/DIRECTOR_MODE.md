## K1.1: entry, desktop result and exclusion

Proposed route: launch a dedicated development build on a disposable origin/profile → **New director session** → choose an original fixture or qualified world/anchor → **Cards / Threads / Storyteller / Checkpoints**. The header always shows world, continuity, era, pack lock, seed and **TEST SESSION**. At 1366x768 use three independent regions: searchable catalogue at left, selected card/thread and player view in the center, causes/lint/controls at right. Keep seed, pause, step and checkpoint controls visible. Long cards and receipts scroll inside their regions. At 1600x1000 expand the middle and evidence regions, rather than enlarging margins. Mobile optimization is deferred.

Ship the director entrypoint and mutation adapters only in the development artifact. Normal play has no director menu, hidden shortcut, global force function or query parameter that can activate it. An ordinary build opened with a director URL must remain ordinary and never fetch director fixtures. A development build still requires a new isolated session before showing controls. Build exclusion and storage isolation are independent acceptance cases.

**Shown/SOURCE:** `src/main.js:297,8109,8270` uses a localhost-plus-URL foundation probe and gated panel. `src/main.js:371-374,8115-8117,8490-8509` names normal/dev save keys and includes cross-release save lookup. **Inferred:** reusing that flag or the dev save key would not establish this proposal's isolation. A new director bootstrap must skip normal save/backup/heir loading before any storage read. It must also skip normal lock acquisition and cross-release import buttons. Use a session-scoped storage adapter that rejects keys outside its namespace, plus a disposable origin/profile so direct legacy storage calls cannot reach personal data. Fail closed if either boundary cannot be established. No automatic copying of an existing save, Downloads scan or private-save import. Fixtures are created from real game constructors and declared synthetic inputs.

Director exports use a distinct `yairpg-director-session` envelope and filename, marked test-only. Normal save import rejects it before writing. Returning to normal play opens a separate ordinary session; it never promotes the director state, earned rewards, knowledge or achievements into a private life. Integrating an accepted pack means installing reviewed definitions under [K3](CONTENT_PACKS.md), never copying this test character.

## K1.2: tools and their exact meaning

| Tool | Proposed behavior | Evidence and limits |
|---|---|---|
| Browse cards | Filter admitted definitions by world/pack/tag, show frozen active occurrences beside their originating definition revision, compare player rendering with safe technical fields | Inspecting consumes no draw. Sealed definitions appear by opaque ID with route/status only; hidden tags, names, predicate values, counts and sort keys stay masked. |
| Browse threads | Show P12 thread IDs, known steps, retained causes, cast references and source-owner links | P12 owns thread storage and objectives. Adapter says unsupported if absent; no thread inferred by parsing log text. |
| Force eligible event | At a paused boundary, select an eligible card and commit through the actual admission/effect/publisher path with `origin=director-forced` and a saved intervention receipt | Skip weighted selection only under a declared adapter. Costs, cast, consent, world laws, expiry and actual consequences still validate. Never patch an event into `s.events` as proof of admission. |
| Pin future event | Retain a requested card ID, scope and due window until eligible; show pending/fulfilled/expired/unsupported status | At the future boundary revalidate actual causes. Pin is a testing request, not a promise of occurrence or a hard canon point. No fabricated person, resource or prerequisite. |
| Prepare controlled case | Apply a named, validated synthetic setup to a new test fork, then run the same admission path | Label seeded-native if exercised through browser; source if headless. Keep natural route separate. Useful for rare, harsh and extraordinary reachable scenarios. |
| Set seed | Choose a new root seed before initialization, or restart a new fixture session with another seed | Existing generated actors, text and draws never change in place. Stream state is inspected only where safe; a seed without pinned revisions and inputs cannot reproduce an arbitrary life. |
| Inspect storyteller | Show supported local style, cadence, input presence, eligible public weight components, cooldowns and draw receipts | D9 owns pacing math. Missing storyteller is **not installed**, not a guessed pressure score. Sealed causes yield opaque review status, not secret field values. |
| Pause / step | Pause the session scheduler, then advance one supported causal boundary or a declared played interval | No second wall-clock timer, automatic offline advancement or guessed calendar conversion. Pausing cannot halfway publish a transaction. |
| Replay / compare | Restore an immutable checkpoint into a new test fork, replay recorded commands and supported context inputs, stop at first semantic mismatch | Exactness is limited to the declared subsystem. Legacy unseeded randomness or uncaptured input makes full replay unsupported. Changing one command creates a counterfactual test, not exact replay. |

Forcing and pinning are interventions. Proposed default: an eligible forced occurrence records selection bypass without consuming the deck's selection draw, applies normal occurrence counters/cooldowns and uses the integrated adapter's saved cast/effect draws. The receipt records that policy and all consumed counters. If P3 cannot safely support this seam, use a separate controlled fixture adapter instead; do not monkey-patch RNG. Natural next-draw comparisons are valid only with no intervention or with an explicitly matched intervention trace. Cancelled/stale pins consume nothing. A due pin suppresses competing selection only at the documented test boundary; it does not secretly edit the deck's history.

Future temporary pacing overrides are session records applied to future ticks, not writes into the pack or past impacts. Show base weights and override weights separately. Harsh/gentle, abundant/scarce, lucky/ordinary cases remain selectable where their world supports them. No fixed lifetime once rule is added.

## K1.3: checkpoint and replay contract

Proposed checkpoint bundle holds `sessionId`, checkpoint ID/parent, engine/build identity, fixture recipe revision/hash, complete pack lock, declared replay scope, played/calendar anchors, full supported save envelope, all RNG consumed state, native inventory/vitals/equipment/custody, people/knowledge, open events/jobs/escrow, controller state, storyteller state if present, and a command/input trace cursor. Checksums detect byte drift; they do not make absent definitions executable. Capture only after durable publication or an explicitly validated pre-command boundary.

Retain a checkpoint's dependency closure and immutable bytes. A bookmark, biography line or visit-history ID cannot reconstruct it. [Timeline T1-T5](../../../../TIMELINES_AND_DIVERGENCE.md#implementation-planning-starts-histories-and-parallel-worlds-2026-10-11) and [intro BR3/BR11](../../../../INTRO_FLOW_CONSIDERATIONS_2026-10-13.md#br-branch-lifecycle) own actual branch lifecycle; director forks do not implement game-world branching. Snapshot budgets are measured storage choices, not gameplay restrictions. If retention fills, offer export or new local storage, without deleting selected checkpoints silently.

Trace commands retain sequence, supported arguments, context revision, played interval, nondeterministic input where necessary, outcome/cause IDs and draws. Replay computes real results; it must never feed saved expected effects back as if they were fresh execution. Compare semantic state plus owner-specific deltas, ignoring explicitly excluded UI-only timestamps. P18 owns replay QA and mismatch reduction. Unsupported native/random inputs must be declared before replay, not hidden after a mismatch.
