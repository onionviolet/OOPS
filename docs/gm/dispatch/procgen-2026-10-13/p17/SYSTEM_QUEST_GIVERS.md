## D3.2: issuer and evaluator are separate roles

Proposed issuer profile: identity/source, scope, what it knows, objectives/agendas, supported output grammar, evaluator reach, reward source, grant handlers, notice timing, disclosed deadline/cancellation and compatible holder/body. These are semantic fields to join P11/P12, not a new persisted owner. An impersonal world law, a sentient patron, an NPC board, a holder-private System and a deceptive interface can coexist. A mysterious agenda can stay sealed by ID; its lawful executor still needs real causes.

Original first journey: an optional acquired System observes a real local shortage, offers a request with several valid methods, freezes conditions/reward source, then evaluates an actual delivered repair. A mundane issuer funds coin; a declared magical handler grants one useful observation function. The status panel shows the known commitment and result after discovery. No status panel is a prerequisite for receiving spoken, sensed or companion-mediated quests. Refuse, postpone, negotiate or use ordinary work routes according to local law, without fabricated shame or hunger death.

## D3.3: honest branching, repeat and save contract

P12 generates structures over supported verbs and objects; P15 generates voice last. System text cannot add a deadline, fabricate a target, sign a contract, mark an objective complete or grant stats. A hidden evaluator can judge secret facts only through an explicit world-local reach; the player/NPC UI receives a separate safe account. If the System lies, store its issued assertion separately from the actual mechanical objective and offer a reachable investigation route where the chosen world supports it.

Natural repeated jobs arise from changed deficits, production cycles, new students, recurring institutions or deliberately renewable magical challenges. Protect the exact reward obligation from duplicate settlement; don't ban all repeat missions. Powerful/free/inexhaustible Systems remain reachable through declared sources, with safe finite per-tick scheduling and complete settlement identities. Physical rewards still need identity/custody; source-issued effects still need actual handlers.

Future gates: selected primary issuer/evaluator/reward laws; authentic objective → supported alternatives → actual completion → useful grant; incomplete/partial/refused controls; duplicate evaluation versus new repeat; pending terms survive source/version update; no display or reload draw; failed write cannot consume/reward; dormant/awakened/absent old saves retain correct behavior; natural acquisition and exact export/literal import at both desktop viewports.
