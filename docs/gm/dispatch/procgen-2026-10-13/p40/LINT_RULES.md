# P40 proposed lint contracts

**PROPOSAL ONLY, 2026-10-14.** Extend root BL1–BL12 and TL2/TL4, not package wiring. Standalone artifact: [determinism_lint.mjs](proposed/determinism_lint.mjs). It reads `src/` beneath explicitly named roots and emits file:line:column plus rule IDs. It never imports gameplay modules, writes files, reads saves or prints source excerpts. The [source probes](proposed/audit_probes.mjs) are separate; lint itself never executes source.

## Proposed use

From the repository root:

```sh
node docs/gm/dispatch/procgen-2026-10-13/p40/proposed/determinism_lint.mjs --self-test
node docs/gm/dispatch/procgen-2026-10-13/p40/proposed/determinism_lint.mjs --root . --json
node docs/gm/dispatch/procgen-2026-10-13/p40/proposed/determinism_lint.mjs --root .claude/worktrees/proc-p34-spine
```

`--root` is repeatable. Default is current working directory, with a required `src/`. Exit 0 = advisory scan completed, **not determinism passed**; exit 2 = lexical scan error; `--strict` returns 1 for any candidate, intentionally too broad for immediate CI adoption. Missing directories/unknown options fail. Root can copy/adopt the standalone file after reviewing the rules; no installation or new dependency is required. Do not gate on hundreds of scratch-collection review notices as if each were a defect.

Current implementation is token-based lexical triage. It skips comments, string bodies, regex bodies and template literal text while scanning template expressions; direct and string-bracket member forms are detected. The 17 in-memory self checks include malformed input, nested interpolation, reference defaults and cosmetic clock exceptions. It is not a complete ECMAScript parser: alias/dataflow tracking, shadowed globals, computed properties, unusual regex/division contexts, imports through indirection and transitive owner analysis can escape it or produce false positives. A clean result is not a security, save or portability proof. Adopt an AST/dataflow stage only if selected, with its own parser tests.

## Rule specifications

“Candidate” is a source review queue, not automatic severity. AST specifications below are proposed future behavior; “lexical” states what the delivered script actually detects. Exact exceptions should have owner, reason, reviewed function/sink and source fingerprint, not broad “UI file” immunity. The two current cosmetic file classifications are convenience triage, not authority to add gameplay there.

## Adoption without false gates

D1: Review deterministic sinks first: storylet selection, condition/controller ordering, product/debit publication and retained reference graph. Classify notices into defect, intentional law, display-only or unsaved scratch; store exact evidence rather than blanket suppressions. The initial 447 main L04 notices are review positions, not 447 saved Maps.

D2: First adoption can remain an explicit developer command with ID-only output. Later blocking mode should operate on curated rules and exact justified exceptions, or new unreviewed candidates against a **refreshed** baseline. This artifact has no baseline mechanism or suppression-file API; those are proposals, not hidden implemented features.

D3: Fixture probes and browser gates complement lint. Lint cannot prove reachable chemistry, fair distributions, no leaked truth, correct grammar or comfortable laptop controls. No raw canon prose, secret values or personal save contents belong in diagnostics. Generated fixture data stays original and public; any real sealed packs emit only IDs/status.
