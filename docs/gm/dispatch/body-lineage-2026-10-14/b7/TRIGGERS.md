# G48-B7.T: generation and publication triggers

Proposal, 2026-10-14. [LEVELS](LEVELS.md) defines the demand bundles;
[CONSISTENCY](CONSISTENCY.md) defines inheritance, observation and migration.
Names below describe future contracts, not existing exports.

## G48-B7.T1 Demand matrix

| Code / trigger | Required resolution | Commit boundary and public result |
|---|---|---|
| T01 Individual admission | Stable qualified person/body identity, generation revision, seed anchor and authored constraints | Admit with its identity owner. Does not introduce an unobserved person or roll a genome |
| T02 Actual sight, hearing, meeting or introduction | Perceivable appearance, voice, apparent age/species; any physical dependency needed for that evidence | Encounter/observation transaction. Publish only what the channel established; an attributed written introduction need not resolve anatomy |
| T03 Disclosure, shared work or household routine | The particular quirk/build/sense needed for the actual result; self-described identity/address if supplied | Same completed dialogue/work cause. Trust changes willingness to disclose, not truth or universal access |
| T04 Tailoring, gear fit, climbing, combat, illness or medicine | Actual dimensions, parts, capacities or reaction parameters read by the selected consumer | Before reserving frozen cost/outcome. Commit physical truth even when no participant can diagnose its name; failed examination may establish only a negative detection result |
| T05 Conception, budding, clone fabrication or another supported creation | Contributors and roles, transmission model/revision, relevant parental snapshots, reproductive inputs and event environment | Creation agreement/event cause freezes these inputs. Birth may later finalize development inputs; traits can materialize later from the frozen capsule |
| T06 Blood key, awakening, ancestor recall, engineered change or transfer | Required line membership/carrier, latent faculty, supported modification and transmission implications | Own domain transaction. Use existing faculty activation/custody authority; kinship, expression and ritual membership stay separate |
| T07 Parentage/genome/lineage examination | The loci/ancestry subset tested, compatible templates and evidence method | Freeze test truth inputs, resolution and observer report. No universal paternity result from seeing a face |
| T08 Real age, growth, injury, transformation or body swap | Existing resolved values plus fields needed by the change; old/new body bindings and developmental anchors | Dated state transition. Update current physiology, preserve birth choices, old snapshots and unaffected person identity |
| T09 Explicit prospective adoption for legacy NPCs | Only newly required fields under compatibility policy | Disclosed opt-in body/mechanics event. Loading and a panel open are not adoption |

Social labels alone are not triggers. Friendship, rivalry and spousehood suggest
likely requests, but a new label cannot reveal body data or select a phenotype.
An unseen NPC's own job can demand T04 without revealing anything to the player.
An authored result can supply a resolved constraint without any random draw.

## G48-B7.T2 Resolve on a plan, save, then reveal

1. **T10 Bind and plan.** Qualify owner/person/instance/incarnation and actual
   body. Validate the supported operation, field allowlist, world/model revision,
   available means, authored constraints and expected record revisions. Expand
   requested fields into a dependency graph. Reject unsupported fields as
   unresolved, rather than substituting zero or an invented anatomy.
2. **T11 Resolve missing inputs.** On a detached candidate, read saved values
   first. Derive missing choices from domain-separated keys such as
   `bodySeed/bodyId/modelRevision/bundleId/birthEpoch`. Use an immutable template
   anchor for correlated traits and a conception/litter anchor for inheritance.
   Do not reuse P4's sequential name/personality stream. Authored values and
   committed parent inputs constrain the result. Save selected values, generated
   absence coverage, model revisions and dependency references.
3. **T12 Reserve and validate.** Resolve applicable costs and actual effects
   with those values; reserve downstream work and enough storage for result and
   closure. Freeze event inputs at the domain's declared admission boundary.
   Recheck expected owner revisions. A stale candidate returns for a fresh plan
   without publishing or changing live values. Rejected previews do not consume
   a gameplay draw or pin a new fact.
4. **T13 Persist and publish.** Save all changed body/parent/child records,
   knowledge, action costs and receipts through the owning durable transaction.
   Publish the actual consequence and observer-safe message after successful
   persistence. On failure, restore live state and retain the previous stored
   bytes. A retried cause uses the same committed values; a new event can change
   mutable state under its own cause.
5. **T14 Read thereafter.** Views read saved projections and never materialize,
   roll, age or enroll bodies. For a first inspection, a user action or host
   observation event owns T10-T13, then rendering reads its result. Reload and
   literal-file import validate saved data and cannot trigger T02 or T09.

A speculative preview can show costs from a detached deterministic candidate
when disclosure is allowed. It does not show concealed parameters or turn a
preview into a diagnosis. If an admitted paid job persists a frozen body-dependent
quote, its required inputs commit with that admission and remain pinned until
settlement; later body changes follow the job's explicit interruption policy.

## G48-B7.T3 Order, work and clocks

Resolve dependency nodes in canonical order with memoization within the plan.
Independent request order, panel open order and batch size must produce the
same joint assignments. Use a constrained latent template or canonical
conditional solver, not independent rolls for two genetically related fields.
The fingerprint of committed inputs detects a mismatch; a hash alone is not
a substitute for retaining those inputs or a supported immutable definition.

New events use the existing played/local clock. No body mutations, conceptions,
births or NPC aging are invented from browser closure. The household's yearly
news-reveal owner and P4's hourly projection retain their current meanings.
Dependency expansion is proportional to the requested bundles and referenced
lineage capsules, with cycle detection; unrelated NPCs need no body tick. Large
requests can yield with a saved continuation cursor, but dependent outcomes
wait for their inputs. Bound work per frame as engineering scheduling, not a
permanent lore cap on children, tests or traits.
