## RN1-RN2: a grammar whose clauses do work

Separate five layers: actual marks → recognized tokens → contextual senses →
typed clause/graph → execution in a world. The player's reading is a sixth,
observer-owned record. A wrong reading changes a prediction, not the marks.
A bad copy can change the marks and thus the actual program.

| Code | Word class | Proposed role and useful distinction |
|---|---|---|
| RN1-N | Noun | A domain such as light, sound or motion; or an exact bound object such as this door. A domain is not an owned quantity of fuel. |
| RN1-V | Verb | Emit, route, hold, sense, release, compare. Its signature specifies accepted domains and outputs. Knowing the word does not supply its operator capability. |
| RN1-M | Modifier | Narrow, diffuse, inward, quiet. Attaches to a stated phrase or group; changes reach, rate or target, with a real consumer. |
| RN1-R | Relation/case | From, into, around, of. Binds source, destination and covered region. A case stroke can reverse a conduit without changing either noun. |
| RN1-T | Trigger | Touch edge, command pulse, crossing, scheduled boundary. Produces an event carrying origin/time/subject, rather than a Boolean that stays true forever. |
| RN1-G | Gate | AND, OR, NOT, delay, count and latch. Distinguish predicates over state from events over time. |
| RN1-Q | Quantity/aspect | Rate, duration, pulse length, threshold, repeat while true. Quantity requires units; aspect determines whether a verb acts briefly or persists. |
| RN1-I | Identity/binding | Exact holder, recipient, oath party, reservoir or anchor. A written name and authenticated identity are different inputs. |
| RN1-P | Punctuation | Phrase frame, group frame, branch split, terminator and reading origin. These can be physical strokes, spaces or knot orientations by world. |

Illustrative teaching grammar, with names printed beside original glyph tokens:

```text
clause  := trigger? gate? verb domain source? destination? modifier* duration?
program := clause | group(program, program) | delayed(program) | counted(program)
```

This is a teaching notation, not a universal magical grammar. A world can make
relations mandatory, use case rather than order, read radially from an anchor,
or let a melody carry scope. Supported words lower into P6 operators. Arbitrary
poetry does not silently create an unimplemented effect.

RN1-S syntax comparison: `HOLD(LIGHT)` retains already supplied light in a
supported enclosure; `LIGHT(HOLD)` illuminates the marked holding region in a
world that admits LIGHT as a verb. Both can be valid but have different output
and fuel contracts. In a simpler script, the second expression is unsupported.
Distinguish a valid unintended effect, a recognized but ill-typed sentence,
an incomplete fragment and an unreadable mark. Not every wrong order should
become a random spell. The executor resolves the actual valid sentence; the
player may discover its result through a paid trial.

RN2 default: each sense is selected by a finite rule, not a guess from flavor
text. Dial: neighboring case markers, phrase role, medium, orientation or
speaker tradition choose a sense. Reasonably: two or three related senses
with clues and a test that separates them before adding rarer readings.

| Code | Context example | Meaning and consequence, all original |
|---|---|---|
| RN2-A | OPEN before a channel noun | Conduct through that channel. The connected payer spends charge. |
| RN2-B | OPEN before a container noun | Release its contents through its real outlet. The rune supplies neither contents nor outlet. |
| RN2-C | OPEN inside a formal agreement frame | Activate a named permission, if the world's contract authority admits it. It does not unlock unrelated physical doors. |
| RN2-D | OPEN stamped on sale cloth | Ordinary writing in a world where the cloth has no executable inscription law. Reading and running remain separate. |

Semantic selection uses saved script revision, token role, bound carrier class
and explicit context. Two admitted parses need a world rule: visible ambiguity,
priority, dual effect or refusal. An implementation data gap blocks admission
before spend; a player's uncertainty does not automatically block experiment.
An explanation can say which observed stroke/neighbor caused the known branch
without revealing a still-sealed mapping.

RN9 deep words: older usage can reveal a narrower, more efficient operator or a
missing binding clause, rather than a generic power multiplier. Default: study
adds a known sense and an actual consumer. Dial: true-name authority, ancestral
pronunciation, obsolete case endings, or no deep-word magic. Reasonably: retain
modern utility; an old form is better only where the local law supports it.

## RN3-RN7: carrier, clock and situated power

RN3 capacity is a vector. Space for marks, minimum stroke separation, channel
bandwidth, burst tolerance, anchor roles and heat/strain response differ from
stored energy. A large empty stone can fit many words yet fail a high-throughput
channel. A fine copper trace can conduct well yet have no fuel of its own.
Default: useful motifs fit at readable spacing. Dial: density, insulation,
layering, material response and local hazard. Reasonably: a small repair or
larger substrate often solves crowding without a mandatory new tier.

| Code | Carrier palette | Specific consumer/limit, INFERRED |
|---|---|---|
| RN3-B | Bone | Curved surface and porous treatment affect recognition and leakage. A repaired bone may need a bridge across a crack. |
| RN3-W | Wood | Grain direction and swelling can move channels closer; coating changes weather exposure, not the written sense by fiat. |
| RN3-S | Stone | Large anchored layouts support site coverage; cracks sever particular links rather than remove an abstract power percentage. |
| RN3-M | Metal | Dense conductors need insulation or channel separation; different heat treatment need not change semantic vocabulary. |
| RN3-P | Paper/cloth | Light, foldable, cheap carriers can burn or lose alignment. A consuming talisman and a reusable chart use different laws. |
| RN6-B | Skin/body | Growth, healing, scars and movement affect fit. Installation tracks actual body region, practitioner, pain/wound cost and removal policy with the body owner. |
| RN6-S | Soul | Enabled only by a sourced or original local soul law. Binding requires the actual source/recipient and capability; not inventory renamed as a soul. |

Cross-talk can occur between two physically adjacent channels even when the
logical graph has no edge. Define a coupling relation separately from intended
ports. Default: adequate separation suppresses it. Dial: leakage transfers
energy, corrupts a sensor, merges event channels or heats the carrier under
explicit world laws. Reasonably: start with one deterministic fault and a
readable symptom, such as a lamp twitching when a nearby alarm is energized.
No extra ignorance roll. Example: 5 units supplied, 1 leaks to a bell and 4
reach the lamp. The accounting includes the leak; neither output gets 5.

RN4 default: sample sensors at meaningful game-time boundaries, then evaluate a
stable snapshot before publishing effects. Dial: faster combat events, slower
ritual windows, spoken command or proximity. Reasonably: no mandatory button
press per upkeep tick; learned safe patterns can run under funded standing rules.

| Code | Construct | Temporal meaning and failure to teach |
|---|---|---|
| RN4-T | Touch, blood, spoken, intent, moonlight, proximity | Each needs a real sensor/operator and a scope. Blood proves a sample under its identity law, not intent; a phrase alone may be replayable. Intent needs an actual mind-reading faculty. |
| RN4-A | Event AND state predicate | Fire on a touch pulse only if the sampled gate is true. Two event pulses need an explicit coincidence window or saved latch. |
| RN4-N | NOT predicate | Negates a known Boolean value. Missing sensor data is unknown, not automatically false and thus NOT-true. A world may declare another policy. |
| RN4-D | Delay | Stores a due time, captured event and target policy. Decide whether conditions are rechecked on arrival; a dead target is not replaced silently. |
| RN4-C | Count | Tracks a defined event identity/window and persisted reset rule. Duration ticks are not distinct touches. |
| RN4-L | Latch/hysteresis | A stateful memory with defined set/reset priority. Different start/stop thresholds avoid flickering near a boundary. |
| RN4-O | OR and parallel branches | Can admit more than one branch; simultaneous outputs draw from the same reservoir through declared allocation, never duplicate full charge. |

Default arbitration: a funded all-or-nothing action reserves its full quote;
shortage pauses it without partial output. Dial: priority branches, partial
output or Noita-style skip may be local laws. Reasonably: expose what the
actual program does on shortage through a known trace, rather than quietly
substituting a cheaper spell. Source caps, sustained draw, storage and evaluator
work budget are separate limits.

RN5 erosion: record physical loss by region and time/use receipt. A worn
terminator can join two phrases; faded sensor ink can produce unknown input;
a severed power line withdraws output. Default: slow readable wear with queued
maintenance from actual ink/tool reserves. Dial: none, seasonal inspection,
self-repair or harsh exposed carriers. Reasonably: comfortable ordinary play
does not require daily attendance. Re-inking can preserve the current text,
restore a documented earlier text or knowingly revise it; those are different jobs.

RN7 formations: anchors have position, custody, power links, coverage and local
communication latency. An entrance ward does not protect the whole wall by name.
Default: small situated networks. Dial: relay distance, redundant anchors,
city scale, mobile nodes, terrain and jurisdiction. Reasonably: evaluate affected
links at events, not every pair of stones each tick. Losing a node can open a
specific passage, disconnect a payer or trigger a reserve mode. A siege can
attack geography or supply, not just reduce a ward-health bar.

## RN8-RN10: read, counter, hijack and bind

| Code | Action | Needed means, changed owner and possible counter |
|---|---|---|
| RN8-R | Read | Observe strokes/position, compare known grammar, test with limited input. Records a scoped hypothesis or decoded clause, not ownership or execution mastery. Hidden back-face text can remain unread. |
| RN8-C | Counter | Break an ongoing construct, jam a specific sensor, insulate a coupling path, spoof a supported input or drain its supply. Pay the counter's real cost. Mechanism matters; dispelling light does not extinguish ordinary fire. |
| RN8-S | Smudge/rewrite | Reach the actual mark and use a suitable tool. Changes that region's token/continuity, custody and wear receipt. A protective cover can block access. |
| RN8-H | Hijack | Change a supported receiver/source binding or controller permission with actual access/capability. The downstream graph then routes real output differently. Knowing a password may allow use while providing no edit right. |
| RN8-D | Defend | Isolate channels, authenticate commands, place critical marks inside casing, monitor continuity or use redundant anchors. Costs come from the design and real means, not universal immunity. |

Default: understanding gives a bounded advantage, such as predicting the alarm's
quiet branch. Dial: open wiring, signed binding, sealed casing, competing authority
or permissive ruins. Reasonably: successful hijacking should yield a concrete
route, useful output or control, not only a label. The same policies apply to NPC
makers and opponents; a counterfeit signature is a testable claim.

RN10 binding clauses declare party, obligation, trigger, duration, release,
witness/enforcer and consequence. Default: an explicit local contract operator,
if enabled. Dial: material seal, spirit authority, body mark, social oath,
revocable pact or exceptional binding. Reasonably: a spirit is an actor with
rights/means under its world owner, not a fuel number. Breaking a stone can
terminate a sensor, release a bound actor or violate an oath only when that
specific clause says so. Engine budget failure does not invent an oath breach.

## RN11-RN13: learning and generated scripts

RN11 proposed ruin route: collect a rubbing of an inscription and its position;
compare the same mark on a door, lamp and broken drain; record candidate senses
with basis/confidence; choose a test that splits those candidates; perform it
on an actual owned or accessible carrier with a real payer. A glow confirms a
light effect under that protocol, not the whole lexicon. An NPC can teach sound
values while still being wrong about a ritual sense.

Default: useful fragments and partial readings. Dial: bilingual plaque,
repeated maker formula, dated regional spelling, living informant, inscription
cheat with a stated fidelity grant. Reasonably: authored evidence should let a
player distinguish relevant hypotheses, not demand blind guessing over all
possible effects. Ruins can be false copies or damaged evidence, with discoverable
provenance. Study/comparison jobs can queue; uncertain dangerous energization
needs the world's declared experimental route.

RN12 separate script from language. A new font alone changes recognition;
new sound values change reading/pronunciation; a new lexicon changes semantics;
new syntax changes composition. Canon worlds keep sourced public languages and
rules unless an explicitly distinct variant is chosen. Original generated worlds
can generate all four layers. Crossing worlds with a rubbing transfers information,
not a compatible carrier, energy source or pronunciation skill.

| Code | Generated layer | Proposed persistent record |
|---|---|---|
| RN12-G | Stroke grammar | Finite primitives: trunk, branch, hook, closed loop, dot; grid attachment points; allowed joins; reading origin and orientation. Reject accidental collisions under that world's recognition rules. |
| RN12-A | Allographs | Permitted regional/medium variants and a distinction between decorative marks and semantic strokes. A cursive loop and carved hook may be equivalent in one script but different in another. |
| RN12-F | Sound values | Stable phoneme/syllable IDs, legal clusters and optional stress/tone marks. Sound is not automatically an effect, and scripts may be silent. |
| RN12-M | Meanings | Token/sense IDs mapped to admitted operator signatures and contextual rules. Truth is sealed; public rows name only IDs and discovery routes/status. |
| RN12-Y | Syntax | Scope frames, order/case rules, binding conventions and admitted fragments. Grammar cannot generate unsupported operators. |
| RN12-E | Evidence | A finite corpus of clues, contrasts and useful test carriers consistent with the saved map. Validate that a relevant distinction has an observation route. |

Save resolved definitions, generator/law revisions and instance bindings before
use. A seed alone is insufficient restoration evidence. Reload, import, ruined
copies and previews cannot redraw the meaning map. Public example status:
`RN12-M017: comparison route authored, discovery untested`. No gloss or glyph-to-
effect lookup for that ID belongs in this paper, a report, a tooltip, a sort key
or a checksum whose value itself exposes the secret. An internal replay trace
may retain truth references; player traces project only known senses and allowed
observations. RN12 IDs here are schema illustrations, not claims that secrets
have been created or discovery implemented.

RN13 copying drift has three separate routes: a changed physical stroke, a
changed reading convention, or an unchanged inscription misunderstood by a
reader. Default: reproduce the actual written marks, with differences saved at
copy completion. Dial: hand precision, mold/jig fidelity, lossy rubbing, oral
pronunciation, deliberate forgery, translations or a perfect-copy cheat.
Reasonably: the cheat can remove copying variance while still not supplying
fuel, mastery, hidden back-face text or compatible materials.

Track copy parent, edition, actual stroke difference, procedure, maker and
inspection evidence. A shared omission in descendants can identify a manuscript
lineage. Repeated copying does not require an arbitrary power decay: harmless
allographs stay equivalent; a one-stroke change can have a large causal effect.
A jig preserves its own error across batches. If execution variance is enabled,
commit its draw with the copy job, not on reading/reload. A proofreading job
compares against an available exemplar; it cannot infer a sealed correct original
from the executor's private truth. Maintenance does not silently repair syntax.

## RN14: a simpler rune economy can coexist

Default for a world choosing this mode: actual essence/blank stock → accessible
altar process → finite runestone batch → spell cost → spent residue or consumed
stone under the local law. Dial: altar access, affinity, yield, reusable charged
stones, traded supply, combination stones or grammar inscriptions alongside it.
Reasonably: short known jobs can queue with exact reservations and stop on
shortage. A stone labeled LIGHT can be an operator ingredient, a charge token,
or both; declare each consumed role so the same essence is not counted twice.
A spell may use prepared stones without the player learning a full compiler.
Yield/multiplier rules belong to the world adapter; RuneScape's rules are not
universal conservation or YAIR balance.

### RN-P1: shaded reading lamp

```text
[|>:.] <bound switch>
  [<:|>] ( [/\:.] <desk> AND [|:~<] [~|:.] <shade> )
  => [|=:>] [o/:|] FROM [o:|>] <cell-A> INTO [v:|.] <desk> FOR 3 minutes
```

Reading: on a fresh touch, if the desk is dark and the shade is not occluding,
emit light over the marked desk for three played minutes. This default teaching
world allows one active lamp interval; further touches during it do not buy or
extend another interval. Dial: replace with paid extension or an explicit
retrigger policy, rather than treating this as a global use limit.

| Code | Execution trace |
|---|---|
| RN-P1.1 | Build: owned copper ring, insulated paths, cell-A with 4 charge,9/12 mark units, peak demand1/2 units per minute. Ports and desk coverage admit this program. These illustrative units include framing/bindings. |
| RN-P1.2 | At minute0, touch eventE1; DARK=true, VEIL=false. NOT VEIL=true; event AND both predicates admits one interval. |
| RN-P1.3 | Quote3 charge, escrow3 atomically; cell free balance4→1. Each completed played minute burns1 escrow, producing desk light; remaining escrow3→2→1→0. No absent-time advance is assumed. |
| RN-P1.4 | A supported three-minute reading job receives this actual illumination. At minute3 light withdraws. Removal of the ring also withdraws coverage; no permanent reading buff. |
| RN-P1.5 | A new eligible touch at minute4 quotes3 but only1 is free. Pause with no spend/output; lawful recharge is needed. Cancellation after minute1 refunds the2 unburned units, not the1 already used. |

Failure: a copying error drops RN-G07 NOT. With an open shade, VEIL=false so
the lamp does nothing. With a closed shade, the altered condition passes and
charge powers light inside the blocked region, without aiding the reading job.
This is a valid wrong program, not a grammar error. Inspection/testing can reveal
the actual changed clause. The notation explicitly treats VEIL as a sensor
predicate, not a new fuel-producing darkness noun.

### RN-P2: two-crossing ruin alarm

```text
[|.:/] [v:|.] <door-A>
  [<:|>] [|:~<] ( [=:|o] <event.subject, keeper-key> )
  => [|::v] <2 distinct crossings in 5 minutes, reset after threshold>
  => [|..>] <1 minute, recheck anchor continuity>
  => [/o:|] FROM [o:|>] <cell-B> INTO <bell-A>
```

Reading: two distinct unkeyed entries within five minutes schedule one bell
pulse a minute later. Latch prevents another pending alarm; new count begins
after that pending alarm settles. Window edge is inclusive in this example.
KEY reads a supported signature, not moral intent or player-entered name.

| Code | Execution trace |

### RN-P3: spoken transfer hatch with a count latch

```text
[.:|=] <recognized phrase on hatch-A>
  [<:|>] ( [=:|o] <speaker, authorized-mark> AND <pressure-safe> )
  => [|<:o] <hatch-A>
  => [|::v] <3 distinct authorized command events, no timeout>
  => [o:>|] <hatch-A> FROM [o:|>] <cell-C>
```

Reading: authorized commands accumulate toward a release. On the first accepted
command HOLD closes the hatch and sets the latch; subsequent accepted commands
increment without reclosing. At the third, a funded RELEASE opens the actual
hatch, clears the count/latch and ends that cycle. A fail-to-fund leaves the
hatch held and count3; a fresh authorized command requests release again without
incrementing beyond3. Identity and pressure are rechecked at release.

| Code | Execution trace |
|---|---|
| RN-P3.1 | Build: owned wooden hatch plate with separated channels, mechanical supported latch, cell-C with 5 charge;10/12 mark units, HOLD cost1 and RELEASE cost2, peak2/2. Holding thereafter is mechanical, not free magical suspension. |
| RN-P3.2 | E20 authorized, pressure safe: atomic HOLD debit1, cell5→4; latch closed, count0→1. E21 unauthorized: no action, no debit/count. |
| RN-P3.3 | E22 authorized: count1→2. E23 authorized: count2→3; release quote2 fits. Publish debit and gate opening together, cell4→2, latch cleared/count0. A real delivery job can now pass cargo through hatch-A. |
| RN-P3.4 | Next cycle: E24 closes, spends1, cell2→1. E25 brings count2; E26 brings count3 but cannot fund2. Held/count3 persists with no fabricated opening. Replenish through the real cell owner, then a fresh qualifying command can release. |

Failure: a copied case-arrow reverses the gate binding to neighboring hatch-B.
If no compatible owned target is bound, construction fails before spending.
If hatch-B is compatible and genuinely bound, the valid wrong program runs on B;
A stays shut and the intended delivery still fails. This distinguishes unresolved
binding from a valid unintended target. A replayed recording does not increment
here because this adapter authenticates a live speaker. A world without that
sensor may admit replay and can teach it as a counter rather than silently
assuming secure voice authentication.

## What the pattern graph needs to support

The three hand traces illustrate design consistency only. They do not pass P6's
SOURCE/NATIVE/PERSISTENCE gates. Any future runnable slice should select a small
subset, keep S6-A's actual paid build/use/withdrawal/replenishment proof, and prove
Save/reload/literal Import where its changed state requires them. For UI claims,
rebuild and exercise a fresh origin at 1366×768 laptop plus wider desktop; mobile
remains deferred. A tracing panel must show admitted player knowledge and actual
observations without exporting sealed truth.
