# P2 domain API and downstream handoff

`src/lamplight_factory.js` exports `createLamplightDomain(operations?)` without registering a domain or installing global readers. Each constructed domain starts with its own fresh slice. It exposes the existing registry descriptor (`id`, `initialState`, `save`, `validate`, `migrate`, `load`, `tick`, `commands`, `projection`) plus `configure`, `dispose`, `getState`, `setState`. `commands.quote/execute/useItem` and the namespaced `lamplight` slice retain the native contract. A standalone domain can quote/execute immediately after configuration, without a registry. A registry still initializes/loads the same schema-1 state through its existing hooks.

Required ports are the narrow existing native stock/transaction/display operations (`actor`, `count`, `itemOwners`, `assertSpend`, `removeItem`, `persist`, `writable`, `location`, `refresh`, `logMessage`, `locationRevealed`, `revealLocation`), plus `ambientLight()`, `clockPosition()`, `bindLightSource(reader)`, `bindReadingLightReader(reader)`. `refreshPanel` is optional. Each binder must return a scoped cleanup function. Clock identity belongs to the host; the domain creates no clock or writer. Stock belongs to the host; failed persistence uses the existing native transaction owner.

`configure` detaches prior callbacks and clears the transient settled-light interval before binding replacement ports. A partial install failure cleans up successful prior installs. `dispose` is terminal and idempotent: it detaches this instance's callbacks, makes commands ineligible and ticks inert, and retains its save slice. There is no registry unregister requirement; disposable hosts can discard their own registry. Saving or examining the domain after disposal does not advance it. An actor/stock deliberately supplied to multiple instances is shared host state, not an assertion of whole-game isolation.

`Hero.bindNativeLightSource(reader)` returns an idempotent disposer for one unique source. Named `setNativeLightSource` remains compatible. `reveal_chain.bindReadingLightReader(reader)` returns a disposer for one reader; this single native reader consumer uses the newest still-bound reader, returning to the previous live reader on removal. Legacy `setReadingLightReader` remains its fallback. Independent hosts supply their own reader destinations, as the isolation fixture does; constructing a factory does not call these native binders itself.

`src/lamplight_domain.js` is explicitly the played game's singleton facade. Existing exports and `domainRegistry` routes remain compatible. Native ambient/calendar/reader defaults live there solely for legacy configure callers. The old actor stub fallback replaces its own named source with a zero callback on detach; actual native composition uses `bindNativeLightSource`, which removes the callback. Independent hosts import the factory directly.

`src/native_tool_domains.js` is the native composition adapter. It configures tools and lamplight directly, selecting only the lamp's operations and its scoped native binders. `configureToolsDomain` configures tools alone. `refreshToolsPanel` supplies the lamp's existing panel redraw. `main.js` changes only its import/call name, with no line growth; no save_files/display hunk or new registry lifecycle was needed.

P4 may edit released tools-domain work/target semantics after P2 final release and P5's separate release. Preserve this adapter's direct configuration and the lamp's `quote/execute` registry routes. Use P3's unchanged `ordinaryLampJourney` for the current-format native lamp contract. Two-instance, reconfigure, disposal, shared native Hero callback and write-rollback fixtures live in `tests/domain_instance_isolation.test.js`.

P1's `items-registration.patch` is applied: items imports/registers the existing enemy equipment item factory. P3 needs no composition patch. FF3's separate household travel/host patch remains with its owner and is not folded into this finite P2 change. Source release is not human acceptance or whole-game reentrancy.
