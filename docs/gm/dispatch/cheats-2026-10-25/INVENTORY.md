## State and priority key

Source-row labels such as `CW-43` are local inventory IDs based on the source line when the owner has no stable row ID. Existing source codes such as `B01`, `SH4`, and `IM17` are retained.

- **built** means the named cheat’s behavior is a runtime feature. Built labels name the bounded mechanism, not the entire reference power.
- **partial** means a related card or surface exists, with behavior still missing. Families remain partial when only a narrower card is built.
- **proposal** means the name or family is design/source material with no cheat-card runtime consumer. Existing general-purpose systems listed as candidates do not change that state.
- **Priority** records only a source-backed status: existing slice, explicit IM17–IM20 ranking/wait, or unranked palette. It does not select implementation scope.

## Coverage and gaps

- The source set has overlapping counts: CHEAT_LIBRARY defines 49 families (including the system-quest shell), 12 player-side cards, 16 enemy-side family policies, 18 information-cheat cards, and four explicitly ranked IM17–IM20 rows. CHEATS_BY_WORLD claims 70 additions beyond the 25 cosmology placements. Its named world tables contain 67 rows, plus 10 prose-only trimmed/limited entries; the latter may account for the stated total only in part and are retained separately rather than forced into the count. It also has four Bookshelf entries and 56 game-source rows. CHEAT_COSMOLOGY contributes 25 placed book cheats, 19 simple cheat archetypes, 17 anime/web-novel placement rows, six Haruhi/Steins;Gate cheat rows, and six full-read Slime rows. The simulator owner contributes three simulation engines, seven modes, seven foresight grades, 13 mapped family rows, and five possible keep/reward forms. The table contains 324 deduplicated inventory entries; counts above refer to original rows before cross-owner alias consolidation. Overlaps are deduplicated by normalized displayed name while all found locators remain in the table.
- `CHEAT_CORE_AUDIT.md` names the active implementation owners, lane dispatch, and rerun triggers; its six audit lanes are not additional cheat cards. Its October 23 row is historical; the D4 implementation receipt is linked from its run log.
- Initial audit: 324 deduplicated source entries, comprising one partial shell and 323 proposals. This includes simulator engines, modes, grades, aliases and policies, so it is not a count of 324 independently implementable cards. D4 adds two explicit runtime rows and updates four named module rows. Six bounded runtime cards are built; the broad reference powers/families retain their initial labels unless their own mechanisms exist.
- Named gaps: Patient Furnace needs an authoritative native offline replay policy, beyond the pure `away_ledger` arithmetic. Rehearsed Foe needs an actor power descriptor and native battle adapter, because `simulation.powers[actor]` validates registry powers rather than arbitrary cards. Pattern Book needs the existing knowledge-redacted `craftLedger` consumer, not direct reading of hidden residue. Most book examples need their world/content mechanism adapters; a source name and a candidate path are insufficient to produce that behavior.

- Candidate ownership is intentionally bounded: `src/expansion_engine.js` and `src/simulation.js` can support deterministic simulation; `src/combat_math.js` supports injected-random combat estimates; `src/seeded_streams.js` owns seeded draws; `src/harvest.js` owns carcass observation; `src/titles.js` owns titles. D4 joins harvest and seeded streams; the other candidates remain extension points.
