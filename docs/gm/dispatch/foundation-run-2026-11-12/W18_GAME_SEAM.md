# Wave 18, lane E23: the game seam probe

*Proposal throughout (AD32), 2026-11-12. Lane `fable/w18-seam`. Agent-verified by one headless test, not human-reviewed. A probe: new test files and this note, no change under `src/`, no build, no interface. Codes: PC95, PC99, E9, E14, E20 to E23, AD5, AD38. "Reading" marks a claim taken from source and not exercised; "inference" marks a conclusion drawn from one.*

## What works today

Test: `tests/engine_game_seam.test.js` with `tests/fixtures/engine_game_seam.mjs` (the mixed valley of seventeen packs plus the host test's blade, ward, bond, feed and casts in its yard, and a clock bridge of about thirty lines). It boots the real game through `scripts/headless/runner.mjs`.

- **Clock.** The game's root clock (`expansion.clock`) is whole minutes and the sky pack already reads the same calendar from it (root minute 0 is 08:00). The bridge is one call, `sync(rootMinute)`, with engine minute equal to root minute. No rounding arises.
- **A day.** The engine restored out of a game save and advanced one minute per game tick for a day equals one engine jump byte for byte. Spans of 30, 7 and 45 minutes through the game's own `update_timer` (travel uses it) agree too.
- **Save, export, import.** A 45,804-character engine save with a working in flight, an armed stored working and a held binding, placed at `expansion.engineWorld`, comes back byte-identical from the game's save, its export file, and its import (validation, preflight in a second game instance, reload).
- **Away.** A banked hour spent through the game's real away bank moved both clocks 60 minutes and the engine equals one jump. A whole banked week spent the same way (`YAIRPG_SEAM_WEEK=1`) took 177 s of wall time, 17 s of it the engine in 167 syncs of 30 to 79 minutes, and equals one engine jump.
- **Engine cost.** A day is 321 segments and about 0.35 s in one jump, 1.4 s minute by minute. A week is 2,061 segments and 10 to 13 s in one jump or in 168 sixty-minute spends.

## How the game does it (for the tie-in)

- `create_save()` in `src/main.js` builds a new object from live state each time; `load()` reads the keys it knows. `validateSaveEnvelope` (`src/save_files.js`) checks known slices and ignores others. Version: the `"game version"` string, a newer one is refused; `fork_schema: 1`; `expansion.schema` with migrations. No checksum. Budget: 2,097,152 characters for the whole origin, compressed above 262,144. A fresh save is 157,975 characters in 74 slices.
- `src/domain_registry.js` is the existing home for a slice: `registerDomain({id, initialState, save, validate, migrate, load, tick})`. The registry writes `envelope[id]`, validates, loads, and calls `tick(consumedMinutes)` from the clock owner.
- One tick a second, one minute a tick awake, six asleep (`config.time_speedup_when_sleeping`), longer explicit spans for travel, rests and held time; the clock can also return 0 (a waiting choice). Each tick writes a whole save.
- Absence is not simulated. `awayBank` banks wall time as minutes (cap seven days, a dial; the rest is dropped) and the player spends it sixty minutes at a time through ordinary ticks.
