# Common rules for the quality deep-dive lanes (2026-11-06)

Direction: [USER_VISION](../../../USER_VISION.md#five-quality-deep-dives-on-the-prose-model-2026-11-06).
Model to copy: the prose pass. Read [PROSE_RULES](../../../PROSE_RULES.md),
`scripts/check_player_text.mjs`, `scripts/player_text_baseline.json` and the head of
[the prose backlog](../../../prose/PROSE_REWRITE_BACKLOG.md). Your lane produces the same
four things for its area:

1. **Sweep.** Measure the actual problem in the current tree with a script, not a guess.
   Report counts, worst examples (quoted, with file:line) and which worlds/starts.
2. **Rulebook** `docs/<NAME>_RULES.md`, 6 to 10 lines, table shaped like PRS
   (Code | Rule | Default, dial, reason). Every line is a default, a dial and a reason,
   never never/always/only (AD5, AD38). Head says: "Proposed 2026-11-06 (AD32);
   run authorized by Weibao, lines not yet accepted." Link existing owners instead of
   restating them.
3. **Check** `scripts/check_<name>.mjs` with a baseline ratchet like PRS5: today's tree
   passes, a new violation fails, fixing one retires its entry. Flags `--update-baseline`
   and `--backlog`. Export the pure scanning function so a test can call it.
4. **Backlog** `docs/<area>/<NAME>_BACKLOG.md`, generated by `--backlog`, ranked by what
   the player meets most (opening surfaces, then frequent surfaces, then reference).

Plus a focused test `tests/<name>_check.test.js` (fixtures in the test, a failing and a
passing case, and that the current tree passes against the baseline) and a lane report
`docs/gm/dispatch/quality-deep-dives-2026-11-06/<LANE>_REPORT.md`.

## Ownership (hard)

- You write only the files your brief names. Nothing else.
- Do not edit `src/`, `styles/`, `index.html`, `package.json`, `dist/`, or any shared doc
  (AGENTS.md, CLAUDE.md, PROJECT.md, USER_VISION, VISION_DIGEST, RULES_INDEX, IDEA_INDEX,
  DESIGN.md, UI_RULES, PROSE_RULES, BALANCE.md). Other sessions have uncommitted work in
  many of them. If an owner needs a change, write the exact proposed hunk in your report;
  the coordinator applies it.
- No fixes to content in this wave. The backlog is the deliverable.
- Never git add, commit, stash, reset or checkout. Never `pkill -f`.
- Run `node` with absolute repo paths; run only your focused test
  (`node --test tests/<name>_check.test.js`), not `npm test`.

## Writing and secrets

- Sealed secrets: cite by ID, route and status only, in every file you write. Never quote
  a sealed truth. When a scan hits sealed content, record its file and ID, not the text.
- No em dashes. Plain, short words. No "load-bearing", "worth stating plainly".
- Player-facing examples you rewrite follow PRS4/PRS6. Voice sample for player text
  (Tingen, a Reports line): "The rent is due Monday. Mrs. Smith will not ask twice."
- Label evidence SHOWN (you ran it), STATED (a doc says it), INFERRED.

## Report shape (under 120 lines)

CHECKPOINT line at top (done / partial + what remains). Sweep numbers. Files written.
Check command and result. Focused test result. Proposed owner hunks for the coordinator.
Top five backlog items. Open questions as defaults the coordinator can pick, not
either/or questions for Weibao.
