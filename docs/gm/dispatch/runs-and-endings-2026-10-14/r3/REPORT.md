# R3: genre mechanics for long runs and endings

2026-10-14. **Proposals only.** No design accepted, gameplay changed, build run, save touched, commit or push. This lane writes only `r3/`; Claude owns integration into part 22. The requested sources are comparators, not a new world implementation order.

The useful default is to separate a person's ending from a campaign's ending and a world's continuation. Let a dead or retired life leave real consequences, show exactly what can carry, and offer continuation, shelving, a fresh premise or prestige when their rules allow. A new life need not finish the whole source plot to have mattered. Keep earned progress understandable without promising universal resurrection, guaranteed survival or a visitable copy of every attempted timeline.

These are deliberately different mechanisms. A reset calendar, a selected challenge profile, a forked save, a visitable alternate world and a prestige settlement should not share an ambiguous button called “continue.”

## Recommended synthesis and scope

The closest combination for the questions is **G01-G03 for history after death**, **G05/G17/G19 for meaningful incomplete lives**, **G09/G33/G34 for explicit reset or shelf semantics**, and **G25/G29/G31 for manageable promises**. Keep G13 as the counterexample to a universal playable bad ending, G14 as the caution against costly knowledge retention, and G18 as a way to offer replay value without inflating prestige power. These are recommendations for integration, not a ranked implementation backlog.

For the first milestone, one realm and one prestige layer can expose a run recap, a carry/settlement preview and a small set of real commitments. A multi-world atlas, simultaneous selves, generalized aggregate simulation and several prestige currencies remain later possibilities. The genre comparisons do not make them acceptance gates now.

If selected later, any desktop board/recap needs a declared laptop viewport and rebuilt behavior evidence. New saved records require validated schema, explicit old-save behavior and save/reload/import proof, including failed writes and repeated settlement where relevant. None of those gameplay gates was attempted by this docs-only lane.
