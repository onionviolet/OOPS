# R6: four whole-save paper playthroughs

2026-10-14. Design stress test, not accepted design, implementation or gameplay proof. Prefix **H** identifies gaps; A, B, C and D identify playthrough steps. Each save starts with a new record and reaches a declared closing state. Continuing after that state remains possible.

The main gap is connective: part 22 describes many sensible options, but does not yet say exactly which event changes control, advances time, settles obligations and pays rewards. The examples below use explicit provisional rules to get through those transitions. They should not be read as evidence that the engine can already do so.

Each transition names five destinations: **body/character**, **soul carrier**, **world instance**, **lineage/legal claims**, and **save/meta record**. Player knowledge stays with the player; a notebook theory is never promoted into character or world fact. Closing a chapter and leaving a world do not automatically kill someone or prestige them. Source packs remain clean templates.

## C. Original world: contracts, a party, debt, probate, afterlife and a new soul

Its declared local law: ordinary debt is secured against the debtor's pledged property and estate; heirs inherit only the remainder unless they separately guaranteed it. It has an afterlife plane accessible to a dead person's continuing soul. Soul destruction there is final for that soul. This save is not hardcore. The initial character is Mara, 25, soul `C-S1`; later life is Tavi with distinct soul `C-S2`.

## Save compatibility and acceptance boundary

These examples need a coordinated optional persistence domain, not thirty independently defaulted fields that accidentally activate a simulation. Proposed records include transition/identity links, instance clocks/content pins, committed selections/streams, deed claims, contracts/escrow, estate cases, trace custody, route-credit provenance and terminal state. Each row in [INTEGRATION.md](INTEGRATION.md) maps the relevant part 22 builds and compatibility decision.

**Recommended migration decision:** additive, versioned, dormant records for existing saves. Absence means “this system is not represented,” not “generate a childhood, new soul, debts, world clocks or a canon-ending schedule on load.” Preserve existing heir semantics and vanilla defeat/recovery. Unsupported active records stay intact for a compatible reader; fail a requested activation/import safely rather than discard state. Do not retroactively pay for guessed deeds. A source update never rewrites a live instance without a qualified explicit update route.

Before any future implementation claims these playthroughs work, run interrupted transition and failed-save publication checks, then exact save/reload/literal-file import at the identity, money, shelf, generation-jump, soul-death and true-ending boundaries. Recheck conservation, RNG/selection identity and terminal state. A deterministic long-run harness is useful source evidence; it is not source fidelity, browser proof or director acceptance. Desktop UI, if later built, needs its own target viewport and rebuilt evidence; mobile stays deferred.

Only Weibao can accept the desired pace and grief intensity, the central cross-run story and its ending, or a change to accepted priorities. Those taste gates do not block saving recommendations now. No new implementation, source acquisition, raw prose, save access, commit or push is part of R6.
