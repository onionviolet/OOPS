# T5 references: what each crafting model actually supplies

2026-10-14. Proposal research extending PI1–PI11, not accepted mechanics. Web sources were read or searched today; archived source audits are explicitly qualified below. No reference game was run. Idle-fit judgments are our inference.

## V1: Four mechanisms worth keeping separate

Semantic combination proposes a name; a recipe consumes declared inputs; an assembly connects parts; a planner finds executable steps toward a goal. One reference can support several, but none establishes all four. An AND/OR dependency display is also not automatically a scheduler or an HTN planner. The incumbent is PI7a/PI7b plus the existing [generation contracts](../../../../research/procedural-materials-2026-10-13/deep/GENERATION_CONTRACTS.md), especially P6/P8/P9. The gap is goal-to-method planning and connecting its products to native consumers, not replacing material truth with word association.

## Semantic discovery and authored properties

**V2. Infinite Craft.** The live [official page](https://neal.fun/infinite-craft/) exposes an item library and discovery presentation, but its readable page does not document the server model. [InfiniteCATs, the research paper's indexed text](https://doi.org/10.1145/3803784.3816855), describes its Infinite Craft-inspired system asking an LLM for a result when a pair has not been merged before. This supports semantic combination as a documented research mechanism; the exact current Infinite Craft backend, model, cache policy and reproducibility are **unverified**. The DOI body failed to open; the [authors' repository](https://github.com/s-almeda/infiniteCATs) was readable as a separate route. Do not present that implementation as Neal Agarwal's source. Informs PI6/PI7d: accepting many names is feasible; generating a name does not supply physical behavior.

**V3. Little Alchemy.** The [original official site's indexed description](https://littlealchemy.com/) advertises combining elements. The developer's [Little Alchemy 2 listing](https://apps.apple.com/us/app/little-alchemy-2/id1214190989?platform=ipad) documents mixing items, a library of connections and an encyclopedia of discoveries. These establish discovery/library play. They do not publicly establish the current recipe-storage algorithm, exhaustive alternate paths or a resource-production simulation, all **unverified** here. The browser body was sparse and a help page failed; the developer listing supplied the readable route. Informs PI2/PI4/PI7a: retain discovered connections and allow authored alternative routes; do not infer arbitrary chemistry or idle throughput from the collection interface.

**V4. Doodle God.** [JoyBits' product page](https://joybits.games/games/doodle-god/) documents element combinations, items and concepts, puzzle/quest modes, artifacts from triple reactions and discovery descriptions. This is documented combinatorial content with framed objectives, not evidence of a physics resolver or planner searching toward every named object. Exact recipe storage and current edition differences are **unverified**. Informs PI2/PI4/PI8: a commission can bound invention, and a finished discovery can get narrative acknowledgment. Discovery text still needs a usable product in YAIRPG.

**V5. Scribblenauts.** In a [2009 developer interview](https://www.nintendoworldreport.com/interview/19950/scribblenauts-interview-with-jeremiah-slaczka), Jeremiah Slaczka describes Objectnaut as an authoring tool for object properties, with family-wide rules and individual exceptions. The [publisher's Super Scribblenauts description](https://www.nintendo.com/en-gb/Games/Nintendo-DS/Super-Scribblenauts-273212.html) explicitly documents dictionary adjectives changing behavior. The [Unlimited publisher listing](https://store.steampowered.com/app/218680/Scribblenauts_Unlimited/?cc=US&l=english) describes creating objects, assigning properties and sharing them. Informs PI1/PI6/PI7b/PI8: a finite vocabulary can create variety through implemented properties. Exact noun counts, adjective precedence/conflict rules, authoring schema and save semantics are **unverified**; do not promise that arbitrary adjectives become mechanics. Dictionary matching and authored properties differ from LLM generation.

## Materials, recipes and schematics

**V6. Dwarf Fortress reaction raws.** The project's [source audit, DF-M02/DF-M03](../../../../research/dwarf-fortress/REPORT.md) records shipped build 24557528 declarations for reactions, reagents, products, workshops, civilization access, preserved containers and separate fuel requirements. Locators: `data/vanilla/vanilla_reactions/objects/reaction_smelter.txt:5–55`, `reaction_other.txt:26–82`; [coverage manifest](../../../../research/dwarf-fortress/COVERAGE.json) pins hashes. This is archived primary-data inspection, **not refreshed primary-source verification**: the manifest's private retained path is absent on this machine today. Informs PI2/PI5/PI10: methods can consume stock while retaining tools and producing useful byproducts. Runtime job reservations, cancellation and present-release behavior remain **unverified**. Adapt declarative method roles; do not copy a raw catalogue or assume its engine transaction model.

**V7. Noita alchemy.** The developer's [release notes](https://noitagame.com/release_notes/) confirm alchemy reactions and Materials.xml tag-related reaction loading. The archived [alchemy audit](../../../../research/noita/ALCHEMY_AND_SUBSTITUTION.md) distinguishes exact selectors, family selectors and extra-input reactions from the community reconstruction of seeded recipes. Its shipped-data extraction is absent locally today, so detailed XML claims remain archived source evidence, **not a fresh binary/source check**. Engine-side seed algorithm and its equivalence to community tools are **unverified**. Informs PI5/PI7b and P6/P8: world-stable recipes need actual feasible inputs and frozen results. No reaction tables, secret truths or dangerous formulas are reproduced here. Noita's simulation is a resolver reference, not evidence of a target planner.

**V8. Minecraft recipe graphs.** Mojang's [crafting guide](https://www.minecraft.net/en-us/article/how-craft) documents inventory/table recipes and required supplies. Microsoft's [Bedrock shapeless-recipe documentation](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/recipereference/examples/recipedefinitions/recipe_shapeless?view=minecraft-bedrock-stable) declares ingredient IDs or tags, outputs, station tags and recipe-book unlocks. Composing those input/output relationships into a backward dependency graph is our inference. Informs PI2/PI4/PI7a: distinguish recipe-book visibility from actual recipe applicability; allow ingredient families without erasing identity. These are Bedrock schema observations, not a claim that all Java versions share that syntax or that Minecraft itself solves arbitrary target roadmaps. Automated production/offline simulation was **not verified**.

**V9. Factorio recipe graphs.** The live [RecipePrototype documentation](https://lua-api.factorio.com/latest/prototypes/RecipePrototype.html), displayed version 2.1.21 during this pass, declares input/output records, machine categories, craft duration and unlock behavior. Multiple outputs and probability/productivity fields prevent treating every recipe as a simple one-parent tree. A graph over these records is our inference. Informs PI2/PI3/PI10: distinguish obtaining one item from sustaining a production rate, and preserve byproducts and required machine categories. Existing [Factorio dossier](../../../../research/factorio/REPORT.md) owns broader supply/research evidence; this lane does not reassert it. No factory, throughput benchmark, current balance or engine offline behavior was **verified by execution**. Pin a version before any schema adaptation; the `latest` URL can drift.

**V10. Caves of Qud tinkering.** The developer's [release roadmap](https://cavesofqud.com/roadmap/), under its completed modification arc, documents learning item schematics through data disks and extending schematics to modifications. The developer's [July 15, 2023 devlog](https://freeholdgames.itch.io/cavesofqud/devlog/560711/feature-friday-july-15-2023) names recipe-disk categories and tiers. This extends TGR5 through modular modifications, not its already-recorded reverse-engineering percentage. Informs PI4/PI6/PI8: a schematic supplies knowledge, while a modification needs a compatible owned object. Precise present-release bit costs, reverse-engineering chance and disassembly yield are **unverified** here; do not import them as universal science XP or a current balance claim.

## Roadmaps, planning and part composition

**V11. Dr. Stone.** The [official season-one episode 23 synopsis](https://dr-stone.jp/story/1st/23/) explicitly calls the communication-device project a roadmap and assigns different work to specialists and the village. This verifies roadmap framing and collective fabrication without reproducing its technical instructions. Informs PI3/PI4/PI10/PI11f: parallel contributions can become recognizable story beats, and assembling them gives the large goal a visible payoff. That narrative interpretation is our inference. Diagram layouts, exact prerequisite counts and the scientific reliability of the series' procedures are **unverified**; fiction is not a chemistry authority. Full manga/anime viewing was not performed.

**V12. GOAP in F.E.A.R.** Jeff Orkin's [GDC 2006 paper, pp. 4–5 and 10–13](https://www.gamedevs.org/uploads/three-states-plan-ai-of-fear.pdf) describes action preconditions/effects, A* search over world states, procedural checks and execution through an FSM. Informs PI2/PI10/PI11a: when a supplier leaves, reconsider a known alternative and validate its current access. This is state/action planning for game AI, not evidence that F.E.A.R. procedurally invents crafted objects or uses HTNs. Cost-optimality under our mixed stock/time/social costs and a craft-scheduler implementation are **unverified**. Borrow revalidation and replanning, not per-frame whole-world search.

**V13. Hierarchical task networks.** Erol, Hendler and Nau's [UMCP paper, pp. 1–3](https://www.cs.umd.edu/~nau/papers/erol1994umcp.pdf) separates primitive/compound tasks and decompositions into constrained task networks. Ordering and state constraints matter alongside alternatives. Its example distinguishes building a house from merely having one through purchase. Informs PI2/PI10/PI11f: preserve player intent, method order and access constraints. A plain AND/OR graph is useful input/display, but does not by itself implement HTN semantics, conflict resolution or temporal resource planning. Soundness of this paper's algorithm does not certify T6 or any YAIRPG planner. Our implementation and scale remain **unverified**.

**V14. Kerbal-style part composition.** The [official KSP site](https://www.kerbalspaceprogram.com/) documents assembling spacecraft from parts and evaluating their flight through aerodynamic/orbital physics. That supplies the distinction between assembling named pieces and a functional composed result. Informs PI1/PI6/PI8: assemblies need compatible interfaces, energy and a named performance consumer; a lamp-with-sensor should not just accumulate adjectives. Detailed connection, staging, resource-flow and failure schemas were **not inspected**. YAIRPG can use coarse authored interfaces without adopting KSP's continuous simulation. The earlier [assembly owner](../../../../worlds/PROGRESSION_AND_ASSEMBLY.md) remains authoritative for the product envelope.

## V15: Research on language-generated crafting

Drake and Dong's [Real-Time World Crafting, arXiv v1, 2025](https://arxiv.org/html/2510.16952v1) evaluates natural-language translation into constrained DSLs controlling a 2D spell-crafting ECS. It offers a stronger PI7c/PI7d mechanism than unrestricted text: generate within a supported grammar. Its evaluation includes an LLM judge and six-person pilot. The authors explicitly limit generalization, note synthetic/good-faith test inputs and identify model drift as a reproducibility problem. It does **not** demonstrate long-lived idle saves, canonical world consistency or generalized industrial crafting. Adapt allowlisted behavior plus validation, subject to our own acceptance checks.

[InfiniteCATs](https://doi.org/10.1145/3803784.3816855), 2026 conference paper, is a directly relevant semantic-crafting study, but only indexed paper text was available. Its [author repository](https://github.com/s-almeda/infiniteCATs) documents combination caching in SQLite and a model API. The README calls the model local while listing a cloud provider, so deployment locality is contradictory and **unverified**. Treat repository mechanisms and paper findings separately; full-paper methods/results and runtime performance were not verified. Informs PI6/PI7d/PI4 through tracing discovery paths. No benchmark from either project substitutes for YAIRPG validation.

## Idle fit and disposition, inferred

| Codes | Usable lesson | Idle adaptation and cost | Disposition |
|---|---|---|---|
| V2–V4 | Discover connections, retain a growing library | Let experiments be active choices; repeat established production through actual jobs. Semantic novelty alone gives no durable idle output | Adapt discovery presentation; park uncontrolled result generation |
| V5, V10 | Authored properties/modifications create many variants | Compile supported properties into an owned item and useful consumer. Requires compatibility and persisted identity | Adapt bounded function/modification vocabulary |
| V6–V9 | Real inputs, tools, stations and useful outputs | Queue known methods, retain tools, reserve shared stock, route byproducts, stop on named shortage. Requires scheduler joins | Adapt declarative methods; no new simulation mandate |
| V11–V13 | Goals, specialists, constrained steps and replanning | Commit one chosen method, run admitted tasks on the local clock, revisit affected branches after world changes. Requires actor knowledge and capacity | Trial on small authored roadmaps |
| V14–V15 | Functional composition and constrained generation | Resolve typed interfaces/behaviors first; language can propose a supported graph. Needs consumer proof and durable receipts | Adapt interfaces; trial offline authoring first |

This comparison adds concrete boundaries and candidate mechanisms to PI. It does not select runtime models or expand the one-realm/one-prestige milestone. All player-facing diagrams, if later selected, target laptop/desktop; mobile optimization remains deferred.
