# T5 language-model routes for invention

2026-10-14. Proposals only. PI7c is an offline content-authoring route; PI7d is a later runtime option, not selected. This lane installs nothing, calls no generation model, changes no saves and selects no provider. Web research in REFERENCES is distinct from a generation trial.

The [story-request plan](../../procgen-2026-10-13/PLAN.md), P15 authoring/lint and P22 creative-director tools, supplies a related proposed workflow. It is not proof that a production pack compiler already exists. The [materials generation contracts](../../../../research/procedural-materials-2026-10-13/deep/GENERATION_CONTRACTS.md) retain product truth, feasibility, revision freezing and knowledge filtering. These routes add target interpretation, graph authoring, receipts and failure boundaries above them.

## V34: PI7c offline authoring, then deterministic play

Example request: “make soap in Harry Potter.” The author first resolves requested world/era, literal soap versus functionally equivalent cleaning, actor starting means, and whether the output is a batch, station or service. Preserve the player's intention; supplied outside knowledge needs the existing I1 player/character distinction, not automatic character mastery. Canon methods remain exact where the world owner qualifies them. A new spell or recipe is labelled original proposal rather than canon.

| Stage | Proposed artifact | Failure boundary |
|---|---|---|
| Interpret and scope | Typed target from V16–V18, world/law revisions, source locators and consumer requirement | Ambiguous input gets supported alternatives or a named unresolved interpretation; no invented world law |
| Author candidate | Stable node/method IDs, AND/OR dependencies, task order, actual acquisition witnesses, fictional access/costs and consumer references | Generated text is an untrusted candidate, not an executable command or discovered fact |
| Compile and validate | Canonical pack plus V37 validation receipt | Unsupported consumer/operator remains a new implementation need; reject dead branches rather than rename them usable |
| Exercise selected pack | Independent fixtures, feasibility witness and later rebuilt acquisition→work→use journey | Source/data validation is not gameplay proof; director taste remains separate |
| Publish a selected revision | Content-addressed immutable pack and migration/compatibility policy | Runtime registration requires the separately authorized integration owner; this document grants none |

Once a pack is selected and integrated, native gameplay reads its frozen definitions. The authoring model may produce different candidates on another run; gameplay determinism comes from preserving the selected artifact and resolver revisions. Seed and temperature settings alone do not establish reproducible model output.

Only authoring/editing needs a model. Established production and offline settlement need no network/model calls. A failed authoring round costs review time and model tokens, but consumes no player stock or progression. Preserve the prior selected pack until the replacement passes compatibility. One small home-world pack can qualify the route without requiring a finished canon-world catalogue.

## V35: PI7d runtime options, unselected

| Option | Role of language model | Determinism and cost | Failure handling |
|---|---|---|---|
| Typed-target interpreter | Parse free text into known functions/forms and find candidate authored methods | Freeze normalized target; deterministic native planner over pinned packs. Model cost only on a novel interpretation | Offer matching supported goals or leave a proposed investigation; no invented method/consumer |
| Remote pack proposer | Propose missing methods through a constrained authoring grammar | Provider latency, per-call cost and drift; freeze complete validated result before it can govern play | Deadline, bounded repair, validation failure and outage leave a pending proposal; authored alternatives continue |
| Local pack proposer | Same proposal role with an on-device model | Hardware/memory/energy and model/version management replace some remote costs. No inference-speed or quality claim verified here | Resource failure or unsupported output follows the same no-publication path; avoid blocking the game loop |
| Hybrid | Resolve known targets locally; queue novel proposals asynchronously, locally or remotely | Cache validated world-scoped artifacts, not bare nouns. Established idle work makes zero generation calls | Keep pending requests separate from admitted jobs; stale responses require current-world validation |

A local model is not automatically deterministic or inexpensive. A remote model is not allowed to write state because it returns well-formed JSON. All options use the same schema and consumer allowlist. Initial PI7a/PI7b remains the incumbent; PI7c is the bounded extension. Runtime selection depends on measured interpretation quality, validation yield, latency, total cost and director preference, not on the word “infinite.”

No generation per idle tick, craft repetition or recipe preview. A model suggests how the existing mechanics could meet a target; it does not resolve physics, invent an executable effect, award knowledge or decide stock debits. A runtime text-only naming option can vary presentation with observer-safe facts, but cannot change mechanics.

## V36: Determinism and saved receipts

| Record | Proposed meaningful fields | Why save it |
|---|---|---|
| Request | Stable request ID; target interpretation; literal/function-equivalent intent; world instance; actor knowledge view; content/law revisions; context fingerprint; status | A reload or duplicated UI request resumes the same pending work; naming alone is not a cache key |
| Authoring provenance | Route, model/provider identifier where available, prompt-template hash/revision, output hash, referenced sources and compiler revision | Explains what authored the artifact; does not claim a provider can reproduce it |
| Selected pack | Complete canonical node/method definitions, interfaces, costs, consumer refs, opaque abstract nodes, visibility policy and immutable content hash | Saves/imports remain playable without the provider or a session cache |
| Validation | Validator revision; assumptions; witness paths; verified/conditional/unsupported findings; world-law and consumer revisions | Distinguishes a lawful feasible pack from unsupported text |
| Execution | Selected method and interpretation; committed native job/stock/tool references; cost ledger; time boundaries; published product and outcome receipts | Planner intent cannot duplicate actual work or stock consumption |

Resolved world/material truth stays in its existing owner, rather than being copied into several conflicting graph caches. Receipts reference frozen truth revisions and preserve any generated definitions actually required by an imported pack. Store the complete selected artifact or durable embedded content, not just a seed, model name or remote URL. A content hash detects identity; it is not a guarantee that the content is safe or feasible.

Cache scope includes world law, target form/magnitude/identity policy, permitted mechanics and authoring revisions. Current actor access/knowledge remains a separate projection; two actors may share a pack while seeing different branches. On a changed context, reevaluate affected witnesses and next-step eligibility. Do not silently regenerate old products or rewrite historical knowledge. A stable sort order and purpose-specific committed draws belong to native generation, not model sampling.

Unknown pack revisions or consumers need an explicit compatibility response: retain the record dormant and explain unsupported execution, or apply a reviewed migration. Do not delete it, recompute its truth or map it to the nearest unrelated item. Provider unavailability must not prevent restoring already accepted content.

## V37: Validation shared by both routes

| Layer | Reject or qualify | Observable acceptance case |
|---|---|---|
| Intent and source | Changed world/era, literal target replaced by a lookalike, canon assertions with no locator | A magical wash is offered as equivalent cleaning and never presented as literally soap |
| Language/schema | Unknown operator, executable script, unresolved ID/revision, oversized/unbounded graph | Only authored allowlisted tasks/consumers can enter a candidate pack |
| Planning | Ungrounded leaves, cycles without an independent bootstrap, mutually exclusive simultaneous means, invalid task order | Glass has an existing unlock/source witness; one paid specialist cannot occupy two overlapping jobs |
| Material/assembly | Invalid units/conversions, duplicate conserved identity, incompatible interfaces, missing capacity/energy payer | Combined lamp/gauge cannot silently share an insufficient housing or the same spent stock |
| Useful output | Named property has no reader; medicine promises unsupported infection care; station exists only in text | One finished item changes a selected native action or service after publication |
| Knowledge/presentation | Author graph leaked to an ignorant actor; sealed ID or internal truth exposed through prose, prices or errors | Different actors receive different known projections of the same physical truth |
| PI9 abstraction | Dangerous/drug candidate contains real instructions, chemical constituents, quantities, conditions or technical facility details | The whole unsafe candidate is rejected; a safe abstract graph can be independently authored |
| Publication/compatibility | Save-local reference only, partial registered effects, update rewrites old truth, failed save changes stock | Failed publication leaves stock, draws and admitted jobs intact; selected pack restores without a model |

These extend P6/P9 to goal interpretation and scheduling; they do not replace those contracts. A static witness proves authored feasibility under its assumptions, not eternal political access. Unknown ingredients can still work under actual laws; an assay must not become a compulsory acquisition prerequisite where the existing contract permits experimentation. LLM plausibility and LLM-judge scores are not feasibility certificates.

For runtime calls, send only the context needed to interpret the request and propose allowed nodes. Filter the actor-visible projection before text generation; do not give that model a sealed world truth catalogue merely to describe a lamp. A privileged offline author can use sealed source privately, but public output still follows the discovery route. Raw user requests or model failures containing restricted details must not be echoed into public logs or item descriptions. Keep any necessary diagnostic private and bounded.

## V38: Costs and failures remain visible and bounded

Let `t_in`, `t_out` be token use, `p_in`, `p_out` the chosen provider's current rates per million tokens, and `r` the number of calls including repair. Proposed cost estimate is the sum over calls of `(t_in*p_in + t_out*p_out)/1,000,000`, plus any separately billed tools, hosting and review time. No current prices, latency or model-quality figures were measured here. Offline authoring amortizes this cost across repeated play; a runtime route pays for new requests and repairs. Useful measurement is **cost per validated, useful pack**, not cost per fluent reply.

Project-level authoring limits can bound graph size, output tokens, repair attempts and model time without imposing a fixed global invention limit on the solo player. A proposed initial request gets one generation attempt and at most one bounded repair before returning a named unresolved proposal; these are computation budgets, not in-world “once” rules. The player can choose another supported method or revisit later.

| Failure | Proposed response |
|---|---|
| Timeout, outage or quota | Leave request pending/failed with a plain reason; no game-stock debit. Already admitted native work continues under its own clock |
| Invalid or PI9-breaking output | Reject before registration; do not trim away significant nodes and pretend feasibility survived |
| World/access changed during the call | Treat reply as a candidate against the original fingerprint; revalidate current context before offering/admitting work |
| Duplicate/late response | Publish at most one selected result per request ID; a later reply cannot overwrite it or settle a job twice |
| Provider charged but game save failed | Retain a separate service-cost receipt if supported; report the model charge honestly. Native rollback cannot refund an external provider |
| Content/model update | New requests use the new revision; existing packs/products keep their semantics or a selected migration |

The proposed technical done check for a future bounded trial is: one ambiguous goal resolves to a supported interpretation, one invalid/opaque-danger graph fails without publication, one valid pack produces a useful native item, and reload/full-envelope import reproduces that exact artifact while the model is unavailable. Include failed-save stock/draw/job preservation. None of these cases was executed in T5.
