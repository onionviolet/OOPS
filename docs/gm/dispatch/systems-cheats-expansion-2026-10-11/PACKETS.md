## P01: admit an exact local contract

Recover live PROJECT, relevant source/world owner and active dispatch checkpoint.
Select original example or qualified local System, whose provider is an actual
registered actor/tool/source. Freeze which observations, grants, currencies,
clocks and lifecycle domains it promises. Identify existing route and first
native action without adding an opening requirement. Freeze exact old-save and
unavailable-definition policy. Reserve proposed new `src/system_provider.js`,
`src/system_provider_host.js` only if no current equivalent owner fits; these
names are candidate file areas, not existing APIs.

Prerequisites: current source fingerprints and director-selected local premise
when fiction is material. Excludes new starting-world pool, universal System
schema and source acquisition. Observable gate: before implementation each
selected leaf has issuer/recipient, real target, saved owner, native entry and
one positive, rejection and persistence case. Approval/selection is distinct
from tests. Routine reversible implementation choices remain the implementer's.

## P02: one connected work-ledger System

Original proposal: the ledger records a measurable craft commission offered by
its real sponsor. Accepting freezes objective/terms; completing actual work
creates an earned claim. Claiming credits ledger points from declared provider
authority. Buy one supported preparation function, use it on a real subsequent
job, then unlock a module whose changed scope serves a different useful job.
Include a permanently taught method and a separately leased assistance function
so provider loss has an observable distinction. Optional host refusal has no
invented penalty; a coercive provider needs its own selected real mechanism.

File areas: selected content definitions under `src/data/`; bounded provider
state/host; `src/simulation_contracts.js` validation;
`src/simulation_effects.js` selected effect adapter;
`src/expansion_persistence.js` durable admission and `src/main.js` native host;
existing quest UI projection only where a matching real consumer is selected.
Native `src/quests.js`/`src/rewards.js` are existing seams, not a second settlement
writer. Slot universalisation, random-world entry, generated quest engine,
companion society and all later evolution axes are excluded.

Acceptance journey: accessible native offer → refuse once without a reward →
accept → consume actual materials through existing craft → complete objective →
claim once → buy usable module with exact points → apply actual function →
upgrade and demonstrate new function → disconnect and retain earned method while
leased execution ends → continue ordinary work. Required negatives: fabricated
UI progress, insufficient points/materials, stale quote, repeated claim,
failed-save no debit/grant and interrupted pending contract. Rebuild/fresh-origin,
natural input pacing, old-save compatibility and save/reload/import are required.
This closes only the selected SC10 leaves, not every fictional System.

## P03: fixed-function depth or causal lens bridge

Select one original mechanism from the worked journeys. Fixed preservation
retains its exact definition across simple storage, commercial logistics and
exceptional-material use; player knowledge, routes and downstream consumers
create development. Alternatively ordinary lens craft plus an actually learned
local method and compatible material creates an apparatus with a genuinely new
inspection function. These can join if both are selected; neither inherits the
other's requirements.

File areas: existing item/recipe/activity data, acquisition and storage owner,
selected observation channel and native menu host, validated optional carrier
state. Prerequisites: exact function and material provenance, real initial input
route and selected custody/perishability/knowledge scope. Excludes universal
storage limits, cheat XP for fixed functions, new world, arbitrary crafting
assembly or research generator.

Acceptance journey: acquire ordinary inputs → improve ordinary tool → learn/test
qualified method → create new actual apparatus or use retained preservation →
perform previously unavailable task → sell/teach/apply actual result → continue
useful ordinary craft. For a fixed-function selection, show its unchanged revision across two distinct
uses. For a lens-only bridge, show ordinary construction and newly supported
inspection without requiring a cheat. Both require missing-source rejection
where applicable, failed experiment disposition,
unique-item transfer/removal and save/reload/import. Ordinary expertise can be
surpassed by a genuinely superior function; continued ordinary viability does
not require every old method to stay optimal.

## P04A/P04B: consequential chance acquisition

P04A selects creation-, purchase- or opening-time commitment. A cache instance
has real custody and two functionally different actual item results, which feed
repair/crafting; duplicates follow selected keep/sell/exchange terms. Proposed
file areas: bounded cache record/host, actual item acquisition owner, roll content
and native UI. Excludes general pity engine and real-money monetization.

Gate: find/buy/earn → appraise or trade unopened → open → use real content →
handle duplicate → retain exact result across save/reload/import. Failure,
repeated click, unavailable content and transferred cache cannot accidentally
reroll or duplicate. If contents are created at opening, appraisal cannot read
nonexistent fixed contents unless its actual power supplies future information.

P04B selects one funded game with rules, opponent decisions, real stake custody
and an informed choice to fold/continue/abstain. Settlement binds rule revision,
round outcome and both purses. Proposed file areas: game content, bounded saved
round/escrow host, actual purse adapter and actor-safe UI. Optional fortune needs
only its selected draw or information target adapter. Excludes casino empire,
global automatic detection and arbitrary negative-balance debt.

Gate: earn stake → compare wager with buying tool → choose terms → funded
opponent accepts → choose legal action → win/loss/selected void settles once →
stop or repeat as a new round → buy/delay tool and use it. Test unfunded rival,
private-hand exposure, interruption, repeat callback and persistence. Optional
automation must prove explicit budget/stop/cancel behavior. Event wagers consume
the event's actual outcome, rather than rolling another unrelated result.

## P05: bounded model, then independently selected real creation

A surveyor configures two irrigation layouts in a versioned bounded experiment,
runs represented water/harvest processes, alters an inlet and compares outputs.
Only supported design knowledge exports; the surveyor applies it through the
ordinary field's own materials/job contract. State stays isolated from actual
purse/crops during rehearsal. Proposed file areas: small pure model module,
validated experiment records, selected simulation runner and native host.

Gate: create → run → inspect → alter → rerun → leave/return → save/reload/import →
apply learned result in actual work. Verify finite workload/resume, cancellation,
real-state unchanged, assumption labels and exact selected export. Excludes
actual autonomous people, real matter creation and full future sight.

A later real pocket habitat is a separate packet requiring actual instance,
carrier custody, resident identity where promised, local clock, viable processes,
creator authority and native binding. Do not present P05's model proof as its
proof. Bound represented coverage without inventing a cap on fictional power.

## P06/P07: source-world qualification and consequential joins

P06 remains with the existing world/source owner. Freeze source edition/range,
canon/inference/invention labels, early regional scope, admitted independent
lives and one actual exceptional function. Candidate file areas are private
content pack plus public generic loader/adapter only as required. Unknown
identity and source prose remain private. Gate: each selected life has coherent
work/learning/application/consequence/continuation, missing-pack recovery and
compatibility; the broader blueprint remains explicitly outside early delivery.

P07 joins a selected predecessor, teaching a permanently learned method to a
registered actor who uses its own resources and allowed clock. The provider
loses contact or changes host; actual leased contributions stop, earned methods
and settled goods follow their carrier, outstanding contracts keep their exact
terms. File areas: existing actor/controller/knowledge records and selected
provider/custody host. Gate: NPC independent action after teacher leaves, scoped
witness response, simultaneous resource exclusion, exact departure/return and
save/reload/import. Excludes universal NPC planning, all death/prestige variants
and generic parallel-world replication.
