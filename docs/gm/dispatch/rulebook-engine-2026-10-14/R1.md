# R1: check resolver families, exact odds and spend hooks (code)

Read COMMON.md in `docs/gm/dispatch/rulebook-engine-2026-10-14/` first.
Root codes: EP1, EP2, EP10, EA1, EA2, EA3, EA17, EA18, A8, A10, A11, MC5-5.

Worktree: `.claude/worktrees/rbe-r1`, branch `codex/rbe-r1-resolver`.

Build, as new files under `src/` with tests under `tests/`:

1. `check_resolver.js`: pure `resolveCheck(profile, check, drawAddress)` for
   resolver families with parameters. Implement at least: sum vs target
   (covers d20 with advantage/disadvantage, 2d6, 3d6), roll under (d100),
   and dice pool counting successes. Outputs degree of success and a receipt:
   profile id@rev, draw address, dice, modifiers, result, and the top reasons
   (GR9). Draws only through `gen_kit.js` addresses keyed by game time, never
   `Math.random` or wall clock.
2. `check_odds.js`: exact probability for each family and modifiers, by exact
   enumeration or convolution with integer arithmetic. Same function must be
   usable by UI, cheats and tests.
3. A spend hook: "before roll" and "after roll" modifiers that spend a named
   resource (fate point, inspiration, effort) and appear in the receipt.
4. Rule pack data: show how a world declares its resolution profile and a
   `ruling` record (question, ruling, source locator, revision) by wrapping
   `rule_modules.js`, without editing it. If an edit to `rule_modules.js` is
   truly needed, describe it in REPORT.md instead.
5. A read model for an author-only inspector: last N receipts, profile, odds.
   No UI wiring.

Tests: per-family golden snapshots for three fixed addresses; seed sweep where
the empirical rate over many addresses matches `check_odds` within a stated
band; receipt replay returns the same result; a spend changes the receipt.

Lane folder: `docs/gm/dispatch/rulebook-engine-2026-10-14/r1/`. Done when the
branch has passing targeted tests and `npm test`, and REPORT.md lists what a
first consumer (D&D slice) would need to wire it in.
