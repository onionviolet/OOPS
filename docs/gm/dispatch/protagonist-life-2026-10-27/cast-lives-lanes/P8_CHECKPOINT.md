## Changes and compatibility default

F1: Eager walk derivation produced **123,540 commands** for the whole-book pack. Every pair also called district lookup, which scanned the place array. That was O(V²) command allocation with O(V³) lookup work, followed by O(V²) registry validation and UI enumeration. The phase probe below measured 13.4 seconds in walk generation alone.

D1: A walk definition is now generated by address when quoted or started, admitted through `createSimulationRegistry`, and reused by ID. IDs, labels, duration, costs, effects and cancellation match the prior definition. Saved jobs reconstruct that exact definition before ordinary validation. This is an unsaved definition cache, not a second transaction owner. There is no replacement of the registry Map API. Small-pack exact state/save results demonstrate that removing unused command definitions does not change saved behavior.

D2: For larger packs, unneeded roles retain definitions and compiled schedule entries. Bodies, actors and inventory owners are created on a non-null scheduled projection or an explicit job, session, controller, program, work-plan, pursuit or pending-command reference. Reference aliases resolve to their incumbent actor. The seated lead remains the native player, including during missing-body checks. Materialization mutates the caller's disposable plan, uses existing body/actor shapes and the original life anchor for `bornAt`, and leaves existing saved bodies intact. Schedule rows and wakes remain unsaved; `simulation.people[id].location` remains the physical authority. Initial/rewind wake construction still costs one map/queue entry per definition; later scans are linear cheap filters, not full remote contexts.

D3: **Compatibility default: packs with at most 256 people retain eager enrollment and native-place registration.** This preserves the live and 204-person byte contract required by the brief. The cutoff is an implementation default, not accepted product direction or a new schema. Above it, native place definitions are installed at entry, movement or restoration, rather than exposing every installed address to native location snapshots at boot. Known cast walk offerings remain in the existing panel. Previously saved places and bodies are retained, including saves made by the eager whole-book path. Crossing this cutoff when generating a future pack changes initial enrollment representation; it does not discard an existing save. A future universal lazy path needs an explicit replacement for the small-pack exact-byte contract.

The prepared domain change was added after the CPU profile showed native-location copies and DOM traversal remained costly. No UI module or UI behavior was changed. Target remains the coordinator's existing 1920×1080 beside floor; mobile work remains deferred.

D4: `tests/village_lead_line.test.js` changes only the child timeout from 110,000 to 240,000 ms, with the requested explanation of the approximately 93-second isolated run and full-suite contention.
