## Method and evidence strength

**natural** means ordinary fresh optional-start play, dialogue, equipment and first fight without injected game state. **seeded-native** means fixture/seed input exercised through shipped browser behavior. **source** means code review or an isolated DOM/font measurement; it does not establish natural acquisition or a runtime event. Verified observations are stated as facts; predicted consequences are explicitly inference.

Both requested fixtures were literal-file imported into a fresh headless Chrome context on distinct origins: ports 18461–18468, one fixture/scheme/size combination per origin. Import wrappers are `runs/mx/{dormant_day3,held_system}.import.txt`; original fixtures were untouched. Four dormant runs exercised the real day boundary with browser reduced-motion enabled. Four held legacy-card runs exercised restore without a live reveal. A separate natural first-win route and supplementary controls/font probes used fresh contexts on port 18469. Context isolation means no personal browser or save was used. Screenshot filenames distinguish `arrival`, `focus` and `read`, so a scrolled screenshot is not arrival evidence.

All eight matrix cases have zero page errors, matching native values for all five core stats and level, no horizontal panel/page overflow, compact density retained after reload, collapse retained after reload, and no status reveal replay on reload. Machine-readable detail: [matrix.json](runs/mx/matrix.json), [matrix.log](runs/mx/matrix.log). Only the observed values are covered: 12.0 strength, 8.0 agility, 10.0 dexterity, 10.0 intuition, 0.0 magic, level 0. ## Event ordering and limits

**MX29 · ML1, ME1; seeded-native.** A corrected copy of the dormant fixture moved the clock back to Day 1 and set both authoritative hero XP records (`character.xp.total_xp` and `levels.person.main_character.total_xp`) to 9. It was literal-file imported on a fresh browser context, then used ordinary elder dialogue, equipped gear and fought. Pre-fight saved XP was verified as 9. The first victory produced exactly this sequence: final hit → enemy defeated → hero reached level 1 and its stat-gain text → an ordinary Technique-notebook observation → system awakening → “Saved the game manually”. After returning to Village, Blooded appeared. There was one stored system message and one reveal. No new combat attack interleaved the defeat/level/awakening sequence in this run. Evidence: [fight-level.log](runs/mx/fight-level.log), [seeded-fight-level.png](runs/mx/seeded-fight-level.png), `seeded-fight-level.json`, `fight-level-seed.import.txt`, and `fight-level.cjs`. Proposed fix: keep gameplay cause/effect together and publish system identification/time consistently; silence or correctly label the automatic awakening save receipt.

The source places defeat and XP before round completion, which explains this ordering. That is consistent with these two observed first-victory sequences, not proof of every encounter, multi-enemy kill, simultaneous title scan or future quest completion. Stage 0 has no system quest completion to combine with the level-up. The ordinary notebook observation between level-up and awakening is a separate effect, not extra system spam.

The “Saved the game manually” immediately after awakening is **not** from an audit click in that moment. `awakenOptionalStart` invokes `save_progress()` with its default manual-save message before the script exits combat; the script's own manual Save happens later. Proposed fix above is a copy/receipt change, distinct from the other worker's durability work.

The first XP seed was incomplete and rejected with “Missing or inconsistent hero XP”; attempts that left the hero-creation overlay open did not test a level-up. Scratch logs/screenshots preserve these setup failures (`fight-level-debug.log`, `fight-level-reload.png`). Only the corrected successful seed with pre-fight XP 9 supports MX29. Its log label `NATURAL_WIN_ELAPSED_SECONDS` is inherited tooling wording; this run is **seeded-native**, not natural.

The natural control used no fixture: new optional system start, elder weapon dialogue, equipment and first fight. It awakened after 30.032 seconds from hero confirmation in this automated route, at Day 1, 08:44, then showed the earned Blooded title. Evidence: `natural.cjs`, `natural.log`, `natural-fight.json` and screenshot. This is one automated path, not a normal player's pacing estimate.

## What was not checked

No mobile optimization, OS-level reduced-motion switch, screen reader, real browser zoom, human taste acceptance, private save, sealed-world content, custom player palette matrix, high-contrast OS mode or every animation frame. Reduced motion was emulated through the browser media feature. Default-body contrast was checked at both sizes; expanded layout controls were checked at 1366×768, and their focus rings were observed, not exhaustively contrasted in every state.

No long earned-title runtime fixture or stage-1 quest names, claims, reward commits, post-claim focus, progress ratios, history compaction, repeatable-message budget or two-tab stress. Long-title truncation is source-only. The numeric width probe temporarily replaced DOM strings, then restored them; it is font evidence, not naturally earned point changes. The point=1 case is seeded and informational. Hover/focus preservation compared card state, not every save domain. Rounding was observed on fixture base values and supported by shared formatting source, not an exhaustive fractional boundary sweep.

No sustained hourly spam soak, background-tab throttling, sleep/travel/offline/import awakening boundary sweep or fight/dialogue reveal queue. Those are separate timing/durability concerns, including work on `ui/cheats-r1`. The general Events/System filter consequence is source-derived. Reduced-motion behavior was exercised on the four day-boundary cases; the normal-motion natural reveal was counted but not frame-sampled. One natural first victory and one seeded same-victory level-up establish their own ordering only. No gates, acceptance flags or source tests were edited or run as substitute proof.
