# W6 calendar adapter fit, not source_ready

Proposed export in existing `world_calendar.js`: `sourceCalendarAt(state, at)` returns the W5 callCalendar payload plus explicit local units for a validated active visitor. Omitted at means actual instance clock.elapsed; explicit at must be a nonnegative integer no later than that retained elapsed. This projects history, never commits or advances a world. Read the actual active visit/instance/profile/definition revision; mismatches return unavailable or reject an invalid coordinate. No root/home fallback. The input is a validated current expansion state, not an arbitrary supplied calendar label.

Reuse one private visitor binding helper for `resolveWorldCalendar` and sourceCalendarAt so they select the same visit, definition and clock. Retain existing home display behavior. Initially bind MoL/Paradise actual active-instance owners; unsupported worlds/home return unavailable through this new source adapter until an actual caller establishes its clock coordinate. HP’s opening-at/root convention remains its existing display owner; adding it requires the actual producer/consumer and current compatibility evidence rather than assuming it is a frozen visitor.

Payload: worldId, instanceId, profileId, profileRevision, at, minuteWithinDay, seasonId, minutesPerHour, hoursPerDay. W5 may explicitly select its known schema fields and obtain source spec units from the payload; strict validators must not implicitly accept unrelated extra fields. Season mappings are source table definitions, never inferred from the adapter. Native minute coordinate is at, date labels remain projection only.

Planned checks: current and historical projection match existing display, local midnight, freeze/reentry, invalid/missing active visit/instance/world/definition/revision/unit, future coordinate rejection, root clock change has no effect while instance elapsed is fixed, byte-identical state before/after, unknown season stays null. Actual source integration remains W5 adoption responsibility and cannot be claimed by adapter tests.
