## Lead profile and minimal integration

The relevant profile is `BE_PROFILE_ID` (`src/seat_profiles.js`) and `lotmBe(state)` in `src/book_world_lotm_cast_host.js`. The cast host gates journey, talk, exchange, divination and object offers to `lotmBe`; generic profile enrollment branches in `src/book_world_lotm_host.js` separately seed probationer stocks and life effects. KJ2 must stay on the fresh Klein lead path and its actual state, not enroll or mutate the probationer bench as a shortcut. The private cast host already loads lead pack rows, but current first-arc `householdActs` is the only demonstrated ordered KJ1 projection.

Minimum missing producer/command/UI link: source-qualified KJ2 rows in the private LOTM pack must bind the next native sequence to the proper existing command families (purchase/exchange, walk, preparation, divination/ritual, topic talk and return), with actual stock, purse, place, respondent, participant, costs and effects. Then the lead host must project that sequence beside the existing action families and filter/display its next eligible/blocked action in the current place panel. The host view already returns `arc`, `objectActs`, `exchanges`, `journeys`, `topicTalks` and `divinations`; UI is in `src/book_world_lotm_ui.js` under the LOTM module/workspace and its `here` tab/nearby door. The KJ1 household sequence proves only that pattern. No code inspection proves KJ2 gameplay.

For implementation, keep the KJ2 panel at the current place-service home opened by Nearby, with the real purchase quote, current location, timed work, respondent/presence reason, retained result and next arc boundary visible at 1920×1080 and actual 14/21px typography. Keep the log column and shared navigation. Mobile remains deferred. Don't add a second quest counter: native completion/evidence remains authoritative; existing KJ1 and unrelated pending jobs need explicit compatibility behavior if definitions change.
