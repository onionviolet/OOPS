# HV2 learning and skill feed

2026-10-14. PROPOSAL ONLY. HV1 uses existing Butchering under [PLAN HM5](../PLAN.md); no new skill is required for its acceptance. This extends [P8 yield knowledge](../../procgen-2026-10-13/p8/HARVEST_YIELDS.md), [P6 tools/textiles](../../procgen-2026-10-13/p6/TOOLS_TEXTILES.md), [agriculture](../../procgen-2026-10-13/p6/AGRICULTURE.md) and [CR1 body interfaces](../../procgen-2026-10-13/cr1/BODY_AND_SPECIES.md), which remain the owners of product execution and recipient compatibility.

## S1. Knowledge unlocks a part, means enable the operation

Separate unknown anatomy, suspected clue, identified part, learned procedure, practiced handling and executable current means. The first states are knowledge; tool/body/source availability is evaluated now. Knowing a gland exists need not teach safe removal. Having high Butchering need not reveal it. Discovering anatomy adds a part-template mapping scoped to supported species/body revision or a declared homologous family; it does not reveal all unrelated species.

Routes include taught dissection, an actual diagram/book lesson, scoped examination, paid expert work, experiment and a supported lens. Each route states what it can reveal and whether it consumes a sample. Examination can damage its own specimen; learning from it can improve later specimen handling. Ordinary known whole processing leaves an undiscovered organ unclaimed unless its declared process destroys it; later discovery works only on remaining stock. A known skill level is not consent, site rights or a usable hand.

S1a: Bind discovery to source truth and an observer receipt. Unknown-to-player is supported truth; missing engine data is unresolved simulation and blocks unsupported spending. A discovered donor function and a harvested material property are different claims. CR1 must verify the receiving route/body before a resulting tonic actually benefits the player or companion.

## S2. Unknown traveler asks become investigations

[Traveler Amendment 1](../../traveler-asks-2026-10-14/PLAN.md#amendment-1-2026-10-14-asks-can-be-out-of-reach) permits ready/stretch/unknown asks and reserves optional grade predicates. Do not restore the superseded fresh-player-only filter.

An original traveler can describe a desired functional specimen using what that traveler knows. The player receives only the disclosed clue and known requirement, not the part's hidden ID in a tooltip. A public, nonsealed example: a mender asks for an intact hide; a specialist's unfamiliar reagent request points to a disclosed anatomist or examination lesson. For a sealed part, logs/reports retain ID/route/status only; there is no automatic secret-answer hint.

Proposed chain: accept or defer request, get an attributed clue, inspect/learn the relevant anatomy, acquire actual means, recover the part, verify grade with an eligible observation, deliver that exact eligible lot. Generation lint must find some supported route in the world, including the discovery prerequisite, not require the player to know it. Stretch asks can need a stronger tool, method, trip or money. Requests wait without absence penalties under the request owner's policy; discovery does not reroll a saved goal or fee.

Ask matching uses explicit part/material and applicable grade predicates; whole completeness is separate from numeric quality. Identity-bound requests may reject substitutes under their local law. Unknown facts can still determine actual eligibility, but the player gets a neutral scoped failure rather than secret disclosure. Older saved requests retain their revision and original matching rules; a new optional grade field must not tighten them retrospectively.

## S3. Candidate sub-skills and broader feeds

Table entries are a palette. Add only a sub-skill with distinct work and a consumer. Native parent registration/XP rules must be inspected before implementation; this is not a proposed second skill engine or a claim that all these parents exist today.

| Sub-skill / method | Work that earns it | Functional output | Broader feed proposal |
|---|---|---|---|
| Skinning | Actual separated surface area/complexity | Better intact-surface recovery, lower cutting damage, supported faster method | Butchering |
| Anatomy | Paid examination and correctly executed new dissection scope | Part recognition and learned access paths; separates knowledge from dexterity | Supported scholarly/medical parent if registered; otherwise knowledge receipt only |
| Meat cutting / tissue extraction | Actual cuts or delicate organ recovery | Yield allocation and supported quality retention | Butchering; magical extraction requires its own local means |
| Tanning | Real P6 hide preparation, chemicals, time and output | Durable leather grade and fitted surface | Existing Butchering/Crafting adapter chosen by recipe; one accounting path |
| Picking / root lifting / tapping | Mature plant part recovery and retained producer accounting | Bruising reduction, useful root geometry or cleaner sap | Herbalism/Farming/Woodcutting by declared method, not all three automatically |
| Shearing / milking | Actual supported donor collection | Coat integrity or clean transferred production | Animal handling |
| Prospecting / panning / selective mining | Sample/extraction/recovery on actual zones/parcels | Scoped knowledge, purity separation or intact crystals | Mining/Digging where supported; assay can be a knowledge method |
| Preservation | Actual salted/smoked/dried/cooled batch transformation | Longer applicable window and altered preparation properties | Cooking/Crafting/local method parent as declared |

S3a: Award XP for completed useful work, with effort/complexity and supported recovery as inputs. Whole processing is the sum of distinct work actually performed, not a bonus for clicking more part buttons. Preview, reload, repeated receipt, discovery text and selling confer no harvest-work XP. Unsuccessful work may earn practice if the method explicitly records real effort, not invented recovered material. Clamp to available source work; slicing one cut into a hundred clicks cannot generate a hundred complete-job awards.

S3b: Use one durable XP receipt per stage/executor. Existing native parent propagation applies once; do not also manually award the parent for the same amount. If one operation contains independently measured cutting and preservation work, its declared budget can split between them. Changing skill trees needs a revisioned compatibility decision. Old Butchering levels remain; adding Skinning starts empty or at an explicitly disclosed non-destructive derived proficiency, never confiscates old XP. No automatic retroactive reward from historical kills or imported receipts.

## S4. Mastery and cooperative work

Competence unlocks methods and improves declared handling, not anatomy truth, quantity beyond source capacity, biological regeneration or every magical function. Techniques can be learned from an NPC, bought, discovered or invented where the owner supports them. Greater mastery may exceed a school benchmark without a universal ceiling. Tool function, grade, body coordination and local energy remain independent means.

Helpers use their own proficiency and earn their actual work receipt. Player instruction/supervision earns only supported teaching/coordination effort, with wage/time opportunity cost if the local method reads it. A companion trained to collect shed material does not instantly perform surgery. Automation repeats learned executable methods with the same costs and source constraints; it does not grant full anatomy on queue admission. Save learned scopes, method versions, executor identity, completed work and pending stages so switching helpers cannot duplicate XP or reroll quality.
