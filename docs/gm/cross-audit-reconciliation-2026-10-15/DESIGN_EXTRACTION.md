# Design-source extraction

Structured provenance sample for the 24 paths in `private/BATCH_design.txt`. This is not a complete semantic inventory of their finding or idea palettes. Each JSON record carries the full-file SHA-256, classification, exact sampled line ranges, original IDs/locators, paraphrase, explicit owner pointer, stated disposition, and evidence stage. “Partial” ranges are literal; remainder is named in each scope note.

## Coverage

- 24/24 assigned source files represented; 1 source record per file. SHA-256 computed from current working-file bytes at extraction time.
- Full read: baseline audit, hunger note, procedural materials/alchemy audit, and UI identity/representation note. Other sources are partial and list exact ranges plus remainder. Long palettes retain representative ID rows only.
- Prompt instructions are classified as prompts, never reported as design findings. Reported source/code/UI evidence is labeled with its stated limits; proposals, folds and questions retain their source disposition.
- This batch does not assert that every finding was extracted, reconciled, accepted, rejected, or implemented. No sealed truths are reproduced.
