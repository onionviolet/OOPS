## Proposed reference and authority contracts

These are field-level semantics for review, not existing exports or chosen serialized shapes.

| Boundary | Minimum meaning and invariant |
|---|---|
| Definition to entity | A versioned definition describes a type. A person, current body, unique component or differentiated lot has an actual ID and revision only when that distinction affects a selected mechanic. Repeated same-type components never collapse under the definition ID |
| Physical placement | One actual component/lot placement, with separate claimant/holder/host/operator where required. A fitting consumes the same surviving specimen into its host reference; native bag/equipment projections account for their existing differing conventions. Aggregate projections never become a second owner |
| Endpoint and contact | World/instance/region/layer plus actual source/body/target/site bindings. A resolver checks the declared contact/reach/authority relation. It must permit genuinely supported remote/layered operations, while ordinary local transactions require actual local contact |
| Due work | Clock owner/reference, unit, due basis and policy revision. Validation compares due with that clock, not unconditionally with the joined clock. Reconcile only authorized intervals and preserve interval union, freeze and selected same-boundary order |
| Live phase | Operation/phase cause, relevant expected revisions, current support/contact/consent, used/unused escrow, outputs and terminal/resumable interruption. Existing host sequence stays useful; it does not replace every current physical dependency. Receipts survive display pruning and replay |
| Operating contribution | Cause and actual source/target reference, channel, composition rule, duration/clock and selected continuation support. Base reserve/history remain state; effective maxima/rates are derived. Any overflow or exhaustion result is explicit, persisted once and source-specific |
| Native projection | Declared read/write domains; prepared reconstruction from one final candidate. A collision rejects or uses a named coherent override. Save-envelope and live actor/body/item/location projections agree. Native reset may use the existing reload boundary |
| Compatibility | Per-family shape schema plus live-compatible/frozen/migrated definition semantics. Freeze only needed operational fields, including audience where relevant. Missing optional records enroll nothing; unsupported versions reject recoverably or remain dormant only under a declared policy |

Prefer a narrow resolver/policy table to a universal architecture framework. Keep one durable publisher. No mandatory entity ID for every coin, full anatomy simulation, immutable-map wrapper overhaul, live hot reload, separate save database, independent timer fleet or generic event-sourcing rewrite is justified by this audit. These are scope simplifications, not measured performance claims.

## Sole ownership and proposed work splits

Shared Engine owns existing engine/realm/native/persistence integration, actual API selection, runtime schema compatibility and publication. Specialist contributors can receive new detached modules only after the master approves exact disjoint reservations. This report reserves no source file.

World GMs own local endpoint layout, source-specific contact/rights/time/absence and failure rules. Bodies/Items/Ability specialists own their real function/acquisition/operating proposals within those bindings. Source GMs retrieve a named missing canon scene if a selected implementation needs one. The assigning master owns canonical plan/RUN, coverage IDs and accepted director decisions. Runtime efficiency and author ergonomics remain with their separate second-pass lanes. The newly added [integration-strategy role](../integration/ASSIGNMENT.md) can compare this contract order and consume the findings; it does not replace the master or Shared Engine writer.

Useful independent later tasks after approval are the compatibility matrix, instance/native-domain binding, shared source lifecycle, selected physical-record codec, and clock/phase/derived-body integration. These are possible work packets, not dispatch instructions; do not launch all roles or widen runtime scope on the strength of this handoff.
