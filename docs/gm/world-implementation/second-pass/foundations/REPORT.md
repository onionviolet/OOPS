# Engine foundations decision summary

Retain the pure planners and one staged native publisher. Add a small set of explicit owner, reference, clock and compatibility contracts around them. The current code already clones candidate state, reserves real means, freezes outcomes, prepares native reconstruction and writes one envelope before publishing live values. Those are useful foundations. A wholesale engine rewrite has no demonstrated benefit for this plan.

This is a planning audit, completed against the dirty `codex/gameplay-foundations` checkout at `97c28efece4fd6248b6f075ad0c6927c3d0432df`. [FINDINGS](FINDINGS.json) contains nine prioritized records with exact source lines, current versus proposed behavior, owners, original world cases and deferred acceptance. [DEPENDENCIES](DEPENDENCIES.md) turns them into a scoped handoff. Runtime implementation remains held for Weibao's review; the assigning master alone edits the canonical plan/RUN.

1. **Bind actual instances before expanding worlds, EF02.** Detached world records already distinguish instance, continuity, era, region and layer. Native commands still compare world IDs and location strings, while Glasshouse routing recognizes one specific instance. A world-scoped fact can also take a direct legacy write path instead of the canonical pocket path. A generic resolver must cover reads, writes, targets, stock and native location, rather than merely create more visit records. Two branches with the same Village label must not share a workshop. Explicit supported remote contact remains possible.
2. **Declare shared lifecycle and revision behavior, EF03/EF08.** The two source interpreters differ: one renews expired acquisition, the other retains the old record; one removal clears faculties, the other does not. These are static edge cases, not reproduced failures in current content. Definition revision matters separately from save shape: world records demand exact revisions, capabilities read live grants, energy retains a frozen policy, and jobs freeze effects but consult current audience fallback. Choose compatible, frozen or migrated semantics per family and preserve recoverable rejection.
3. **Join physical records with native owners, EF04/EF07.** Micro already proposes conserved bodies, components and lots. A missed accounting detail is that native equipment leaves the bag while simulation equipment references bag stock. One generic counting rule would miscount them. Use actual specimen/lot identities only when their properties matter, validate placement and custody joins, and declare each adapter's writable domains. A valid-shaped native patch can still conflict with another projection, so explicit overrides need one coherent final plan.
4. **Bind time and consequential settlement, EF05/EF06.** Presence/activity clocks already exist, but paid jobs use joined due times. New local work needs a clock reference and matching validation. Cross-family order currently reconciles pocket expiry, expansion jobs, chronicle and simulation work separately. Freeze the intended simultaneous policy before supported upkeep or irreversible work. Retain prepaid ordinary jobs; add phase receipts, live support checks and persisted interruption only where refunds or consequences change.
5. **Derive composed values without overwriting base state, EF09.** Micro's separate capacity, recovery, upkeep, output and strain channels need a base/contribution/derived split. Ending one source removes its own contribution; it does not erase training or refill reserve. Native execution reads that same result. Keep genuine exceptional functions and source-specific exceptions intact.

All new cases here are original engineering fixtures. No book/franchise canon was newly read or asserted. Checks cover report JSON, evidence paths/lines, links, whitespace, dependency order, fingerprints and readback. They establish an inspectable planning packet, not working gameplay or token/runtime savings. Director review and master integration remain the next decisions; later generated-save, browser, interruption and publication gates remain unrun.
