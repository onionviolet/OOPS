# Ink/inkjs and rot.js: pinned source comparison

Recommendation: extend the current YAIRPG engine for the held qualification scenes. Keep Ink/inkjs as an optional later authoring dependency for genuinely long branching conversations; defer rot.js until a selected player interaction requires grid pathfinding or occlusion. Neither candidate should own YAIRPG's clock, inventory, rewards, people, RNG or durable publication.

This appendix supplies external-source evidence for the parent [assignment](ASSIGNMENT.md). It does not audit the whole local engine, authorize adoption, change the canonical plan, or claim playable verification. Local seam mapping belongs to the parent GM. Live [PROJECT resume](../../../../../PROJECT.md#design-session-resume-point-2026-10-04) preserves the runtime review hold and deferred behavioral checks. All adapter names below are proposals, not existing APIs.

## Ink format and authoring facts

Ink 1.2.1 and inkjs 2.4.0 both declare compiled-story format `21` and minimum compatible story format `18`. Each constructor rejects stories above its current version or below its minimum, with a warning for a different supported version. This establishes matching format gates, not tested semantic parity for every script. The pinned inkjs README's compatibility table explicitly reaches Ink 1.2.0/inkjs 2.3.0; it does not certify the newer pair. [Ink Story.cs](https://github.com/inkle/ink/blob/35c63e52f1d36060930dc7ed3cfba38ea224b528/ink-engine-runtime/Story.cs#L19), [inkjs Story.ts](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/Story.ts#L53), [pinned compatibility table](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/README.md#L208).

Ink is a narrative component intended to fit a game's own UI. ## Ink cursor, save and external-function risks

| Verified fact | Integration implication, proposed |
|---|---|
| `currentChoices` filters invisible defaults and reassigns indices. `ChooseChoiceIndex` selects from that current array and restores the choice's generating thread. [choice access and selection](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/Story.ts#L57) | A UI index is not a durable action ID. A request should carry stable authored action identity plus scene/cursor/content revision, then resolve against the current offered choices. Revalidate actual funds, stock, actors and private knowledge at commitment; an earlier Ink guard or displayed price cannot authorize a stale purchase. |
| `Flow` serializes call stack, output, choices and choice threads. Choice serialization includes text, source/target paths, index, original thread index, invisible-default flag and tags. [Flow.ts](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/Flow.ts), [choice serialization](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/JsonSerialisation.ts#L582) | Saving only a knot name, selected index or globals loses continuation semantics. Preserve the complete opaque Ink state for a matching compiled asset, plus a stable application-level checkpoint/receipt for migration or retirement. |
| Both inspected runtimes write Ink save version `10`, minimum load `8`. inkjs writes flows, variables, evaluation stack, visit/turn counts, turn index and random state; its loader rejects missing/too-old save versions but does not validate a maximum future version or content hash. [inkjs StoryState.ts](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/StoryState.ts#L31), [Ink StoryState.cs](https://github.com/inkle/ink/blob/35c63e52f1d36060930dc7ed3cfba38ea224b528/ink-engine-runtime/StoryState.cs#L25) | YAIRPG must validate its own wrapper version, exact supported Ink version and compiled content identity before loading. Format compatibility alone does not establish compatibility after changing story structure. Treat imported cursor data as untrusted, retain the last good state, and expose a recoverable error. |
| Call-stack loading resolves stored container paths; missing content can throw, and approximate matches warn that story content may have changed. [CallStack.ts](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/CallStack.ts#L334) | Prefer pinned content for in-progress scenes. Reject approximate recovery for game-bearing choices; provide an explicit checkpoint migration or retirement rather than silently directing a paid scene to nearby content. Renaming knots alone is not a complete migration plan. |
| External functions are synchronous. General binding defaults `lookaheadSafe=true`; convenience binding defaults `false`. Unsafe calls are stopped during newline lookahead and error during string/choice generation. Missing bindings are errors unless explicit Ink fallbacks are enabled. [external calls/bindings](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/Story.ts#L1838) | Bind only pure reads of a frozen, actor-scoped game snapshot, explicitly specifying the flag. No real inventory, RNG, payment, save, reward or people mutation inside callbacks, tags, variable observers or `onMakeChoice`. A Promise is not an asynchronous settlement API. Editor fallbacks should be obvious placeholders and stay disabled for game-bearing production bindings. |
| Upstream explains that glue causes prospective evaluation; a pure function must tolerate repeated calls and change no game state. Tags and variables are alternative integration mechanisms. [Running Your Ink](https://github.com/inkle/ink/blob/35c63e52f1d36060930dc7ed3cfba38ea224b528/Documentation/RunningYourInk.md#actions--vs-pure-functions) | Tags may identify whitelisted authored intents, but cannot directly contain executable arbitrary commands or unrestricted native effect payloads. The game still owns validation, staging, costs and publication. |
| inkjs's RNG uses a multiplicative PRNG; the C# runtime uses `System.Random`. Ink random state is independent of YAIRPG's RNG. [JS PRNG](https://github.com/y-lohse/inkjs/blob/edccead8700e9f21be9825d87d8645d8c82a9936/src/engine/PRNG.ts), [C# random evaluation](https://github.com/inkle/ink/blob/35c63e52f1d36060930dc7ed3cfba38ea224b528/ink-engine-runtime/Story.cs#L1505) | Do not promise identical random sequences across runtimes. For the first optional adapter, prohibit Ink `RANDOM`/shuffle from deciding rewards or outcomes; route those decisions through saved game draws. Pure prose variation could later use separately declared, seeded narrative randomness. |

Proposed optional cursor envelope: `{adapterVersion, storyId, compiledContentHash, compilerRevision, runtimeRevision, checkpointId, cursorJson, lastGameReceiptId}`. This is a dependency design, not a selected save schema. Missing old-save cursor data should enroll no story and grant nothing. Cursor variables may hold conversation-local state; authoritative stock, clock, people knowledge and durable consequences remain in their existing owners.

If later approved, an adapter should preview/advance a working story copy, request an existing native action using stable IDs, and stage the resulting cursor with that action's existing durable settlement. Publish visible success only after the joined save succeeds. Failed storage retains both prior game state and cursor. A re-render or reload must never execute a narrative command again. This atomic bridge is the main unresolved implementation cost, not provided by Ink's `ToJson`.

## rot.js responsibilities and limits

| Subsystem | Verified upstream behavior | Recommendation for YAIRPG |
|---|---|---|
| Browser/local delivery | TypeScript source, ES2015 modules under `lib/`, ES5 prebuilt global `ROT` bundle under `dist/`; npm entry `dist/rot.js`, module entry `lib/index.js`, no declared runtime dependencies. [pinned README](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/README.md), [package](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/package.json) | If selected, import only needed module paths behind one adapter. No CDN/runtime network dependency, new renderer requirement or measured size/performance claim. |
| A*/Dijkstra | Coordinate-grid algorithms use boolean passability and topology `4/6/8`, default `8`. Both give every edge cost `1`; A* rebuilds work per computation, while Dijkstra caches toward one target. Callback emits start-to-goal coordinates; no route emits nothing. [Path base](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/path/path.ts), [A*](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/path/astar.ts), [Dijkstra](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/path/dijkstra.ts) | Optional pure path query for one selected grid encounter. Terrain time, danger, fuel, diagonal corner rules, movement rights and occupancy stay authored game rules. These APIs do not solve weighted travel or a realm/passage graph. Recreate cached Dijkstra on passability revision changes. [manual cache warning](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/manual/pages/path.html) |
| FOV | Light-pass callback plus origin/radius returns visible coordinates, distance and visibility. Precise shadowcasting includes the origin and stops beyond it if that origin does not pass light. Recursive shadowcasting offers 360/180/90 views and states 4/8 support, not hex. [FOV contract](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/fov/fov.ts), [precise](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/fov/precise-shadowcasting.ts), [recursive](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/fov/recursive-shadowcasting.ts) | Pure geometric visibility candidate only. Capability eligibility, secrecy, detection, sound, memories, magical sight and cross-realm observation remain existing authored knowledge/observation rules. Geometry never grants NPC/private facts automatically. |
| RNG | Singleton Alea RNG seeds from `Date.now()` at module import. `getState` returns four internal numbers, `setState` restores them, and `clone` creates an independent generator with that state. `setState` performs direct assignment without validation and does not restore `_seed`. [RNG source](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/rng.ts) | Do not replace the current saved RNG or introduce singleton draws in previews. Path/FOV sources do not call RNG. If a later map generator needs rot RNG, isolate a synchronous saved-state adapter or author a deterministic generator using the existing game RNG; clone alone does not redirect generator imports. |
| Map generation | Cellular, Rogue, Uniform, Digger and features import the RNG singleton. Uniform/Digger also use wall-clock `Date.now()` time limits; Uniform can return null and Digger can stop early. [Cellular](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/map/cellular.ts), [Uniform](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/map/uniform.ts#L56), [Digger](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/map/digger.ts#L61) | Defer procedural generation. A seed alone is insufficient evidence for identical map output across machines/runtime budgets. If selected later, save accepted generated geometry, generator revision and failure outcome; do not regenerate an already visited world from seed alone. |
| Scheduler/event queue | Simple is round-robin; Speed uses `1/getSpeed()`; Action accepts durations. The event queue advances its own elapsed time while popping entries. Heap ties use insertion timestamps. These inspected classes have no public JSON save/load API. [scheduler manual](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/manual/pages/timing/scheduler.html), [event queue](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/eventqueue.ts), [heap](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/MinHeap.ts) | Borrow explicit duration and deterministic tie-order patterns only if a named local gap exists. Do not install a second actor scheduler or clock. Object references, repeat lists/current actor and queue ordering would need a custom save protocol. |
| `ROT.Engine` | Calls scheduled actors' `act()`, with nested locks and thenable continuation. The official manual calls it backward compatibility and recommends modern async/await instead. [engine source](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/src/engine.ts), [manual](https://github.com/ondras/rot.js/blob/46782e248c2db9d379a5e4f13bb8323f18dff04b/manual/pages/timing/engine.html) | Defer adoption. It does not supply YAIRPG's transactional effects, persisted jobs, native clock or lifecycle/absence policy. Rendering and input can remain native while querying path/FOV. |

The useful conditional spatial interface is small: `findPath(readOnlyGrid, origin, target, movementPolicy)` and `visibleCells(readOnlyGrid, origin, radius, facing)`, returning derived values without publication. Map/actor positions, occlusion revisions, chosen moves, costs and remembered explored cells belong to the existing game save owner. Rebuild derived path/FOV objects on load; do not serialize library instances. Parent mapping must identify the real grid/position owner before proposing an adapter file.

## Two candidate comparisons for the parent report

**Everyday herb/trader/resident case, original proposal:** a learned herb property supports either selling actual stock to a trader or preparing a funded resident treatment/project, with abstention and a remembered return. Ink can express branching explanations, choice wording and later conversational callbacks. The existing engine must own herb custody, availability, learned knowledge, recipe/body capability, coins, work duration, recipient consent and actual settlement. A short encounter with two approaches does not demonstrate that Ink repays its cursor/build/migration overhead; the simpler current declarative scene route wins provisionally. No new item, price, clock policy or NPC fact is selected here.

**Long scene or spatial scene, original alternatives:** a sustained multi-speaker negotiation with repeated topics, interruptions and many authored branches is a stronger Ink pilot because its missing benefit is authoring/narrative continuation. A smoke-screened rescue with alternate doors, visible blockers and a materially different safe route is a stronger rot pilot because its missing benefit is grid routing/occlusion. Waiting, withdrawing or using an earned perception/movement technique must change actual options through game rules, not automatic library callbacks. A location-menu rescue with authored routes can remain simpler than a grid. No grid, movement mode, renderer, broad campaign system or qualification-scene replacement is selected by this appendix.

## Conditional adoption, uncertainty and removal

| Route | Status and actual unresolved cost | Fallback/removal |
|---|---|---|
| Current scene/action owners | Recommended for held initial pair, subject to parent seam audit. Need connected native consequences and authoring validation whether or not a narrative tool is used. | No new dependency or opaque cursor; use existing stable scene/action state. |
| Ink/inkjs playback adapter | Optional later prototype. Requires stable action identity, actor-scoped snapshots, joined cursor/game settlement, bounded original content, toolchain/content pinning, compile diagnostics, save validation/migration and native accessible UI. Author productivity, bundle/load cost and maintenance burden are unmeasured. | Feature flag disables new enrollment. Retain inert cursor data/content identity and existing paid receipts. Resolve in-progress scenes through an explicitly authored safe checkpoint/refund-or-retention rule; never reset world consequences or replay payments. Only remove assets/runtime after all supported cursors migrate or retire. |
| rot path/FOV adapter | Defer pending a player-approved grid interaction. Requires geometry/position/knowledge owners, movement policy, stale-grid handling and a bounded visible proof. No evidence here that spatial fidelity improves an idle location menu. | Keep outputs as ordinary game data. Replace library queries with an independently implemented bounded algorithm or authored routes through the same adapter; stored maps/positions/consequences persist. |
| rot maps/RNG/scheduler/engine | Defer. They duplicate current owners or add determinism/save responsibilities without an identified current player benefit. | Current engine remains authoritative; pattern borrowing does not require a package. |

Later acceptance gates, currently unperformed: representative compiler/runtime format behavior; stale/changed choices; reload at an offered choice and after a paid consequence; refused/failed storage with neither cursor nor resources advanced; known/private information filtering; exact-content mismatch recovery; keyboard/focus behavior; meaningful comparison of authoring effort and visible gameplay. A spatial pilot additionally needs blocked/no-path results, changed geometry/cache, corner/movement policy and knowledge-safe occlusion. These are backlog criteria, not suites authorized or executed in this pass.
