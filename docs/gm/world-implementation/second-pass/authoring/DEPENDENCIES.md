## Recipe 1: register an ordinary Frontier inspection

Start from the retained [Short Measure draft](../../../../worlds/original-frontier/REPORT.md), especially its [integration requirements](../../../../worlds/original-frontier/REPORT.md#exact-integration-work-to-include-in-the-combined-plan). Its definitions, sources and views are distinct exports, and its prior registry check is a historical shape receipt.

Map one required mechanic ID to the actual command, stock owner, participant/site/time reservation, attributed report, resulting knowledge/source, Native publication and Here/Quests consumers. Declare opening as an explicit opt-in. The current draft's physical-stock inspection and journey timing gaps stay open; neither a namespace nor a factory corrects them. Native accessibility facts come from the host. Pending copy describes the inspection, while result copy waits for settlement. Later acceptance includes changing employer stock, refusing/delaying and returning to the Town receiver, with one retained wage/stock/history result. Those behaviors were not run here.

## Recipe 2: reuse a helper type without duplicating a person

The existing [helper definitions](../../../../../src/helper_content.js) already combine `instanceKey`, `$spawn.helper`, role-based `actorDefinitionId`/`targetDefinitionId` and controller actions. [Effect preparation](../../../../../src/simulation_resolution.js) binds aliases in order within the prepared effects list and freezes the template. [Spawn execution](../../../../../src/simulation_effects.js) allocates the actual actor/owner and attaches template controllers.

A local factory should emit namespaced JSON definitions plus author-only source-path metadata. It must preserve template IDs versus generated actor IDs, put spawn before same-list alias use, and use role selectors for reusable commands. A later command targets the saved actual actor, not an alias carried from another preparation call. No factory may synthesize a native NPC binding by naming an ID. The hypothetical two-hired-carrier variant is original: later gameplay qualification would give each its own input, job, controller and returned output, preserving both across reload. Current helper support is retained, not proof of that new variant or arbitrary multi-instance worlds.

## Recipe 3: compile a cooperative project with a branching offer

Use the current [field workshop](../../../../../src/field_workshop.js) as the ordinary single-worker baseline. The proposed two-worker beam-fitting variant is original: actor/target role, co-location, both participant reservations, paid inputs, site capacity, cancellation and completion/observed-completion keys must survive compilation or receive an actionable error. Do not infer participants solely from effect recipients: a recipient of a report need not be occupied labor.

For an offer, display an author graph showing ambient occurrence → response window → each response terminal/continuation, plus expiry → fallback. The existing road response deliberately settles `secured` or `detour`, while expiry schedules the fallback; retain that distinction. Private truth stays author-only. A generated graph must mark unresolved external starts and opaque/contextual predicates as unknown, not prove a branch unreachable by guessing.

## Preserve and simplify

Preserve the single executor/save publisher, negative-cost reservation, native item reconstruction/unlock guards, deterministic cause/RNG services, frozen jobs/templates/policies and observer-specific projections. Preserve the crossing's real alternative functions: a kit repairs faster and is consumed; reusable anchors repair without consuming the rope; the footpath leaves the crossing unrepaired. A template must not flatten those routes into renamed identical rewards.

Begin with JS modules, an explicit family merge and a diagnostics/manifest pass. Defer a general DSL, editor, hot reload, automatic save repair and universal world template until a selected authoring case demonstrates their need. Read only the changed package and its declared closure for review. This is a bounded-work suggestion; no token, development-time or runtime saving was measured.
