## Actual exports, ready for Engine binding

Engine's [INTERFACE S2](../../INTERFACE.md) accepts these actual six exports and supersedes its earlier suggested family-wrapper names. All six named exports are implemented, synchronous and side-effect free for plain snapshot inputs. No imports, DOM, native getters, command callbacks, random draw, enrollment, registration, grant or persistence. Do not pass native owner objects/getters; pass scalar/record snapshots.

| Export | Input and actual return |
|---|---|
| `projectDiscoveryFeature(input)` | `{id,label,description,discovered,unlocked,eligible,hint,requirements,reasons,details}`. Returns null if unknown; genuinely known hint uses `hint:{known:true,id,label,text}` and returns only that safe hint identity/text; discovered feature returns known text with status discovered/blocked/available and `control:{visible,enabled}`. Unlock and eligibility require literal true. |
| `projectNativeSkillDiscovery(input)` | Same common input plus existing `totalXP` and actual normalized `visibilityThreshold`. Native name is absent unless native unlock is true and finite nonnegative XP reaches the actual threshold. Never defaults threshold to zero or lowers it for a hint. |
| `projectTechniqueDiscovery(input)` | Common input plus the existing validated `record`. Actual observation discloses; understood+owned unlocks execution controls. Existing host preview supplies executable eligibility rather than a new proficiency/body/fuel rule here. |
| `projectAcceptedWork(input)` | `{accepted,id,label,description,remainingMinutes,details}`. Retains an actual player's commitment even if its ordinary feature/panel is unavailable. Uses known action label and authoritative remaining time, no frozen result/effects. General work/cancel/resume controls remain host-owned. |
| `projectDiscoveryCatalog(rows,{query})` | Receives already projected rows/null. Searches only their safe searchText; returns filtered entries, visible count, availableCount and hintCount. Raw registries/previews must never be fed directly. |
| `projectDiscoveryPanel({id,label,entries,retained})` | Uses already projected entries and accepted-work rows. Returns null for empty future panel; otherwise safe panel identity/counts and unfiltered retained accepted work. Panel title itself must be public or already known. Core navigation/recovery is not run through this future-feature gate. |

Common output whitelist: id, label, description, status, requirements, reasons, surfaces, control and searchText. Work adds authoritative remainingMinutes. Unknown returns null, not a hidden object carrying a secret ID/name. Hints never return the private feature ID, requirements, availability or definition text.

Requirement/reason inputs are explicitly player-qualified `[{known:true,text}]`; a requirement may also carry a known boolean `met`. Unknown or bare raw strings are omitted. Details are `[{known:true,surface,text}]` with surface description/tooltip/preview/return. A known unlocked but unavailable feature with no disclosed blocker gets the neutral “The required preparation or access is unavailable.” This does not disclose whose private means or decision caused a blocker. No code path spreads a raw preview, registry record, knowledge body or input fields into player-facing output.

Native constructor-normalized `visibility_treshold` is intentional upstream spelling. [Skill](../../../../../src/models/skill.js), lines 55 and 153-155, owns the threshold/unlock visibility rule. Its getName/getTotalXP read through getDefaultSkillXP; [LevelableComponent](../../../../../src/components/levelable_component.js), lines 104-106, calls fillSkillXPObject in that read. Engine should read existing `character.getLevelableComponent().skill_progress[id]` without initialization and map absent XP to zero. Derive the current rank name from already stored current_level and native names, or use an already evaluated safe display name after the same gate. Renderer must not invoke getter-driven record creation to discover an undisclosed skill.

### Four selected functions

The [Ability requirements](../../abilities/SKILL_REQUIREMENTS.md) freeze frontier.brace_control, frontier.trail_reading, frontier.timber_judgment and frontier.shared_inquiry. Its returned draft uses per-family knowledgeKey/powerId plus discover/learn/practice/use command IDs; Engine S2 defines the canonical family fields and owns that mapping. The projection stays generic and does not create a parallel family catalogue.

For these four, Engine derives discovered from the actual family's player knowledge record or acquired player-owned method, and unlocked from the actual relevant command/function ownership. Merely meeting Lio/the craftsman, native Equilibrium/Perception/Woodworking already being unlocked, registry membership, or preview visibility does not disclose the full method family. An explicitly public demonstration/field lead can be a separate safe hint/native activity; observation or teaching supplies the earned record, not this renderer.

Brace cards/encounter links preserve paid consented instruction and current stamina/body/partner support. Trail controls retain the real inspected crossing/route evidence and one-survey owner. Timber controls describe actual stock/yield and mastery without producing kits on render. Inquiry controls show only actual agreed comparison/report evidence; private teacher work or road/actor state does not become an explanation. Known source/fuel/tool/access failure preserves method knowledge and its blocked card. Future milestone labels need their own player-qualified disclosure, not automatic exposure of the entire milestone array.

These bindings are concrete requirements for Engine's shared integration, not a claim they are already applied. Reversible layout/wording choices within this scope need no further human permission. No unrelated panel/framework rewrite is requested.
