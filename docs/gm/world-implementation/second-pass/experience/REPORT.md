# Player experience and discoverability: decision return

Planning proposal, 2026-10-04. Make the existing depth easier to find, compare and resume before adding another large navigation layer. The strongest immediate finding is a source binding mismatch: Glasshouse jobs route attention to People while their panel belongs to Here. The remaining recommendations refine player-facing contracts already implied by the [canonical plan](../../IMPLEMENTATION_PLAN.md), rather than redefine world mechanics. [FINDINGS](FINDINGS.json) contains ten prioritized findings with exact evidence, owners, world cases and unrun acceptance gates.

1. **Unify action destinations and readable feedback (EX01, EX03).** Resolve waiting work, event links and panel destinations through the same binding. Preserve the current once-per-new-attention opening and later player tab choices. Workshop blockers currently live in disabled-button tooltips, while Body and Glasshouse show visible reasons. Extend the better pattern, with focus recovery when completed work or expired opportunities removes a control. Preserve stable buttons, semantic tabs/details and concise status. This is a targeted integration change, not a UI framework rewrite.

2. **Explain what an action spends, uses and produces (EX02, EX06).** Body descriptions and Rat-step previews already do useful work. Carry their clarity into route, item and pocket actions through existing preview/knowledge owners. The paired-device label includes a template, but the actual command retains it: show reusable support separately from spent logs, kit and stamina. Link known item functions to actual legal activities. Trial notes should connect paid preparation, observed result and its limited conclusion; the original damp/sound trials already provide a concrete starting case. Avoid another inventory or an exhaustive recipe graph.

3. **Make starts, clocks and interruption reviewable (EX04, EX05).** Entry mechanics are already covered in the plan; their player journey needs an explicit preview. Show the supported place/era, traveler or separate life, starting means, retained progress, declared obligations, exit and failure terms. For continuing play, distinguish a response waiting for the player, funded work continuing and a timed offer on its actual clock. Glasshouse already explains supported resident time versus paid-job completion. Reuse that distinction in return/reload recaps, without selecting an absence, death or reset policy.

4. **Keep local choices and remembered people navigable (EX07, EX08).** Retain Here/Practice/People and the native Quests separation. Filter discovered activities by useful purpose, place and a player-chosen goal as content grows. Explain outputs/access and known route requirements, so gathering, craft, exploration, social work and return visits remain understandable. Enrich People with actual agreement/result timestamps and attributed reports where the record carries them. Last met must stay different from current intelligence. Detailed maps and a second progression ledger can wait for a case that needs them.

5. **Preserve optional play styles and visible automation control (EX09, EX10).** Existing three-kit packing already reserves each unit and pauses after current work; expose the remaining target and actual next-start blocker. Keep ordinary advancement and slow practice useful alongside active choices. Preserve genuinely superior supported functions and source-specific exceptions. Apply current discovery guards to every new reason, tooltip, search result, start preview and recap.

These are original UX proposals grounded in inspected local code and completed [macro](../../depth/macro/REPORT.md)/[micro](../../depth/micro/REPORT.md) findings. Book examples are plan-level cases, not newly verified canon. No browser, game suite, save, build or benchmark ran, and no gameplay or measured savings are claimed. [DEPENDENCIES](DEPENDENCIES.md) provides five scoped handoff groups and concrete journey sketches; [CHECKPOINT](CHECKPOINT.md) owns final document checks and writer closeout. The assigning master alone reconciles the plan; director review and later playable/human acceptance remain open.
