## From reviewed indexes to playable era recipes

Normalize each relevant source event into a small adapter view: edition/claim/locator/review status; branch/era/body/life; actual occurrence interval or partial order; narrative reveal position; participants/place; actual prerequisites and supported before/after changes; observer learning/disclosure; revision/contradiction/unknown. Do not assign precise dates to a relative chronology.

Keep five time coordinates: source reveal order, occurrence in the selected history, each observer's learning time, local world clock and body/subjective exposure. Outside played/calendar clocks are separate references. A flashback advances reveal without advancing current local time. A copied memory describes another carrier's experience; it does not prove this actor performed the event. Unknown synchronization cannot generate exact deadlines.

An era snapshot is a source-qualified baseline recipe at a declared occurrence boundary, with source cutoff, contemporary people/bodies/means, available places/institutions, existing obligations and knowledge-holder constraints. It is not a dump of everything read before a chapter cutoff. A later reveal about ancient history may inform the author baseline while remaining unknown to earlier residents. A spoiler-free author request with an earlier cutoff can retain an unresolved placeholder and defer the affected action.

Build only consequential before/after states supported by the source. Leave unmentioned stock, unseen travel and exact fuel unknown. Original gameplay additions explicitly state origin, constraints and parameter status. Missing facts block claims of canonical fidelity; they need not block a labelled source-compatible original local project.

## Background, aggregates and promotion

| Scope | What exists | Promotion gate |
---|---|---|
| Background reference | Dossier people/places/events, no enrolled gameplay identity or stock | Choose a reviewed contemporary baseline or labelled original profile; resolve identity and continuity before materialization |
| Declared aggregate | Authored regional quantities/processes with units, cause/history horizon, allocation rights and limits | Reserve/debit attributable means when creating an individual lot or worker; aggregate “prosperity” is not a bag of unlimited coins |
| Actual participant | Stable identity/body, enrolled life/location, actual owners, goals/knowledge/stock, controller/work and receipts | Use real planners/native bindings and bounded active resolution; leaving view does not delete identity/history |

Promotion is proposed tooling, not a shipped adapter. Reconcile existing identity/aliases/counterparts and previous visits first. Freeze generation seed/overrides once; give only explicit knowledge and means. Link prior aggregate contribution to prevent double production or duplicate stock. Do not run historical controller ticks to manufacture undocumented years of work. Demotion can retain durable actor state and summarize declared background activity; it cannot erase commitments/custody or reset a later meeting.

Resolution follows player-relevant causal needs: nearby independent work, owed deadlines and supported remote contact can be active; distant regions can remain background or declared aggregate. Presence/support clocks differ from joined paid-job completion today. New off-screen policies require explicit Engine adapters. Current native location/world labels cannot isolate two historical copies of a town.

## Concrete depth and engine capability criteria

Extend the canonical plan's campaign/mechanic ledgers; this packet proposes criteria, not a second global tracker. Each required ID names source qualification or O status, actor/means/context, native/UI consumer, lasting result, alternative/refusal and later acceptance. A world is deep enough for the reviewed scope when these observable gates close:

| Criterion | Concrete acceptance consumer |
|---|---|
| Ordinary life and connected geography | Obtain material through two contextually distinct supported routes, use it in work/care/preparation, traverse real routes and encounter independent supply/availability changes |
| Institutions and several viable paths | Craft/service/investigation or combat paths overlap without forced class choice; earned rights, duties, teaching and enforcement change actual available actions |
| Local distinctive functions | Every selected item/talent/ability/rule has actual acquisition, support, use, growth, counter/interruption and portability cases; descriptive rows stay explicitly reference-only |
| Independent people and consequential history | Two same-prior actors choose differently from real means/history; one off-screen funded action settles once; learning, refusal and relationship changes affect a later project |
| Mature outcomes and return | A resolved arc changes a working local institution/route/function, residents continue under declared scope, and compatible earned knowledge/item/contact changes a home action or later visit |

“Days of local play” needs later pacing and human acceptance evidence across these loops, not a word count, artificial wait or automatic depletion. Ordinary routes remain useful without forced daily upkeep or jackpot gates. One realm/one prestige remains the first milestone; these criteria describe broader campaign scope without enrolling it now.

Current APIs and limitations are in WB-C01–14. Minimal missing contracts are reference/query adapters, explicit activation, generic instance/read-write joins, retained individual profiles/evidence/episodes and optional ranked-selection/consumer bindings. Preserve pure plans, legality checks, deterministic commitments and durable publisher. Broader physiology, arbitrary spell geometry, loops and institutional/romance lifecycles remain feature-triggered work, not prerequisites for every ordinary scene.

All checks in this task are documents/JSON/links/readback. Runtime and performance acceptance are deferred; no whole-universe simulation, perfect detail recall or measured token savings is claimed.
