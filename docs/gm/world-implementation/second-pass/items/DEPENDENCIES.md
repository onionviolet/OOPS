Start with content-only pills/passive relics where current primitives suffice; permanent outcomes, actual deployment and nested containment receive specific shared adapters only when selected. Preserve original shell/inventory UI and no universal rarity/side-effect rules. The integration/world-bank lanes may consume these reports; this Items audit sends no external message and edits neither canonical owner.

## Decisions and acceptance

Master/director decisions: select the two item cases; choose additive old-save compatibility or an explicit incompatible optional schema; choose policies for current physical/tool revalidation versus paid escrow; select which condition/dose/preservation fields actually affect those cases; select the source cutoff and exact living-source rules if that optional case is included. No numerical balance, death/reset policy or new destination is approved here.

Future qualification uses each finding's positive/adverse/retention cases. Minimum connected gate: old ordinary keys still work; owned spare and borrower stock differ; all initial inputs validate before any output; multi-output/cancel preserves used versus unused stock; one real function changes with charge/repair; disposal cannot duplicate an installed/unique part; failed publication leaves old bytes/live state/RNG unchanged; native UI and return history reflect the same owners. New record compatibility, generated-save/import/reload, failures and browser proof remain deferred under current instructions. Document checks establish this packet only.

No cost benchmark or token telemetry was collected. Minimal bulk records, bounded trials and boundary-based maintenance are proposed complexity reductions, not measured savings. All runtime/shared/source folders remain read-only in this audit.
