# Reusable component and effect contracts

Planning revision 1, 2026-10-04. These are **proposed authoring requirements**, not exported functions, registered definitions, save fields or a chosen schema. [Worked cases](WORKED_CASES.md), [engine requirements](ENGINE_REQUIREMENTS.md) and the [held main plan](../../IMPLEMENTATION_PLAN.md) own their use. Engine alone selects actual modules/native/persistence interfaces after director review.

## C1: person, body, lineage and source identity

| Record group, proposed | Minimal meaning | Invariant and non-substitution |
|---|---|---|
| Person/life | Stable person, current life, remembered history, actual continuity/era | A copied name, counterpart role or prior-life memory is not the same current person |
| Mind/soul | Actual carrier IDs and selected shared/independent policy | Multiple bodies may share one mind/resource source only when a supported rule says so; no duplicated pool by default |
| Host body | Current body/form/revision, anatomy, support, condition, known adult/maturity policy where relevant | Current physiology is checked for execution and adult scenes; inherited cosmetic demographics are insufficient |
| Biological ancestry | Source-qualified lineage/genetic origin and known-versus-private evidence | Acquiring an organ does not retrospectively change ancestry unless an independently selected source effect actually changes it |
| Component specimen | Definition/revision, one instance ID, provenance, donor/creator, physical condition, held/container/attached status | Definition labels are reusable; actual organ/unique artifact IDs are conserved. An eye cannot be both attached and loose cargo |
| Acquired faculty | Actual source instance(s), installed/held/body support, awakened/active/suppressed state, permitted functions | Origin `acquired` and constituent `lineage` do not encode biological ancestry or every donor power |
| Learned method | Actual learner, definition/revision, demonstrated/understood/practiced state, evidence segments and mastery | A copied method does not fabricate fuel, donor memories, compatible limbs or an organ |

Biological donor, legal claimant, current holder, installed host, mind/controller and operator are distinct references. A living person's body autonomy cannot be reduced to an inventory-owner flag. Multiple eye-dependent abilities resolve their actual source set: losing one eye can disable a paired function while leaving ordinary vision/other acquired methods intact under its source rule. Do not assign every member of a source family the same apparatus or maximum stage.
Current support: body effect values are scalar; actor sources/faculties are keyed by source definition ID; power `lineage` records constituents. These do not implement sockets, several specimens of one organ type, paired-organ requirements or shared biological/soul identity. New native body/source projection must read one authoritative ownership graph, not store a second eye in the bag.

## C2: conservation, custody and phase receipts

Physical states form a declared graph: `attached → detached-held → preserved-held → reserved-for-fit → attached`, with independently authored damaged/spoiled/destroyed branches. Each move requires the actual initial holder/body/container and expected revision. Removing a mount returns the same surviving specimen. Restoration/refinement that truly creates a new source records which old source was consumed and its actual cause.
Donation requires specific current decisions and terms; theft/extraction requires its selected acquisition/failure rule and disputed claim/history. Incapacitation, death, legal salvage permission and anatomical removal are separate facts. Source-supported regeneration may create new tissue only under its actual rule; it never duplicates the same old specimen ID.
For generic lots: lot ID, item/material definition, actual quantity, owner/holder/container, provenance, production cause, quality, condition/contamination, preservation policy and revision remain separate. Splitting makes child quantities whose sum equals the debited parent; merging preserves necessary provenance/condition distinctions or explicitly rejects. Native template/quality keys may project compatible aggregate counts but cannot become the authoritative lot registry by adding an arbitrary unconsumed JSON property.
Every phase has one receipt, frozen input set, used/unused escrow, output identity and relevant revision guards. Release returns only untouched reserved material to the rightful holder. Used materials, wounds, already published donor loss and time are not refundable by generic negative costs. A phase after extraction can fail without undoing extraction. Unique/exported objects and wage claims survive display-history pruning and cannot be recovered twice after rewind/reentry.
`stageAcquisition` checks all debits against initial inventories before grants; item/custody effects protect entire keys and stage holder changes. They do not track per-lot selective loans or physical organ attachment. Reuse those owners/publication services while adding the missing validated instance references.

## C3: host costs and effective operating budgets

Keep the following channels independent, each with its own support and clock policy:

| Channel | Derived quantity | Invalid shortcut |
|---|---|---|
| Reserve capacity | Effective maximum for an actual pool/body/source, including selected modifiers | “Advanced power capacity” is not a chakra-reserve ceiling |
| Recovery | Rate/amount, eligible context, source/body support and clamp | A lower recovery rate is not equivalent to continuous reserve consumption |
| Upkeep | Elapsed supported duration × declared rate; discrete exact accumulated remainder where needed | No upkeep at render time, no hidden repeated charge on reload |
| Startup/action cost | Actual accepted activation/use, idempotent receipt | No charge from inspecting a button; no activation cost silently masquerading as a passive drain |
| Output/throughput | Current supply and function demand, target/reach/material envelope | Owning large reserve alone does not permit unsupported instantaneous output |
| Control/strain | Learned control, interference/injury, accumulated use strain and its real recovery | Strain is not secretly the same field as fuel, organ wear or social rank |

Effective values are derived from actual operative constituents. Training may change only the selected method/control/cost terms; acquiring a source supplies only its supported functions. Loss of capacity needs an explicit overflow/clamp policy, persisted with the cause; never silently delete or refill reserve on a definition change.
Typed stacking declares each contribution's channel, target pool/body/component, scope, priority, duration and `sum`, `max`, `min`, exclusive or source-specific composition. One actual eye cannot be counted twice because two ability names reference it. Two genuinely independent sources may combine if their interfaces permit it. No universal exclusivity, slot ceiling or mandatory balancing drawback is selected.
A cover, deactivation, faculty suppression, host injury, source exhaustion and physical removal are separate changes. Source-supported exceptions may bypass a defined limit. Unknown deactivation/covering effects remain U rather than receiving a convenient automatic off switch.
Current `applyEnergyEffect` stores integer fixed policies and supports discrete recovery/use/refund. A fresh learning operation starts reserve at zero and rejects an already learned ID. Composed reserve modifiers, physiological recovery, maintained costs and insufficient-upkeep resolution need their own adapter/compatibility choice. Existing ticking conditions are scaffolding, not a complete host-burden subsystem.

## C4: atomic actions and continuing effects

Proposal TX1 binds operation/phase ID, requester, actual body/source/target/endpoint, definition revision, expected host sequence, relevant component/lot/site/consent/encounter revisions, paid inputs and uncertainty policy. Native UI submits current identities; preview quotes without creating a source, random draw, relationship or stock.
Commit rechecks known physical prerequisites, stages costs/reservations and freezes random outcome once. Consequential settlement again checks actual support/contact/custody when the action requires it. An already executed physical cause is never erased because its magical supplier later stops. A destroyed magical construct and continuing ordinary fire have different consumers/counters, as MC03 demonstrates.
Use explicit `intent/reserved/windup/irreversible/settled/interrupted` phases when they change refunds or anatomy. Do not require six phases for a simple rope purchase. The action defines the last reversible boundary and what can resume after interruption. Consent/source loss stops future supported use but retains prior valid history/cost/output.
A continuing effect binds actual source/body/target/contact, its clock, accepted startup, next due boundary, upkeep remainder, duration, typed stacking and stop rule. The scheduler must bound work; exhaustion stops/suspends/causes an authored consequence without negative reserve or an infinite throw/retry loop. Restoration creates a newly eligible paid use, not unpaid retroactive coverage.
Order is selected once: reconcile the authorized time interval and already-due support changes; derive effective bodies/pools; settle eligible recovery/upkeep in the declared order; resolve startup/target/position/reactions; apply function/damage/physical aftermath; emit per-observer evidence; persist and publish once. Source-specific simultaneous rules can differ but must be explicit and deterministic. MC01 arithmetic fixes startup/use before its four recovery/upkeep minutes; it is one fixture, not a franchise formula.
Current simulation jobs freeze effects and `completeJob` applies them without general physical/source/consent revalidation. Boundary order currently processes jobs before conditions/life. Retain explicitly prepaid frozen ordinary work where selected, but add live continuation/order semantics before claiming surgery, sustained wards or battlefield timing work.

## C5: resource nodes, populations and tactical effects

Resource node proposal: actual endpoint/node revision, resource class, stock/available/reserved quantities, environmental/tool/source/rights requirements, qualified yield table/revision and local-clock replenishment rule. Unique specimens reference C1/C2; they have no generic renewable-loot rule. Node debits and resulting native-owned lots share one transaction.
Population proposal: bounded eligible aggregate count and stock, actual cause/template/era, promotion receipt and stable actor IDs. Promotion spends the aggregate and transfers finite equipment, then normal actor lifecycle owns that person. Demoting on reload or generating a replacement with the returning captain's name is invalid. Existing fixed actors are separately referenced, not entries in a player-level distribution.
Tactical proposal: encounter/roster/side/position revisions, actual contact/line/reach, observer channel, permitted targets, action costs/phase, projectile/support object, actor policy, frozen RNG and persistent aftermath. A scout can see without attack reach; an ally can refuse combat while carrying cargo; a projectile remains spent after launch even if its source later disappears. Strength/threat band and spatial reach are distinct dimensions.
Guard/escape/loot effects have real consumers: interpose a reachable actor paying actual effort; move through an open route with actual stamina/interception; transfer only eligible abandoned/owned stock. An “escaped” flag alone cannot teleport a party, and native one-HP defeat cannot produce death or organs.
Existing spawn/effect/claim/seed services do not validate population/depot budgets or battlefield geometry. Current party combat binds player, Mara and Lio in one nonlethal encounter; flexible roster, positions, arbitrary target selection and loot/escape require native integration.

## C6: relationship intent, dialogue and projects

Relationship proposal: actual people/current bodies/era, per-direction memories/beliefs/preferences, current availability and contact, meaningful relationship state and scoped decisions. Keep known adulthood/current maturity and willing reciprocity distinct from trust, wages, gifts, species labels, prior-life age or institutional power. No threshold on a favorability axis automatically grants romance.
A specific invitation, its mutual acceptance, shared time and later relationship step are different records. A withdrawn decision prevents future intimate use while retaining its original occurrence as history. Friendship, mentorship, rivalry and paid work remain valid alternative pursuits; choosing them need not punish unrelated access. Critical current consent/refusal/state survives the current 32-memory text cap and imports under selected compatibility rules. Receipt dedupe tests explicit membership, not timestamp truthiness at clock zero; contradictory reports retain separate occurrence/attribution while the current belief can change.
Every dialogue line declares supported speaker knowledge/context and offered executable action. A private surgery, undisclosed donor history or unseen NPC motive cannot enter dialogue from author metadata. New disclosure uses an actual communication channel/recipient; reveal time does not rewrite event time. Original Mira lines remain fresh fictional prose, not Naruto voice evidence.
Project proposal: exact site/rights/claim revisions, phased dependency, materials/lots/reservations, workers/tools/occupancy, actual structure and utilities, warehouse capacity, production/training/care/defense functions, damage and repair state. Blueprint knowledge, site ownership, use permission and physical completion are different things. Additional capacity requires a real expansion, not a label or doubled inventory.
`compileSiteProject` compiles paid dependent phases but does not forward helper participants/tool reservations. An integration wrapper or new selected compiler contract must bind all actual workers. Current site capacity is not a full tenancy/use-rights policy, and generic world facts do not implement a warehouse, structure or raid resolver.

## C7: endpoints, clocks, return and publication

Actions bind all four endpoint IDs: world, instance, region, layer. Same source family/world ID alone does not establish contact or common history. Each clock interval is authorized by actual presence or supported activity lease; overlapping visitors count one local interval, not doubled time. Browser/absent freeze remains the initial proposal for these new cases. Local stock/spoilage/work/environment cannot borrow joined time silently.
Host-body costs travel with the actual host/pool clock. A clinic container left in a frozen instance uses its declared local preservation rule, while its detached organ is not executed in a traveling body's slot. A shared mind/soul does not create independent energy/inventories in each body. New life, earlier branch, projection and live rewind explicitly resolve bodies, sources, custody, outside time and exported claims.
`world_instances.js` supplies detached instance identity, scalar facts/sites/claims, visits and unioned freeze clocks; `realm_clock_leases.js` supplies bounded support-authorized activity. `realm_state.js` and its native host currently bind the one Glasshouse prototype. None enrolls this Naruto annex or makes generic jobs local-clock tasks.
New records require a chosen additive migration/explicit compatibility decision and future save/import/retention proof. Old saves receive no organ, romance, node stock, patrol, new title or retroactive construction. Persistence must validate the proposed component/lot/body/clock records before one durable write; native anatomy, inventory, combat, location and UI publish only after success. Missing adapter means the case remains planning, never an “implemented” JSON example.
