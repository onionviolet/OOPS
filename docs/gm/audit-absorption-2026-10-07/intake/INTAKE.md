## Contradictions, stale claims and evidence limits

1. **Audit queue changed across owner generations.** The first-wave `DELIVERY.md` describes 19 candidates still queued; current `QUEUE.json` says the historical three plus current 19 are all delivered and `remainingLatestCandidates` is empty. Use the latest queue and remainder receipt for current disposition while preserving the older statement as a historical checkpoint.
2. **Old ownership snapshots are not live state.** Project files and checkpoints preserve historical thread IDs, active/released labels, bundles and hashes. For any shared write, source/build claim or replacement dispatch, refresh the actual owner status and current files first, as the project workflow requires.
3. **Delivery vocabulary can look like acceptance.** “Source/native/UI/compatible-state/current-build complete” and syntax/build/map/link checks prove authored/package state, not player behavior, save/reload, error recovery or creative-director acceptance. Current AGENTS explicitly defers the broader suites; keep them unrun.
4. **Source coverage is not uniform.** Full-book metadata/manifests, canonical reader indexes, game exports and dossiers have materially different semantic coverage. Counts, profiles, installed DLC, code symbols, world briefs or registry rows cannot be upgraded to full source reading or complete world parity without the owner's specific evidence.
5. **This inventory is intentionally broad but shallow.** It hashes 2,374 owner files while only 11 were opened as semantic inputs. Exclusions and metadata-only flags are recorded in `SOURCES.json`; this intake cannot settle every source claim or every old/latest checkpoint conflict.
