## Risk checklist for final integration

Root's received completion message reports repairs to the Glasshouse whitelist/global single visit, expansion11 admission/lower-schema retention/audit enrollment, native registry/action/binding/read/stage/snapshot/restore, presentation/items/People/Events and condition-immunity context. MOL condition projection remains the worker's explicit native-stat export. These are **root-reported joins**, not independent verification by this review; the following points retain the rationale and final static acceptance targets.

- **Supported time is separate from display time.** Instance presence/freeze clocks do not automatically freeze generic simulation jobs/controllers/condition expiry. Jobs cannot be left behind on departure without an authored pause/retention rule; NPC support must fail safely when away. Permanent conditions or local-deadline storage avoid silently inventing absence aging. Existing generic condition timers at simulation.js407–434 use the common clock.
- **Condition immunity receives an incomplete context.** simulation_effects.js231 calls `simulationFacts` without registry and without full gameplay/native/vital context. Existing facts helpers tolerate absent registry in the inspected paths; this is not proof of a generic condition crash. A new immunity predicate that requires current MOL body/source/stock/fuel support needs the full context passed through. Its left side also evaluates when no immunity is authored, so preserve the ordinary no-immunity path.
- **Vital persistence is already owned.** simulation_effects.js156–165 stores changed native NPC vitals in simulation.people and player offsets in plan.native, so ordinary NPC vital effects are durable. expansion_engine.js601–603 returns full `vitals` only for causalStories; a new leaf that reads full staged vitals after clock advancement must request that preservation explicitly. Do not claim this is a generic lost-NPC-vitals bug.
- **Body/death policies remain finite.** A local source encounter must disclose lethal/nonlethal consequences, apply actual life/body/vital conditions through current owners, and retain them across return. Registry membership cannot provide arbitrary named-person combat, source protagonist replacement, resurrection or save rewind.
- **Save compatibility is additive and exact.** Existing old5–11/optional simulation5/frozen-job readers remain. MOL-absent saves stay absent; new MOL1 saves require this updated reader. New strict fields require explicit admitted version/migration, not runtime normalization of source rights, received knowledge or finite stock. save_compatibility.js only retires the old Jade Hollow prototype and does not need a MOL detachment path.
- **Source secrecy needs actual receipt boundaries.** MOL private Zorian/time-loop knowledge is not player knowledge; current court/academy/teacher rights are separate facts/receipts. People/Events/center views use observer-safe received records. The current root-selected scope is independent Cyoria/academy-era play, not full novel parity.
