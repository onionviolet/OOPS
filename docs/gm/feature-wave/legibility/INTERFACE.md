# Action legibility interface v1

Implemented projection is `src/action_legibility.js`; DOM helpers are `src/action_legibility_ui.js`; scoped style is `styles/action_legibility.css`. No save field or schema change, no registry/actor enrollment, no RNG, no committing callback inside a projection. Features INTERFACE v1 and existing native durable publisher remain authoritative. New gameplay remains implemented-unverified.

## Actual callable projection

`projectSimulationActionLegibility({state,registry,context,commandId,disclosure,preview?,facts?})` returns null for hidden/completed/claimed commands and otherwise a player-facing action row. Reuse the host's actual preview and facts when already evaluated. `context` must be that action's live native/campaign context including target and travel/body/busy gates. This adapter does not replace action-host legality.

`playerActionDisclosure({state,context,items,people,facts,locations,sites,powers,energies})` supplies only current own coins/vitals and externally qualified labels. Item maps are keyed by actual stock keys, values `{known:true,label}`; available counts come from the actual native/simulation bag. No parsing an unseen item key into a name. Energy labels need actual discovered method evidence; helper uses acquired saved policy/reserve, never a new registry default. Participant `{known:true,label,termsKnown:true}` is required before their agreed costs or reservation becomes visible. Knowing a person's name alone reveals no private means. Site `{known:true,label,termsKnown:true}` discloses accepted reservation; capacity failure needs `observed:true`.

Known requirements use `disclosure.facts[factKey] = {known:true,label,valueKnown?:true,requirementText?,notText?,values?:{[actualEnum]:publicText}}`. Numeric and boolean comparisons use the real predicate. String/ID equality needs a supplied public value label or requirementText. A known term does not disclose current private truth: met/not-met appears only with `valueKnown:true`, backed by current own state or an actual current observation. Unobserved fact leaves are omitted; partial OR groups never name/count hidden alternatives or reveal their truth. Missing facts never satisfy a negation. Do not mark every authored rule reason as current observed truth.

Other disclosure records: `requirements`, `blockers`, `costs`, `preparation`, `completion`, `reservations` accept `{known:true,id?,text,met?}`. `reasons` accepts `{known:true,match:<exact real evaluator reason>,text:<player-safe wording>}`; matching is required, so static metadata cannot invent a current failure. `alternatives` accepts `{known:true,id,label,description?,eligible:<actual alternative preview>,visible?:boolean}`. Known methods, recovery, native Rest/Sleep, manual ordinary approaches, withdrawal and useful return should be linked through their existing callback owners. Do not add a future alternative by inspecting an unknown definition.

`projectActionLegibility({id,label,description,discovered,unlocked,preview,definition,facts,disclosure,context})` handles external real evaluators such as native combat/passages, Backlog and Ink. `preview.eligible` is authoritative. A current eligible typed cost array is a quote; early blocked previews show disclosed nominal terms, with unresolved formula costs omitted. `disclosure.duration={known:true,minutes}` can represent an external evaluator's duration. Public external cost prose must be explicitly qualified in `disclosure.costs`. No effect/outcome/roll inspection or predicted success.

`projectAcceptedWorkLegibility({job,clock,actorId,label,disclosure,context})` reads only own frozen costs/cancellation/participants/due. Supply the known command label, never job outcome prose. `projectSimulationAftermath({state,observerId,prefix,people,witnessedCauses})` reads only that observer's knowledge ledger. `projectActionAftermath` accepts actual retained `{known:true,observerId,id,text,at,cause,basis}`. Cause explanations need separate `{known:true,observerId,cause,text}` with an exact matching retained cause; a matching ID alone is not an explanation. Inferences/recollections/instruction remain qualified accounts. Do not read NPC private/current state or simulation.log for a player recap.

## DOM consumers

`createActionLegibilityList({parent,onAction,onAlternative,onCancel,onError?,focusFallback,idPrefix})` exposes `element`, `render({actions,work,aftermath,enabled,notice})`, `destroy()`. `createActionLegibilityPanel({...options,label,read})` exposes `panel`, `render(view?)`, `destroy()` for Notebook use. Native action menu remains primary. The parent controls panel discovery and busy/navigation placement; recovery/cancel use actual host callbacks and remain outside hidden feature-family gates. Global enabled must mean actual publication availability, not merely actor occupancy, or cancellation is incorrectly disabled.

Buttons retain action-specific labels and guard `aria-disabled`; shared callbacks recheck fresh state/sequence and publish through the single existing durable owner. Async callbacks use a local pending latch. No automatic saved-success assertion. `onError` must return player-safe text; default errors disclose no raw evaluator/internal/private message. Known terms/blockers link through aria-describedby. Keyed rows and details retain nodes/open state; removal moves focus to caller fallback. Keyboard/button/details behavior, visual layout, save/failure handling and director acceptance remain deferred.
