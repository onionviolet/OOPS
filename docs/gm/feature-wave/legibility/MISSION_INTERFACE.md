# Hub, mission and chain projection extension v2

Direct steering: NESTED_WORLDS_AND_DEEP_TROPE_CHAINS_2026_10_05.md. Preserve in-flight recognition/replacement and original legibility APIs; same reserved paths and sole Features integrator. No independent clock, settlement, rewards, native instance or save owner.

`projectMissionLegibility({mission,viewerId='player',people,vocabulary,actions,recovery})` returns `{visible,id,label,actions,aftermath}`. A host-qualified mission header needs `{known:true,id,label,observerId:viewerId or recipientId/recipients}`. Individual `terms/preparation/portability` rows need `{known:true,id?,text}`. `objectives` also have `scope:'issuer'|'local'`; hidden issuer motives, local goals and undiscovered branches are absent, without unknown-slot placeholders. Preacceptance terms never become an accepted mission or predicted result.

`mission.clocks` are authoritative `{known:true,id,label,remainingMinutes?,unit?:{known:true,label},policy?:{known:true,text},at?}` snapshots. Return deadlines, extraction, settlement, hub/local/subjective/transit clocks are independent supplied rows. The projection does no Date/time arithmetic, clock advancement or inferred rate/offline relation. Keep frozen absence and actual extension/withdrawal options explicit through their host actions.

`mission.stages` are retained addressed accounts with `{known:true,id,text,observerId or recipientId/recipients,occurred:true or current:true,at?,basis?,cause?}`. Only actual current/occurred extraction stages appear; a frozen next outcome is not a stage. `settlements` additionally require `occurred:true`; only an actual once-published settlement receipt can state a payout. `aftermath` uses the addressed account contract for actual local welfare, changed revisit and relationships, never private current NPC state, numeric affinity axes or predicted friendship. All accounts preserve heard/inferred/remembered qualification. Settlement and local peace/welfare are separate receipts.

`projectTropeChainLegibility({chain,viewerId,people,vocabulary,actions,recovery})` returns the same view shape. Chain header uses the addressed known contract. `links` are individually addressed known accounts with learned `label?`, known `phase?:{known:true,label}` and actual text/time/basis/cause. Only supplied discovered links appear; the projection never reads author futureLinks/branches/motives/actors or a branch count. `closures` require actual occurred receipts; no forced checklist order or automatic replacement adversary. Legal known tests, cooperation/refusal, restitution/retreat and source/fuel preparation stay separate host actions.

`projectHubCampaignLegibility({hub,missions,chains,viewerId,people,vocabulary})` composes known hub accounts/services plus only discovered mission/chain groups. Return `{visible,groups}`; each group is directly renderable through existing `createActionLegibilityList`. Hub header is known/addressed; `.accounts` are retained visible accounts and `.actions/.recovery` are actual host-qualified offers. A known hub does not reveal its undiscovered destinations, missions, competing issuer or source-world identity. Native mutable hub/destination owners and source topology remain Features-owned.

Actions/recovery use `projectEssentialRecovery`'s exact plain displayed command token and real preview. No renderer constructs an acceptance, extraction recovery, extension, early withdrawal, breach or settlement option the host does not support. Typed costs/requirements stay in normal core `definition/disclosure`; source-world nouns require qualified vocabulary. Conditional portability terms never themselves carry goods, rights, body/source/fuel or allies across an edge.

Retained replacement/portability aftermath can distinguish actual body, occupant, controller/soul, memory/method/mastery, source/faculty/lineage, fuel/capacity, held/equipped/carried goods/custody, title/authority/rights, obligations/curse/oath/debt and supported allies. Each remains an individually known receipt field. A remembered method, copied face or portable title never implies any other carrier moved; an unseen soul/controller or private burden is omitted.

Features freezes actual hub/mission/chain schema and ledger/preview mapping. Its presentation wrapper should pass only reported/player ledger rows and actual native previews; feed groups to shared lists and route unchanged row.command to the one staged publisher. If using the existing feature panel, map actions to `{id,label,command,eligible:row.control.enabled,legibility:row}` and keep aftermath qualifiers in the shared list. Add actual native/UI imports to final matched bundle; mark these helpers source-implemented until real joins exist. Browser/gameplay/save/failure/keyboard/regression/director gates remain deferred.
