# Observer and replacement projection extension v2

Direct steering: BOOK_WORLD_SUBTLETY_2026_10_05.md. Same reserved role files and sole reconciled Features integrator. Original legibility v1 calls and saved states remain compatible. This extension creates no save field, identity/carrier owner, recognition decision or mutation. Exact native/Backlog/Ink receipt joins remain integrator-owned.

New read-only exports in action_legibility.js:

- `projectRecognitionLegibility({records,viewerId='player',people={},vocabulary={},tests=[]})` returns `{actions,aftermath}`. Each record is an actual retained account `{known:true,id,observerId,recipientId? or recipients?,text,at?,cause?,basis?,statusKnown?,status?,test?:{known:true,kind,label?},supersedes?}`. Own observer records need no additional audience; another observer's judgment requires a real addressed/heard recipient. No reading all NPC beliefs or actual hidden identity. Recognized, claimed, suspected, disputed and corrected are account statuses, not underlying truth. A correction updates only a visible older account of the same observer; both entries stay retained. Cross-observer disagreement is not a silent revision of somebody else's belief.
- `projectReplacementLegibility({receipts,viewerId='player',people={},vocabulary={},recovery=[]})` returns `{actions,aftermath}`. Each receipt uses the same addressed-account contract and may include `changes:[{known:true,id?,carrier,text,before?:{known:true,text},after?:{known:true,text}}]`. Carriers are separate appearance, credential, role, credit, opportunity, body, occupant, memory, source, fuel, mastery, holdings, custody, rights and obligations. Project only the individually qualified retained changes; never infer any other inheritance from a face/title/body/office transfer or inspect actual private carrier state. Do not state that a missing donor/occupant died or survived without a known receipt.
- `projectEssentialRecovery({actions,viewerId='player'})` returns actual core action rows from host-qualified `{known:true,recipientId? or recipients?,observerId?,id,label,description?,preview,definition?,facts?,disclosure?,command?}`. Actual preview remains authoritative. Recovery is not gated by discovering an optional identity/power family. A missing preview is unavailable, not permission. Known honest entry, withdraw/return, undo disguise, release duties, compensation, rest or repair remain their own real host callbacks.
- `projectSubtletyKnowledgeLegibility({state,viewerId='player',prefix='backlog.registry.',metadata={},people,vocabulary,tests,recovery})` is the concrete owner-ledger join. It reads only `simulation.knowledge[viewerId]`, keeping actual value/at/cause/basis. `metadata[actualKnowledgeKey]` must be `{known:true,...}` and may supply observerId/medium/test/statusKnown/status/supersedes/changes/witnessedCauses; it cannot introduce an absent record or override its account/time/cause. The result merges attributed recognition and carrier/recovery into one existing shared-list view. Never pass `state.backlog.replacement.recognition`, NPC knowledge or situation.privateTruth as viewer knowledge.

`people` contains only viewer-qualified `{known:true,label}` names. A previously heard alias can be supplied as a separate known public label; do not substitute the actual hidden actor name. Vocabulary is optional `{known:true,terms:{appearance?:{known:true,label},...}}`; only learned terms override neutral wording. World name/continuity/unknown method families stay undisclosed. Tests are core actions with the same addressed/public contract; knowing that an observer exists is not knowing their secret body/soul test.

Recovery/test controls require a cloneable plain command object carrying the owning host's exact displayed operation/token. Missing or unsupported transport produces a visible binding blocker and disabled action even if a supplied preview says eligible. The helper never generates a replacement sequence. Main's actual replacementRecoverySnapshot supplies `{id,sequence:expansionState.sequence}`; actual Backlog commit rechecks that displayed sequence.

A known test can use a neutral supported kind or an explicit `{known:true,label}` for that world's own disclosed test vocabulary. Unknown enum IDs never become labels. A retained known `supersedes` pointer itself expresses an explicit account amendment unless `correctionKnown:false` or an explicitly known different status says otherwise; it still requires a visible older account by the same observer and non-backward retained timestamps. This accommodates actual Features receipt rows without guessing an undisclosed recognition outcome.

Existing `createActionLegibilityList` renders the returned actions/aftermath without a new UI or persistence engine. Additional carrier descriptions enter retained aftermath prose and qualifiers. Each observer's test/judgment remains attributed. Inference, recollection and testimony/instruction stay marked. Causes require known text with actual retained matching cause, never a private source baseline or merely shared IDs. Ordinary clothing/room/greeting details can remain prose, with no checklist or mechanical flag.

Features/Backlog should freeze the actual replacement receipt schema and pass only player/heard ledger records into these helpers. Ink can use the same host-qualified actions and vocabulary in its original continuation. New extension source/native/UI/build status belongs in INTEGRATION.json and its later receipt; the earlier bundle qualifies only v1 until rebuilt with these exports and real consumers. Behavioral/keyboard/save/failure/director checks remain deferred.
