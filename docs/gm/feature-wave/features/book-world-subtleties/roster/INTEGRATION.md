Released worker scope: `src/feature_expansion_book_roster.js` and this directory only. Features is the sole shared integrator. Eight profiles, eight optional original scenes, eight topology dispositions and eight finite causal authoring graphs are immutable and inert. This is implemented-unverified authoring/rule code, not eight playable adaptations.

| `getBookRosterProfile(profileId)` | Frozen profile or `null`; reads nothing else. |
| `evaluateBookRosterRule(profileId, ruleId, input)` | Explicit host-supplied boolean snapshot against a qualified local rule. Returns `supported`, `blocked` or `unknown`; missing source procedure stays unknown. |
| `evaluateBookRosterRecognition(profileId, observerRuleId, input)` | Same narrow authoring check, with observer-only belief disposition, no inferred suspicion and an actual later-evidence correction requirement. Does not prove true identity. |

| `evaluateOriginalFrontierOfficeReplacement(snapshot)` | Pure fixed original office/duty admission below. No saved state, grants, transfer, timer, XP or publisher. |

All results carry empty `grants`, `mutations` and `clockChanges`. `supported` means only narrow authoring admissibility. Existing native previews/stagers/validators still decide and perform actual work. Never place complete profile/source/graph records in a player UI: they contain author knowledge. Display only host-derived player-known evidence and original selected prose.

## Selected original office consumer

Current authoritative owner is [Backlog replacement](../../../../../../src/backlog_expansion_replacement.js), `REPLACEMENT_IDS`, `REPLACEMENT_CONTRACT`, `stageReplacementCommand`, `validateReplacementRecord`, `replacementCarrierView` and player-safe `replacementView`. `backlog.replacement.accept_office` moves the same right/duty, while Eda remains herself. This is an additional narrow source/authoring guard; native Backlog validation remains authoritative. The graph records no new state and does not replace the native receipt/knowledge/relationship owners. The parent has reserved the selected connected relay scene; this worker has not duplicated it.

The snapshot must carry every exact metadata key below, taken from `originalFrontierOfficeRuleContract`:

```js
{
  schema, revision, contractId, operation, commandId, worldId, location,
  donorId, recipientId, officeId, dutyId,
  donorBodyId, donorControllerId, recipientBodyId, recipientControllerId,
  actual: {
    sameLivingParticipantsPresentAndFree,
    donorOwnsActualOffice,
    donorOwnsUnperformedDuty,
    donorWilling,
    recipientAcceptsDuty,
    exactTwoSealDutyConserved,
    personalCarriersRetained,
  },
  effects: {
    fromActorId: contract.donorId,
    toActorId: contract.recipientId,
    rightId: contract.officeId,
    dutyId: contract.dutyId,
    transferred: contract.transferred,
    retained: contract.retained,
    borrowed: [],
    grants: [],
    additionalCarrierChanges: false,
  },
}
```

`actual` values are explicit booleans derived from current native truth and informed acceptance. They are not arbitrary player answers, dialogue tags, a credential belief or personal inventory guesses. `sameLivingParticipantsPresentAndFree` checks the actual fixed Eda/Orrin/Bera actors, bodies/controllers, Village presence and occupancy; recipient metadata requires the current player/native body. Ownership checks use the actual held office/duty claims. Two-seal conservation verifies donor currently owes two, recipient owes none before this appointment, and prospective transfer preserves that same duty. `personalCarriersRetained` checks the prospective plan/transfer boundary, not only the narrative text. Missing, malformed, mismatched actor/body/contract/effect snapshots return unknown. A complete matching snapshot with an explicit false actual prerequisite is blocked. A matching positive snapshot is supported and still grants nothing.
