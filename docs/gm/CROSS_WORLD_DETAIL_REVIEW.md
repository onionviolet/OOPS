# Cross-world detail review reference

2026-10-12. **Status: proposed authoring reference, document-checked; all gameplay cases specified-not-run.** Human authority accepts the cross-world review direction in the [rulebook precedent](../RULES_FROM_SCRATCH.md#cross-world-audit-precedent-special-rules-and-little-details-2026-10-12). The families, record extensions, examples and sequencing below are agent proposals. They accept no world mechanic and authorize no implementation. The twelve accepted rules remain the authority.

A small detail matters when it changes an actual choice, function, belief, relationship or later cause. A clean apron can remain description. A cleaned instrument matters mechanically when a selected test consumes its cleanliness. An extraordinary method can solve the whole problem outright. This reference does not require compensating fatigue, scarcity, decay, paradox damage, institutional resistance or power ceilings.

## How to reuse this reference

Use the world's existing brief and detail ledger. Reference IDs CW01–CW36 identify review families, not engine features or player-visible discoveries. Several families may map to one local detail; one family may expose several existing details. Do not replace earlier IDs or create one subsystem per row. Map selected details to [S00–S14](../WORLD_COMPLETION_STANDARD.md#sections), with one primary owner and explicit joins.

1. **RW1 Select and qualify.** Read the current world authority and source boundary. Choose relevant families for the represented region/era/start, mark the rest deferred, source-gap or not applicable with a reason, and retain the wider horizon. Missing adapters are missing work, not evidence that a family is irrelevant.
2. **RW2 Bind details.** Give each meaningful local leaf a stable ID, owner, source/premise status, read scope, choice, actual consumer, knowledge route, causal join and observable case. Extend existing records only where needed. Keep truth-bearing fields in sealed/private owners.
3. **RW3 Prioritize joins.** Start with an existing choice whose result feeds another existing activity. Rank contradictions, lost means, altered causes and durable consequences before decorative tracking. Select a finite connected slice without deleting later starts, endings or disciplines.
4. **RW4 Integrate specialists.** Delegate only named uncertainties with disjoint outputs when authorized. The world GM reconciles source versions, clocks, body/person identity, actor knowledge, resources and events; the shared integrator retains shared state authority. Inspect actual artifacts and dependencies rather than accepting completion messages.
5. **RW5 Update evidence.** Record source review, authored contract, inspected binding, source edit, build, browser observation, save/reload/import and director acceptance separately. Repair the affected criterion when inputs change. Close the finite reference/design packet when its document gate passes; selected gameplay still needs its own authorized packet.

A proposed compact local record extends the [rulebook record](../RULES_FROM_SCRATCH.md#reusable-detail-record): `local ID; CW families/S sections; selected version/era; claim kind + locator/read scope; competing explanation; actor means and choice; physical result; observer receipts; affected cause/consumer IDs; sole state owner or missing seam; disposition; criterion + evidence revision; next gate`. Use prose for small details; this is not a save schema.

Useful dispositions: investigated, source gap, authored proposal, selected work, deferred, not applicable with reason. Attach a separate verification stage and actual human acceptance reference. “Investigated” says nothing about implementation; “selected work” is not accepted lore. Do not use a single status to collapse these dimensions.

## Source admission and uncertainty

| Code | What is known | How to admit it |
|---|---|---|
| SA1 Shown effect | A particular event, target, result and context were read | Bind work/edition, scene/page or prepared-text locator and read extent. Do not infer a universal range, cost or duration from one occurrence |
| SA2 Stated explanation | A narrator, character, manual or institution explains a mechanism | Preserve attribution and reliability; distinguish a warning, a legal restriction and a demonstrated physical limit |
| SA3 Interpretation | A reader infers a model consistent with selected evidence | Name the inference, alternatives and counterexample to seek. A successful test can settle its local case without proving every case |
| SA4 Other continuity | Fan/AU, adaptation, game, later edition or companion source supports it | Keep its own source set and explicit admission decision. Shared names do not merge incompatible laws or hardware availability |
| SA5 Authored extension | The proposed game needs behavior the source does not specify | Label the exact invented parameter or outcome and its gameplay purpose. Missing detail permits a proposal, not a false canon claim |
| SA6 Unknown/outlier | Scope was unread, conflicting or uniquely exceptional | Record the unresolved boundary or exception. Unknown does not mean impossible; an outlier need not redefine ordinary operation |

For a local detail, separately ask whether the actor acquired a product, read a method, practiced it, can execute it, can teach it and can reproduce it at scale. These can coincide where the source supports it. Likewise separate ownership, custody, use permission and actual access without forcing all four to differ. A world's automatic copying, perfect recognition, unlimited production or freely shared knowledge remains possible when its selected mechanism provides it.

The tables below are **questions and original hypothetical cases**, not assertions about any franchise. Each uncertainty is a source/premise question for the receiving GM. Each case is a proposed observation, **specified-not-run**. The condition described in a case belongs to that hypothetical premise, never to every world.

## Six connected examples

These are original hypothetical design probes with declared local premises. They are not lore evidence, accepted mechanics, engine capability claims or hidden future content. Each includes alternatives, a causal cut and an observation that could later verify the selected contract. All six are **specified-not-run**.

### CX1 A useful household repair

**Premise:** one household has a cracked kettle; a chosen repair method restores the vessel but does not create water. Families CW02/06/10/15/20/29/36, sections S04–S06/S10/S14.

Borrow tools, use a held repair method, pay a repairer or replace the kettle. Record actual kettle custody, damage and result; preserve the actor's observed evidence separately. A repaired kettle enables this household's tea service. A guest who actually receives tea can attend the scheduled conversation; other guests need their own invitations and routes. The repair does not establish a village-wide service, friendship score or restored missing contents.

**Causal cut:** if the guest never receives the invitation, repair does not cause attendance. If a selected full restoration method creates water, this is a different supported means, not a forbidden shortcut. Texture such as the kettle's color remains text unless a real consumer reads it.

**Acceptance probe:** repair changes the kettle's usability; water stock changes only through the admitted operation; the particular guest response follows witnessed hospitality. Repeat/reload does not duplicate custody, consume tools twice or grant repeated first-service rewards. Native consumer and save fields are **to inspect if selected**, not established here.

### CX2 A potion batch becomes a particular service

**Premise:** an original setting has a defined remedy with a prepared base, recipient-specific final step and an actual assessment method. No franchise recipe is implied. Families CW04/09–14/16/18–20/25/28/30/36, S04–S11/S14.

Prepare or buy admitted ingredients, request a bench, choose a known procedure, obtain supported help, test within the instrument's scope, divide actual portions and offer one to a recipient whose requirement and relevant body compatibility are known. A successful manufacture and a suitable treatment are separate claims. Buying a finished remedy can resolve the same need without manufacturing mastery. The recipient's improved condition may let them staff one planned ferry departure. A delivered message and actual ferry capacity then determine who travels.

**Causal cut:** changed color alone does not establish treatment; untested portions retain their proper uncertainty. One successful dose does not create demand, trained workers, region-wide supply or universal health. A source-supported flawless or instant process may bypass the preparation uncertainty, with its actual output entering the same consumers.

**Acceptance probe:** batch/base/portion identities, sample allocation, observed test scope and delivery settlement stay coherent through cancellation and save/reload/import. Only the relevant recipient condition and dependent departure change. Procedure timing, dose behavior, injury and storage remain explicitly authored/source-gap fields until qualified. A remedy produced correctly but incompatible with this recipient does not count as the promised service. No current native batch support is claimed.

### CX3 A disguise meets a record and a witness

**Premise:** a temporary appearance effect copies face and voice but not memories or personal authority; a gate clerk uses a face check and a separate work order. Families CW01/02/21/23–25/27/29/36, S02/S04/S09/S10/S14.

The actor may disguise, seek sponsorship, obtain legitimate work access or disclose their purpose. The disguise changes the body presentation consumer, not the person/controller record. A face-only witness may believe the apparent identity. The clerk can still request the order, and an actual message may later change their belief. Outfit fit follows the chosen body rule; no generic damage or social punishment is added.

**Causal cut:** one witness's suspicion does not inform all institutions. Expiry changes the baseline presentation once, not family history. A source-qualified soul detector or perfect impersonation would change this case's evidence boundary, not establish all-world recognition.

**Acceptance probe:** during and after expiry, body, equipment, controller, held order and each observer receipt remain separate; reload preserves the selected clock's remaining duration. Gate response uses that clerk's evidence. Source gaps include stacking, renewal and any memory-copy route; proposed native overlay and recognition bindings remain uninspected.

### CX4 Extra study in an overlapping interval

**Premise:** a selected temporal device permits a self-consistent overlapping interval and preserves its traveler's memories; it does not independently manufacture stock. Families CW10/11/19/24/29/31/36, S04/S06/S07/S11/S12/S14.

Use the device, use ordinary study time, seek a teacher or carry a written lesson. Device operation, experienced study duration, local calendar and the two temporal appearances are distinct records. The later appearance can study an actually available text; a teacher knows only the encounter they observed. A craft job progresses according to its chosen process clock and actual participants, not simply because the calendar label changed.

**Causal cut:** a witnessed anchor bounds this selected self-consistent model; no paradox punishment is invented. A mutable-history device is a separately admitted option. If a source supports genuine object copying or instant memory download, model that mechanism explicitly instead of treating it as save duplication.

**Acceptance probe:** restore the declared overlap, reconcile borrowed book custody at reunion, retain the actual lesson and account for exported results. A supported mechanism may duplicate objects, but repeated loading must not multiply them beyond that mechanism. Temporal identity, rollback, event receipts and persistence need a dedicated future engine audit; generic timers prove none of them.

### CX5 A small intervention changes a meeting and a later institution

**Premise:** a natural-course meeting requires a courier, a delivered notice and a particular available teacher. Families CW04/19/21/25/28/30/32/33/36, S01/S04/S05/S09–S11/S14.

Repair the courier's equipment, send the notice another way, warn the teacher, refuse to intervene or pursue another goal. A successful equipment repair changes the represented departure cause; timely notice can change the teacher's plan; an actual lesson can let a learner execute a method. That learner may later demonstrate it to a local workshop. Wider adoption requires the chosen diffusion means and recipients, which can be exceptionally fast if supported.

**Causal cut:** timely arrival does not guarantee agreement. If the teacher declines, the lesson does not occur; another genuinely motivated actor can offer it without being manufactured merely to restore canon. Later marriages, births and organizations are reevaluated only when their represented prerequisites change. Unmodeled downstream history remains unresolved, not forced back onto a canonical ending.

**Acceptance probe:** save event occurrence separately from source expectation and each observer's receipt. Compare intervention, failed intervention and abstention for this same scope; only affected dependent plans change. Verify an era-late start's actual teacher/resources rather than granting future research knowledge to earlier actors. Historical causality and downstream cast support remain future binding/source gates.

### CX6 A workshop, an heir and a returning traveler

**Premise:** a maker leaves a manual, a device, a workshop agreement and a willing apprentice. The selected crossing carries the manual and device; the origin world freezes during absence; a receiving heir has their own body and prior knowledge. Families CW01/10/17/19/22/24/26/29/33–36, S02/S04–S07/S11–S14.

Entrust the shop, finish an order, negotiate its continuation, depart or stay. At a destination, use the admitted device, hire a compatible operator, adapt the interface or commission an equivalent. Reading the carried manual supplies its actual information; mastery or supply-chain reproduction requires actual means unless a supported carrier transfers it outright. Back home, succession transfers what survived through actual claims, not a canned one-lesson inheritance.

**Causal cut:** a freeze policy does not silently finish the apprentice's order. An advancing-world policy is a separate selected option with actual duty/time rules. A copy of the maker need not control the heir, and affection need not transfer contracts. Unlimited retention is possible through an admitted carrier; loss is not a required balancing tax.

**Acceptance probe:** departure, missing-pack restoration, destination use, succession and return conserve the declared identities/claims and any explicitly supported copying. Reload/import neither silently changes the world clock nor rerolls the start. Native travel, legacy and cross-world item consumers must be inspected before a runtime packet; no changes to current heir behavior are claimed.

## Integration and proof worksheet

Use one selected detail's causal path to locate missing seams. The following worksheet is proposed review practice, not a new engine API or a demand for a complete source universe simulation.

| Join | What the world GM establishes | What a later authorized implementer must inspect/prove |
|---|---|---|
| Means → operation | Particular actor/body/method/tool/access supports selected choice, including strong bypasses | Actual reachable caller, target validation, commit/cancel ordering and failure policy |
| Operation → object/service | Exact affected object, quantity, function or condition; ordinary versus exceptional copying | Sole mutable owner, applicable stock/reservation accounting and actual downstream consumer |
| Result → observer response | Who senses, receives or learns which evidence and why they respond | Actor-safe UI, records and response handler; no hidden-truth leakage or omniscient global rumor |
| Response → history | Which plan/event prerequisites changed, unaffected events and unresolved horizon | Actual cause/event/instance binding and durable occurrence receipts; no forced canonical replacement |
| History → continued play | Which closure, body, carrier, claim, project or alternate start survives | Supported continuation plus compatibility/old-save/missing-pack policies and save/reload/import journey |

For any selected case, write `entry action → committed change → downstream visible consequence → interruption/alternative → restoration`. Name revision and the actual observed result. Hypothetical walkthroughs refine a contract; they cannot close a browser gate. A tooltip, metadata field or test-only caller cannot establish an executable native consumer. This packet did not inspect current engine files, run source tests, build, use a browser or touch saves.

The reference-level gate is finite: source-neutral inventory with explicit uncertainties and six causal probes, usable local integration workflow, valid owner links, preservation of accepted rules, and private/sealed exclusions. A world may use a smaller selected subset without being judged against all 36 rows as mandatory gameplay. A later delivery names its own remaining authoritative playable gate rather than advertising a checklist percentage.
