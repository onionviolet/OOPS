## Record contract v1

Endpoint is exactly `{worldId,instanceId,regionId,layerId}`; references are compared across all four fields. Key generation uses an ordered JSON tuple, avoiding delimiter or object-property-order aliasing. Display names are not endpoint identity/knowledge.

Connection: `{schema:1,id,revision,from,to,kind,controllerId,open,bidirectional,openedAt,expiresAt,lifetime,duration,requirements,costs,openingCosts,chronology,layerPolicy,cargoPolicy,observationPolicy,flows,closure?}`. `kind` is `physical|view|projection|manifestation`; times use the supplied nonnegative integer played clock. `lifetime:null` is an explicitly permanent access policy, not immortal residents. Finite lifetime must be positive. Requirements and actual binding checks still apply to permanent access.

Receipt invariants now enforce that expiry is exactly the actual opening plus the declared finite lifetime, or null for permanent/unopened access. Overflow rejects. A closure belongs to a closed, previously opened route, follows that opening, and an `expired` closure must follow its actual lease. Previously opened closed records need a closure receipt. These checks accept records produced by the current open/close planners; they reject inconsistent prototype records without inventing or migrating private save data. Engine must separately require an open bound return route for an active conventional Glasshouse visit, since that fixed native slice supplies no alternate exit.

`realmConnectionBinding` takes a validated **trusted authored** connection and clones its static fields: schema/id, all four endpoint fields, kind/controller/direction, lifetime/duration, requirements/costs and every operating policy/flow. `validateRealmConnectionBinding` validates the loaded route and compares that complete static contract with normalized object-key ordering; arrays retain their authored order. Revision/open/openedAt/expiresAt/closure remain mutable receipts. Never derive the expected binding from the loaded route itself. A fixed one-coin/immediate native publisher must reject different costs, duration or endpoints until it implements those variations. JSON validation also rejects hidden/non-enumerable properties, accessors and unsafe keys before cloning or canonicalizing.

Boundary rule: `{id,revision,operations,bodyForms?,sourceId?,methodId?,authorityId?,anchorId?,costs?,exceptions?}`. Exception: `{id,sourceId,methodId,operations,bypass,bodyForms?,costs?,duration?}`. Supported bypasses are `operation/source/method/authority/anchor/closed/expired/direction/layer/observation/route_cost`. An exception must be deliberately selected and backed by an actually owned active unsuppressed source with that operation, acquired method and supported current body form. It cannot bypass life, actual reserve, complete cargo, existing destination or free arrival-position requirements. Zero-cost/zero-duration superior sources stay zero when the authored exception declares them; no plane-rank conversion or equalizing fuel tax.

Context: actual `{actorId,sequence,clock,endpoint,life,body?,busy?,methodIds?,authorityIds?,sources?,resources?,anchors?,knownBoundaryIds?,knownConnectionIds?,evidence?,bindings?,cargo?,cargoComplete?,presenceIds?,observation?,contact?}`. Body is `{id,revision,form}`. Source includes `{id,revision,ownerId,owned,active,suppressed,operations,bodyForms,availableAt?,expiresAt?,sharedPresenceSupport?}`; resource is `{ownerId,resourceId,amount}`; anchor is `{id,revision,available}`. Context is a host-derived authoritative snapshot, not player-supplied booleans or registry metadata posing as actual means.

Binding is `{endpoint,available,positions:[{id,free,bodyForms}]}` for a **supplied existing** endpoint; these modules do not establish that its native state is isolated. Native return position/contact must be measured by the host. Passage consumes neither body nor cargo; it emits movement references to current owners.

Cargo snapshot is `{itemId,ownerId,holderId,classId,count,equipped,transferable,authorizedConnectionIds}`. Physical passage requires `cargoComplete:true` and the full held manifest. A caller cannot omit forbidden stock while moving its body; deposit/transfer it first through real owners. Borrowed cargo needs the exact connection permission. Policy `{allowed,maxUnits,allowEquipped,classes}` uses finite count units, not implemented mass/volume/container physics. Projection/material manifestation admits no carried-stock duplication in this version.

Observation is an actual active receipt `{id,connectionId,connectionRevision,subjectId,observerId,active,disclosure?}`. Detection needs that specific subject/link; identification additionally requires a recipient-qualified disclosure or a registered identifying source under `identification:"qualified_source"`. Detection alone provides no name, biography, contact or bodily passage. Contact additionally needs `{id,actorId,targetId,connectionId,connectionRevision,targetEndpoint,validThrough,channel}`; channel is `touch|impact|material_signal`. An endpoint label alone is not contact.

Evidence is `{id,recipientId,at,kind,text,boundaryId?,connectionId?,boundarySnapshot?,connectionSnapshot?}`. Kinds: observation/report/recollection/inference/instruction. Optional snapshots contain witnessed revision and (for connection) open status. Public views retain observation time and remembered snapshot; they do not silently refresh state while elsewhere or disclose private source/anchor/authority diagnostics. A newly local sighting must first supply actual evidence through the host. A remembered rule is not present certainty.

Request is `{expectedSequence,expectedRevision,operation?,direction?,exceptionId?,arrivalPositionId?,cargo?,presenceId?,reason?}`. Operation defaults to the connection's declared kind; direction forward/reverse refers to exact endpoints. A manifestation/projection needs a fresh presence receipt list and source-owned shared-presence support. It references one existing actor/body/resource ownership graph, without acquiring faculties, independent minds, resources or held weapons.

## Plan and effect order

Every planner returns JSON `{schema:1,connectionId,connectionRevision,expectedSequence,operation,allowed,reasons,costs,duration,arrival,effects,guards,cause,unsupported}`; successful open/close also returns `nextConnection`. Invalid JSON/schema references throw; unsupported circumstances return disallowed reasons and no arrival/effects. Preview does not debit, disclose knowledge, update a route or advance a clock.

1. Host reconstructs actual context and validates request sequence/revision, life/body/source/method/authority/anchor, origin/destination/chronology, physical cargo and contact/position.
2. Quote sums duplicate reserve debits before checking availability and permission. Opening pays opening fee plus actual boundary/source activation costs; passage pays route plus selected source-use costs. A `route_cost` exception waives only the declared route fee. The host must persist actual debits once at commitment; the module never decrements them.
3. Apply movement/view/shared-presence/interaction **after** its real support/costs are committed and, for timed use, the emitted resolution guard is freshly checked. Current simulation jobs do not implement those new checks automatically.
4. Apply the cause-bound use receipt and publish knowledge only to supported witnesses. Close/open replace only this route revision. Closure stops its admitted flows while retaining interior, residents, cargo ownership and old evidence; it performs no automatic extraction or collapse.
5. Persist the master's complete native/expansion plan before publishing body/location/inventory/route/UI state. `guards` and `cause` describe required host gates; they are not an implemented replay ledger or save transaction.

Current-time planning rejects future opening/closure receipts, stale sequence/revision, expired routes or source support that cannot last through the selected duration. Explicit actual source exceptions can bypass closed/expired route access while still needing an existing destination/body/position/stock. All `record/historical` chronology is explicitly unsupported; archive replay, later-to-earlier messages, branch rewriting, autonomous emergence and resurrection need different registered adapters.
