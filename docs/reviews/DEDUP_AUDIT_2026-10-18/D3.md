Compared against the src world modules (`book_world_mol_*`, `book_world_paradise_*`, `proto23_world_*`, `steam_*`, `feature_expansion_destination*`), `src/data/`, `src/seeded_streams.js` and the other src files the docs cite. ### D3-F2 (medium, rule-violation): sealed-secret ID format collides with ordinary local codes, and the sealed location the rule names does not exist

**Status: VERIFIED** for the collision and for the missing directories.

- `docs/worlds/WORLD_SECRETS_AND_DISCOVERY.md:118-125` tells agents to name secrets as "S1 to S4", "S2's Medicine route verified". The same short form is an ordinary local code elsewhere: `S1..S3` are source-reference rows in `docs/worlds/NONHUMAN_STARTS_ENGINE_SPEC_2026-10-14.md:331-333` (rows about `main.js` create_save, persistence, save migration), design rows in `docs/worlds/CONTINUATION_CHOICE_CONSIDERATION_2026-10-13.md:102-104`, `docs/worlds/SELF_AS_PLAYER_LORE_CONSIDERATIONS_2026-10-13.md:213-215`, `docs/worlds/VILLAIN_STARTS_AND_OTHER_SELVES_2026-10-14.md:208-210`. A report line like "S2 verified" is ambiguous, and a grep for a sealed ID returns unrelated rows. Also `S2` means "INTERFACE revision S2" in `docs/worlds/original-frontier/ABILITIES.md:38`.
- The standard rule says original-world sealed notes live in `docs/worlds/<world>/sealed/` and a sealed data file beside the world's content in `src/`. No such directory exists under `docs/worlds/` and no sealed data file exists in `src/` (checked with find and grep; the only `sealed/` paths are `docs/gm/dispatch/procgen-2026-10-13/p5/sealed/` and `docs/research/novels/jojo/audit-2026-10-11/SEALED_C2_DESIGN.md`). `.gitignore` has no sealed rule. So the rule currently has no registry of real secret IDs, and I could not check any ID against anything.

Why it matters: the rule protects against leaks by ID, but IDs are not unique or registered. Cannot audit.

Minimal fix: define the format `<worldId>:S<n>` (for example `reference.proto23.village:S2`) in `WORLD_SECRETS_AND_DISCOVERY.md` (single owner) and add one line saying where the registry actually is (or that none exists yet). No other doc needs a change.
