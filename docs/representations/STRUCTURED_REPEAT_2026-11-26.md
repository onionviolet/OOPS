The old projection offered three climbs because every non-once timed action was called repeatable. The first climb moved the player away from the required house location, so another climb could not follow immediately. The fix keeps `repeatable` for future reuse and derives `queueRepeatable` for consecutive dispatch. It changes no authored source definition, once-ever flag, saved identity or native pending-work format.

The [pure forecast](../../src/structured_queue_repeat.js) suppresses a queue when unconditional self-relocation ends away from the action’s required place, or literal actor-fact writes prove its next requires/visibility predicate false. It uses the existing rule evaluator’s unknown semantics without full fact copies or simulated effects. Outcomes, dynamic values and unsupported effects retain the previous eligibility rechecks; this is a bounded forecast, not a promise about unknown future circumstances.

The actual session-queue dispatch boundary in [the structured panel](../../src/structured_pack_ui.js) handles both row and Here requests. It limits a stale repeat request to one action when the current quote cannot queue, then rechecks before scheduling another run. The main action host already commits a single native command and does not forward times as a batch. Single actions, returning and later redoing an action remain available. [The runtime projection](../../src/structured_pack_runtime.js) supplies the qualifier; no Fang domain operations changed.
