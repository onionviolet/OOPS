# Area guide: which established abstraction do I use?

Navigation for implementing agents. It creates no rule, no code family and no new seam. Rule codes are pointers to [RULES_INDEX](RULES_INDEX.md), the seam counts live in [SEAM_REGISTER](SEAM_REGISTER.md), and the engine, world port and world data pattern is in [CROSS_WORLD_SYSTEMS_TRANSFER](CROSS_WORLD_SYSTEMS_TRANSFER.md).

Date: 2026-11-09. Built from a read of the source at the current working tree by one coordinating reader and five sub-readers; every backticked file and function name was then checked by a second script (1,154 names, all found except one shorthand and one name listed as not a file). "Only" in this guide describes what the code does today, not a design limit. Nothing was run: no test, build or game session. Function and file names were checked by grep against `src/` and `tests/`.

By default a new slice declares data through the seam named here and does not add a parallel module inside a story-window file (AR11, AR14). Keep this guide current in the same change that alters a seam's entry points. "Not established" means a few minutes of reading did not settle it.

## People and ties

- Use this: `person_ties.js` (five tie kinds as relationship axes, rule facts, offers); native `relationship` effect in `simulation_effects.js` (the one edge store); `person_memory.js` + `person_memory_effects.js` (episodes, derived bond, reaction lines, gossip; world-neutral); `people_knowledge.js` + `people_sources.js` (what the player knows about people); `recurring_people.js` (a named role promoted to a real person at first durable reference); `person_standing.js` / `person_loyalty.js` (derived reads over episodes).
- Declare: `registerWorldTies`, `registerPeopleSource`, `defineRole`, `installRoleDefinitions`.
- Write: `tieEffects` (returns relationship + observation-note effects, apply through `applySimulationEffects`), `tieOfferCommands`, `tieOfferEffects`, `promoteRole`; memory is written by the engine: each `relationship` effect pushes `plan.memoryEffects`, which `memoryForPlan` (called in `expansion_persistence.js`) turns into episodes via `rememberEffect`.
- Read: `tieValue`, `tieFacts`, `tieShownView`, `tieOfferView`, `knownPeopleView`, `carriedKnowledgeView`, `peopleSources`, `derivedBond`, `reactionLine`, `bondTotal`, `recalledPhrase`, `readMemories`, `standingView`, `standingLines`, `loyaltyOf`, `debtOf`, `roleDefinitions`, `roleRegistered`.
- State: `simulation.relationships[holder][subject].axes` (edge, written by the `relationship` effect, with per-cause receipts); `person_memory` slice via `createMemoryDomain` in `domain_registry.js` (written by `remember`, `flagSilence`, `addClaim`, `mergeImpression`); knowledge in `simulation.knowledge.player`. Ties, standing, loyalty add no store.
- Copy: `src/book_world_lotm_colleagues.js` (`LOTM_TIES` plus the expense-claim function that calls `tieEffects`); HP: `src/world_packs/book_hp_lead_life_data.js` (`HP_LEAD_TIES`, `hpLeadTieCommands`); people rows: `src/book_world_hp_people_source.js` `registerHpPeopleSource`; role: `src/book_world_lotm_constables.js` `promoteConstables`.
- Test: tests/person_ties.test.js, person_memory.test.js, person_memory_effects.test.js, people_sources.test.js, people_knowledge.test.js, hp_people_source.test.js, recurring_people.test.js, recurring_colleagues.test.js, person_silence.test.js, person_memory_persistence.test.js.

- Do not: `generated_people.js` (village travelers with seeded asks, original game via main.js; not the cast seam) and `npc_lives.js` (Village household yearly lives, its own bond statuses) as a base for book-world people.
- Competing: yes. Three parallel person stores exist: `simulation.relationships` (ties), `person_memory` (episodes, read-derived bond), and `bondStatuses` in `npc_lives.js` (Village family); `relationship_view.js` / `relationship_web_view.js` read them separately.
