## 2. Subtle aspects the built version flattens

- **Famine passivity (Food benefits and Famine, 10-13).** He wanted starvation XP to be very hard but never gated, and passive progression considered "across applicable systems". Built Famine is a flat 0.01 XP per underfed minute (`src/absorb_p23/exposure/exposure.js`); no one audited other systems for passive paths.
- **"Both, depending on the world" (JJK Q1-Q5, 10-10; Power scale clarification, 10-02).** He answered era, scope and identity questions with "all possible". Built rules mostly implement one default per feature (one start kind, one hub topology), not a per-world dial.
- **Meaning of "keep it that way for now" (Center menu, 10-02).** The center menu was explicitly temporary; the workspace replaced it. Any text still assuming center-menu primacy is stale.
- **Hanzi field was endorsed, then questioned for complexity (10-02, four entries).** He liked it but asked repeatedly whether it was necessary. The repo has neither the glyph view nor a recorded decision to drop it; `src/ui/walk_map.js` is an unrelated ring figure.
- **Quiet, discoverable specialness (JJK, "I won't know what's special about myself until uncovered").** Built cheat status windows and sealed secrets cover this for cheats, but hidden-strength NPCs (village chief) and appraisal gates are absent, so the 10-02 "attack the chief and he turns out super strong" moment cannot happen.
- **Simplicity as a requirement (Ability coverage, 10-13).** "Don't make it too complex", "a list, not a programming language", and depth levels D0-D4 were stated as conditions on the habits idea. The built `everyday_life.js` habits are routines, and the D0-D4 ladder is unbuilt, so the optional-depth promise has no implementation to honor.
- **Vague wording on purpose (Notebook overlap, 10-03; Discovery-aware menus, 10-03).** He asked for vaguer discoveries and for menu content to appear only when it comes up. Built People view follows this; the planned World/Factions catalogue is intentionally absent, which is correct, but wording acceptance is pending.
- **Means decide on both sides, including enemies (Text VFX, bluffs, knowledge and means, 10-10).** "Enemies would not have access to logs unless they do", and appraisal levels and types. Enemy knowledge via means is in AD6, but the bluff idea (faking an unknown ability) has no mechanism, though he called bluffing in general "a good idea".
- **Effects scale with the character (JJK, "a god looking at the screen").** He wanted outrageous UI-breaking effects reserved for god-level characters, few, and relative to capability. The built presentation layer only has the restrained skill cue (`src/native_discovery_feedback.js`).
- **Mastery beyond creator is a relative comparison, not a level (Mastery beyond Advanced, 10-02).** He said base it on books but also on rarity and other differentiators; the built mastery systems are per-world proficiency, with no comparison to a creator or known frontier.
