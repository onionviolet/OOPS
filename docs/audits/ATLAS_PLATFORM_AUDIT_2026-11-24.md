# Atlas platform audit, 2026-11-24

Recommendation: extend the existing atlas DOM/SVG canvas for bounded aggregates, with addressable row pages and shared pure UI components. Do not make the game figure renderer or shell inspector the atlas platform. Sigma is the runner-up if measured visible graph density exceeds the bounded renderer's budget.

This is a critical review by the assigned Codex lane, not an additional independent model vote. Recommendations remain proposals under AD32. The brief's newer instruction permits departing from the reference appearance; it overrides UR177's picture-matching requirement for this atlas exercise, not the game's general design rules.

Scope: rounds 3–4 of the [platform note](../reviews/WORLD_ATLAS_PLATFORM_2026-11-24.md), including every R5–R18, T1–T4, FR1–FR6, L1–L3 and DC1–DC4 item, the Fold and the implementation path. The [ideaboard](../research/WORLD_ATLAS_IDEABOARD_2026-11-22.md#implementation-workspace-proposal-2026-11-24) remains the plan owner. No runtime or owner document was edited.

## Canvas choice

Choose **T1 plus T4: a bounded DOM/SVG aggregate viewport and lazy row pages**, preserving an adapter boundary so a dense renderer can replace the viewport later. This is a workload-based engineering recommendation, not a measured claim that DOM beats WebGL. The user needs to find a blocker, inspect its canon evidence, and hand a concrete change to an owner. Rendering every ledger row simultaneously does not improve that route.

### Bounds that make the recommendation credible

**C1 Data before rendering.** Build small world/kind/blocker aggregates and a ledger-scoped lookup index. Fetch a selected page of rows on demand. Keep the 33.9 MB raw ledger text out of the initial client payload. Cache against input hashes; report unavailable/stale sources. Refresh preserves selected ID, filters, camera and open folds, or explicitly says a row disappeared. Do not send private source text or developer truth to a player projection and then hide it with CSS.

**C2 A visible workload budget.** Proposed first qualification envelope: at most 250 visible aggregate nodes, 500 visible edges and 100 mounted result rows. These are starting test bounds, not accepted product limits. Collapse additional relations by type and retain searchable row access. Cache edge geometry after layout and use simpler routes for dense views. Keep camera updates to transforms/requestAnimationFrame rather than reconstructing records. Raise the envelope when measurements support it.

**C3 Browser acceptance before technology lock-in.** On the intended older 8 GB laptop, measure initial usable time, peak process memory, p95 pan/zoom frame time, selection latency and repeated open/close/refresh growth at 1920×1080 and 1280×800. Proposed interaction targets: p95 frame below 33 ms and row selection below 100 ms after data arrives. Exercise empty graph, keyboard focus after culling, Back/Esc, disconnected/offline operation and resize. Include data search/parse separately from draw time. No current target-hardware claim is made.

**C4 When Sigma wins.** If the useful task requires thousands of simultaneously visible relations and the bounded DOM/SVG version misses the agreed interaction budget after culling and route caching, test pinned Sigma on the same dataset and hardware. Keep the same row IDs, selection model, token roles and HTML inspector. GPU speed does not solve an unbounded layout/search pipeline or observer leaks. Cytoscape becomes preferable if graph analysis/compound editing, rather than viewing, is a required first task.

**C5 Existing owners stay authoritative.** Canon evidence belongs to readers and source locators; case schema to the runner/validator; mechanism work to the foundation queue; player discovery to runtime observation; delivery proof to task receipts. The atlas joins them with explicit many-to-many mappings. The existing 81 repeated bare IDs make this an immediate requirement. A name match stays inferred and does not become a canon citation or a game binding automatically.

## Ranked decisions for Weibao

These are proposed defaults to record through existing owners, not requests to repeat authorization for this audit.

1. **D1 Adopt the corrected evidence ladder.** Keep case success, module reachability, player-action proof and persistence proof as separate fields. This prevents the atlas from promising play that does not exist.
2. **D2 Use T1 + T4 for the first slice.** Gu ledger page, aggregate blocker map and row detail, using existing tokens/components; Sigma remains the measured fallback. Do not precede this with a figure-system rewrite or full grammar rebuild.
3. **D3 Keep engine-only foundation waves valid.** Reject FR2 as a universal gate; tie-in waves report player outcomes, engine waves report held-out capability and a named future consumer.
4. **D4 Make atlas writeback a candidate handoff.** Include composite row ID, source hash, proposed change, owner, scenario and diff. Adoption follows existing owner review and user authority; the atlas does not silently edit runtime or live packs.
5. **D5 Fund a bounded hardware qualification in implementation time.** Agree on a visible workload and measure it before replacing the renderer. This audit spent no reading credits or paid API budget.
