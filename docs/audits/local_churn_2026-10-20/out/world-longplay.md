# world-longplay: Implementing entire worlds end to end (everything between a source book and a playable, finished world) / what breaks, repeats or goes stale after ten hours or ten idle in-game years

1. Dynamic NPC Memory Drift
Default NPC interactions should reference the player's past actions rather than resetting to a neutral state after long periods of idle time. A builder would check this by running a simulation where the player ignores an NPC for ten in-game years and then returns to see if the dialogue acknowledges that gap. Effort M.

2. Resource Depletion Recovery
Default resource nodes should regenerate or find alternative sources so that long-term idle play does not result in permanent economic stagnation. A builder would verify this by pausing the game for a long duration and checking if the world's economy has recovered or shifted to new supply chains. Effort L.

3. Stale Quest Loop Detection
Default quest systems should detect when a player has completed the same type of task repeatedly and offer new variations or endgame content. A builder would test this by completing a hundred similar quests and observing if the game suggests new objectives or increases the stakes. Effort M.

4. World Event Fatigue
Default scheduled world events should vary their frequency and impact to avoid feeling like repetitive background noise after many in-game years. A builder would measure this by logging event triggers over a long simulation and checking for patterns that feel monotonous to the player. Effort M.

5. Lore Contradiction Accumulation
Default lore updates should flag conflicts with older established facts when new content is added to prevent long-term narrative incoherence. A builder would check this by running a consistency audit on a world that has received multiple content updates over time. Effort L.

6. Player Agency Erosion
Default decision points should remain meaningful even after the player has made hundreds of choices, ensuring that later decisions still affect the world state. A builder would verify this by making a series of choices and then checking if a late-game decision can still alter a major outcome. Effort L.

7. Idle Reward Diminishing Returns
Default idle mechanics should adjust reward scaling to keep long-term accumulation engaging without breaking the game's economy. A builder would check this by simulating ten years of idle time and analyzing the rate of reward acquisition over that period. Effort M.

8. Cultural Evolution Stagnation
Default societies should evolve their culture, laws, and norms based on the player's influence over long periods to prevent a static social environment. A builder would test this by observing a faction's behavior after the player has interacted with them for a long time. Effort L.

9. Technical Data Bloat
Default save files should compress or archive old data to prevent performance degradation as the player's history grows. A builder would check this by loading a save file from a very long play session and measuring load times and memory usage. Effort M.

10. Discovery Fatigue
Default map exploration should introduce new mysteries or hidden areas as the player masters the current map to prevent the world from feeling fully known. A builder would verify this by exploring a map thoroughly and checking if new points of interest appear or change. Effort M.

11. Character Growth Plateaus
Default character progression should offer new challenges or goals once the player reaches the maximum level or skill cap. A builder would check this by maxing out a character and seeing if the game provides new ways to improve or specialize. Effort S.

12. Narrative Relevance Decay
Default side stories should update their relevance based on the current state of the main plot to avoid feeling disconnected after long play sessions. A builder would test this by starting a side story early and finishing it much later to see if it still makes sense. Effort M.
