# dlg-legibility: Dialogue: voice, knowledge-aware lines, barks, rumor, reactions, refusal, return visits / what the player can see, inspect, trust or be confused by on screen

1. Visual distinction between rumor and fact
The screen lacks a clear visual marker to tell the player if a spoken line is verified knowledge or hearsay. A builder would add a color code or icon next to dialogue lines and test if players can sort truth from fiction quickly. M

2. Clarity of refusal reasons
When a character refuses to speak, the interface does not show why the refusal happened. A builder would implement a tooltip that appears on refusal and verify that it explains the blocking condition without breaking immersion. S

3. Inspectable knowledge state
The player cannot easily see what a character knows versus what they do not know before speaking. A builder would create an inspection panel that lists known facts and check if it updates correctly after new information is shared. M

4. Visual cue for repeated lines
The screen does not clearly indicate when a character is saying the same thing as before. A builder would add a subtle fade effect for repeated text and confirm that players notice the lack of new content. S

5. Return visit visual state
The interface fails to show if a character has changed their mind or mood since the last visit. A builder would add a status indicator above the character portrait and test if it accurately reflects current attitude. M

6. Interruption feedback
The player may not realize if they have interrupted a conversation or if the conversation has ended naturally. A builder would add a distinct end-of-scene animation and verify that it triggers only when appropriate. S

7. Voice style consistency
Different characters may use text styles that look too similar to distinguish easily. A builder would apply unique font weights or spacing per voice type and observe if players can identify speakers without names. L

8. Rumor propagation trail
The screen does not show how a rumor moves from one character to another over time. A builder would create a map overlay showing rumor spread and check if the path matches the logic of the world. L

9. Reaction timing delay
The visual delay between a player action and a character reaction may feel unresponsive. A builder would measure the lag in milliseconds and ensure it stays under a comfortable threshold for idle play. S

10. Trust level indicator
The player has no visible meter to gauge how much a character trusts them. A builder would add a trust bar that changes with interactions and verify that it aligns with dialogue availability. M

11. Knowledge gap visualization
The interface does not show what information is missing from a character's perspective. A builder would highlight unknown topics in a list view and test if players can identify gaps in the narrative. M

12. Scene exit clarity
The player may be confused about when a scene is truly finished and they can leave. A builder would add a "scene complete" banner and confirm that it appears before the return to idle mode. S
