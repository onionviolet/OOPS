## Proto23's handoff after a win

The [published Proto23 HTML](https://23html.github.io/) awards XP and drops in the enemy-death handler. While a fight area still has enemies, it calls `area_init`. At the end of a finite area it logs “Area cleared”, calls the area's `onEnd`, and exits combat. Some `onEnd` handlers advance a story scene or return to a training menu. The base handler is empty, so the next destination belongs to the area. The shared win path has no victory page or required Back press. The earlier [END3 proposal](../gm/dispatch/play-surface-2026-11-14/PROTAGONIST_WALKTHROUGH_UI_ELEMENTS_2026-11-20.md#how-the-fight-ends-what-yair-and-proto23-do-and-where-end1-to-end11-2026-11-22) already describes an immediate return for OOPS. The current local trial still holds the compact verdict until Back.

- **END3 follow-up · Return on settled outcomes.** A completed wolf hunt returns to its owning place with the final exchange and loot in Reports. If the encounter's state has a live aftermath decision, keep that choice in the center. If the same encounter is continuing, show the next opponent in place.
- **Handoff check.** A rapid repeated combat input must not activate a newly displayed place action. Verify where focus lands and whether the return preserves the initiating row and scroll when it still exists. Opening a prior report stays a free inspection.
- **Idle check.** Test a single hunt, a continuing pack and a pending person outcome. An automatic handoff can return the interface without beginning a new hunt. Send summary and loot once through Reports, including on reload. Defeat destinations stay with the encounter's rules.
