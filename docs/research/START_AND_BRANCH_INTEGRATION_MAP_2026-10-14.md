## 2. IR2 fact namespace options

**VERIFIED mismatch:** the pure graph permits arbitrary fact values, add/unset and `{knows, fact, eq}`; its knowledge stores `{value, channel, at}` and reveal lists (`WT:src/anchor_snapshots.js:26-32,47-66,134-157`). Native simulation facts are scalar actor/world/campaign/journey effects. Native knowledge requires a stable key, textual value, `seen|interpreted|understood` stage, played timestamp and cause, with optional validated basis; stronger knowledge is protected from weaker overwrites (`src/simulation_contracts.js:57,66,85,249`; `src/simulation_effects.js:281-284`). Runtime predicates expose scoped facts and character knowledge separately (`src/simulation_effects.js:109-113`). The two vocabularies are not interchangeable.

| Ref | INFERRED option | Fit, cost and failure mode |
| --- | --- | --- |
| O1 | Keep flat canon facts, explicitly project selected facts/effects into real owners. | Reuses pure derivation, lint, provenance and authored event order. Fits a registry of immutable definitions plus mutable native owners. Needs a typed binding table and occurrence receipts. Risk: two stores claiming authority over the same stock, body or quest. Prevent this by assigning each key one authority: graph facts for authored canon state; native owners for actual mutable gameplay; graph mirrors of native facts are read-only inputs or reconstruction checks. |
| O2 | Rewrite events to read native scoped predicates and emit native typed effects directly. | Reuses validated simulation requirements/effects and custody/resource rules. Reduces runtime projection ambiguity, but the current pure graph interpreter cannot execute those semantics. It needs a pure envelope reducer or a replacement derivation layer, historical owner fixtures and pinned native semantics. Arbitrary flat set/add/unset cannot bypass custody, body identity, claim uniqueness or XP publication. |

**INFERRED D1 recommendation: O1 with a strict typed adapter.** Keep source/canon records independent of DOM and native classes. Compile mapped runtime consequences into the existing effect vocabulary, using the structured registry's namespace/collision/reference checks. This advances OG1 toward one validated runtime vocabulary without claiming the modules already share it. Do not introduce a second general inventory, relationship or truth store.

**INFERRED knowledge binding:** keep machine-readable canon belief values private to the derivation domain when needed for `knows` equality. Map actual deliveries to `simulation.knowledge[actor]` only through an explicit value-to-text/stage/channel policy and real cause. Do not coerce a boolean into prose and pretend equality semantics survived. Native stage ranking and pure overwrite semantics also need an explicit reconciliation rule. Player-library knowledge belongs outside the character's ledger in the proposed profile. A revealed event is merely past its reveal coordinate; it does not prove this actor observed it. CX lenses must grant actual knowledge through an authorized observation route, not expose `snapshot.facts` or debug `explainFact` wholesale (`docs/INTRO_FLOW_CONSIDERATIONS_2026-10-13.md:1585-1604`).

**VERIFIED adjacent precedent:** the live causal-story core validates received knowledge and separates private truth from cumulative closure views (`src/causal_story_core.js:81-86,390-406`). Reuse that distinction; this bounded story subsystem is not evidence of a generic canon graph runtime.

## 3. IR3 clock binding

**VERIFIED:** native date uses 30-day months/12-month years; absolute biography minutes are a conversion, not a timer (`src/game_time.js:8-55`; `src/life_record.js:60-68`). Joined advancement computes consumed expansion minutes, advances the native calendar by that amount and publishes both (`src/main.js:1249-1270,7220-7237`). Instance clocks use played elapsed with freeze semantics; world views disclose elapsed only when known (`src/world_instances.js:271-282,310-340,407-427`). Local calendar adapters already exist, for example Mother of Learning (`src/book_world_mol_native.js:19-20,35-38,142-149`).

**INFERRED D2 binding:** persist a clock descriptor per authored branch: unit, canonical origin/anchor coordinate, joined-clock origin and, where relevant, instance identity/local elapsed origin. For a simple active world, `canonAt = anchorAt + (consumedJoinedClock - joinedOrigin)`; for a freezing visit world use its consumed local elapsed instead. Convert source calendar dates through a world-specific adapter. A source chapter number or fuzzy window is not automatically minutes. Resolve windows once from the pinned world revision/event ID/seed and preserve the resolution contract. Native `knowledge.at` remains a valid joined timestamp even when source occurrence time uses another axis.

**INFERRED D3 boundary policy:** reconcile due events at scheduler boundaries, including travel/sleep jumps. Preserve the pure ordering canon events, changes, inserted events at equal time (`WT:src/anchor_snapshots.js:68-80`). Declare how native completion/actor death at that minute interleaves with canon before implementation. A pause-before-important-event needs persisted pending status and a pre-effect stop, not a stop after the event already ran. `deriveIncremental` may cache ordinary forward progress; resets currently force full finite rederivation (`WT:src/anchor_snapshots.js:163-169`). Do not do full derivation or source JSON comparison on every rendered frame.

**VERIFIED report reconciliation:** the offline audit distinguishes callback progression from wall elapsed, general catch-up absence, narrow prepaid packing, frozen instances, supported observation leases and scheduler budgets (`docs/research/OFFLINE_TIME_AND_BRANCH_CLOCK_AUDIT_2026-10-14.md:19-32`). Current source still requests time through `update_timer`; Date.now is used for scheduling correction (`src/main.js:7286-7304`). **INFERRED:** first integration should use played time only. Do not derive login rewards from `saved_at`; resting branches freeze. General OT work is separately gated, with numeric wall cursor, cap/remainder, one recipient and rewards/cursor atomically committed. Pure loop reset restores graph facts/knowledge only (`WT:src/anchor_snapshots.js:85-109`); it does not reset native inventory, quests, paid jobs or bodies. Keep real-game reset disabled until an ownership-aware reset contract exists.

**INFERRED D4 home, consistent with save-shape P1-P5:** adopt a separately versioned outer profile as a future compatibility decision. Authored branch metadata holds pinned graph/pack revisions and hashes, base/anchor reference, resolved start recipe, hidden/revealed state, timed changes, clock binding and bounded derivation/receipt state. **INFERRED migration boundary:** secure exact legacy bytes first; wrap the complete existing state as branch one with a nullable legacy anchor and empty new player unlocks. Keep the actual current location, pending work, inventory, RNG, instances and dormant data. A biography is lossy and cannot reconstruct these owners. Unknown raw extras need declared preservation because normal serialization rebuilds fields. The adapter must unwrap the active native envelope before biography staging/native loading, then commit it together with profile metadata in one guarded root. Do not send an outer profile directly to `lifeSaveStorage` or split pointer and effects across independent mutable keys (`src/main.js:422-447`; save-shape report: `113-142`).

**INFERRED first release:** one inline branch/root, backup-first, no branch switching or new offline credit. Native/import transport must dispatch by explicit format/version before the existing actual-loader preflight; preserve native exports and strict content rejection (`src/save_files.js:158-191`; `src/main.js:7116-7128`). Legacy/profile writers need shared arbitration, since today's lease covers the selected legacy key (`src/main.js:605`). Pins cannot supply missing code. Valid unavailable branches need a preservation/recovery route; unsupported schema is preserved input, not executable content. Adding a canon subdomain under expansion instead is possible only with an explicit validator/migration contract; it would not itself implement the proposed profile/branch ownership.
