# Progression source lane

## What the code shows

The trainer is a real purchase path. `TraitTrainer` assigns one of seven skill categories from its explicit parameter or owner UID. Dialogue exposes training outside a user zone and subject to the inspected guild condition. The list excludes unused rows, handles guild-tagged skills by current guild zone, and otherwise filters by category. On click it computes the platinum price; `TryPay` rejects insufficient funds before any skill mutation. After payment, an existing skill calls `ElementContainer.Train` and raises temporary potential, while an unlearned skill calls `Learn` and adds base value. Cost is at least one, uses element-specific train/learn cost, applies the 80% modifier when element 1202 is present, and doubles guild-tagged costs below rank 2. Training at potential 1000 is unavailable. This purchase path does not directly award XP or a level; `ModExp` is a separate progression path. See [PROGRESSION.json](PROGRESSION.json) for precise source spans and hashes.

The gene machine is a staged trait/body progression path for eligible non-player faction members. It requires an installed, powered machine; selects an unhosted, unsuspended, living, default member in the current zone; and suspends that character. `InvOwnerGene` checks slot capacity, duplicate brain DNA, invalid feats and invalid actions before attaching the item and deriving a completion date from DNA duration. Once time completes, the machine checks that the gene's root card is the target, applies the DNA, destroys the item and releases the target. A failed root-card identity check skips the mutation but still releases the target. `DNA.Apply` can alter body slots, feats, abilities and learned/base elements, then refresh derived state. A DNA-added body slot is functional: `CharaBody.GetSlot` resolves equipment against body slots, and `IsEquippable` rejects missing slots. This is a game-source description, not proof of shipped-runtime behavior.

## What YAIR already has

YAIR separates native skill discovery from technique observation/ownership and execution eligibility. Its native adapter reads saved XP and the skill's actual visibility threshold without creating an XP record. Its optional body loop grants an inactive inherited aptitude that can be awakened, makes trained grip depend on two recovered drills, and makes an acquired palm mark result from actual rough-kit work. Both traits have actual capability or presentation consumers. Existing progression records also support explicit prerequisites, costs and mutually exclusive branches.

A useful candidate is an authored, paid mentor action that asks the player to demonstrate ordinary skill mastery, then offers one lasting specialization with a distinct use. For example, completing a prepared climb after conditioning could unlock either safer route preparation or faster packing. The action, threshold, branch and effect remain original proposals until the content owner binds them to concrete commands and capabilities.
