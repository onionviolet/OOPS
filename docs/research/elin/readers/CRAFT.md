# Elin reader: crafting, material, quality, and item function

See [CRAFT.json](CRAFT.json) for hashes, precise reviewed ranges, limits, and YAIR input fingerprints.

The connected path starts with `RecipeManager.BuildList` generating recipes from external source rows. `Recipe.Ingredient` holds both a requirement and a concrete selected `Thing`; its predicate validates categories/ids/origins and optional material tags. A malformed row can fail recipe construction: `RecipeManager.Create` removes that recipe and logs the exception. This is a row-local fail-closed exception, not a claim that all craft failures behave the same way.

`TaskCraft` is the queued-work caller. Each progress tick grants 20 skill XP. At completion, each craft resets required quantities, checks ingredients, splits and destroys required inputs, calls `Recipe.Craft`, then grants 200 skill XP. If validation fails, it reports `invalidCraftResource` and returns before later crafts, end effects, and stamina cost. `IsIngredientsValid` stages each split as it checks it; if a later ingredient fails, earlier splits remain in the task's `resources` list because cleanup occurs only after all checks pass. `PutOutResources` can put staged resources on the zone, but a repository-wide symbol search found no caller, so the subsequent fate is unresolved from this trace. This ordering deserves runtime confirmation before stronger claims.

`RecipeCard.Craft` uses the selected main material and skill-derived quality bonus to build a crafted item. Skill deficiency can turn a dish into a failed dish; the crude flag and quality bonus are carried through `CardBlueprint`. The resulting item receives ingredient mixing and its trait's `OnCrafted` callback before being held by the player. `GetQualityBonus` awards higher bonus with skill headroom and recipe level while a sizeable skill deficit produces a negative bonus.

Material and quality feed item function. `Thing.ApplyMaterial` applies the selected material's dice, attack, damage, dodge, and protection values to equipment elements. `Card.GetTotalQuality` combines item level and material quality, then scales by the item's quality; `Card.Power` consumes total quality. `CraftUtil.MixIngredients` also uses a gem ingredient's material hardness in a map recipe's range calculation. The source repository establishes these control-flow relationships, while the omitted external rows prevent reporting concrete Elin iron/steel stat values.

YAIR already implements a substantial parallel path. `ComponentRecipe` creates a typed component with skill/station-derived quality; `EquipmentRecipe` combines compatible components using tier-weighted quality; `Weapon.calculateAttackPower` uses the selected head and handle values/multipliers and final quality/rarity. The inspected `main.js` component and equipment branch derives quality, constructs inventory keys, adds the equipment result, and removes the selected components. Item recipes calculate availability, spend actual inventory, award skill XP, and report successes/failures. Forging recipes include Iron chopping axe and Steel chopping axe. The current reference gameplay working tree also contains a conserved cooling sleeve loop with a real material effect and paid field consumer; this aligns with AGENTS.md's implemented-unverified label. All these source fingerprints describe the dirty inspected working tree, not a committed baseline.

A bounded original candidate is a playable acceptance run of existing content: forge a steel axe head, pair it with the intended handle in the Axe recipe, inspect the resulting name/quality/attack, equip it, then use it in an ordinary expedition encounter. The unresolved product question is whether the visible interface previews the chosen modifiers and derived attack clearly before component spend. Later browser acceptance should prove recipe availability, compatible parts, one-time input consumption, a computed owned/equipped weapon, combat use, and no partial spend or phantom output when parts are insufficient. This is an acceptance proposal, not a request for duplicate crafting or cooling systems.
