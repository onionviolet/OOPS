## Changes

The library previously tied its summary to prepared shards and retained output caches without explicit bounds. It now reports observed recognized output files separately from held text, prepared ranges and completion. The existing first-owner rule for ambiguous historic prefixes remains intact. Direct links expose existing batch outputs without creating prepared shards, source aliases or method receipts.

The production findings CLI builds one world per child process, retaining the counts matrix rather than every world's source fold in the parent. A mixed-world legacy fixture proves byte-identical output against the original in-process fold. Programmatic callers retain the existing fold API. The directory resolver is shared without adding a library/reader-slice import cycle.

The server output-list cache retains at most eight results and 16 MiB of estimated JSON string weight, with a 30-second lifetime. The browser digest cache retains at most two worlds and 32 MiB of estimated JSON string weight. Oversized results still render but are not retained. These budgets bound retained cache weight, not the active page's entire heap. Source-alias SHA checks read 64 KiB chunks and preserve the exact digest contract.

The inventoried largest input file was 383,311 bytes. Per-file streaming of JSONL was not required by that measurement; simultaneous retention across worlds was the demonstrated concern. A large individual world's active view remains a separate measured cost.

The first full staged build stopped at `ttks4`: five numeric people identities in one authentic historical output reached a string identity join. Strict nonblank string identity admission now excludes malformed census/rules/people/places identities without coercing them into invented records. The actual `ttks4` retry exits 0 with 103 observed orphan slices. A synthetic regression preserves valid rows while excluding numbers, objects, arrays and blank identities. Earlier completed stage files are partial build output, not an accepted complete snapshot.
