# Implementation packets

PROPOSALS only. No packet is assigned or accepted. Each is a possible single
playable slice, not permission to implement all five or add a realm/prestige.
Director direction and the existing owner decide scope. The generation GR
contract is a proposal. Reuse existing state, transaction and knowledge owners;
ordinary repeated options remain reachable, with world-qualified limits.

## WP1: labor and deployment receipt

Owner: `docs/ENGINE_EXPANSION.md` plus world economy/population owner. Source:
B1/B3 in [formula digest](ECONOMY_AND_BATTLE_DIGEST.md), PW-W1.

Scope: one already modeled resident cohort chooses ordinary work or deployment.
Show quoted production forgone, actual casualty and actual surviving return.
Keep counts, training quality and partial injury distinct. Do not copy Warsim
coefficients, civilization ranks, its source slavery policy or army limits.

Compatibility: additive cohort/deployment IDs in the existing envelope; old
saves do not acquire a deployment, loss or return. Command receipts prevent
repeat settlement after reload. First verify the existing detach/return owner,
then add only its missing state rather than a parallel population ledger.

Desktop gate: rebuilt 1366x768, work ledger and selected force visible together.
Done: normal work/deploy choices, a loss and survivor return change the same
population once; failed/canceled action debits nothing; reload and literal
import preserve a changed-positive deployment and its later return.

## WP2: one eligible repeatable petition

Owner: `docs/CHARACTERS_AND_WORLD_EVENTS.md`, world economy owner. Existing
read seam: `src/event_feed.js` projects discovered simulation events and
opportunities without rolling or granting rewards. Source: E1/E2/E4.

Scope: one original local request consumes existing actor funds/time and
creates a useful recipient fact. Candidate weight, eligibility, quiet result,
cadence and repeat conditions are explicit. Manual help, refusal and funded
delegation use one resolver. World history justifies any repeat restriction.
No giant court menu or copied petition prose.

Compatibility: new event ID/version under existing simulation event state;
absent old events remain absent. Known receipts persist; hidden NPC actions
stay outside the player feed. Quiet draws must not shift unrelated generator
streams if the addressed-generation proposal is selected.

Desktop gate: 1366x768 request detail, actual treasury and action result remain
visible. Done: eligible/ineligible, low-funds, quiet, manual and delegated
routes; changed recipient state has a later reader; reload/import preserves
pending and completed state without a second payout or private truth leak.

## WP3: names describe actual traits

Owner: characters/world-events owner, generation foundation proposal. Existing
reader: `src/character_bio.js` joins known sources, causes and conditions.
Source: N1/N2/N5.

Scope: one generated person's alias/title and biography reference fact IDs.
A title's bonus reads an earned trait record; merely changing a display name
has no grant effect. Validate aliases at authoring time; use bounded fallback
for an invalid content chain. No source tables or raw story text copied.

Compatibility: preserve revealed names and existing trait IDs; table revision
changes affect only explicitly unseen future generation. No automatic legacy
renaming or retroactive ancestry from a patronymic.

Desktop gate: 1366x768 identity, known cause and affected action readable
alongside one another. Done: title acquisition changes a real action, rename
updates derived displays, unknown facts stay unknown, reload/import retains
known identity and does not duplicate the title grant.

## WP4: quote and settle one upkeep cohort

Owner: world economy and engine owners. Source: B2/B5. Existing transaction
owner must be found before coding; event feed reads only its result.

Scope: one ordinary recurring group cost with an affordability forecast,
explicit rounding and an original world-qualified shortage/recovery outcome.
Do not import Warsim's whole-or-nothing wage model without selecting it as
balance. Compare total cost, actual debit and after-state separately.

Compatibility: additive due/settlement ID, old save missing this cohort stays
absent. Restore/viewing does not advance time or run a wage settlement.

Desktop gate: 1366x768 next due cost and current available funds visible
without covering the primary action. Done: exact-funds, one-below, zero-member,
small rounding and interrupted/catch-up routes settle once; reload/import
preserves pending due state and the same next resolution.

## WP5: retain a generation recipe through one observed consumer

Owner: generation foundation proposal and existing persistence owners;
`src/save_compatibility.js` already preserves retired content instead of
silently destroying old state. Source: S1-S3, N3.

Scope: one generation family records its definition/revision/address and
freezes the revealed output under the existing envelope. Exercise one action
that reads it. Validate old/new table edits and fallback without writing
external mutable Data-style recipes.

Compatibility: versioned additive fields; no inferred enrollment, discovery
or reward on import. Retain the original envelope on unsupported schema.
Do not adopt a 1,904-token positional format or copy a separate raw roster.

Desktop gate: 1366x768 known person/output and consuming action visible.
Done: generation is stable for fixed inputs, reveal is retained, later content
revision does not rewrite known output, and save/reload/literal import preserve
both the output and a changed-positive consequence.
