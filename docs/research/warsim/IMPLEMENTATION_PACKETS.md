# Implementation packets, proposed and unassigned

No implementation authorization or owner transfer is implied. Integrators must
recover current owners and dirty state before writes. Existing generation kit
is the preferred seam, not a new Warsim-shaped engine. All work is in one
current realm and world-qualified. These packets are ranked alternatives;
finish a playable slice before selecting another.

## WP1: one faction trait with three readers (P1/P4)

Owner: generation foundation and CHARACTERS_AND_WORLD_EVENTS; law semantics
consult NONHUMAN_SOCIETY_LAW_AND_ECONOMY. Input: one current world-supported
faction, one authored trait and real negotiation/economy routes.

Generate an identity and trait at stable addresses, record the table revision,
then project known facts. A policy trait changes one offer condition and one
finite resource flow; description reads those facts. Names are labels, never
mechanical IDs. A proposed example is a trading group that asks for a local
market permit, with an alternative paid escort agreement. Setting-specific
facts must be confirmed by the owner, not imported from Warsim.

Exclude a new species catalog, global politics, a universal civilization score,
new realm and copied source content. Dependency: a real faction reader and the
live tag API; do not assume proposal-only overlays are implemented.

Gate: fixed-root same-input replay; irrelevant name edit changes no outcome;
unknown policy stays unknown. At a rebuilt fresh-origin desktop 1366x768,
player reads the known terms, pays a real cost, sees changed flow and causal
report, then Save/reload/literal Import preserves both agreed terms and next
pick. Persist resolved facts or make an explicit compatibility decision.

## WP2: role-qualified person pool (P2/P7)

Owner: CHARACTERS_AND_WORLD_EVENTS and generation foundation. Start with one
existing actor role in the current world. Give role/culture/era tags to a small
reviewed pool; use stratified picks for categories, not copied ID arrays.
Reuse one name and identity across an encounter, workplace and known log.
Backstory stores fact references when true; unsupported anecdote is explicitly
what this person says. No imported biography prose or generated secret truth.

Exclude a new quest generator and simulated lifetime history. Gate: deliberate
name collisions keep IDs distinct; incompatible role story cannot be selected;
fallback is named; rename updates ordinary surfaces but preserves an in-world
letter if its words were frozen. Rebuilt desktop route reveals the actor and
uses a role-qualified action; Save/reload/import retains identity, disclosure
and next pick. Table revision cannot rewrite a seen person.

## WP3: productive mobilization (P3, PW-W1)

Owner: ENGINE_EXPANSION and the actual economy/force owners of the selected
world; Province War may design its own packet against PW owners.

Quote deployment from one existing worker population. Show projected work
missed, cost and return conditions. Resolve payment, deployment, casualties,
return and production from one shared record with a cause receipt. A civilian
worker cannot keep doing the same full-time job while deployed. Stronger troops
need not be artificially equalized to weak ones.

Exclude tactical combat overhaul, seasonal famine death and a second population
ledger. Dependency: native population/work reader and resolvable combat or
expedition, not only a generated headcount.

Gate: compare two deployment choices on the same state; count conservation
holds, casualties affect later work once, survivors can work after return.
Rebuilt desktop quote and report stay visible together at 1366x768. Save,
reload and literal Import preserve an in-flight deployment and its return.
Current YAIRPG food direction remains comfortable unfed play with no hunger
death; a levy economy must not silently change that rule.

## WP4: useful contextual petition (P5/P8)

Owner: CHARACTERS_AND_WORLD_EVENTS, storylet and generation foundation owners.
Use one real current-world need, one relevant repeatable petition and one quiet
outcome. Eligibility reads the cause, resources and observed actor knowledge.
A daily game-time address fixes the occurrence; known result is frozen.
Resolved petition changes actual money, access or work, with a receipt.

A routine delegation policy applies the same resolver and costs. Keep an
exception visible. No mandatory unique-trait limit or artificial once-only cap.
Exclude thousands of visitors and a new standalone court UI.

Gate: need absent blocks the petition; repeated eligible route remains possible;
quiet outcome and bounded visitor budget work; delegated and manual resolution
of the same case have the same authorized consequence. Rebuilt 1366x768 desktop
route plus persistence keeps the next petition and pending delegated cost.

## WP5: competition with useful stakes (P6)

Owner: ENGINE_EXPANSION and thematic UI; selected world's competition/training
owner. Pick an existing tournament, examination or sparring route, not a new
realm-wide gambling layer. Generate entrant facts from the same person rules;
reader gives training, patronage or known record consequences.

Quote stake and return separately. If betting is appropriate to the world,
bookmaker terms and real purse govern payout; displayed uncertainty is based
on known inputs. An odds-sight cheat reads true resolver odds through its owner.
A strong entrant is allowed to be strong. No mandatory equalization or global
solo-player anti-abuse rule.

Gate: public information, actual resolver and quoted settlement agree; a cost
is paid once; win and loss each produce useful causal records. Ordinary income
remains a playable route. Rebuilt desktop proof and changed-positive
Save/reload/import retain entrant and outcome. This packet does not assume the
2024 Warsim exploit is still present.

All native gates above are future acceptance checks, not checks run by this
research lane. Mobile optimization is deferred. Proposals to update owner docs
must be made by the coordinator or authorized integrator, not this output lane.
