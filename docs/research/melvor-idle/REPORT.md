## Offline and automation boundaries

`game.js:1769–1800,2074–2168,2199–2227` runs the same 50 ms passive/active ticks and death check during catchup, with a default 24-hour processed cap and a one-minute offline trigger. Passive systems can continue alongside one selected active action. Offline combat is disabled unless its setting is enabled; a selected Slayer area additionally needs Slayer unlocked. Golbin Raid is excluded from the ordinary offline trigger.

The return panel compares actual bank/equipment/food/prayer/soul/XP/currency/kills/discovery snapshots. It can show losses and full storage. Recipe depletion, enemy attacks and death remain real; the panel does not award predicted gross rates. A processing error reports diagnostics and attempts to stop the active action. No rollback or atomic settlement guarantee was established. OFF01.

Ordinary crafting checks/preserves/consumes ingredients **before** reward insertion. A full bank can lose a new item type even with default stop-on-full; that stop occurs after the failed output. Existing stacks can grow at full slot count. Currency/XP processing can still occur. Public shop purchases instead preflight output capacity before consuming their game-currency costs. These differing failure orders are part of the findings, not a recommended YAIRPG implementation pattern. OFF02/SHOP01.

Current-character perma-death clears the local save slot and, if signed in, the corresponding PlayFab character save. It does not delete the user's cloud account. Protect Item affects ordinary equipment-loss support, while perma-death exemptions use separate event/raid/free-death branches. A last Protect Item payment after a lethal attack may remove protection before the tick's death penalty; this remains a source-ordering inference with runtime behavior unverified. C1/C4.

## Useful authoring interfaces

Data packages use registered namespaces, stable IDs, ordered hard dependencies and conditional `dependentData`/modifications. Public DLC accessibility is separate from registered/enabled content and actor readiness. AoD depends conditionally on TotH data; ItA has conditional AoD mode/relic modifications. Missing namespaces and invalid references throw; registration rollback was not established. DATA01.

Mod contexts expose data packages/builders, lifecycle hooks, namespaced APIs, resources and character/account storage. Character storage unlocks at character load, serializes under the mod ID through the existing save encoder and has a 2^13 capacity measured by JavaScript string length in this implementation. It rejects at 100% and warns above 75%. A missing installed mod is skipped by the reviewed decoder path. Method patches can change arguments/returns and warn about overlap; save/database/native/cloud classes are blacklisted. MOD01.

The [official typing project](https://github.com/GamesByMalcsPtyLtd/Melvor-Typing-Project) was pinned to `aa84a4253d998ab03f396aee9e1c0b3a9df0582c`. Its modern declarations include Abyssal/Cartography/Harvesting/Corruption, while package 1.13.0/changelog metadata still points to an older V1.2 release. The hosted executable code governs current claims. Wiki pages returned 403 and mod.io offered only a JavaScript-required shell; accessible primary executable/declaration sources supplied the authoring evidence. No mod installation or arbitrary method patch was performed.

YAIRPG already has declarative registries, exact recipe definitions, versioned receipts, native stock/equipment adapters, independent actor jobs, body/source/consent checks, filtered knowledge and one durable publisher. Reuse them. Melvor's mod patcher is not a reason to add a secondary publisher, mutable shadow inventory or new scheduler.
