## Current behavior

| Code | Evidence state | Finding |
| --- | --- | --- |
| F1 | VERIFIED (read) | The native calendar is an explicit `Game_Time`: year/month/day/hour/minute and `day_count`. `goUp()` defaults to one minute, carries through 60-minute hours, 24-hour days, 30-day months and 12-month years; seasons/weekdays/moon phase derive from it. It is not the system date (`src/game_time.js:8-55,63-112`). |
| F2 | VERIFIED (read) | Main `update()` recursively schedules `setTimeout`. Each callback calls `update_timer()` once. At default `tickrate:1`, ordinary time requests one game minute per approximately one wall second; native sleep defaults to six minutes per callback. Pack-active time takes its own default one-minute path before the sleep multiplier. Speed changes multiply tickrate, rather than request full elapsed time (`src/config.js:19-23`; `src/main.js:7127-7151,7226-7246,7898-7913`). |
| F3 | VERIFIED (read) | `Date.now()` measures timer lateness, but only adjusts the next delay, capped at ±100/tickrate ms. It does not convert the wall interval to simulation minutes. `total_playtime` increments by 1/tickrate per successful update, not the actual elapsed wall interval; autosave/backup counters likewise count successful callbacks (`src/main.js:7228-7235,7630-7654,7673-7693`). Returning early when no time advances skips these counters (`src/main.js:7244-7246`). |
| F4 | VERIFIED (read) / INFERRED | Save creation writes `saved_at` as a local date string `YYYY-MM-DD HH_MM_SS`, without a timezone. Loading restores the saved calendar and expansion, then startup sets a new `start_date = Date.now()`. Searches of `src/` found `saved_at` used for save/backup labels and forbidden transition paths, not elapsed progression. Thus no general wall-clock catch-up on load was found (`src/main.js:4904-4913,4941-4944,5266,5308,5328-5330,7759-7760,8491-8509`; `src/expansion_persistence.js:38`). The negative architectural conclusion is INFERRED from those paths and search. |
| F5 | INFERRED | Background tabs can continue only insofar as browser callbacks execute. A delayed main callback still requests its fixed minute amount, with limited later smoothing. There is no gameplay visibility handler reconciling hidden elapsed time; the found visibility handlers control visual effects. Closed documents have no callback loop. Therefore background/closed progress is not generally equivalent. Exact throttle behavior was not measured (`src/main.js:7226-7246,7673-7693`; `src/settled_text_effects.js:128-131`; `src/native_discovery_feedback.js:60-62`). |
| F6 | VERIFIED (read) | Native action attempts have a separate 0.1-second/tickrate interval and increment an iteration counter. Neither path replays all missed wall time; loading explicitly does not restore current enemies (`src/main.js:2517-2541,5324`; `src/models/combat.js:197-215`). An offline adapter must account for these separate consumers, not just advance a calendar. |
| F7 | VERIFIED (read) | Expansion has an integer `clock`, sequence and RNG. The joined host passes integer minutes to `advanceSimulation`, then advances the native calendar and effect durations by the **consumed** clock difference. Native nonjoined time advances the calendar directly and calls `advanceExpeditions` only when relevant pending work/opportunities/sources/visits exist. Native absolute calendar minutes and expansion elapsed minutes are different coordinates, not interchangeable timestamps (`src/expansion_engine.js:75,139-140,588-598`; `src/main.js:1189-1198,1234-1255,7175-7180`). |
| F8 | VERIFIED (read) | The scheduler visits the next job/opportunity/chronicle/simulation/world boundary in order. It stops on an ended life, blocking available opportunity, waiting choice or player session. After 512 boundaries it returns `remaining` and `budgetExhausted`; the host currently synchronously drains that remainder while no choice stops it. This is a causal work budget, not an offline elapsed cap or a browser work/yield budget (`src/expansion_engine.js:598-640`; `src/main.js:1237-1250`). |
| F9 | VERIFIED (read) | Generic world instances save `{elapsed, observedAt, unit:'played_minutes', absence:'freeze'}`. ## Suggestions, ranked

1. **S1:** Prototype one active-life elapsed ledger before branch selection: numeric wall cursor, conversion remainder, cap, unspent-time reason and atomic publication. Reuse the joined scheduler/publisher and preserve legacy freeze defaults (F7, F8, F13).
2. **S2:** Choose one noncombat queued task plus one eligible passive condition for the first adapter. Compare equal elapsed intervals split into ticks, one jump, background return and closed return. Explicitly retain E1 offline pause until a new policy is selected (F6, F14; OT2/OT10).
3. **S3:** Add a pause-before-event barrier and durable return report before broad catch-up. Separate elapsed cap, causal boundary budget and browser execution budget; yield instead of synchronously draining arbitrary long work (F8; OT3–OT5).
4. **S4:** Keep resting branches frozen by default. Introduce a moving-world exception only with the T4 ownership/policy contract, reentry cursor, overlap rules and selected-world tests. A parent ID or local clock is insufficient (F9–F12; OT1/OT6–OT8/BR6).
