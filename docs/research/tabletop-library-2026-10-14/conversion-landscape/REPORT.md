# Existing rulebook-to-game conversions

Research snapshot: **2026-10-14, America/New_York**. Completed bounded landscape audit under the [saved brief](../handoffs/CONVERSION_AUDIT_BRIEF.md). Recommendations below are proposals. No game implementation, purchase, installation, commit or push was performed.

## Findings that change the decision

**F1. Borrow procedures and content workflows selectively.** The useful precedents occupy different categories: finished authored CRPGs, mechanical roguelikes, human-run VTTs, campaign generators, solo journals, and experimental AI adjudicators. None inspected establishes a complete rulebook-to-autonomous-world converter. This is the result of this bounded sweep, not proof that none exists anywhere.

**F2. A rules engine does not supply a world's ordinary life.** Torment's designer explicitly describes limiting possible actions so their consequences can be handled convincingly. Its finished game is evidence for authored Numenera adaptation, not automatic implementation of every Cypher setting. [Developer explanation, 2014-03-28](https://www.adamheine.com/2014/03/ama-adapting-numenera-to-crpg-and-what.html?hl=en), [released game](https://store.steampowered.com/app/272270/Torment_Tides_of_Numenera/).

**F3. Ars Magica has a particularly relevant inspectable implementation.** The maintained Foundry fork contains explicit seasonal/laboratory activity classes, validation, progress and diary handling. It still expects a table's authored inputs and judgments. The original repository's archive is a transfer to a successor, not evidence the implementation disappeared. [Predecessor notice](https://github.com/phaldaros/arm5e), [maintained fork](https://github.com/Xzotl42/arm5e).

**F4. Partial automation can hide consequential omissions.** The sampled Godbound fork states that damage automation, core initiative, low magic and some multi-target attacks are unsupported. A Word/Gift sheet is therefore poor evidence of automatic divine projects or world simulation. [Maintainer's feature limits](https://github.com/sealtrowitz/foundry-godbound).

**F5. Text supports deep mechanical play, but does not remove the adaptation work.** Incursion demonstrates a d20-derived dungeon game with a defined action space and substantial original departures. Its current fork also shows why an old project's current status must be checked through successors. Neither its dungeon nor an AI chat sample establishes continuing residence and cross-world consequences. [Current fork](https://github.com/networkingguru/incursion-roguelike), [game's description of its rules relationship](https://incursion.wikidot.com/faq).

Recommendation: retain the existing YAIR approach in [the library's adaptation proposal](../CORE_TITLES_AND_ADAPTATION_PLAN.md#d2-recommended-composition) as the incumbent. Inspect seasonal activity handling first, then structured rule data/migrations and durable generated places. Do not adopt a universal tabletop framework on the evidence here. That recommendation does not promote any book world ahead of the standing [user direction](../../../USER_VISION.md#tabletop-systems-and-distinct-multiverses-2026-10-14) or change the [multiverse owner](../../../worlds/MULTIVERSE_STRUCTURES.md).

## Useful negative findings and interactions

**N1. No verified idle conversion was found for the sampled book families.** Searches combining the family names with video game, text, idle, roguelike, adaptation, Foundry and GitHub primarily produced the candidates above. The seasonal code is not an offline-progress system; solo journal tools are not autonomous idle games. This is a bounded negative, not a global absence claim. No replacement runtime or new acquisition follows from it.

**N2. Failed funding, unfinished prototypes, dormant branches and transferred maintenance differ.** C04's funding failure is evidenced; C05's present fate is unknown; C12's sampled branch is old and incomplete; C07 and C06 have successors. None supports a claim that its book's rules cannot become a game. The failed Kickstarter fetch was replaced by publisher/interview/contemporary-participant evidence. Exact campaign totals, seen through a secondary tracker, are unnecessary to the recommendation and are not used as primary proof.

**N3. A faction editor is not a faction decision engine.** Sectors stores faction records; the [ShawnsVTTs developer article, 2026-05-30](https://shawnsvtts.com/blog/faction-turns-in-stars-without-number) separately claims purchases, attacks, state updates and a turn log. That article is documentation-only evidence, not a verified faithful SWN faction engine. It is worth inspecting only if faction-turn bookkeeping becomes the named problem. A developer's claim that groups often abandon bookkeeping is experience/opinion, not measured prevalence.

**N4. Data volume and open rules do not settle the GM gap.** Datasworn can carry a move or oracle, and VTTs can calculate a roll. Someone still decides when it applies, which facts it creates, who knows them and what changes later. For YAIR, explicitly classify each borrowed procedure as authored, mechanically resolved, bounded generated, human-resolved or unsupported. This is an accounting recommendation, not a new global interface design.

**N5. Power portability and world persistence need their own proof.** A body-switch dialog, imported character or reusable attack formula does not show that a continuing traveler retains knowledge, physical carriers, remote access and actual consequences correctly. Preserve differences between those cases. Likewise, months or seasons in a book do not impose months of real waiting. Proposed idle compression must preserve causes, earned outputs and interruptions, with visible consequences on return. These points account for existing direction; they do not authorize another world slice.
