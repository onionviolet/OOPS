# M1: Xeus24 mod.js lines 1-4700

Coverage: every line 1-4700 of mod.js was read with the Read tool (12 chunks of 300-400 lines). The mod's section 19 (XP curve) runs on to about line 4757, so lines 4701-4757 are unread here. Index.html was grepped only to confirm what is patched (cited as `index.html:N`). The YAIRPG source was grepped only, not read. Labels: SHOWN = stated or visible in the code at the cited line. INFERRED = my reading. UNKNOWN = not determinable in this range. All code is paraphrased, no listings. Findings that live in sections 20+ (title ranks, picker, colours, save slots) are NOT covered: see Gaps.

## 0. Overall pattern (code quality worth learning from)

- Delivery. The mod is one plain `<script>` loaded after the game script, sharing its top-level `var` globals (1-5, 27-29). Each system captures the original function in a new `MOD_*_original` var, then reassigns the global to a wrapper. SHOWN for `giveSkExp` (307-312, 2329-2346, 2900-2921), `ontick` (891-895, 1350-1355, 2585-2591, 3516-3521, 4015-4019, 4114-4118, 4342-4346, 4411-4415, 4548-4560), `allbuff` (1160, 2620-2729), `dmg_calc` (1757-1792), `lvlup` (1794-1799), `renderSkl` (2944-2976, 3581-3639), and `chss.frstn1main.sl` (1999-2008).
- Tick hook. About ten stacked `ontick` wrappers each call the previous one, then run their own step inside a try/catch ("a tick must never die", 1354, 2589). SHOWN. Note: the stack gets deep and the order matters, so a later wrapper that anchors on the original `allbuff` silently orphaned earlier wrappers (comments 1156-1159, 2150-2154, 1321-1324).
- Guards. Almost every function is wrapped in a try/catch that swallows errors, with a comment saying why (e.g. 226, 2147, 2233, 3126). Optional dependencies are guarded with `typeof fn === 'function'` (e.g. 2590, 3188, 3618). SHOWN.
- Idempotent installers. `MOD_installLiveDesc` is re-run safely via a `_modDescInstalled` flag (1090, 2766, 3319). `MOD_applyBody` is idempotent by design (2101-2103). SHOWN.
- Delta reconciliation for saved fields. Whenever the mod changes a field the base save persists (`you.res`, `you.mods`, `you.hpm`, `you.satm`), it records its own contribution in `global.flags.*` and applies only the difference on each tick, so loading never compounds the bonus (affinities 3475-3491, money 4077-4087, body multipliers 2106-2148). SHOWN. This is the single most reusable idea in the range.
- Registry instead of competing writers. When two systems wanted `hpm`, the author built a factor registry (`MOD_BODY`) and one writer, with a rule: set every factor on every call, 1 when inapplicable (2071-2104). SHOWN.
- Save compatibility rules stated in the header (14-25): milestone granted-flags save by array index, so milestones are only appended; skill exp saves positionally, so new skills go at the end of `skl`; actions save by id. Skills restore by id (2431-2438), so consolidated skills keep their old ids. Item ids obey an id-range-to-class scheme (536-563). SHOWN.
- Perk migration. A revision number in `global.flags.mod_perk_rev` triggers a one-time re-fire of perks whose effect changed (4377-4417). SHOWN. The comment notes the flag is overwritten by load, so the check re-runs once after an old save's levels are restored.
- Derived instead of stored. "Trains faster" perks are computed by summing flags on granted milestones, because the stored `p` is restored positionally after milestones re-fire and would clobber them (2459-2496). SHOWN.
- Developer-facing console API (`modHelp`, `modCaps`, `modRenown` and so on, 943-985), plus a persisted-settings pattern in localStorage with try/catch (256, 283-288, 4442-4472). SHOWN.
- Change log in the header documents bugs the author fixed in the mod itself (33-91): enemy STR is armour so scaling it zeroed damage (39-42, 1385-1406), `hpTrack` wrote `hpmax` which `stat_r` recomputes (83-85, 2077-2082), `global.titles` doubling on load (67-70), a skill shipping with the same name as a base-game skill (574-583). Worth reading as a bug list for "what breaks when you patch a live game".

## 1. Systems catalog

Format: system, lines, what it does with numbers, patch technique, save fields, relevance.

### S0 Save backup before update (97-227)
- SHOWN. On first load of a new mod version, copies the live save key `v0.3` and all three slots (`p23_slot_1..3` plus meta) into a rotating backup record (123-208). Three rotating backups under `p23_backup_1..3`, "oldest" decided by a sequence number rather than the clock (114-119, 151-185). A fourth key is a once-per-24h daily backup that cannot displace version backups (126, 220-225). Backup runs first, uses plain string keys, and failure never blocks game load (107-112, 226). When storage is full, it frees only the slot being replaced (172-179).
- Patch technique: an IIFE at the top that reads localStorage before the game loads the save. Save fields: `p23_backup_1..4`, `p23_mod_lastver`.
- Relevance: ALREADY-HAVE. YAIRPG has a validated envelope, migration and backups (audit sec. 5). The "seq number not clock", "free only the replaced slot" and "daily backup that cannot evict version backups" details are small ADAPT candidates only if our backup rotation lacks them (UNKNOWN; not checked).

### S1 Speed control (229-289)
- SHOWN. `global.fps` is a speed multiplier on the self-rescheduling main loop and combat divisor (233-236). `setSpeed(n)` caps at `MOD.max_speed = 20` (94, 249-252), saves to `p23_mod_speed`, and re-arms the running sustained-action interval at the new rate (258-265). Restored from localStorage at load (281-289).
- Relevance: NOT-RELEVANT as a feature (YAIRPG is a fork with its own tick; a speed dial is a design call for Weibao). Pattern is simple. Note: it is a console and settings-box feature, not a save field.

### S2 Skill XP multiplier (291-326, 4442-4472)
- SHOWN. Wraps `giveSkExp` and multiplies exp by `MOD.skill_xp_mult` unless the recursion flag `res === false` (the original's level-up overflow path), so overflow is not double counted (299-312). Default 1 since v4.2 (93; was 2). Persists in `p23_mod_skillxp` (4442-4465).
- Relevance: NOT-RELEVANT. Good example of respecting a recursion flag when wrapping.

### S3 Extended milestones (329-495)
- SHOWN. Appends perk tiers at skill levels 20/25/30/40/50 to 10 weapon masteries (370-371), Fighting, Sleep, Walking, Meditation, Gluttony, Greed, Patience, 4 crafting skills and 3 gathering skills (373-495). Example numbers: mastery tier = STR +3 (lv20), AGL +3 and EXP +5% (25), STR +4 and crit damage +15% (30), STR +6 AGL +4 and STR growth potential +8% (40), STR mult +10% and EXP +10% and Fighting EXP +15% (50) (354-367). Fighting 50: STR mult +15%, HP mult +10%, EXP +15%, masteries EXP +25% (385-389). Stat fields used: flat adds (`stra` etc.), multipliers (`strm` etc.), `exp_t` (global exp gain), `stat_p[0..3]` growth potential, `mods.sbonus`, `mods.cpwr` (343-344, 335-342).
- Patch technique: push onto each skill's `mlstn` array (346-351). Fresh objects per call because `g` (granted) is mutated per skill (353).
- Save: granted flags save by array index, so append only; the game re-fires unfired milestones at or below current level on load, so new perks are retroactive (14-21).
- Relevance: ADAPT only as a pattern. YAIRPG skills give smooth multiplicative bonuses with no perk ladders (audit F2). Discrete milestone perks would be a design change, not a titles-adjacent item. Do not copy numbers.

### S4 New skills and sustained actions (497-937)
- SHOWN. Four skills: Qi Circulation (id 901, INT), Wildcraft (key `frg`, id 902), Calligraphy (903), Conditioning (904, STR) with a shared 9-tier perk template (514-534): levels 2/5/10/15/20/25/30/40/50, e.g. +1, +2 and EXP 2%, +3 and energy effectiveness 2%, ... multiplier +18% and EXP +15% at 50. Per-level continuous effect: INT or STR increases by `lvl*3`% for Qi and Conditioning, `lvl*2`% for Calligraphy (1148-1150). Wildcraft effect: find chance per tick = 1% + 0.15% per level (1154).
- Four sustained actions (toggle, 1 tick/s, shared single timer) (607-770): Circulate Qi (exp 0.4/s, trains Qi 0.9, Meditation 0.35, Patience 0.2 per tick), Forage (exp 0.4/s, Wildcraft 1.0, finds one of 4 existing items, energy cost +0.05/s), Practice Calligraphy (exp 0.5/s, Calligraphy 0.85, Reading 0.3, Patience 0.3), Endurance Drill (exp 0.6/s, Conditioning 1.2 while fed else 0.4, Toughness 0.4, Walking 0.5, energy cost +0.15/s x run multiplier). Common precondition: not in battle, civil, not asleep, not reading, not working (629-634).
- Earning (773-838): unlock via perks on base skills: Toughness 4 (Drill), Harvesting 4 (Forage), Reading 8 (Calligraphy), a plain perk on Temperance 5; Qi Circulation is granted by clearing the three dojo tutorial fights (flags `tr1_win`, `tr2_win`, `tr3_win`) with a tick check, plus the first breakthrough pill and reveal of the skill row (840-895). Reason given for using milestones: requirement shows in the skill panel and load ordering is already solved (793-797).
- Patch technique: construct `new Skill()` / `new Action()`, assign fields, `giveAction()`. Escape hatch `modUnlockAll()` (926-936).
- Save: action by id. `global.flags.mod_firstpill` (877-880).
- Relevance: ADAPT (idea). Sustained actions that train several skills at once are close to YAIRPG's activities. Unlock-by-skill-perk-or-story-flag is the idea; adopting it is a design call.

### S5 Live skill tooltips (989-1125, 3274-3321)
- SHOWN. Skill `desc` becomes a getter (via `Object.defineProperty`) that appends a computed effect line and a "Next perk" line each time (1084-1125); a setter keeps assignment working (1099-1104). `MOD_EFFECTS` maps skill key to a string function with formulas quoted from the base game, e.g. Fighting attack +2% per level, Trading buy prices -0.5% per level, Sleep recovery x(5*lvl) (1010-1069). Action descriptions also made live so they show current skill levels and cap (3274-3317).
- Relevance: ADOPT-IDEA (small). Showing exact current effect and "next perk in N levels" in tooltips is a UI nicety; YAIRPG's smooth bonuses could show current numerically. Only if not already shown (UNKNOWN; not checked).

### S6 Continuous effects (1127-1160)
- SHOWN. Added-skill effects applied via the `allbuff` hook after `stat_r()` resets stats, so they recompute rather than stack (1135-1146).
- Relevance: NOT-RELEVANT (engine-specific).

### S7 Naturally discovered skills (1162-1371)
- SHOWN. Nine skills that appear from play: Wayfaring (travel counter `smovet`, xp 3 per unit, delta cap 5), Battle Scars (damage taken `dmgrt`, 0.15, cap 40), Footwork (dodges `dodgt`, 2, cap 5), Curiosity (`popt`, 0.4, cap 12), Collecting (`igtttl`, 1.5, cap 20), Weatherworn (xp 0.12/tick outdoors in rain or snow), Nightwalking (0.1/tick outdoors at night), Lunar Attunement (0.35/tick outdoors under moon phase 4), Second Wind (0.15/tick below 25% energy) (1211-1288). Per-level effect pct per skill: 1.5 to 3 (e.g. Footwork 3, Lunar 3) on the skill's stat; condition-gated skills pay a x2 bonus while the condition holds (2611, 1299).
- Mechanism: one `ontick` wrapper reads `global.stat.*` counters the game already keeps, grants `xp * min(delta, cap)`, with the first tick a baseline-only read so a loaded counter is never paid as a jump (1329-1348).
- Relevance: ADOPT-IDEA (mechanism). A counter-delta watcher with a per-tick cap and first-tick baseline is exactly how an O1 title system should read YAIRPG's `game_stats` counters. See TITLES section.

### S8 Enemy scaling and added areas (1373-2036)
- SHOWN. Enemy scaling solved per spawn against the player's current power by running the game's own damage function many times (`MOD_probe`, 1509-1531; `MOD_meanDamage` stratified on crit roll, 1564-1585). Targets (1442-1456): kill an average enemy in 8 landed swings, enemy kills you in 20, enemy lands 45% of its swings; HP spread exponent 0.6, attack spread 0.3, margin 1.7 (no spawn worse than 1.7x of winnable), boss kill 2.0 / die 0.7, exp reward scales as `hpm^0.5`, existing area level ranges x1.4 (tutorial areas exempt, 1827). Enemy STR left alone because in this engine STR doubles as armour (1408-1419). Enemy damage rescaled by wrapping `dmg_calc`: keeps the shape of the raw roll (EMA of mean, damped 0.6, clamped 0.5x to 2x of target) but fixes the magnitude (1759-1792). Scaling goes through the idempotent multiplier fields so `lvlup` can run again (1618-1624).
- Setting `Fights`: 'original' (default since v4.6) leaves the author's areas unscaled and scales only the mod's own areas (1460-1481); localStorage key `p23_mod_fights` (1465-1471).
- Three endgame areas (1864-1907): Sunken Hollow (creatures lvl 30-40), Ashen Spire (45-58), Long Vigil (55-68), endless size, extra forage drops at 3/5/8% each. A gate location reachable after golem arena IV clear (`trne4e1`) via a wrapped `chss.frstn1main.sl`; Spire needs 10 Hollow kills, Vigil needs 15 Spire kills (1942-1983, 2209).
- Relevance: NOT-RELEVANT for the formulas (tied to the base engine's subtractive damage). ADAPT idea: "solve enemy HP per spawn so a fight takes N player swings" is a general difficulty-anchoring technique, but YAIRPG's group combat and fixed templates make it a separate design decision. The "re-run the real damage function with side effects parked" probe is a good testing pattern.

### S9 Player survivability and body multipliers (2038-2168)
- SHOWN. Max HP follows offence: factor = (new STR / old STR) ^ 0.92 (`hpTrack`, 2067-2069, 2713-2715), published through the factor registry `MOD_BODY` and written once (2106-2148). Reason: offence grew about 20x while HP grew about 1.5x across levels 10-30 (2051-2054). Gotcha documented: assigning `hpmax` or `satmax` is lost on the next `stat_r()`, so write the multiplier inputs instead (2073-2082).
- Relevance: NOT-RELEVANT for numbers; the factor-registry pattern is an ADAPT note if YAIRPG ever has several systems writing one stat.

- Ten consolidated "played" skills (2441-2452, ids 1001-1097) with `pct` totals like 2.332 for Killing Intent; driven by counters (e.g. `akills`, `deadt`, `crftt`, `rdttl`, `plst`, `dodgt`, `slvs`) or predicates such as outdoors, night, any hardship. ### S11 Skill panel: sections, parent skills, collapse, hide-maxed (2768-3321, 3440-3640, 3643-3690)

### S14 Selling and item values (3691-4043)
- SHOWN. The base game had no selling. This adds Buy/Sell tabs injected into the shop (found by `global.menuo === 4`, 3976-4013) using vendors' unused `dfl` sell-back field (0.2 to 0.3; default 0.25, 3685-3698, 3734). Price rules in order (3705-3716, 3837-3874): (1) vendor price if any, lowest across vendors; (2) craftable: sum of recipe inputs x 1.25 / output amount, recursive, depth 6; (3) equipment: 5.3 x (STR+AGL+INT+SPD+dpmax/10); (4) rarity-and-type fallback: type base prices {100, 2, 70, 16, 25} x rarity multiplier {0.25, 1, 5, 15, 45, 130}; (5) drop-source: 0.8 x (lowest creature level that drops it)^1.25 x (1/drop chance)^0.35, used only if higher (3756-3764). Sell price = value x dfl x (1 + Trading use + sqrt(reputation) x 0.004), minimum 1 (3884-3890). Each sale gives Trading XP 1 + 2% of price and reputation +0.05 (3911-3913). Quest and worn items cannot be sold (3892-3897).
- Relevance: ALREADY-HAVE (selling with saturation and haggling in YAIRPG, audit F8). ADOPT-IDEA only the value-derivation ladder if YAIRPG has unpriced items (UNKNOWN).

### S18 Skill XP curve (4564-4700+)
- SHOWN. Base per-skill cost is `round(50 + (lvl+1)^ln(9*lvl+1))`, super-exponential, 109 to 110 costs 1.16e14 (4570-4574). Replaced by a two-part curve (4598-4616): levels 0 to 9 use the original formula exactly; level 10 onward grow geometrically from the last original cost at a ratio solved by 80-step bisection so the whole 0-to-110 climb costs the same wall-clock time as the earlier mod curve (`50 x 1.106^lvl`, total divided by its 2x multiplier) (4623-4678). `setXpCurve({vanillaTo})` re-solves. Installed per instance by overwriting each skill's `expnext` (4688-4700); applied again at the very end of the file for late-created skills (4680-4684). Character level curve is untouched (4618-4620).
- Relevance: ADAPT (idea). YAIRPG already has a geometric curve; "match the author's formula where perks were designed, then solve the ratio" is a tuning method, not a feature.

### 2.4 Renown (4260-4348, 4350-4373)

### 2.6 What O1 can learn (all idea-level, my read)
1. Count titles from the catalog's own `have` flags, never an array that load rebuilds (4270-4272, 4293).
2. Add new title ids in a block clear of existing ids (4162-4163) so old saves are untouched.
3. A counter-delta watcher (first tick baseline only, per-tick cap) is the way to turn lifetime counters into triggers (1329-1348). For YAIRPG, replace the `global.stat` counters with `game_stats` (see src/main.js:4392 for the titles field in the save).
4. A named-predicate table (2375-2419) is a data-driven way to express "condition holds" triggers.
5. Make titles do something small: a stat or a displayed effect. The mod gives a title a perk bonus at the same level (flagship tiers 55/60/70/75) and a meta-reward (Renown) for the collection size. Thresholds roughly geometric (2, 12, 30, 60, 105, 160, 230, 320, 430, 550; ratios shrink from 6x to 1.28x).
6. Do not copy: stats from titles that scale the whole build (Renown compounds 5% per level), because the author needed a whole balance pass elsewhere to stop runaway power (2593-2599, 2454-2458).
