This is not an availability count. Behavior column is paraphrased from declarations/help plus inspected generation branches. It is STATED where supplied by help; cited generation locations are SHOWN structure, not an end-to-end proof of every behavior. Full movement/AI exception closure is partial. Per-row generation locators are presence indexes from a text scan; an indexed branch is not automatically an inspected method body.

`REQ` expressions are tiny executable identifiers, not prose dumps. They must be interpreted through landlock.cpp, including mode-aware numeric macros from hyper.h. `REQAS` inherits another rule. `ACCONLY` is evaluated separately for available parent lands. NATIVE values distinguish treasure-increasing kills (2), creatures that occur (1), and others (0). Monster column lists identifiers referenced by NATIVE, not an exhaustive spawn roster. Shared elemental, mirror and warped treasure must not be counted as independent reward families.

SHOWN: `setdist` and distance stages create content near exploration; `fargen` prepares terrain, and many `ONEMPTY` branches place local monsters and treasure. `landgen.cpp:notDippingFor` depends on local versus retained treasure, peace and chaos. This makes repeated boundary dipping and deep exploration different. Exact local treasure rates vary; no single global formula explains every land.

SHOWN example, Icy Land (`landgen.cpp:1054`): ordinary eligible empty cells test `hrand(5000)` against `PT(100 + 2*(Yeti kills + Wolf kills),200)` and require `notDippingFor(Diamond)`. Enemy spawning uses `hrand_monster(8000)` against twice `(diamonds + Yendor hardness)`. `PT` substitutes a mode-specific value in Pure Tactics, so copying the normal kill curve into that mode would be wrong. Exact RNG stream behavior and long-run balance were not simulated.

SHOWN: `repairLandgen` (`landgen.cpp:2875`) repairs mismatched cave/alchemy terrain, removes some ice or red-rock leakage and clears wrong-land Red Gem/Rose items. This is generation repair, not permission to erase a player's already owned inventory on crossing.

STATED vs SHOWN example: basic Crossroads help says ten of every other treasure for Hyperstones. Executable eligibility excludes Grails and rescued-princess treasure, handles selected geometry and available land list, and skips duplicate mirror treasure. Use `count_at_level`, not that sentence, for exact rules.
