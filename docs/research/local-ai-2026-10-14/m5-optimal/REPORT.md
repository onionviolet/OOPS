## A1: Smallest comparison that could change this recommendation

Select **one** question before authorizing execution: baseline versus Gemma26B for useful responsiveness, or baseline versus Hemmingway for natural writing. Start with three fresh synthetic packets: a supported-site draft, a constrained creative scene followed by one factual correction, and a short companion reply with an explicit unknown. Run both models with two seeds, thinking off: four requests per model/seed, **16 requests total**. Lock prompts, exact artifacts/templates, sampling and tokenizer before execution. Counterbalance order and blind model labels. Reuse the supported-site validator rather than inventing a new game compiler.

Only after that screen, use the winning pair on one equal-fact 4K/8K case with the decisive fact moved between start and end, keeping the stated output reserves. Record first uncached and immediate repeated-prefix behavior separately, then one ordinary-desktop contention case if companion responsiveness is still relevant. This staged expansion answers named gaps rather than rerunning the whole old unrun packet. No such trial has been run or authorized here.

Record first final-answer token, completed-answer time, actual prompt/reasoning/final tokens, peak memory/pressure, queue time and MTP acceptance. Retain failures, empty answers and output caps in the denominator. Blind review records factual/agency violations before prose preference and editing minutes. A meaningful reduction in waiting/editing with acceptable semantics can change the choice; no arbitrary percentage is a new acceptance requirement. Close results favor keeping the incumbent until a named failure warrants expansion.

## R1: Boundaries that affect the decision

Local inference can keep request contents on the Mac, but client telemetry, cloud fallback, logs, prompt caches and saved transcripts need separate inspection before claiming complete offline privacy. Model weights, active context, cache and durable memory are distinct. Keep personal records separate from world canon/actor knowledge. Durable companion memory needs reviewed writes, source pointers, corrections, deletion across journals/summaries/embeddings/caches, expiry and restart recall tests. A long context or successful correction in one chat does not establish memory. The planning owner's narrow Ghost activity-summary phase grants no screen-derived commitments or persistent personal-memory expansion.

For YAIR, generation produces reviewed candidates. The existing one-site `validateDraft`/`compileDraft` route supports 14 fields and scalar gather/work/pay; it does not prove arbitrary quest/NPC effects or a general live AI-to-game pipeline. Native occurrence, people/knowledge and Ink consumers retain state authority. Proposed new mechanics may be invented explicitly; they do not become live through prose. Accepted content must eventually survive provider loss and Save/reload/export/literal-file import through its integration owner.
