# Reusable source-to-emergence research flow

Saved at the user's request, 2026-10-15. Research only. This is a repeatable analysis route, not authorization to install, launch, alter saves, publish, or implement reference code.

1. **RW-A1: pin the actual available source.** Read installed manifest and engine/module layout. Hash the input before extracting; record version/build, tool version, exact command, exit status and export hashes. Reuse prior pinned exports when matching. Managed assemblies allow targeted class export; a native binary requires a different route and must not be mislabeled as managed decompilation. A type list establishes inventory, not reading.
2. **RW-A2: choose a connected chain.** Name one observable question. Follow local state and perception into relationship/classification, utility or plan selection, the real action consumer, world consequences and persistent state. Read the rejection and interruption paths along that same chain. A method name, UI description or unused parameter is not evidence that an effect exists.
3. **RW-A3: audit combinations by event order.** Check the actual caller and scheduling order, cached versus live values, shared resource ownership, callback guards, special species/mode branches, and which values are refreshed only while observed. Challenge surprising formulas against direct consumers. Mark source facts separately from inferred scenes that have not been observed natively.
4. **RW-A4: audit cleanup as state ownership.** For each temporary relationship, effect, body, grip, intent or offer, record owner, creation, refresh, expiry, replacement, interruption, death, room unload, abstraction and load reconstruction. Look for both sides of paired references, delayed flags, guards against recursive callbacks and differences among early-return paths. A normal-path cleanup claim never proves all paths.
5. **RW-A5: save complete evidence and exact gaps.** Keep full private exports, receipts and any raw windows outside committed prose. Publish paraphrased decoded chains with method/line/hash locators, an inventory distinguishing captured/window-read/full-read, exact unread complements and missing consumers. Validate links and hashes. Only a later authorized native observation can establish live encounter behavior; no implementation or product adoption follows from saving a report.

For each proposed emergence example, preserve a compact record: initial state; what each actor knows; trigger; admission gates; selection rule; action constraints; world mutation; resource cost; expiry/cleanup; persistent subset; unverified branch. This makes a surprising story explainable and lets later reviewers distinguish a designed exception from a rule composition.

The Rain World pass demonstrates why this flow matters: continuationBonus is stored but not consumed by the comparer; stopTracking is not read in the threat cleanup body; friend selection is not established by the followClosestFriend name; and RealAI cleanup differs among abstraction branches. These corrections came from consumer reading, not simulated behavior.
