# Admission, work, collection and interruption

SHOWN source/data. `Object.PlaceInMachine` selects a rule using `MachineDataUtility`, calls `OutputMachine`, then reduces extra consumed items and the required main count. `OutputMachine` stores the produced item in `heldObject`, rule ID in `lastOutputRuleId`, a copy of input in `lastInputItem` and calculated work time. The snapshot is not extra owned stock and must never be counted as refundable inventory.

All five installed records have `AllowLoadWhenFull=false`, `PreventTimePass=null`, and no overnight-clear condition. Full means the single held-item slot is occupied, not inventory space. `CheckForActionOnMachine` temporarily clears the slot while trying `addItemToInventoryBool`; on failure it restores the held item and returns before clearing readiness or auto-loading. This prevents a full player inventory from deleting the finished good in the reviewed source.

`minutesElapsed` is host-authoritative and consults `ShouldTimePassForMachine`; generic data can block by season, weather, inside/outside or always. Those options are not enabled for these five. `Game1.shouldTimePass` stops single-player world time for pause, many menus and events; multiplayer uses world time-pause state. No real-world offline catch-up was established. Casks use daily updates, so do not describe them as ordinary minute timers.

`Object.performToolAction` emits ready ordinary output, but not unfinished ordinary output. `Pickaxe.DoFunction` and `Axe.DoFunction` emit machine identity and remove the placed object. Thus unfinished keg/jar/dehydrator/furnace work is not carried into the dropped machine in these paths. No launch was used to verify debris pickup, explosion behavior or multiplayer races; those remain unread/native gaps.
