# Conditions and consequential choices

SHOWN static source and selected parsed tables. Full strings and command sequences remain private.

`Data/Events/<location>` is a string dictionary: a key contains event ID plus slash-separated conditions; its value contains a slash-separated event command stream. `GameLocation.checkEventPrecondition` rejects already seen IDs and dispatches each condition through `Event.CheckPrecondition`. `Preconditions` supplies readable handlers plus legacy aliases: `f` compares friendship points, `M` checks current funds, while other handlers check time, season, weather, mail, prior events, presence and multiplayer authority. AND across conditions is distinct from the separate game-state-query language used by 1.6 model fields.

The installed Farm record for `3917587` combines Alex friendship 3500, funds 5000, year/time/day and marriage-related constraints. The question offers a 5000-money branch versus refusal; its named `giveAlexMoney` stream runs `money -5000`. This is a real paid heart-event example. The static `Money` command adds a signed amount and clamps negative balance to zero. It does not independently reject a stale unaffordable choice, so availability is not a transaction guarantee. Exact later all-location aftermath was not traced.

`Event.DefaultCommands` includes movement, dialogue, question, quickQuestion, fork, money, item and friendship commands. `answerDialogue` stores answer index, inserts branch commands for quick questions, or selects named forks. Festival fishing/target-game choices explicitly test 50-money availability and show a failure message without launching the minigame on shortage. `shaneLoan` contains a paid 3000 branch, but its complete authored entry gate was not read and is not used as the heart-event proof.

Ordinary `Characters/Dialogue/<NPC>` dictionaries use calendar/relationship/context keys and inline markers. `NPC.loadCurrentDialogue` reads points divided by 250, day/save-seeded random context and more specific lines before fallback. `Dialogue` supports `$query`, `$q` and `$r`; the `$r` fields include response ID, signed friendship delta and continuation key. `chooseResponse` changes friendship, records seen response IDs, optionally executes an extra argument and reads the continuation. These immediate callbacks are not evidence of atomic cursor-plus-cost publication.

Gift processing uses universal love/like/dislike/hate/neutral category, item and context-tag rules, then specific NPC preferences. Base point changes in `receiveGift`: loved +80, liked +45, neutral +20, disliked -20, hated -40. Silver/gold/iridium quality multiplies positive loved/liked effects by 1.1/1.25/1.5; birthday multiplier is 8; spouse reception halves its multiplier. Special tea has a distinct capped positive route. Limits/refusals are checked separately in `tryToReceiveActiveObject`; a rejected gift is distinct from an accepted harmful gift. These are donor balance values, not recommended YAIRPG defaults.

Selected complete private captures: 150 Abigail, 38 Gus and 52 Caroline dialogue entries; 12 Saloon, 28 Town and 27 Farm event records, including their conditions and branch IDs. Parsed breadth does not imply every line or event was semantically audited. Most heart events live in locations, not an NPC-named event file; attempted `Data/Events/Abigail.xnb` was absent.

SD-P4 should use YAIRPG's existing staged host and stable response bindings. Pair cost, cursor and useful consequence in one durable plan; execute success, refusal, shortage and later changed continuation. Do not inherit donor lifetime seen flags as a solo-player once limit.
