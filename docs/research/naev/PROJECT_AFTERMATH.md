# NV-D3: Local work to changed revisit

Pin `f8982244800e86553217a2dba555a0f41c2b87ba`. Shown means inspected static source, not runtime proof.

Antlejos starts as a landable barren place. The first escort outcome applies the first authored diff, adding refueling. Common helpers own a list of nine stage diffs and ensure an earlier Antlejos stage is removed before the next is applied. The repeatable supply mission stores its destination, volume, reward, marker and mission state; at the pickup it checks actual free capacity, then adds objective cargo. At return it adds delivered volume to the cumulative project total, pays, logs, compares current stage/thresholds and advances at most one stage in that completion callback.

The final stage changes population, local description and bar text, adds inhabited status, jobs, commodities, outfits and shipyard services, and adds tech catalogues. This is a mechanical difference on revisiting the same place, not just a new location label. XML stage data is authored. It does not prove continuous terraforming simulation, population migration, an autonomous workforce or a conservation model for every fixture in the settlement. The campaign readme states ten main missions plus repeatable supplies; only selected mission callbacks and shared project logic were deeply traced.

Source persistence saves the applied world diffs before the player and other domains because loading order can otherwise clear them. The pattern to adapt is retained authored phases with useful downstream services. YAIRPG should use existing native effect and place owners rather than introduce a second freeform XML mutation store.
