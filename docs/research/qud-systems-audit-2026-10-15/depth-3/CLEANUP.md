## CL1: generic removal does not synthesize feature cleanup

Mutations.RemoveMutation checks remaining modifier providers first. If they remain, it removes the inherent mutation from the list, sets BaseLevel0 and optionally resynchronizes; the component remains supported. Otherwise it calls Unmutate, then GameObject.RemovePart, removes the mutation list entry and calls AfterUnmutate. Removing the last modifier has a similar Unmutate→RemovePart→AfterUnmutate route. Thus loss of inherent rank is not always component removal. [Mutations L425-441,663-679](../private/depth-3/source/XRL.World.Parts.Mutations.cs)

GameObject.RemovePartAt unregisters the part's events, cleans legacy event lists, calls part.Remove, sends PartRemovedEvent, clears ParentObject and flushes transient caches. BaseMutation.Unmutate only resets LastLevel; BaseMutation.AfterUnmutate and IPart.Remove are empty at the read definitions. There is no generic call here to SunderMind.EndSunder or ForceBubble.DestroyBubble. The prior gap is narrowed: the ordinary direct removal path does not supply those feature-specific calls. Other PartRemoved listeners, object destruction, effect validation or later zone cleanup can still matter. This is a static missing-direct-cleanup finding, not a reproduced leak. ## CL2: psychic battle validates a relationship, not the supplier mutation

MemberOfPsychicBattle has duration9999, an other-object reference and attacker role. EndTurn and BeforeTakeAction remove it for invalid/missing other actor, zone separation, missing counterpart battle effect, or an allied nonplayer attacker. BeforeTakeAction makes a nonplayer attacker PassTurn and blocks its normal action. That supplies the previously missing NPC channel behavior.

IsInvalid does not test that the attacker still has SunderMind. If both valid actors remain in one zone with battle effects, removing that mutation alone is not a listed invalidation condition. The regular SunderMind.EndSunder call would remove both roles, but its own Unmutate lacks that call, and base removal does not add it. Native ordering, PartRemoved listeners and reference disposal after removal remain open. BeforeRender also removes an effect when its other reference resolves null and exposes the two participants' cells to the involved player. [MemberOfPsychicBattle](../private/depth-3/source/XRL.World.Effects.MemberOfPsychicBattle.cs)

## CL3: follower opinion is different from allegiance and support

IOpinion defaults positive opinions to Duration0, negatives to16800, and reapplication cooldown1200. These are data contracts; the final timed-opinion evaluator is not located in this pass. ## CL4: temporary descendants include inventory, equipped gear and implants

Inventory.GetContents adds stored objects. Body delegates to BodyPart.GetContents, which adds equipped gear and cybernetics once, recurses child body parts, and does not add default behavior in that enumeration. Inventory's generic event cascade forwards to stored objects when cascade bit2 is enabled, using a copied list for dispatch. Body's generic eligibility uses bit1; BodyPart forwards to equipped, implanted and default objects while guarding first-slot duplication and recursing child parts. MakeTemporaryEvent's declared271 cascade therefore has relevant body/inventory routes, extending the prior capture beyond just its root handler. World-map and exclusion flags still affect some generic routes; their whole event graph is not declared closed. ## CL5: final rifle effects close two different limits

Suppressed rejects nonmobile actors and ApplySuppressed vetoes. Its LeaveCell handler charges1000 energy and vetoes movement only when duration>0, movement is not Forced and Type is not Teleporting. It is therefore not universal displacement immunity. Reapplication extends the found duration but returns true afterward; duplicate-instance behavior depends on ApplyEffect's caller and is not silently treated as a merge-only effect. [Suppressed](../private/depth-3/source/XRL.World.Effects.Suppressed.cs)

Disoriented owns -Level DV and MA shifts. It vetoes on ApplyDisoriented, otherwise extends a same-strength duration or chooses the incoming Level/Duration when their product is greater. The replacement branch updates fields without visibly reapplying shifts there. Removing reverses owned shifts, and copy-without-effects hooks unapply/reapply. Higher-strength replacement must be checked before assuming the displayed field immediately matches live DV/MA. This is static code evidence, not a demonstrated UI defect. [Disoriented](../private/depth-3/source/XRL.World.Effects.Disoriented.cs)

Terrified creates a real Flee or FleeLocation goal, panicked and indefinite in the goal constructor, tied to a finite effect duration. It resolves a source ID or location, can pick a visible source if none is given, requires a Brain, replaces existing Terrified, and invokes FearApplied. Its removal calls Goal.FailToParent, connecting effect cleanup to planner cleanup. The goal is nonserialized; action-start validation can recreate it after load. The shared movement-goal outcome and escape quality remain unobserved. [Terrified L95-203](../private/depth-3/source/XRL.World.Effects.Terrified.cs)

## CL6: flight has source-aware failure and different risk rolls

GetMoveFallChance takes the best eligible source's BaseFallChance-Level, clamped at zero; GetSwoopFallChance instead uses4×BaseFallChance-Level. MaintainFlight separately tests ongoing-effort movement eligibility, active PowerSwitch, and outside the world map rolls1..200 against the particular source's BaseFallChance-Level. These are distinct contexts, not one universal fall percentage.

StopFlying removes the matching-source effect, with a fallback to another Flying effect if none matched; toggles its ability and emits source-stop events. Only the last counted flight effect triggers full NotFlying events. It gravitates afterward. FailFlying first stops movement, invokes StopFlying with failure semantics, starts5 involuntary cooldown and, when the last source fails, applies Prone and emits full failure/position events. Multiple suppliers can preserve flight while one fails. Final gravity/falling HP damage remains in downstream movement/physics, not proven by this helper alone. [Flight L151-246,320-377,408-456](../private/depth-3/source/XRL.World.Capabilities.Flight.cs)

## CL7: recoiler power can be paid before final transit succeeds

ITeleporter refuses no destination or nearby hostiles when combat use is disabled before the power check. It resolves the destination zone, then requests active status with UseCharge=true before custom/subject failure handling. Plane/world/protocol compatibility has distinct flags. Finally it calls ZoneTeleport; only success records LastTurnUsed. The previously traced onboard wrapper pays its1000 energy and cooldown only on true, but that does not imply already used source charge is refunded when later transit fails.
