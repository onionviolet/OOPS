# Alternate references, body identity and restoration

## A6-1: a damage-history holder can save an otherwise detached actor

A concrete ordinary assignment chain exists. `GameObject.TakeDamage` builds a TakeDamage event containing the owner/attacker, source and phase, then sends it through `FireEvent`. The TakeDamage branch invokes Physics.ProcessTakeDamage. That method reads source/attacker/owner, rejects incompatible phases, then sets `LastWeaponDamagedBy` from Weapon, `LastProjectileDamagedBy` from Projectile, and `LastDamagedBy` from Owner or Attacker. The assignments occur near the beginning of the pipeline, before its full downstream damage resolution. The static example therefore requires that this assignment branch was reached; it does not require this audit to claim every attempted hit deals positive HP damage. [GameObject L6141-6182,6202-6223,8125-8142](private/source/XRL.World.GameObject.cs); [Physics L3185-3226](private/source/XRL.World.Parts.Physics.cs).

The generated Physics writer calls ValidateGameObjects, then writes each of LastDamagedBy, LastWeaponDamagedBy, LastProjectileDamagedBy and InflamedBy with the ordinary full-body `WriteGameObject` overload. This is materially different from writing only an ID or reference wrapper. ValidateGameObjects only applies GameObject.Validate to each field. Validate rejects null and invalid objects, clearing an invalid ref. The entire IsValid helper defines validity as nonnull, having Physics, and not being in a graveyard. A living contextless actor still qualifies. No same-zone, active-zone, current-cell or explicit-importance filter occurs on this path. [Physics L496-521,662-668](private/source/XRL.World.Parts.Physics.cs); [GameObject L2325-2352](private/source/XRL.World.GameObject.cs); [complete validity helper](private/source/XRL.World.QudGameObjectExtensions.cs).

Conditional combination: actor A reaches this damage-history assignment on saved object B; the unresolved vortex later queues A, removing its world context and scheduler entry; B still holds A when B is written. B's Physics writer enrolls A's body in the object table. This is a source-supported alternate holder, and disproves a blanket claim that queue omission necessarily prevents every pending victim from being serialized. A concrete live save exhibiting this sequence has not been created or inspected.

Thermal attribution is another version of the same holder: entering aflame, frozen or freezing state assigns InflamedBy to the supplied Actor. The field name therefore covers more than burning alone. It too is written as a full object reference. This audit reads only the assignment windows, not every temperature/event precondition. [Physics L4056-4118](private/source/XRL.World.Parts.Physics.cs).

These are transient historical links with actual cleanup. A later damage event overwrites all three damage-source fields, even when event parameters are null. GeneralAmnesty clears all four. Suspending also clears all four. Invalidity cleanup can clear them before writing, and reset clears them when the Physics instance resets. Therefore the example requires B's relevant field to remain set until the body-writing pass; a suspended holder can lose this particular route. These are conditions, not a universal retention guarantee. [Physics L2216-2223,3127-3134,3185-3226,662-668](private/source/XRL.World.Parts.Physics.cs). Full reset/pooling and every emitter of the clearing events remain bounded by the primary research graph.

## A6-2: object-table identity preserves data, not placement

Ordinary WriteGameObject writes a null marker for null, reuses an existing token for an enrolled object, or adds the object to TokenGameObjects/TokenByGameObject and marks it pending serialization. The full-body pass loops against the changing table count, so body serialization can discover and append further objects. It writes each enrolled body using GameObject.Save, including its parts, before clearing that object's pending-write bit. Cyclic damage-history graphs therefore reuse tokens instead of recursively duplicating every referenced object in these methods. [writer L3019-3109](private/source/XRL.World.SerializationWriter.cs); [GameObject L1903-1968](private/source/XRL.World.GameObject.cs).

The reader allocates a GameObject placeholder for every table entry before reading the bodies. ReadGameObject returns the placeholder for a normal token, preserving shared identity even when the body is read later. ReadGameObjects reads each indexed body into its already allocated object with GameObject.Load, with framing/error recovery. Parts are then reconstructed. This is a graph reconstruction operation, not a cell placement sweep. [reader L125-240,417-455,566-662](private/source/XRL.World.SerializationReader.cs); [GameObject L2047-2120,19326-19340](private/source/XRL.World.GameObject.cs).

Physics writes and reads its current cell, inventory owner and equipped owner directly. Its Read assigns those backing fields from the stream. Attach only installs itself as the owner's Physics component. If the actor was genuinely contextless when written, these context fields are null and remain null on this core reconstruction path. A null cell writes only a null zone ID and ReadCell returns null; it does not select a fallback cell. A nonnull cell uses zone ID and coordinates, which may require retrieving the zone, but that is a different saved state. [Physics L496-568](private/source/XRL.World.Parts.Physics.cs); [writer L2704-2715](private/source/XRL.World.SerializationWriter.cs); [reader L1298-1308](private/source/XRL.World.SerializationReader.cs).

GameObject.Load invokes each part's ObjectLoaded after loading parts and legacy registrations. FinalizeRead resolves delayed external part binds, then finalizes effects and parts. Generic reader finalization reads event registries and finalizes every tokenized object, clears external-bind scratch state, runs compatibility and removes explicitly flagged invalid objects. None of the inspected generic loops assigns a cell simply because an object is contextless. The compatibility method returns immediately for file versions above400; its older branch adjusts particular fist equipment and regenerates body defaults. RemoveInvalidObjects handles an explicitly maintained invalid list; it does not iterate all contextless actors as an orphan sweep. [GameObject L2207-2245](private/source/XRL.World.GameObject.cs); [reader L665-765](private/source/XRL.World.SerializationReader.cs).

This audit does not enumerate every part/effect's custom ObjectLoaded or FinalizeRead callback for every possible queued actor. An unusual actor may contain behavior that assigns context or activity. A retained body can also be moved later by another owner. The proven statement is that the named core restoration paths do not recreate the lost vortex transport relationship or place a null-context victim automatically.

## A6-3: delayed reference wrappers can share a preserved body, but do not preserve it alone

The two WriteGameObject overloads differ. The reference-aware overload first reuses a previously enrolled object token even when Reference is true. If absent and Reference is false, it enrolls the body. If absent and Reference is true, it writes the existing string ID property with marker1, or writes null if that property is absent. It does not automatically generate that string property in this branch. A positive BaseID and an existing string ID property are separate facts. [writer L3038-3067](private/source/XRL.World.SerializationWriter.cs); [GameObject L393-449](private/source/XRL.World.GameObject.cs).

GameObjectReference.Set records the object's integer BaseID and caches the object pointer. Its Write writes that integer and then calls the reference-aware overload with Reference true. Read stores the integer and result of ReadGameObject; the wrapper itself supplies no body construction, context placement or activity registration. The complete wrapper class contains no automatic retry or fallback search of its integer ID. Individual consumers of the wrapper can impose further policies. [complete wrapper](private/source/XRL.World.GameObjectReference.cs).

The important timing is deliberate: Writer.Write(GameObjectReference) only queues the wrapper in a separate reference table. FinalizeWrite first writes all enrolled GameObject bodies, then event registries, then appends token tables. AppendTokenTables writes the queued wrappers before the generic token-object table. Thus a party/leader reference wrapper can reuse A's body token if another ordinary holder, such as B's Physics, enrolled A while the body pass ran. Without that enrollment it falls back to the string ID/null branch. This audit does not treat later generic token-object serialization as an unrestricted guarantee of enrolling bodies after the body pass. [writer L2730-2743,2832-2910](private/source/XRL.World.SerializationWriter.cs).

On read, Start preallocates table placeholders, then reads the reference wrappers before the full bodies are loaded. Token references can therefore attach to the same placeholder that will later receive A's body. Marker1 instead calls GameObject.FindByID at that time. The read FindByID(string) checks its one-entry last-find cache and searches the active and cached zones, returning null if none is found. It is not a scan of the reader's entire token table and does not construct a body merely from an ID. The wrappers' own integer field remains data, even if their Object pointer is null. Exact party/leader consumer fallback behavior belongs to the primary lane. [reader L181-240,432-452](private/source/XRL.World.SerializationReader.cs); [GameObject L3080-3121](private/source/XRL.World.GameObject.cs).

This combination means two NPC relationship references that look identical in game terms can deserialize differently depending on whether some independent full-body holder enrolled the target. The report makes no native claim about which naturally spawned NPC currently has such holders.

## A6-4: contextless nonplayer activity is explicitly rejected

MakeActive without Force requests scheduler admission only when the object has a Brain. AddActiveObject checks validity, nongraveyard status and an Energy stat, and can accept a null-zone actor. But ValidateActor later rejects a nonplayer whose CurrentCell is null. RunSegment removes actors failing this validation before granting energy or beginning their action. The player alone receives an attempted repair to the active zone's spawn cell. Therefore depth5's failed-teleport activation request must not be described as guaranteed continuing NPC activity. [GameObject L3521-3533](private/source/XRL.World.GameObject.cs); [ActionManager L299-327,664-749](private/source/XRL.Core.ActionManager.cs).

Two inspected ordinary activation routes require world membership. ZoneManager.ActivateObjects iterates zone objects, makes them live and active, with a world-map TerrainTravel exclusion. Brain's EnteredCell handler makes an actor active if its entered cell is in an active zone and it is absent from the action queue. Brain.Attach only installs the Brain pointer and combat flag; it does not itself call MakeActive. A tokenized body that remains outside all cells is not selected by these zone/entry routes simply because it was deserialized. ActionManager.Load separately restores its saved queue and ensures the player entry; vortex queuing had removed the normal victim entry before saving. [manager L1695-1765](private/source/XRL.World.ZoneManager.cs); [Brain L1364-1378,2043-2056](private/source/XRL.World.Parts.Brain.cs); [ActionManager L85-140](private/source/XRL.Core.ActionManager.cs).

**Bounded fate:** A can survive as serialized object data through B's retained damage attribution. That does not restore the vortex's nonserialized queue, location dictionary or pending destination relationship. On the inspected core routes A can be reconstructed as a still-contextless, inactive actor referenced by B and possibly other wrappers. A later object-specific or external placement rule could change that state. Whole-graph retention, all custom callbacks and native save/load outcomes remain open.
