# Storyteller: several schedulers, explicit eligibility and successful history

**SHOWN F13:** Storyteller.StorytellerTick ticks the incident queue then samples components every 1000 game ticks. MakeIncidentsForInterval obtains targets, checks component minimum day and target tags, and also considers ongoing enabled quest-part incident makers. It is not one global random event list. TryFire requires CanFireNow and TryExecute success before Notify_IncidentFired and lastIncidentTick. StoryState stores per-incident fire ticks, recent random incidents/quests, last big threat and population-count history. Forced incidents skip normal target history recording in Notify_IncidentFired. An attempt, a fired incident and a finished quest are distinct; quest lifecycle remains in the prior aspect report.

**SHOWN eligibility:** IncidentWorker.CanFireNow checks target admission, earliest day/difficulty, threat point range, biome, layer whitelist/blacklist, scenario switches, population, refire spacing, Anomaly level, active map conditions and endgame restrictions. Forced/bypass flags have narrower branch effects, not a universal permission model. It then calls the subclass admission, with a same-tick cached result. The cache is keyed by worker/tick in this body, not every parameter tuple; multi-target same-tick behavior was not dynamically checked. Never copy that cache blindly into an actor-aware eligibility projection.

**SHOWN selection:** StorytellerComp.UsableIncidentsInCategory separates ordinary/Anomaly pools and asks current eligibility. IncidentChanceFinal multiplies the worker base chance, current-population curve, population intent factor, current incident factor and recent-occurrence penalties, then floors at zero. RandomMain first samples an MTB opportunity, chooses weighted categories with a maximum-large-threat-interval preference, then uses a population-increase/nonincrease selection split with fallback. Space changes spacing and MTB parameters. A weight of 2 is not two incidents a year.

**SHOWN scheduling:** OnOffCycle calls IncidentCycleUtility. It builds deterministic potential interval hits from persistent world random value, target seed, component index and cycle number. It spaces hits inside on/off windows using bounded attempts, then accepts a fraction according to day/threat/progress curves. Target admission can still reject a scheduled opportunity. The seeded calendar is different from RandomMain's stochastic MTB timing. Swapping component order or content can affect seed identity; source pins matter.

**SHOWN F14 population:** StorytellerUtilityPopulation sums actors across maps/caravans/transports. Babies count zero; juveniles interpolate from a child weight toward adult weight, prisoners/slaves apply their own multipliers, and borrowed colonists add to the value. Quest intent includes pending nonhistorical population-increasing quests. CalculatePopulationIntent reads a population curve and scales positive intent by population-adaptation days. BaseStoryteller XML crosses from positive to zero around 11 and negative by 20 in its curve; that is selection pressure, not a hard colonist cap. Each storyteller can override curves. Whole-game recruitment and raid death policies were not read.

**SHOWN F15 threat:** DefaultThreatPointsNow has separate wealth and pawn contributions, health/age/slave/cryptosleep adjustments, target random range, adaptation, difficulty threat scale and days-passed factor, clamped by the source. Do not confuse this threat budget with population intent, per-incident eligibility, or final incident chance. Odyssey copies StoryState into the mobile carrier, so moving need not erase recent incident history, but every arrival merge edge was not proven.

**INFERRED RW-D7:** extend P10/P12/P13 using existing storylet/event owners and K12/K18/K32/K34: known admission reason, scheduling policy, candidate selection, attempted command, successful occurrence receipt, saved aftermath and recurrence identity. No hidden event names in player diagnostics. Start with one harmless recurring opportunity plus one ineligible control. A quiet rejection must neither spend stock nor start a success cooldown. Canon-calendar events should follow the branch integration owner's stable same-time ordering, not an independent timer. This donor is not authorization for browser-closed injury, forced bad events or population caps.
