# Odyssey: one traveling home, several rule domains

**SHOWN F1:** `Gravship` stores actual thing/pawn objects with local position/rotation, roofs, foundations, terrain, gas, power state, parent connections, movable areas, storage groups, slaughter settings and room temperature/vacuum records. Its constructor captures valid connected substructure and copies map StoryState. `GenerateGravship` performs PreSwapMap then despawns those originals, removes ship terrain from the old map and creates a world object. `GravshipPlacementUtility` places retained things/pawns and runs PostSwapMap. This is object transfer plus local coordinate reconstruction, not regeneration from a colony template. Pawn gene/ideology/skill/relationship trackers stay with the pawn object; every nested tracker was not audited.

**SHOWN F2:** current XML has concrete Surface and Orbit plus abstract OrbitLayer. Orbit inherits space defaults, disables caravan formation, opts into restrictive incident/arrival/game-condition admission, sets a smaller raid points factor and changes distance scaling. `PlanetLayer.TryGetPath` exposes layer connections; `TryGetPathFuelCost` requires a layer path, adds its cost, projects the origin to the destination layer, then adds traversal distance multiplied by destination range factor and fuel rate, with a minimum cost. The shown orbit range factor is 20. This source formula is not a YAIRPG quote implementation; its cache keys and every caller were not validated.

**SHOWN physical consequence:** Odyssey's Space biome declares vacuum. `VacuumUtility.PawnVacuumTickInterval` requires Odyssey, spawned pawn, vacuum biome and vulnerability; local vacuum must reach 0.5. Severity is proportional to vacuum and remaining vulnerability after VacuumResistance. Active genes can prevent vacuum burns; apparel/body coverage has its own reader. A place rule interacts with the same traveler body. It does not simply subtract levels on arrival.

**SHOWN F3:** `WorldComponent_GravshipController.TakeoffEnded` abandons the departure map unless a grav anchor was detected, otherwise updates bill destinations. `AbandonMap` notifies and removes left-behind pawns and abandons the parent. `Gravship.CheckAffectedGoodwill` also checks transported nonplayer pawns for kidnapping consequences. Moving a passenger has social meaning. `Gravship.TickInterval` advances transit and chooses arrival into an existing map or generation of a new one. `TickManager.DoSingleTick` visits loaded maps and advances world/story/quest work on one game clock. This is not browser-closed catch-up or independently frozen universes.

**SHOWN persistence:** Gravship.ExposeData distinguishes deep retained pawn/thing objects, reference connections, Def terrain IDs, spatial data, travel progress and StoryState. Placement reconnects infrastructure and restores some local context. Copying story history matters: changing a physical address need not erase recent pacing history. It does not prove exactly-once recovery across an interrupted takeoff or landing.

**INFERRED YAIRPG:** RW-D4 should use the nested-world owner's existing carrier table: traveler/body/controller, learned method, physical fuel/tool, credential jurisdiction, passenger consent, departure-place disposition and each clock. Link K2/K5/K15/K18/K25/K28 and P05/P13/P16/P23. Existing start/branch integration requires full native owners and staged effects; do not replace a save with a derived arrival snapshot. A persistent houseboat or workshop is a NEW spatial carrier subcase, not a reason to build a general vehicle system now.

**Limit:** orbit and surface are layers of one RimWorld world. No arbitrary magic conversion, soul/body substitution, alternate timeline duplication or independent universe engine was shown. Native ship transfer, vacuum, multiple maps and save/reload were not run.
