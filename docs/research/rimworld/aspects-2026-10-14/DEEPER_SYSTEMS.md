# Highest-payoff previously incomplete systems

Selection: the prior feature aspect pass explicitly left A01 dialogue/quest grammar, A02 quest closure and A04 migration/autosave unread. These three offer the largest useful extension to the older five mechanic traces. Each analysis is source-grounded; YAIRPG transfer is inferred. Nothing here selects an implementation.

## D1: Conversation as an occurrence, a grammar request and an action surface

**Shown, social path:** Pawn_InteractionsTracker.CanInteractNowWith rejects unavailable/cooldown/position/capability cases. TryInteractWith rejects self-targeting, adds initiator/recipient memories and skill XP, checks a social fight, then either calls the worker or skips ordinary worker aftermath. Bubble, last-interaction state and PlayLog entry follow. AddInteractionThought scales effects through the other pawn's SocialImpact and records that pawn as source. InteractionWorker_Insult supplies a small base weight multiplied by directed negative-interaction factors. This joins a relationship reader to selection and an actual memory writer, rather than treating a sentence tag as a relationship mechanic.

**Shown, language path:** InteractionDef holds worker, effects and separate initiator/recipient log packs. PlayLogEntry_Interaction stores actor references and extra sentence packs. ToGameStringFromPOV_Worker pushes RNG state, seeds by logID, selects a perspective pack, adds RulesForPawn constants, resolves r_logentry and extras, and restores RNG state. GrammarResolver filters by constants, tags, usage, priority and customizer bucket, reduces repeated-rule weight, backtracks unresolvable rules and bounds depth/loops. Failed translated resolution falls back to untranslated rules. It is not an LLM or a single giant dialogue tree. A changed grammar pack or pawn state can still change later wording.

**Shown, player choice path:** FactionDialogMaker.FactionDialogFor selects relation-sensitive greeting keys and capability-based options, decorating social-disabled actors. RequestTraderOption requires ally standing, an allowed seasonal temperature and elapsed cooldown; each requestable trader can also require a title. Its accepted callback adds TraderCaravanArrival with fire/retry ticks and concrete faction/trader parameters, writes lastTraderRequestTick and spends goodwill. It then links to a result node. DiaOption supports both stored links and linkLateBind. Action runs before the linked node is chosen. This is a reusable framework, not an assertion that all callbacks recheck every predicate at click time.

**Failure/limits:** a log with missing participant refs returns an error representation; fallback text does not repair a lost social consequence. A fight can replace worker aftermath after initial effects were applied. The flag named ignoreTimeSinceLastInteraction does not bypass CanInteractNowWith's unconditional early cooldown. No transactional commit boundary or exact crash recovery is established. Speaker labels, relation, social skill and symbols were read; portraits and every conversation builder remain unread.

**PROPOSAL P1/P4:** use an original stable occurrence with speaker, target, host result and render seed. Persist host results first, then render a cosmetic view without issuing actions. Return choices should query current world state. Recurring conversations get distinct occurrence identities as often as the world permits. Existing character/dialogue owner: `docs/CHARACTERS_AND_WORLD_EVENTS.md`; execution contracts: `docs/ENGINE_EXPANSION.md`. Do not copy dialogue, character lore or donor wording.

## D2: Quest lifecycle separates offer, activity, outcome and cleanup

**Shown, state:** Quest stores offer/accept/expiry ticks, accepter, root script, owned parts, outcome, cleanedUp and cleanupTick. Its State derives from these fields. Accept runs PreQuestAccept hooks, records accepter/tick and emits its scoped Initiate signal. Notify_SignalReceived admits global or matching Quest{id} tags and dispatches according to each part's listen mode. The SignalManager transports signals synchronously to receiver snapshots, catches exceptions and caps work per frame. It is not a durable message queue or a delivery receipt.

**Shown, timed work:** QuestPartActivable admits first enable or explicit reactivation. Enable stamps game tick and announces activation. Complete first checks active state, changes it to Disabled, then emits the part completion and authored outgoing signals. QuestPart_Delay waits until enableTick plus delayTicks; optionally it waits for a home map too. Duration and source enableTick are serialized. Relative countdown, absolute-date tooltip, alert critical threshold and targets derive from the same deadline. This is a useful distinction between saved cause and derived presentation.

**Shown, closure:** Quest.End refuses historical resolution, writes outcome, invokes guarded cleanup and optionally sends typed letters/sounds. Cleanup calls every pre-cleanup hook, every cleanup hook, then marks cleanedUp and notifies managers. Exceptions are logged per hook, so a cleaned-up flag does not prove every side effect completed. Historical quests later discard parts after 1,800,000 game ticks; the record remains distinct from live handlers. Quest.ExposeData restores part-to-quest ownership and removes null parts. Reward implementation for every part is not reviewed.

**Failure/limits:** disabling before signal emission protects the same enabled interval from repeated Complete calls, but explicit reactivation can allow a later interval. It is not a universal once-only limit. Save/reload must include activated interval identity and consequence state to avoid double settlements; donor source alone does not prove this property across every reward part. Signal storms are cut off at a frame ceiling, and receiver exceptions can leave partial consequences. Script generation and all 156 raw QuestScriptDef records are indexed but not semantically traversed.

**PROPOSAL P3/P5:** keep authored offer, accepted commitment, deadline, outcome, handler cleanup and journal retention separate in the existing event owner. Give repeatable events new interval IDs and explicit per-world recurrence. Test pending reload, deadline crossing, expired offer, lost target, repeated signals and historical journal reopening. Owner: `docs/CHARACTERS_AND_WORLD_EVENTS.md`; persistence and scheduling contract: `docs/ENGINE_EXPANSION.md`.

Sources: source/RimWorld.Quest.cs (State, QuestTick, Accept, End, ExposeData, Notify_SignalReceived, CleanupQuestParts), source/RimWorld.QuestPartActivable.cs (Enable, Complete, Notify_QuestSignalReceived, ExposeData), source/RimWorld.QuestPart_Delay.cs, source/RimWorld.SignalManager.cs.

## D3: Save compatibility is staged policy plus concrete repair hooks

**Shown, write:** GameDataSaveLoader.SaveGame writes metadata and a deep Game through SafeSaver, updating lastSaveTick after the helper returns. ScribeSaver creates XML, tracks internal errors and refuses to finalize after serialization trouble. New saves write directly. Existing saves use new/current/old rotation; promotion failure removes partial files and tries restoring old. leaveOldFile preserves the prior copy in permadeath. SafeSaver first clears stale .new/.old files, so stale artifacts are not an automatic recovery chooser. SafeMove makes bounded retries. These are actual source branches, not demonstrated atomicity.

**Shown, preflight/load:** PreLoadUtility reads metadata and presents mismatch dialogs; header failure logs and resets Scribe but does not universally reject the load action. ScribeMetaHeaderUtility records build version and ordered running mod IDs/names; ordered mod comparison is significant. BackCompatibility.IsSaveCompatibleWith broadly allows earlier same-major 1.x minor versions. A converter chain applies version-qualified pre/post-load, def-name and object repairs. A permissive version policy is not evidence that every changed field is safely migrated.

**Shown, reconstruction:** ScribeLoader loads XML variables, resolves cross-references and invokes post-load initializers. Game.LoadGame clears caches, constructs world/maps, finalizes references and spawn/init work, then invokes loaded-game and post-compatibility hooks. Selected absent/null maps/parts have repair paths; others log or throw. Generic deep/value/reference helpers establish different ownership and identity roles. Cached RulePack rules and alert objects are not the durable records that generated them.

**Shown, autosave:** Autosaver counts simulation ticks, delays while save-blocked, resets its counter when scheduling, chooses unused configured slots then the oldest existing slot, or uses the unique permadeath file. GameDataSaveLoader.SaveGame catches and logs errors, so the autosaver is not a verified-success retry loop. No wall-clock elapsed-time integration appears in the reviewed Game.LoadGame/TickManager paths. An idle RPG needs an explicit passive/offline policy instead of inferring one from this donor.

**PROPOSAL P2:** candidate load should parse, migrate, resolve identities, validate actual consumers and rebuild caches before replacing the currently playable state. Keep failed imports reviewable; define compatibility per field/content identity. Write-failure and corrupt-import checks must use disposable generated saves, never user saves. Owners: `docs/ENGINE_SAVES_AND_SCALE_REVIEW_2026-10-11.md` and `docs/ENGINE_EXPANSION.md`. Individual converter bodies, power-loss behavior, user saves and runtime recovery remain untested.
