# Proposed implementation packets

Research handoff only. No packet is accepted or executed. Read the live owners and recover current writer reservations before edits. One playable slice precedes the next. Source examples refer to the pinned KoLmafia client and dated wiki sources in [SOURCE_LEDGER](SOURCE_LEDGER.md).

All packets reuse native item, skill, quest, clock and save owners. No second inventory, timer, XP authority or hidden client allowance. Browser checks use a fresh origin after rebuilding. Proposed desktop target: 1440×900, with rule/reason, current means and useful actions visible together. Mobile optimization is deferred. Persistence gates include Save/reload and literal-file Import; a passing source test does not prove them.

## P1: action-aware optional rule profile

Owner: LIFE_SIM_NORTH_STAR and ENGINE_EXPANSION; inspect `chronicle.js`, capability admission, inventory/equipment and native action consumers. Reference: Bees/G-Lover item predicates and YouRobot permission consumers.

Outcome: select one original optional profile at a supported start. One normally valid action becomes conditionally unavailable or transformed, with an explained alternative. Preserve underlying ownership. Scope excludes a universal challenge catalogue, copied KoL classes and mandatory restrictions on ordinary play.

Persist only selected profile ID/revision and necessary earned state. Ordinary old saves retain baseline behavior. A rule must apply to the real action commit and to queued execution, not only hide a button. UI preview must agree with the same admission result.

Done: acquire the affected tool naturally, show an allowed control and a denied/transformed action, obtain the stated alternative and produce a useful native result. Rebuild and observe it at the target viewport. Save/reload/import preserve the chosen profile and owned tool without replaying rewards. The director's feel judgment remains separate.

## P2: existing skill, new learning route

Outcome: one authored optional place or teacher teaches one existing useful method after evidence that fits the world. A selected queued/idle learning route is permitted where lore supports it. KoL's exact four-turn cadence is a source example, not tuning authority.

Persist visit/practice evidence through the current job and actor owners. Award knowledge through the real learning path, then let existing XP/mastery continue. Exclude 180-skill mapping, randomizing all teachers and a parallel discovery XP counter.

Done: show the missing method, perform the supported learning activity, learn it, then use it for a concrete task. A control visit without the qualifying activity does not teach it. Reload/import during and after learning retain exact progress and do not replay an earned grant. Repeatable study stays possible under its declared terms.

## P5: explicit mode-exit conversion

Owner: ENGINE_EXPANSION, TIMELINES_AND_DIVERGENCE and save/transition owner. Reference: Tiny/Grey You/Robot/Shadows aftercore differences.

Outcome: for one already-supported mode, preview what remains owned, what becomes inactive and how body/resource values translate at exit. Exit is a supported transition with validated inputs, not a string change that replays initialization.

Persist the necessary transition evidence in the current owner. Specify old-save compatibility and definitions that changed since the run started. Leave repeat entry and different world exit policies reachable. Exclude deleting personal saves, global stat resets and adopting KoL's 40-turn clamp.

Done: naturally exit with both retained and mode-bound state present. The preview matches the actual result; no negative/overflowed resource appears. Reload/import before and after exit yield coherent behavior and no duplicated grant. An interrupted transition restores to a supported state.

## P8: scoped renewable allowance

Owner: ENGINE_EXPANSION; energy_resources, game_time and jobs. Reference: Tome shared/per-source scopes and robot resources.

Outcome: one supported module exposes an allowance with an explicit owner, unit, recovery source and clock. Compare a shared pool with a per-source reserve only if that decision is actually unsettled. Do not add a daily cap simply because KoL has one.

Ordinary unfed play and optional alternate world policies remain supported.
