# Top three deeper systems

Ranked for payoff at the inspected source seams. PROPOSALS only. All paths, revisions and function locators are in ASPECTS.md; the private hash census pins source bytes. Other inventoried modules remain identified or prior-documented, not newly audited.

## DS1 Choice response adapter

ChoiceUtilities parses encounter ID, numeric option and visible label separately. ChoiceManager iterates responses, checks script intervention, stops for manual handling, and notices fight redirects. Missing whichchoice can be recovered from selected encounter-name fallbacks; a page can legitimately provide only a continuation link. The architecture survives heterogeneous HTML by using specific exceptions. It does not reveal server branching predicates or dialogue speaker records. YAIRPG should use native structured IDs and explicit effects, with a manual route for unknown content, rather than reproducing an HTML parser as its authoritative dialogue model.

## DS2 Preference durability

PreferencesFile journals key changes, supports explicit removals, truncates incomplete/corrupt tails and replays sequentially onto the loaded snapshot. On publication it flushes/syncs a temp file, validates it, rotates a valid snapshot to backup and moves the temp into place. Failure leaves journal recovery available. This revision is stronger than a simple whole-file settings write, but it is still client preferences. A partial salvage must not be called an exact restored game. YAIRPG can borrow the last-good publication principle while requiring its own typed envelope/module validation.

## DS3 Quest-state recognition

QuestDatabase maps stable quest keys to progress strings; QuestLogRequest visits several journal pages before finishing at the normal section. QuestManager and specialized handlers also update inferred progress from other responses. Thus the visible journal and immediate encounter evidence both feed the client projection. Text matching can break when wording changes; structured state should be primary in YAIRPG. Keep current objective, completed consequences and alternative route requirements separate. No global story graph or server event scheduler is proven by these adapters.
