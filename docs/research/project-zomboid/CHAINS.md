CH8: Recipe `time` is not one universal clock. Manual `ISHandcraftAction.getDuration` returns recipe character time times 5, then base action modifiers apply. Recipe details divide character time by 10 for their seconds label. These source paths should not be silently equated with world-time drying. No wall-clock timing was measured. `CraftRecipe.getTime(character)` reduces base time when relevant skill exceeds the highest requirement.

CH9: Drying explicitly reads the local environment. Outside precipitation adds temporary wetness, with snow at half that rate. In dry conditions wetness declines by drying factor. While temporary wetness is positive, elapsed work is held. Otherwise elapsed work advances by game seconds times factor. Temperature is clamped 0..40 C, divided by 20; below 20 C the ratio is squared. Thus factor is 0 at/below 0 C, 1 at 20 C and 2 at/above 40 C. This is shown in `DryingCraftLogic.onUpdate/getDryingFactor`, not a proposed global weather law for YAIRPG.

CH10: Drying progress tooltips report temperature category, wetness, rate or pause reasons. `CraftRecipeData.save/load` retains recipe identity/version, elapsed time, inputs, consumed flag and batch ratio. `DryingCraftLogic.save/load` also retains wetness and reconstructs previous elapsed times. A mismatch logs a warning; successful recovery was not exercised. CraftLogic accounts for pending outputs when calculating free capacity and has explicit stop/cancel paths. Exact cancellation refunds and every output publication failure are unread, so do not promise lossless arbitrary interruption.
