## F1–F5 Findings that change implementation

**F1 Source representation needs several independent owners.** Object learning,
colony manifestations, death-triggered activation, restoration, behavior writing
and newly discovered applications are different consequences. A single summon,
damage skill or universal weakness table will erase them. Source acquisition,
holder, manifestation instances, control, application knowledge and effect
lifetime must be distinguishable where the selected power needs them.
Primary examples: JS04, JS06–JS12; secondary exceptions: W1.

**F2 The old engine packet understates existing foundations.** Current source
has same-instance equipment durability/repair, opt-in completion revalidation,
qualified observation and replay, physical native gates, a finite local rewind
and reviewed prepaid offline work. Reuse these where their real semantics fit.
They do not establish arbitrary historical restoration, unrestricted memory
access, space erasure or general JoJo time manipulation. Live audit F2/F4–F9
records the exact existing and missing seams.

**F3 Execution and knowledge need separate checks.** Command power gates are
not automatically inherited by encounter responses. Authoritative facts are
legitimate admission inputs, but visible reasons/quotes and NPC decision
predicates must not expose facts their holder cannot learn. Common command
plumbing alone does not prove NPC/player knowledge symmetry. Audit these at
each native, response, controller and routine consumer, not only the button.
Live audit F2/F9/F10 owns the inspected failure paths and probe status.

**F4 Actual transformations need identity and declared settlement order.**
Touch requires supported contact rather than shared location. Repairs must
retain the appropriate object and custody; transfer must name exactly what
moves and what the donor loses. Delayed use needs live source/target support
checks. A deterministic scheduler is useful, but does not resolve every
fictional simultaneous interaction. Independent vital clamps do not implement
a conserved two-body transfer. Live audit F1/F5/F8/F11 covers these boundaries.

**F5 Time and continuity cannot be one toggle.** Stopped action, historical
replay, acceleration, local rewind, forecast and parallel-world travel need
different contracts. Generation range can also differ from the range in which
an emitted effect remains active. Retain source-specific rules and unknowns;
do not copy adaptation/game/novel exceptions between continuities.
Primary JS05/JS13/JS16 and secondary W4/W6 supply representative anchors.

## D1 Implementation sequence

The candidate is C2-JF, an original local discovery/interaction proof drawn from
the existing conceptual packet. Its everyday outcome, multiple response routes
and durable aftermath exercise useful shared seams without requiring all later
temporal/topology systems. Exact hidden mechanics stay in the agent-only fixture;
the public design owner records safe route IDs and acceptance status.
This is a delivery candidate, not an accepted campaign or a mandatory Frontier
opening. One realm and the existing prestige milestone remain intact.

| Task | Concrete work and reused owners | Completion gate |
|---|---|---|
| I1 Freeze fixture and evidence | Choose explicitly original semantics for C2-JF; retain source comparisons as comparisons. Bind target identities, actual means, routes, interruption and counterpart policy. | Every selected consequence has one owner, a saved fixture rule and a visible route; source uncertainty is not silently filled as canon |
| I2 Unify activation and safe projection | Reuse registered powers/preview, native gates, knowledge and observation; add only needed scene contact and common response/command support checks. | Invalid/stale/lost-support use rejects correctly; NPC and player obey the same means; visible UI reveals only held evidence |
| I3 Add minimal actual transformation | Reuse custody/acquisition, object identity and durable staged publication; name the selected function/object consequence and ordered receipt settlement. | Same target, real debits and exact donor/recipient consequences; replay cannot duplicate a result |
| I4 Join playable content | Native opening of optional encounter, useful investigation, different routes, withdrawal/abstention and ordinary-life aftermath. Learned repeat work uses supported automation only. | One connected journey playable from a generated fresh start; no parallel stock, reward path, clock or mandatory chore meter |
| I5 Prove compatibility and delivery | Add absent-domain defaults/validators or migration as required; rebuild and run fresh-origin native UI, save/reload/import and failed-storage cases. | Evidence belongs to each changed behavior; source/build passing alone is not gameplay acceptance |

Later source-selected slices can earn general memory constraints, original-form
repair, spatial topology, temporal domains, paired vital transfer or exact
source-instance copying. Do not build them all as speculative prerequisites.
Strong powers keep their actual functions; mandatory nerfs, slot ceilings,
mana pools, weakness puzzles and universally obtainable counters are not added.
