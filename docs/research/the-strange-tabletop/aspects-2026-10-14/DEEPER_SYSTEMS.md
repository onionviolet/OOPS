# Three deeper systems

## D1: Translation is an ordered change of context

**STATED, S01/S02:** departure selects a different recursion; arrival adapts form, equipment context and basic local knowledge. Descriptor/type remain; focus normally changes, with a draggable exception. Local choices and return position generally remain stable. Equipment is in local abeyance while current Pools remain shared. These statements require several owners even when one human GM adjudicates the whole crossing. Inapposite passage bypasses adaptation and basic knowledge grants but cannot guarantee local functionality.

**SHOWN, S10 printed pp.13-15:** a translation gate supplies a concrete transition; local focus handouts appear there. A nearby active influence lets imported threats retain some powers on Earth. This exception has a cause, range and active condition, not a permanent exemption tag on every creature. The adventure supplies useful known facts about local death and a specialist information verb.

**SHOWN, S13 printed p.10:** Samurai Sky supports Standard Physics normally and Magic under particular lunar conditions. This is why a `world.genre = fantasy` field would be insufficient. Full law taxonomy and decay timing remain unread.

**INFERRED proposal:** preview known changes; stage the real actor, local holdings, source support, return location and disclosure grants; persist; then expose arrival. Derive active support from real local conditions. Store original gear once and restore real remaining stock, rather than reconstructing it from a starting template. MWTS-P01/P02/P04 own proposed checks. No transaction architecture is claimed for the tabletop source.

## D2: The same useful power can wear local clothing

**SHOWN, S13 printed pp.110-111 and 122-123:** cypher entries have level, Earth/Ardeyn/Ruk forms, effect, eligible use and duration. Item shape communicates context. The automated turret entry even adapts its deployed manifestation to a preindustrial Standard Physics setting. This is stronger than merely renaming an inventory line, but does not justify changing all effect math on every border.

**SHOWN, S13 printed pp.10-14:** artifact entries add origin classification and law to level/effect/depletion. Some support Magic or Mad Science. Depletion can have item-specific timing and aftermath. The preview does not provide the full universal artifact border rule; distinguish declared law from a recovered exact enforcement procedure.

**STATED, S05/S07; SHOWN generic S12:** reusable form/power authoring and regular consumable turnover create situational variety. A small carrying allowance is a source-specific mechanism, not a mandatory YAIRPG lifetime cap. Artifacts are not guaranteed permanent just because they are not single-use.

**INFERRED proposal:** keep definition, instance, custody, operating support, remaining uses and displayed form distinct. A changed image/name never remints the item. Do not import generic SRD carrying-limit options from editorial S09 as Strange canon. MWTS-P03 extends existing synthesis P16/P04 rather than proposing a new universal item engine.

## D3: Fiction seeds a living place; it need not freeze it

**STATED, S03; SHOWN, S13 printed pp.4-5:** deliberate worlds coexist with leaked fiction. Emergent recursions and artifacts can develop from interactions and local invention, so original additions are source-supported as a setting possibility. That does not authenticate a changed detail as the original book's canon.

**STATED, S06:** personal-recursion rules and a design/maintenance sheet exist. **UNREAD:** creation resource, timing, prerequisites, size, law choice, expansion, owner control, death and travel exceptions. No invented build cost or procedure is attributed to the book.

**INFERRED proposal:** use the existing K1-K34 card to author an original small destination, with laws, a useful verb and a declared return/carry/clock policy. Keep source setting, continuity/branch, persistent instance and mission IDs separate, as the nested-world owner already requires. A personal home adds local residents, holdings and obligations only through actual content; its seed is not a save file. MWTS-P06 is a new candidate within existing P15/P22 work, not a selected implementation or a prerequisite for current Village work.
