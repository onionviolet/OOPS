## D2 Save merging does not promise rollback

Sources: A04; v1 L3500-3563; v2 L2890-2958.

Shown: Saving enumerates registered state by stable IDs. Loading merges those objects before invoking onLoad/update/assertion. Error handling retains source text but does not undo earlier merges. v1 accepts legacy base64 before compression; v2 strips line breaks and omits that fallback in the read method. Version strings are written, but the traced loader does not dispatch explicit migrations from them.

PROPOSAL: Use detached validation and definition rehydration with versioned compatibility; error backup is separate from atomic rejection.

Boundary: No user save access or executed corruption test.

## D3 Habit averaging and explanation

Sources: A08; v2 L5435-5470,L5557-5585.

Shown: Sleep trend is a saved EMA initialized480minutes, updated on currentDay subscription, with alpha0.00135 and tolerance6 for propagating visible updates. Its displayed five-year wording describes recent years, not a literal rolling archive. Age contributes a separate multiplier, food adds a separate quality modifier. Health then multiplies energy elsewhere. Inferred EMA half-life is ln(0.5)/ln(1-0.00135), about513days, so label and exact numerical response should not be conflated.

PROPOSAL: Use a named habit trend with an honest timescale and transparent contributions; numerical rates remain proposals.

Boundary: Formula read statically, not a physiological claim or gameplay timing proof.
