## What Scroll of Taiwu adds

**TF1. A profession can open functions rather than merely bigger numbers.** Retained `ProfessionData` separately stores seniority, learned skills, historical unlocks and cooldown dates; `IsSkillUnlocked` checks seniority while `IsSkillLearned` reads separate state. The [career digest](../scroll-of-taiwu/aspects-2026-10-14/DEEPER_SYSTEMS.md) traces function completion separately. For YAIR, ordinary practice can open a useful technique, diagnosis or teaching route using our existing learned-skill pattern. A separate profession bar is unnecessary unless it answers a distinct player question. This pass did not trace a particular Taiwu farmer/fisher profession skill, so no such ability is claimed.

**TF2. Match the contribution to the task.** Re-read `BuildingDomain.GetBuildingAttainment` chooses max, sum or average depending on the operation/formula; it returns zero without the required manager. `ClacBuildingTimeCost` sums worker attainment plus baseline contribution for construction. `OfflineUpdateShopManagement` checks leadership and output capacity and can invoke teaching. The word Offline in these method names does not prove closed-app simulation. These are village/facility rules, not evidence of ACS-style physical field jobs or a personal fishing minigame. Adapt the principle: one expert's diagnosis, several people harvesting and an apprentice learning need different contribution rules. Do not give every extra farmhand an identical yield multiplier.

**TF3. Make the choice, means and consequence visible together.** The [existing Taiwu ingredient-to-use trace](../taiwu-ingredient-use-2026-10-15/INGREDIENT_TO_USE.md) follows one herb through different authored products to actual stat/injury consumers. Its [UI evidence](../taiwu-ingredient-use-2026-10-15/UI_EVIDENCE.md) depicts adjacent input/tool/result selectors, storage source, attainment and quoted resource allocation. I directly re-inspected retained official image U1 in this pass: input and tool lists are visibly separate, with custody tabs and detail controls. It is a crafting demonstration, not a Taiwu farming or fishing screenshot. Its original is2560×1440; inspection displayed2048×1152. Actual interaction at1366×768 remains untested.

That pattern fits our **method detail**: selected crop/catch goal, actual means, required competence, known outcome and real cost visible together. Taiwu's authored material families do not establish free chemistry, breeding or procedural recipe invention. Our repeatable discoveries remain a separate proposal grounded in selected world rules.

## Five ranked concrete proposal packets

Every EP is **LATER, unselected**. Observable checks below describe a possible future acceptance demonstration, not authorization to implement or a new mandatory backlog. This pass completes the research/accounting work only.

### EP1. Connect one courtyard crop to Farming

**Gap:** EG2/EG4. **Player example:** keep the existing greens crop and perform its care with personal Farming competence contributing to one concrete choice. A proposed trained inspection could identify readiness/care status from accessible evidence, or a practiced care method could reduce a real care cost. Pick one change; do not invent a stress system merely to make diagnosis useful.

**Skills/powers/discovery:** award personal practice through the existing Farming XP path only for actual completed qualifying work, including legitimate routine completion. Keep MG06 stage notes and evidence attribution. No XP for viewing details, cancelled work or someone else's labor. A power's later contribution is separate from competence. Exact XP and milestone values remain design choices.

**Reuse/cost:** MG06 commands, skill definitions, skill/action effects, native XP publication, existing knowledge. The explicit join between simulation completion and native skill award needs review; source presence in another domain does not prove that join already fits. Preserve native fieldwork and harvesting identities.

**Future demonstration:** same paid seed→crop→existing meal route, with two legitimate care choices giving the promised difference; skill progress once, failed/cancelled work gives no completion reward, state survives save/reload/import. No extra prestige or larger farm required.

### EP2. Give one existing fishing spot a meaningful method choice

**Gap:** EG1/EG3/EG8. **Player example:** continue ordinary routine fishing, or choose a targeted presentation for an already-known catch goal. A skill can improve handling/selectivity; a world-supported sensing/control power can alter access or presentation. A proposal such as current control matters only if that current is represented by a real admission/outcome rule. Do not pretend it already exists.

**Hands-on choice:** optional intervention can select a tactic or respond to an informative situation. Returning to routine retains the same ongoing work and committed outcome. A detailed view or more clicks grants no blanket reward bonus. Routine work can yield an unusual observation too.

**Reuse/cost:** keep native gather/skill/inventory and use one selected spot. Settle the Riverbank XP/display discrepancy before using it to compare methods. Any bait route requires actual bait debit and a relevant catch consumer; otherwise describe the method without imaginary bait consumption. A universal tension minigame is not selected.

**Future demonstration:** ordinary versus selected method changes one declared decision/output distribution; current tool/skill/access and costs remain effective, no reroll by reopening/changing view, catch has one traced useful consumer, and interruption/reload retain the paid state. Source drop rolls can yield multiple species per cycle, so a new 'single catch' intervention would require an explicit compatibility choice.

### EP3. Make one capability combination and one discovery reusable

**Gap:** EG4/EG6. **Player example, original fiction:** an earned perception method notices a recurring feeding sign; a known water-control technique enables a presentation. Alternatively, established plant knowledge identifies a useful growing condition that a suitable power can provide. These are examples to select from, not content claims.

**Proposal:** record observed conditions, executing actor/means, changed variable and actual result; distinguish a correlation, a tested explanation and a reproducible method. Learning a method changes an available action or useful preparation. Learning one use does not reveal every use of a fish/plant. Save method inputs/known conditions and confidence through existing knowledge, with domain-owned resolution rather than a universal recipe engine.

**Power contract:** state the specific constraint changed, coverage/target, real cost if any, activation/expiry and actual result. If a fitting power entirely solves watering or access, let it. Do not impose a manual-first gate, mana tax or ecological penalty to preserve chores. A capability name or aptitude does not itself execute a verb.

**Future demonstration:** a known combination produces its repeatable effect; an unusual result records available evidence without invented certainty; a routine/helper report can carry an observation through an actual route; opening a notebook neither spends time nor reveals sealed/unknown truth. No breeding claim without actual inheritance.

### EP4. Delegate one chore, not an entire new economy

**Gap:** EG5. **Player example:** entrust one harvest-ready plot to one available helper, while personally fishing elsewhere if the existing concurrent-action rules permit. Start with harvest to avoid requiring new continuous watering/growth rules. A power/device that genuinely performs care can be an alternative means in a fitting world, not a mandatory unlock tier.

**Proposal:** reuse an actor job with agreement/access, claimed target, actual effort/competence, input/output custody and defined completion/cancellation. Show who is doing it and where the crop goes. The helper gains their qualifying practice; the player can learn by an actual report/teaching route rather than receiving their embodied skill automatically. Taiwu supplies task-dependent expertise; ACS supplies work-intent versus execution; Immortal Life supplies temporary named-chore coverage.

**Reuse/cost:** existing participant reservation, job preview, clock, cancellation, knowledge basis and foreman pattern are candidates. The current foreman command is specific, so extending it to crops needs a real actor/task join. Do not remove an NPC's normal availability or impersonate a helper with player facts. Avoid extending the manual-first repetition rule to all delegation.

**Future demonstration:** one helper completes one authorized harvest into correct custody; an unavailable/busy helper cannot also work elsewhere; cancellation, access loss, expiry, crop already harvested and save/reload do not duplicate goods/rewards. Background crop growth and browser-closed progress are separate decisions, not implied by delegation.

### EP5. Put routine, focused work and knowledge in appropriate UI homes

**Gap:** EG7. **Target:** populated1366×768 laptop, existing Proto23 composition. **Surface/home proposal:** place summary for the river/plot, activity detail as a shared center view, reference notebook in the existing knowledge home. Actions return through the shared controller to a labelled destination with bottom Back/Esc. Preserve status/current work/full-height log. Projects holds proposed features until selected.

Proposed summary wording, with values always taken from actual state: “Courtyard greens · tended · grow for3 played minutes”; “River fishing · you · routine method · next cycle”; “Harvest assignment · [known helper] · [actual waiting reason].” The first example describes the current authored grow command, not passive growth. A power/assignment row is absent until that means exists and is known. UI controls do not expose raw command IDs, resolver names or engine terminology.

Use text plus icons for stage/blocked/expiry; do not rely on color or transient hover alone. A routine plan explains its stopping condition and shortages. Important decisions follow the existing pause policy, while ordinary results can be summarized. Do not silently spend stock, switch methods or sell an unusual result. Preserve selection/scroll on refresh and avoid one log entry per routine chore. Any later UI execution follows [UI rules](../../UI_RULES.md); present source-backed quotes without claiming undiscovered exact probabilities. Current gathering obscures names but displays chances, so any new experiment preview needs a deliberate known-information adapter rather than exposing the whole catch table.

**Future demonstration:** a player can identify current work, actor, next action, cost and return route from a populated desktop screenshot; opening/closing or switching detail keeps work/RNG stable; keyboard/text-size/unknown-information behavior is exercised; separate human feel acceptance remains open. No prototype or rendered-YAIR behavior claim accompanies this proposal.
