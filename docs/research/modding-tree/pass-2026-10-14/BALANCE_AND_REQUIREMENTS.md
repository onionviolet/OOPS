# Balance and requirements digest

**F3 (shown):** Rewritten's SOFTCAPS registry gives a known limit a title, start threshold, transform family, magnitude and display condition. Root, exponent-root and logarithmic transformations are implemented, with reverse transformations for threshold calculation. A separate side tab renders only disclosed entries. This reduces drift between mechanics and explanation, though descriptions are still authored strings. **F10 (shown):** Communitree's starting self-synergies apply chained softcaps, then a hard ceiling. Aarex upgrades selectively remove softcaps. A higher layer is therefore a change to lower-layer behavior, not merely another currency. These are manually placed feedback controls; no inspected source supports automatic balance. [communitree/js/layers/jacorb.js:49–78](https://github.com/ducdat0507/communitree/blob/38efac6d1b9e68db158c260fcb343d1881b29256/js/layers/jacorb.js#L49-L78); [communitree/js/layers/aarex.js:193–244](https://github.com/ducdat0507/communitree/blob/38efac6d1b9e68db158c260fcb343d1881b29256/js/layers/aarex.js#L193-L244)

**F13 (shown):** Profectus requirements separate visible status, eligibility, whether payment is needed, display and optional bulk support. A visibility prerequisite can be invisible yet still block an action. Arrays implement conjunction, not alternatives. Boolean true is unlimited bulk eligibility, false is zero; numeric eligibility is clamped to one unless maximizing is supported. Costs and non-spent requirements appear in separate groups. [profectus/src/game/requirements.tsx:16–48](https://github.com/profectus-engine/Profectus/blob/d69197d5c7225a0bb58b5a4d5f8e19c1c04a61ea/src/game/requirements.tsx#L16-L48); [profectus/src/game/requirements.tsx:292–372](https://github.com/profectus-engine/Profectus/blob/d69197d5c7225a0bb58b5a4d5f8e19c1c04a61ea/src/game/requirements.tsx#L292-L372)

**F14 (shown):** bulk costs are cumulative by default and maxBulkAmount defaults to one. Small batches can sum directly; larger formulas need inversion and, for cumulative costs, integration. directSum is an accuracy/performance knob. A repeatable adds remaining limit and visibility to the same requirement list, checks eligibility, pays, then increments quantity. Requirement objects are marked SkipPersistence; owned quantities persist instead. [profectus/src/game/requirements.tsx:182–241](https://github.com/profectus-engine/Profectus/blob/d69197d5c7225a0bb58b5a4d5f8e19c1c04a61ea/src/game/requirements.tsx#L182-L241); [profectus/src/features/clickables/repeatable.tsx:105–123](https://github.com/profectus-engine/Profectus/blob/d69197d5c7225a0bb58b5a4d5f8e19c1c04a61ea/src/features/clickables/repeatable.tsx#L105-L123); [profectus/src/features/clickables/repeatable.tsx:182–191](https://github.com/profectus-engine/Profectus/blob/d69197d5c7225a0bb58b5a4d5f8e19c1c04a61ea/src/features/clickables/repeatable.tsx#L182-L191)

**F15 (inferred):** independent affordability is insufficient for shared-resource costs. Two requirements costing seven coins each can both pass at ten coins; sequential subtraction with a zero clamp does not enforce a fourteen-coin total. This is a source-derived counterexample, not an executed test. Likewise arbitrary payment hooks do not establish rollback. Adapt the vocabulary to YAIRPG's planned commit, aggregate aliasing resource costs and verify the quote at commitment.
