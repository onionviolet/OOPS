# Hogwarts Legacy deep pass

The strongest new results are in XP and shields. XP uses cumulative boundaries, and the challenge-progress consumer checks completion before paying again. Talent points accrue for newly crossed levels starting at five. Shield acceptance uses incoming gameplay tags and current defense state; the selected Stupefy bypass is explicitly disabled on Hard. These results now have native consumers behind them, rather than numbers or tutorial wording alone.

AI and dialogue also have useful structure: separate perception profiles, awareness/memory curves, attack-ticket state, companion boundaries, choice visibility/selectability, named conversation results and conditional reward selectors. Full shipped tables and English text, selected readable flows and native pseudocode are preserved in the [gitignored private archive](../private/README.md). Global per-line dialogue effects, the final damage equation and several native AI details remain unresolved. No game, injector or user save was opened; no YAIRPG source, commit or implementation was made.

## Seven ranked new proposals

These are suggestions, not accepted decisions, dispatches or extra gates for another active lane. Existing LP1..LP8 retain their owning proposals and current implementation status elsewhere. If selected, use one small playable slice at a time and YAIRPG's desktop/laptop-first direction. No mobile work, new realm, prestige layer or action-combat port is selected here.

| Rank / code | PROPOSAL | Smallest useful result and cost |
|---|---|---|
| 1 / NP1 | Record why an activity pays and when that source is exhausted | One known criterion grants a receipt and useful progress; repeated exhausted work refuses that same reward without blocking other learning. Requires one award consumer and persistence. It must preserve accepted passive/idle progression, not impose Legacy's global ladder. |
| 2 / NP2 | Resolve typed defenses and control states explicitly | One known defense accepts a supported method/tag, with one authored exception and separate break/reaction/recovery outcomes. Requires a real consumer and clear failure feedback. Colors can explain the rule but do not define capability. |
| 3 / NP3 | Give a small enemy group an attack budget | Independently informed enemies choose actions, then obtain a finite execution slot and cooldown. Requires one visible mixed encounter and interruption/release handling; table weights alone are insufficient. |
| 4 / NP4 | Separate noticing, memory and action | One observer can hear a real noise, accumulate suspicion, remember a last known place and lose certainty. Requires body/site-appropriate senses, bounded update rules and one observable refusal/decay route. |
| 5 / NP5 | Give one meter named gains and one real spend | Show a gain cause, current amount, cost and useful spent result. Requires no duplicate reward after restore and no spending without its actual target/support. Keep combo count and stored resource separate. |
| 6 / NP6 | Make one dialogue choice write one consequential fact | A known choice changes a specific promise, access fact or reward route, and a later consumer reads it. Requires the actual state write, later consequence and reload/import proof, not a generic friendship animation. |
| 7 / NP7 | Select local situations through explicit eligibility | One place/state-eligible situation has a finite cooldown, capacity and completion record. Requires real actor/place ownership and persistence; probability never bypasses missing prerequisites. |
