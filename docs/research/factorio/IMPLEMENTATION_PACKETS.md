# Selected original YAIR implementation packets

These five packets are provisional selections from the broader 14-path research map. They are not all the findings, an implementation dispatch, or a completed game feature. Root integrates any chosen shared/state/native/UI/save changes. Each packet uses the existing durable publication, supported played clock and actual inventory/body/site owners. Rates, names and game feel remain creative-director proposals.

## FAC-P01: A finite retort with two real outputs and a visible stall

At an opt-in Village work site, choose a small resin-distillation batch. It produces useful sealing resin plus spent residue in separate owned trays. Collect, safely repurpose or dispose of residue before further batches; a full tray pauses future starts.

**Source basis:** FAC-03, FAC-04, FAC-07, FAC-10 in [FINDINGS.json](FINDINGS.json).
**Current owner and gap:** Existing command/job/site/inventory/publication owners; a new narrow site-capacity adapter must be explicit. Current deterministic stock-band projection is single-output. Receiver capacity and coproduct settlement need a qualified original adapter.
**Preparation and cost:** Reconcile current resin/material owners; bind exact item keys and actual site rights. Reuse existing finite work plan; do not create another timer. One actual input lot, declared fuel or actor effort and one site reservation. Exact fiction/rates remain proposals.
**Commitment and later use:** At acceptance reserve this batch only and reserve both output destinations. At supported settlement publish both realized outputs and capacity use once. Collection clears the matching tray only. Sealing resin prepares an existing surveying/storage application; residue has a separate authored safe sink with its own costs.
**Time and failure:** Existing supported played clock. Accepted jobs retain pinned definitions and suspension policy; future starts re-quote actual support. Missing fuel/input/site/receiver capacity denies the next batch without spending. Accepted cancellation terms are explicit; output failure cannot silently delete/refund processed material or spill into someone else’s stock.
**Compatibility and ownership:** Optional new records absent in older saves mean unenrolled. Schema/validation decision and generated-save later gate are required; no private save reads. New isolated content/host/definition modules; root owns any registry/native/state/save/UI joins.

**Later observable gate:**

1. A normal batch spends its actual input and yields two distinct owned outputs.
2. Ignoring the residue tray stalls future starts with the cause shown.
3. Collecting/disposing the exact residue re-enables a supported next batch.
4. Cancel/save/reload cannot double input returns, output or site capacity.

**Delivery state:** proposal-only; not implemented; later gameplay/save/failure acceptance deferred.

## FAC-P02: Measure one better tool, then prove its useful function

Use a known stamped brace or lens sample to choose a precise finishing method, ordinary serviceable use, or lossy salvage. A successful finish improves one measurable load/measurement function used in a later task; quality is not just a sale-price badge.

**Source basis:** FAC-06, FAC-07, FAC-13 in [FINDINGS.json](FINDINGS.json).
**Current owner and gap:** Existing native full item keys and unique maker history; current sample/material/fit owner must be reused. Existing item quality fields alone do not establish every proposed new tool function. Reconcile current material/fit adapters before adding one.
**Preparation and cost:** Pin current measured material and equipment functions; preserve continuous native quality and ordinary option. Actual selected object, finishing materials, willing craftsperson time/site and optional premium method.
**Commitment and later use:** Consume/replace the selected owned key once; retain provenance and declared property. Salvage yields explicitly fewer useful inputs plus waste, without returning already consumed fluid/fuel. A later load-bearing job or measurement quote checks the exact object function, not a global fact named quality.
**Time and failure:** One finite job on supported played time; a chance outcome if selected is pinned with its accepted cause. Failed work consumes only declared forfeit inputs and retains an honest remaining object/byproduct; wrong custody/tool fit denies use. A returned object and worn-out object differ.
**Compatibility and ownership:** No global rarity-tier migration. Optional authored object/function ID only, with existing saved item validators preserved. New narrow craft application content; root/current material owner integrates exact native consumer.

**Later observable gate:**

1. Two serviceable objects with different useful functions produce different actual later quotes/outcomes.
2. Ordinary serviceable object remains useful.
3. Salvage demonstrably loses material and conserves ownership.
4. Transfer/trade/storage/save/reload retains the exact functional object key and provenance.

**Delivery state:** proposal-only; not implemented; source inspiration is selected.

## FAC-P03: One volatile ingredient lot with a useful spent form

Gather an original volatile herb lot, choose careful immediate treatment, quick stabilization for travel, or convert older stock to a weaker safe preparation. Unused material becomes an owned spent residue with a useful compost/craft function.

**Source basis:** FAC-08, FAC-09, FAC-12 in [FINDINGS.json](FINDINGS.json).
**Current owner and gap:** New opt-in lot deadline record joined to existing native inventory, custody, job and clock publication. Existing crop warnings remain their owner. Inventory snapshots currently primarily own counts by item key. General lot merging/splitting and expiry require an explicit versioned adapter, not facts detached from stock.
**Preparation and cost:** Choose a single new original item family and declare supported-world/body and absence policy before enrollment. Actual lot, stabilization materials and work time; preservation is a paid method, not a universal freezer buff.
**Commitment and later use:** A lot ID carries quantity, provenance and deadline across bag/chest/escrow/job input. Successful processing declares inherited/reset freshness. Expiry settles once from that exact lot into its safe spent output. Treatment potency or remaining safe handling window and later compost/material use.
**Time and failure:** Supported played time only initially, with explicit freeze under unsupported body/realm and no real-time ageing while closed. Compare current crop-clock joins before integration. No fresh refund after paid elapsed spoil time; accepted input ownership and actual deadline survive cancellation according to declared terms. No hostile egg analogue or old-food decay is selected.
**Compatibility and ownership:** New-family enrollment only; older saves/items have no lot decay. Migration and generated-save acceptance required before any persistence change ships. Isolated lot model/content/host prototype; root owns shared clock/state/native/save joins.

**Later observable gate:**

1. A lot expires once with the same deadline after custody/storage movement.
2. Processing has a documented freshness rule and actual useful consumer.
3. Unsupported clock/body preserves the selected lot coherently.
4. Save/reload/import or a failed publication cannot duplicate residue or refresh the lot.

**Delivery state:** proposal-only; not implemented; exact rates/fiction provisional.

## FAC-P04: A supplier route with capacity, fuel and an honest interrupted delivery

Commission a willing existing supplier to take a finite kit order between two established places. Choose a normal delivery route, fund a rest/refuel stop, or build a small permanent cargo crossing. The receiver obtains goods only on actual delivery.

**Source basis:** FAC-05, FAC-12, FAC-14 in [FINDINGS.json](FINDINGS.json).
**Current owner and gap:** Existing independent actor/body/stock/custody/work/site/travel owners; actual route planner and receiver support must be named. A generic transfer effect is not physical courier movement. Reuse current independent transit bindings or report unsupported segments before accepting work.
**Preparation and cost:** Willing actor, supported independent movement, real custody contract and receiving-site room. One-route prototype only. Fee, actual supplier-carried goods, their stamina/fuel and route construction stock if selected.
**Commitment and later use:** Acceptance transfers/reserves specified cargo and own finite means; travel, unload and return are separate observable states. Shared named interrupt policy can propose rest/refuel when support fails, without altering accepted commitments. Receiver’s real kit use/project; permanent crossing affects future route cost/access rather than granting stock.
**Time and failure:** Existing supported independent clock; no unobserved movement claim beyond admitted adapter. Stop/pause versus reroute is explicit. Full receiver waits or takes a selected alternate destination; no path/absent actor/insufficient means preserves actual cargo custody. Interrupted journey and bodily loss are separate, no universal cargo-loss policy.
**Compatibility and ownership:** Optional explicit order/route records; old jobs remain frozen and old world absence policies retained. New one-route content/host only; root owns actor movement/stock/custody integration.

**Later observable gate:**

1. Order acceptance alone does not increase receiver stock.
2. Delivered exact cargo decreases supplier stock and increases receiver stock once.
3. Full/unavailable destination produces visible waiting/reroute without conjured delivery.
4. Changed return/revisit, save/reload and cancellation preserve route/cargo obligations.

**Delivery state:** proposal-only; not implemented; no source-game rail/grid clone selected.

## FAC-P05: A working sample teaches a context-dependent process

Make and demonstrate one working heat-supported process at an established workshop, then record a portable method that can be attempted elsewhere only with compatible material, environment and means. Teaching another willing worker transfers knowledge, not their equipment or fuel.

**Source basis:** FAC-01, FAC-02, FAC-10, FAC-11 in [FINDINGS.json](FINDINGS.json).
**Current owner and gap:** Existing source/power/mastery/knowledge/discovery/native recipe/job owners with one explicit contextual execution rule. Existing predicates can gate selected context, but continuous environment/heat support must be read from a real owner. A global learned flag cannot substitute for that owner.
**Preparation and cost:** Actual production/examination receipt, supported sample function and selected local environmental facts. Existing skill XP remains independent. Real sample inputs, an actually supported heated site, own effort or willing instructor time and a consumed test piece.
**Commitment and later use:** Successful sample yields a method discovery and useful output. A later contextual quote checks environment/source/fuel/body/site; teaching stores observed/understood knowledge without copying physical resources. A later cold-region repair or material conversion and an ordinary local alternative.
**Time and failure:** Finite paid work under supported heat/body/site clock. Loss of continuing support suspends or fails according to pinned terms. Knowing the recipe with an incompatible environment returns a specific missing condition. Failed demonstration cannot grant mastery or fake a crafted sample.
**Compatibility and ownership:** Additive opt-in knowledge/method records; absent fields disclose/enroll nothing. No new realm/prestige or blanket engine port. New narrow original process/sample content; root integrates current heat/site/knowledge consumer.

**Later observable gate:**

1. The actual sample receipt unlocks a useful process.
2. The same learned method is usable in one supported context and explicitly blocked in another.
3. Bringing suitable heat/material means makes it usable without resetting the character.
4. Teaching, transfer, save/reload and failed commitment preserve acquisition versus execution.

**Delivery state:** proposal-only; not implemented; original experiment pending director selection.
