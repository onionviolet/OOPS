## Exact trail

Opening a Things record, including its People/Groups/Powers views, adds a collapsed evidence section. It requests `/record-handoffs` after expansion, rather than expanding startup `/data` or loading the queue for each selected node. Matching requires the saved canonical record route, its world, and its record family (`entity` or `rule`). Display labels do not participate. A composite group/institution record exposes the two families separately when both exist in the admitted digest.

The endpoint reads existing local public Workbench statements and their recognized public file fingerprints. It does not walk private reading outputs, source prose or runtime import dependencies. The response projects the exact matching proposals' report metadata and native receipt metadata. Private/sealed proposal, record and source markers are excluded. Unknown metadata is not projected.

The detail reuses the existing implementation report/native proof renderer with attachment forms disabled. It retains source route, fixture/setup description, tested bundle and receipt identity, file drift and the on-demand exact-build comparison. The source-proposal link opens the original Workbench statement and its qualification trail. A saved draft is described as awaiting an implementation report. An empty match reports a missing exact Workbench statement, without declaring a feature absent.

Existing “In OOPS” coverage captions now explicitly say “Snapshot bindings” for group/law/power records. Static binding coverage and later attached native receipts remain separate evidence layers. No command is declared playable from a label or a report count.
