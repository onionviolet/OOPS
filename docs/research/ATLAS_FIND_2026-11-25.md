## Visible behavior and scope

The header has an inline labelled **Find in Atlas** search field and Find button, available across all sections and on the normal home page. The Find navigation section opens `#find`. Query, result-type filter, world filter and page are encoded in the hash, for example `#find?q=Klein&type=subjects&world=lotm`. Result links are ordinary stable anchors, so browser Back restores those search parameters. Enter submits the header form. Empty search, no matches, Clear search, retry and per-group pagination are supported.

Server-side search groups **Subjects and places**, **World rules** and **Cheat catalogue**, with world/source kind, concise outcome text and recorded status. World display and filter choices reuse the existing canonical reading-library title lookup, including Super Supportive and You Are Summoned; when it has no mapping, the existing supplied label or ID remains. Routing keeps the original IDs. Counts describe matching indexed records, not unique fictional people or corpus completeness. Source rule statements are linked once in full where the title would repeat the same statement. A single-type group's heading carries its count once. Unindexed and withheld reading rows are explicitly outside search; no matches are not a claim that something does not exist in the source or game.

The server reads admitted reader JSON projections one at a time and retains a compact search index. It never reads raw private reader outputs for Find and does not send full corpora to the browser. Public native-library/cast records, the existing safe world-rule projection and the authored cheat catalogue are included. Explicit sealed/private/withheld records are excluded; private paths and unselected free-form fields are omitted. Source labels, stated identities and actual routes are retained without guessing a person's current location or playable status. Cast-only places link to the exact existing book place route; admitted reader subjects link to their exact Things record; native catalogue subjects use a newly admitted exact focus segment on the existing creature/library route.

Cheat terms include the exact matching per-CTC ordinary/advantage comparison, its evidence and implementation hooks. This makes `pelt` find CTC64 and `carcass` find CTC1 without invented synonyms. CTC detail routes use `#library/cheats/CTC64`; coordinator owns the separate cheat detail design and source wording. Exact reviewed proof assets for CTC21/CTC64 are individually allowlisted, without general filesystem serving.

The index is created on demand and reused during one running server snapshot. A normal API probe read 44 admitted reader files with zero unreadable files; cold first query took 5.87 s, subsequent sampled queries 20–33 ms on this machine. Those are observed local timings, not a performance guarantee. Responses are bounded to eight results per group/page and small filter metadata. Restart Atlas to refresh changed underlying input projections.
