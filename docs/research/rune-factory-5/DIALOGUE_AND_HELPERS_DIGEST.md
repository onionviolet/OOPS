# Dialogue, relationships and helpers

F1. `SubEventData` has 204 event rows with target NPC IDs, required love levels, occurrence rate, repeat flag, gender, love progress, weather, date count, prerequisite script flags, prior event completion, item IDs, joining NPCs and forbidden NPCs. `EventUnlockData` has 2,628 rows with script/event-point IDs, day/time bounds, story flag, on/off conditions, NPC conditions, flag conditions, scene and position. The schemas are shown. Sentinel semantics and boolean grouping require native readers.

F2. Event 1001 names NPC 2, love-level field 1 and script flag 20001. Event 1010 names NPC 2, love-level field 2 and prior event 1001. This is a concrete staged prerequisite chain in data, not a runtime proof of its complete admission rule. `UILoveEventConvTextData` adds 520 parallel character/flag/number/step/text-ID references. `ScenarioTalkData` has 16 scenario-to-NPC talk masks; `BirthTalkData` has 32 birthday talk masks.

F3. `NpcStatusDataTable` contains 30 NPC configurations and four gift preference arrays, plus birthday, returned-goods category and other personal fields. `LovePointManager` exposes favorite lookup, gift restriction checks and love-point additions with an `isOriginal` argument. `PresentItemParamDataTableArray` instead holds 193 monster present-effect rows and 26 monster-category rows. Do not mistake monster stat gifts for the human relationship preference table. `FriendParamDataTableArray` has 31 level-to-Atk/Def rows; the consumer remains unread, so it is not a universal human romance bonus claim.

F4. Full English dialogue source was acquired, not decoded. `Eng/Event/pack.bytes` is a 22,952,998-byte binary payload in bundle `e5a7b3a52fcb2b3e585bf6f3e9e93ff2.bundle`. The English master bundle includes `AdvIndexData` with 23,778 offsets. `AdvScriptId` provides names; `ScriptWork` exposes binary reading, command arguments and text arguments. `CommandList` names choice, condition, gold-change and reward operations. A capability list does not establish that any chosen branch charges, fails or persists atomically. No raw dialogue is published here.

F5. Failure is represented in the model. `ConditionsForLoverJudgment` has a confession-success probability array and checks involving NPC, love level and event steps. `NpcSaveParameter` retains `IsRefused`, jealousy and date restraint; the date record retains a meeting deadline. Exact probabilities, retry reset and missed-date effects are unread. Keep these findings separate from a demonstrated paid choice.

F6. Helpers have durable assignment and progress. `FriendMonsterStatusData` carries farm/house/room identity, order, work area and daily worked/seeded/yield flags. `FarmSupportMonsterData` carries worker ID, state, work time and cell index. `FarmMonsterWorkState` names Wait, Move, Action and End. `FarmSupportMonsterController` names clean/water/seed/crop paths, lumber/stone additions, crop-item lookup, end checking and target selection. These are structural facts; concrete output amounts, destination inventory and obstruction rules remain inferred.

F7. `ConstFarm` explicitly stores friendship thresholds, tired-HP percent, feed power, work HP ratio and farm/seed cost fields. In this build the friendship field is 3, tired-HP field 50, work HP ratio 8, farm work cost 0 and farm seed cost 1000. Units and enforcement must be traced before calling these percentage debits or coin costs. There is no demonstrated exact blocker receipt or next-useful-action UI.

F8. Two sampled NPC schedules, `Date_001` and `Def_000_h1`, have NPC ID, time list, weather list and time data. The catalog contains hundreds of separate lifecycle schedule assets and 30 lifecycle lottery byte assets. This is scheduled behavior data, not proof of an autonomous planning simulation or offline catch-up.
