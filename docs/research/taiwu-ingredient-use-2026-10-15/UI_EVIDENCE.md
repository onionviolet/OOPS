Candidate filtering is stronger than the pictures alone: specific-target material candidates first match RequiredLifeSkillType, then selected source; compatibility uses CraftableItemTypes.Contains(correct MakeItemType), derived grade range and maximum available attainment. The upper-result grade can require a building capability. Disabled-state tooltip keys distinguish type mismatch, grade mismatch and attainment. This is source logic; no user test proves the messages are visible or legible.

The evidence covers adjacent selection/detail/quote and a depicted optional effect tooltip. It does not cover result/use screens or validate a native click sequence, scaled text, keyboard access, readability, cancellation, error recovery or layout at1366×768. Those remain exact gaps, rather than being silently filled from an unrelated screenshot. No supplementary footage was needed to establish the finite static chain; the retained primary images are better matched to this particular manufacturing interface than an unpinned walkthrough.

Any future YAIR use of these observations is a proposal. A settled implementation would still follow the existing Proto23/UI rules and populated laptop proof; this research creates no new UI owner, replacement shell or mobile gate.
