# Agent usage rules

Standing workflow, 2026-10-16. Authority: [Weibao's request](USER_VISION.md#agent-generation-and-book-usage-2026-10-16); router: AD37. Readers may delegate lesser agents under AU9, following Weibao’s later correction on the same date. These rules constrain execution cost, not the ambition or required honesty of source coverage. They apply to internal workers, detached CLI readers, visible chats and successors under every provider. Host restrictions still apply.

## Before generating another agent

| Code | Required behavior |
|---|---|
| AU1 | **One coordinator by default.** Spawn for a named independent outcome that saves total work. Available slots are capacity, not a target. Reading alone does not require a world GM, reader manager, critic and synthesis agent. |
| AU2 | **One shared budget per task.** Before bulk dispatch, record the source/edition, requested result, reused evidence, model/effort, maximum invocations, source volume, output limit and stop condition in the existing checkpoint. Include coordinator, children, retries, reviews and successors in usage accounting. Readers may spawn lesser agents from preallocated portions of this same budget. The root owns the aggregate ledger; reserve an invocation and source range before launching so siblings cannot overspend it. A reader and its descendants do not each receive a fresh allowance. |
| AU3 | **Budget a whole book once; keep exploratory work small.** An unspecified exploratory book task defaults to four generated-agent invocations and 48,000 source words across the tree. An explicit full-book request instead uses the finite source-sized plan in AU13: one pass over the entire available edition, planned short-lived readers, and a bounded repair reserve. It does not require repeated approval every 48,000 words. Default concurrency remains two generated agents across all levels. Count the pilot against N. Release finished worker capacity with supported host controls before another batch; completion is not permission to accumulate dormant managers. Helpers, delegated reviews, retries and successors consume the same planned invocation budget. General non-book delegation still defaults to two worker invocations unless otherwise budgeted. These are operational defaults, not token-price equivalents; AU7 still limits allowance/spending. |
| AU4 | **Use the first real shard as the pilot.** Inspect evidence quality, actual input including fixed host instructions, output, response count and available usage before dispatching the rest. Include this shard in completed book coverage; do not repeat it for calibration. Adjust remaining shard sizes and project the whole finite plan from the pilot. A full-book request authorizes that declared plan within AU7, not unlimited expansions. Ask once only if it requires a larger explicit usage ceiling, paid fallback, stronger-model bulk work or a material scope change. Unknown allowance means report uncertainty and retain the finite plan and per-reader limits; it is not a reason to run indefinitely. |
| AU5 | **Route extraction cheaply.** Default bounded chapter reading and source-fact extraction to GPT-6 Luna, medium, when supported; use a currently available comparable lower-cost route on other hosts. In Claude sessions that route is haiku (2026-10-23): bounded readers, extraction, lookups and sweeps run on haiku, synthesis and code on sonnet; rerun a thin or contradicted shard on sonnet and say so. Verify availability. No silent fallback to a stronger model or higher effort. Keep cross-source synthesis with the existing coordinator; escalate a named unresolved difficulty, not the entire book. |
| AU6 | **Keep raw chapters out of the coordinator history.** Fresh readers receive only the extraction brief, exact source range, relevant verified facts, small continuity capsule and output path. No full-history forks or automatic loads of every project owner for settled source extraction beyond mandatory host instructions. Extract/index once; each raw range has one reader owner, reused across all requested research topics. Return at most 200 words plus artifact paths; retain deep evidence privately. The coordinator reads incremental summaries, uses a compact finding index and retrieves only consequential or conflicting source spans. It does not load all reader files or the whole corpus to synthesize. |
| AU7 | **Stop at the first exhausted bound.** Stop expansion at the active plan's invocation/source/response limits, an explicit token ceiling or the observed allowance ceiling. With a trustworthy live meter, the default task ceiling is five percentage points of any reported included-usage window from its starting reading unless a larger finite ceiling is explicitly authorized; reserve room for in-flight work and check between waves. Shared-account changes are a conservative stop signal, not proof this task spent them. Without a meter use the finite AU3/AU13 plan and AU10/AU14 limits, and report unknown allowance. No paid/API fallback without explicit spending authority. |
| AU8 | **Fresh contexts keep the same budget and evidence.** Save completed source spans, artifacts, usage, remaining invocation/repair reservations and the next exact range. A fresh reader or coordinating successor consumes its planned slot but does not reset the book ledger. Completed shards are not reread for onboarding. A reader is finished when its bounded shard is delivered; do not resume it for the next shard. At an exhausted plan or allowance ceiling, checkpoint the unread remainder and ask once for a specific additional finite budget. Planned shard transitions are not budget renewals. |
| AU9 | **Delegate downward within the reserved budget.** A reader can delegate a smaller settled extraction to a lower-cost supported model, or lower effort on the same small model when suitable. Use a fresh bounded brief, exact disjoint range, output owner and remaining budget. Default topology is root → reader → lesser extractor; extractors are leaves unless a larger topology is explicitly budgeted. Count all descendants toward the same concurrency, invocation and source limits. The reader integrates notes and checks selected claims; it does not reread its child's entire raw range. If no cheaper suitable route exists, use tools or read directly rather than silently launching another full-size peer. |
| AU10 | **Bound the payload and the number of times it is carried.** Each fresh reader owns at most 12,000 source words, reduced when pilot-measured tokenization or host overhead requires it. Preassemble its full source payload offline; load it in one response when it fits, otherwise at most three measured pieces. Size tool output to fit the payload before loading; preflight counts/locators, not the full body. On truncation fetch only the omitted span, mark it unread until inspected and debit the repair reserve. Target total reader input context below 60,000 tokens; at 60,000 stop further raw loading and deliver/checkpoint. At 80,000 do not run another tool round; save/return the partial result within the reserved exit budget. These are conservative policy thresholds, not model context limits. Mandatory host instructions count. If context telemetry is unavailable, retain the source and response-count bounds, estimate overhead from the pilot, and do not assert a precise cap was enforced. |
| AU11 | **Prepare source and receipts outside the semantic loop.** Use existing resumable acquisition and deterministic extraction/indexing. The coordinator receives paths/counts/errors, not page bodies. Dispatch readers only after complete local shards exist. A finite browser-only capture budget remains required. Prepare stable chapter/paragraph locators, hashes and coverage skeletons once. Each reader writes one consolidated evidence artifact and a short return; avoid per-chapter model calls for note appends, hashing, waiting or validation. Preserve any material intermediate result before a failure without turning each paragraph into a model round trip. |
| AU12 | **Measure the whole tree without mistaking tokens for quota.** Record per-response input, cached input, output, model and timestamps where available; sum each response once, not cumulative snapshots. Keep usage, context pressure and shared-account allowance separate. Record unexplained meter jumps as attribution gaps and stop further expansion at AU7's threshold. A quota breach stops the current wave at a durable checkpoint, including active children, without losing artifacts. Later cheap agents cannot retroactively justify an exceeded budget. |

| AU13 | **Plan full coverage across one to three coordinating chats.** Default to one coordinator; use a second for synthesis or a third for a justified major boundary when needed and host-authorized. These are visible orchestration chats, not a promise that the raw book fits their context windows. Size internal reader contexts by source tokens/words, not chapter count. For W source words, start with N = ceil(W / 12,000) disjoint shards, adjusted for chapter boundaries and pilot-measured tokenization/host overhead. Reserve N reader invocations plus min(3, ceil(0.1 × N)) repair invocations, and explicitly count any necessary helper/integrator/successor slots. A larger shard count requires resizing this one declared plan, not silently repeating an exploratory tranche. Default source exposure is one complete pass plus at most three repair shards; name the exact repair spans. Delegated extractors replace an assigned reader slot/range rather than add another full read. No empty reader-manager tier. |
| AU14 | **A reader is a short-lived extraction job, not a rolling chat.** Target one source-load round, one consolidated artifact-write round and a final return; use at most six model responses including the final return and any recovery. Preflight the source before launching; the response allowance is not permission for six full-context tool cycles. Check count/context before another call; reserve the final response for notes or an explicit partial/unread handoff. After delivery, retire the reader. A next shard starts with fresh bounded context, never a follow-up to that same reader. Fetch repair-only gaps with one reserved small job. If the host cannot supply a fresh reader route, checkpoint at the bound and disclose that limitation rather than continue a hundred-call reader. |
| AU15 | **Carry continuity as evidence pointers, not accumulated prose.** Give each shard a capsule of at most 1,500 tokens with current identities/terms, prior claims relevant to the task, open questions and source locators. Cap the coordinator's working finding index at about 4,000 tokens, keeping detailed and superseded evidence on disk with stable IDs. These limits cover working summaries, not the private research archive. Readers label new, corroborated, contradicted or unresolved facts and preserve speaker, chronology and edition. Do not invent unseen causes to fill a summary gap. Resolve cross-shard contradictions with targeted retrieval, including earlier evidence that a later event changes. For nonlinear narrative retain occurrence versus revelation separately. |

## Source coverage and stopping

A targeted mechanics query uses existing notes and indexed searches first. A requested full read still requires every claimed range to be read: keyword searches, extraction scripts and file hashes do not establish semantic coverage. Preserve unread ranges explicitly. A bounded research stop does not reduce the user's requested full-world horizon or authorize implementation.

Before full-book dispatch, record the finite plan in the existing checkpoint:

`AU1-AU15 | edition/hash + W: ... | goal/topics: ... | prior read spans: ... | coordinator chats planned: 1 (target <=3) | shard manifest + N: ... | reader model/effort: ... | invocations: N + repair reserve + named helpers | concurrent max: 2 | source exposure ceiling: W + named repair spans | reader responses max: 6 | context target/stop: <60k / 80k | usage start/ceiling: ... | continuity index + artifact home: ... | next: first unread shard/pilot`

For the audited 434,016-word source, simple arithmetic gives 37 shards at 12,000 words, plus at most three repair invocations before any explicitly named helpers. This is an illustrative plan, not a new dispatch or a measured usage estimate. Actual chapter/token boundaries can increase N and must be reflected before dispatch. The whole book is budgeted once; 37 short internal jobs need not become 37 sidebar chats. One job loading its source once and writing its notes is different from four jobs each retaining 64 chapters for around 100 responses.

If the host supports a real token/response limit, set it as well. Otherwise source size, fresh-context boundaries and per-response counts are instruction-level controls. Compaction, caching and small final replies do not prove history was removed or quota was low. A final return cannot retroactively save the cost of dozens of earlier calls carrying the raw source. Subscription percentages must not be converted from raw tokens without supported measurements.

## Scope of this change and validation

The user reported spending 75% of their tokens on one book. The follow-up [session audit](reviews/BOOK_RESEARCH_USAGE_AUDIT_2026-10-16.md) reconstructs the root and five workers, distinguishes cached token traffic from allowance, and leaves the abrupt shared-account meter jump unattributed. The previous playbook recommended parallel readers and 100-160-chapter runs, while the GM prompt allowed automatic successors without a cumulative cost bound. Those recommendations are superseded here; their dated examples remain history.

This is instruction-level enforcement. No running agents were interrupted and no host quota controller was installed. The referenced `tools/book_deep_dive/launch_codex_reader.py` was absent when checked, so it was not patched. Future launchers must enforce available limits and refuse unbudgeted expansion.

Source-level walkthroughs: a small lookup stays in one chat; a full-book request declares all disjoint shards once and includes its pilot in coverage; a reader finishes after its bounded extraction rather than accumulating the next shard; lesser agents consume reserved slots; truncated output yields an omitted-span repair; a seventh reader response or a breached context/allowance limit triggers a checkpoint, not another raw-text cycle. These are policy checks, not measured agent trials or demonstrated token savings. The [audit round 3](reviews/BOOK_RESEARCH_USAGE_AUDIT_2026-10-16.md#more-to-consider-round-3-whole-book-reading-with-bounded-contexts) records the changed defaults; older four-reader whole-book limits and 100,000-token stop thresholds are superseded.
