# Fullmetal Alchemist implementation packet proposal

Status: design proposal only. No runtime implementation is authorized by this packet. Any future implementation needs a new explicit scope and current owner/effect-transfer review.

## Candidate first slice

| Status | Field | Proposal |
|---|---|---|
| Proposal | Slice | East City supervised materials bench: identify one sample, prepare one simple transmutation, choose to execute, ask for review or stop. |
| Proposal | Continuity | `fma.manga` or `fma.brotherhood`, selected only after primary episode/chapter verification. Keep adaptation evidence distinct. |
| Proposal | Target | Desktop/laptop first. Show sample, method stages, available tools, cost/payer and result in one readable work area. Mobile optimization deferred. |
| Proposal | Player value | A small complete loop demonstrating material knowledge, an actual input, a learned method and an observable consequence. |
| Proposal | Out of slice | Stones, human transmutation, soul binding, full military arc, randomized truths, other continuities, prestige and cross-world transfers. |

## State and ownership proposal

| Status | Data | Candidate owner / current gap |
|---|---|---|
| Proposal | Sample identity, quantity, custody | Existing inventory/material owner; verify typed material support before work. |
| Proposal | Method source, learning, confidence | Existing knowledge/ability owner; avoid duplicating learned-source state. |
| Proposal | Array/tool and readiness | Existing item/crafting owner or bounded adapter if none supports setup. |
| Proposal | Operation stages and result | One transmutation executor owns commit; preview must not mutate. |
| Proposal | Cost payer and consumed inputs | Same operation commit references the real matter/energy source; no parallel cost manager. |
| Proposal | Bench access, teacher, permission | Existing location/relationship/occurrence owners; exact consumers must be inspected. |
| Proposal | Continuity and snapshot | Proposed world authoring contract; current runtime world binding is not assumed. |

## Required acceptance cases for a later authorized build

| Status | Case | Observable check proposal |
|---|---|---|
| Proposal | Valid simple operation | Rebuilt desktop origin consumes only declared input and produces the declared result once. |
| Proposal | Missing material | Preview and execute fail with a grounded missing-input reason; no inventory mutation. |
| Proposal | Unknown composition | Character cannot execute a result requiring knowledge they lack; review action can improve evidence. |
| Proposal | Partial method | Only learned stages resolve; no hidden completion. |
| Proposal | Abstention/interruption | Stop preserves uncommitted input and does not create a cost or obligation. |
| Proposal | Reload/import | If persisted, save/reload and literal-file import retain committed state exactly; migration/compatibility decision is required. |
| Proposal | Continuity check | The same content ID cannot load facts from another branch without an explicit authored crossover. |

## Dependencies and gate

First verify source pages/primary scenes for the chosen transmutation, inspect current inventory, crafting, knowledge, location and persistence owners, and obtain a live source-writer transfer before editing shared code. Then rebuild and exercise the changed behavior on a fresh browser origin. Source tests, bundle bytes, served bytes, browser behavior, persistence, installation and human acceptance are separate states. No executable dependency or native pass is claimed here.
