## Grounding: what the code has today

- **Save shape.** The game version is `v0.6` (`src/game_version.js:3`). Expansion engine schemas run from 5 to 11 (`src/expansion_engine.js:58-62`, `src/audit_remainder_state.js:8`). Schemas 1 to 4 migrate additively (`src/expansion_engine.js:254-268`). Optional top-level domains (`pacing_e1`, `life_record`, `npc_lives`, `content_packs`, `customization`, ...) follow one pattern: an absent domain stays absent or takes a default, and an unsupported schema gets rejected before any mutation (`src/save_files.js:38-90`). Every staged write goes through one path, `persistExpansionPlan` (`src/expansion_persistence.js:7`).
- **One body, one visit.** The engine allows at most one active retained-world visit (`src/expansion_engine.js:142-143`). Content packs allow one active optional visit (`src/content_packs.js:42`).
- **World instances.** These already carry `continuityId`, `eraId` and `parentInstanceId`, but the clock policy is hard-asserted to `absence: "freeze"` (`src/world_instances.js:97-112`). `planWorldClock` already returns `absentBy` (`src/world_instances.js:310-346`). Shape checks are strict and reject unknown keys (`src/world_instances.js:39-41`).
- **Time and weather.** One native calendar and one weather model exist for the home world (`src/game_time.js:193-195`, `src/weather.js:37,194,198`). Other worlds have played-minute instance clocks with no calendar or weather. The header text comes from `update_displayed_time` (`src/display.js:3877-3883`, which still has a "color coding?" comment) and the temperature/rain field (`src/display.js:3885-3910`).
- **World tint.** A binary warm/cool tint exists. `away` means the player's world is not `base.frontier` (`src/main.js:8306`), which sets `data-world-theme` (`src/workspace_views.js:44`), which styles the page (`styles/workspace.css:198-199,285-289`). - **Heirs.** `createHeirChronicle` carries one lesson (`src/chronicle.js:273`). `buildLifeHeirSave` carries `npc_lives`, options and `life_record` into a fresh envelope (`src/life_experience_host.js:8-30`). `main.js` builds the chronicle panel without `beginHeir` (`src/main.js:8170-8177`), so `src/chronicle_ui.js:120` hides the heir button. This is a source-inspection inference; it was not checked in a browser.
- **Idle.** The tick loop is `src/main.js:7119`. Closed-browser time grants nothing. The one explicit offline mechanic is the prepaid packing escrow (`src/backlog_expansion_time.js:43-52`). Transit clocks assert absence freeze (`src/backlog_expansion_transit.js:41,250`).
- **Crossings.** Exact stock manifests with no copying: `src/realm_cargo.js:97,187` and `src/native_realm_traveler.js:15`. Traveler modes are physical, projection, alternate body and shared body (`src/realm_traveler_profiles.js:5`). Boundary operations: `src/realm_boundary_rules.js:2,103`.
- **Reputation and memory.** Reputation is an integer per region (`src/reputation.js:5`). Unknown saved regions throw (`src/reputation_state.js:6-16`). The elder relationship uses trust/respect/fear axes (`src/chronicle.js:78,132`). Village lives advance yearly (`src/npc_lives.js:33`). Knowledge basis is limited to kind plus attributedTo plus situationId (`src/causal_situations.js:52-57`).
- **Discovery and log.** Module eligibility: `src/workspace_layout.js:7,92,101`. Discovery cue policy: `src/native_discovery_policy.js:3`. Log: `log_message(message, type)` (`src/display.js:770`) and `eventFeed` (`src/event_feed.js:5`).
- **Starts.** The structured start draws an equal-width index from `state.rng` (`src/structured_pack_runtime.js:36-43`) and commits a receipt (`:52`). Native creation covers race, gender and height (`src/character_creation.js:71-79`).

## Engine improvements (EI)

These are engine-level changes, not world content. Their purpose is to make one canon world plus several parallel or AU copies cheap to add. They follow two tracks. The **build-time track** (EI1 to EI5) creates each copy as its own structured pack, so it needs no runtime save change. The **runtime track** (EI6 to EI10) has one shared definition with many live instances; it is cheaper per copy later, but it needs migrations. Starting with the build-time track gives playable AUs soon. The runtime track can follow once two or three copies show what they actually share (F's WI10 rule). Everything here is specified-not-run.

## Shared engine versus per-world

**One engine with world dials:**
- Frame/header/edge token layering (RF1-RF3), driven by the RF4 card.
- Discovery gates and reveal styles (RF13).
- Calendar mapping and festival windows (RF6).
- Absence-policy enum and clock planner (RF7, extending `planWorldClock`).
- Custody-transfer succession with a per-world dial for what survives (RF8).
- Carry/convert/suppress table per edge (RF9, RF16).
- Instance plurality and copy tags (RF10, RF11).
- Institution memory records with spread rules (RF12).
- Log voice classes (RF14).
- The contrast and seal lint (RF19).

These match E's clusters (CLI3, CLL3 and CLC1 are dials on RF7, and CLL1 is a receipt on RF8/RF9) and SHARED_FOUNDATIONS K02/K05.

**Per-world packs:**
- Unique-verb hosts (RF17), their content and numbers.
- The specific token values, glyphs, named days and voices.
- Which edges a world opts into, and which panel only that world reveals.
- Start cards and their eligible histories.
- Each world's succession, death and law specifics.
- Sealed variants and their routes.

A world's lore absolutes (for example the train ward in MOL10 or attunement limits in DDC8) stay inside its pack.

**Reasonable test before promoting a per-world feature to the engine:** it shows up in three worlds' rows, and a second world can use it with different local rules (SHARED_FOUNDATIONS P5).
