# Q. Cross-life carryover and retrofitting prior systems (proposal, 2026-10-13)

Weibao (2026-10-13), on the code finding "Nothing carries across lives except the heir": "That doesnt have to be the case, more to consider? Prior stuff can be changed to better fit future capabilities?"

Everything here is a proposal. Rows use Default + Dial + Reasonably. Nothing here is accepted. His direction itself is recorded in `docs/USER_VISION.md:96-102` and `PROJECT.md:40-45`: heir-only carry is current code, not a design limit; earlier designs and code may be revised, each with a save compatibility decision; accepted rules still hold until he revises them.

**Accepted rules this file works inside** (`docs/RULES_FROM_SCRATCH.md`):
- Rule 5: things cross lives and worlds only through a carrier (soul, item, record, teacher, cheat, system, world rule). So every CL row names a carrier and a cost.
- "Knowledge doesn't automatically cross" (`:61-69`): knowledge stays with the body and life unless something carries it, and it can fade or be wrong.
- The heir (`:33-59`): the heir inherits what was actually left (things, records, people, standing, blood, unfinished business, plus anything a world or cheat carries further). The one-lesson rule is scrubbed.
- Rule 1 (Weibao's refinement): anything is still possible "by carrying over from a prior run". That is an accepted opening for a meta-layer carry. It still needs a named source per rule 5.
- Rule 7 and the idle table (`:138-154`): absent worlds hold still unless their own rules say otherwise. A world can therefore move on across a gap between lives by its own rule, with no rule change.

**Already covered elsewhere (not repeated):** the "plans that narrow the next-life roll" table, stashes, corpse runs, letters, dead-man's switches, family vault, continuity link record and lone-wolf routes (`docs/LIFE_SIM_NORTH_STAR.md:3527-3760`); the twelve player-layer cards, especially Heirloom Compact, Traveler's Pattern Book, Rebirth Ledger, Instinct Inheritance, Hall of Selves and World Deeds (`docs/CHEAT_LIBRARY.md:368-590`); the reset dials R1 to R6 and foreknowledge decay F1 to F5 (`docs/research/DEATH_AND_RESET_CONSIDERATIONS_2026-10-10.md`); per-world death and heirs (`docs/worlds/SUCCESSION_BY_WORLD.md`); recognition by soul, face or habit (`docs/SELVES_AND_ECHOES.md`); the profile ledger, earned options and CA21 soul carry-in (scratch M, EO1 to EO17); the heir picker, carry list at crossings and profile key (scratch K, MR4, MR10, KA1, KA5). This file adds: the save layer each carry lives in, the carrier-to-form map with costs and what the player sees, per-world carry profiles for the eight priority worlds, and the retrofit survey.

## What the code does today (read 2026-10-13, not run)

New findings beyond M and K:

- **The heir loses almost everything the accepted rule says it keeps.** `buildLifeHeirSave` starts from a fresh envelope and copies only `current time`, `npc_lives`, `options` and `life_record` (`src/life_experience_host.js:8-25`). It re-creates the whole expansion state (`:17`), which drops the simulation's people, relationships, custody, claims, titles and jobs (shape at `src/simulation_contracts.js:218`), every world instance, MoL and Paradise campaign state, and the village career. Inventory, storage, money and home come from the fresh envelope, so none of them carry over.
- **The heir is frontier-only and anonymous.** The milestone hard-codes `worldId:'base.frontier'` (`src/life_experience_host.js:24`) and the name `'The heir'` (`:19`). Only the immediately previous grave is kept (`inheritedFrom`, `src/chronicle.js:273-280`). Earlier graves survive only as lossy `life_record` lines.
- **The NPC cast that does carry is one fixed Village household.** `createVillageLives` builds six named people with seeded death years (`src/npc_lives.js:5-22`). It has no world key and no template list. The old craftsman is an inline person in `src/simulation_content.js:60`.
- **World tint is binary.** `dataset.worldTheme = view.away ? 'cool' : 'warm'` (`src/workspace_views.js:45`), with two CSS palettes (`styles/workspace.css:198-199, 285-289`). The code comment there says palettes stay independent of sealed IDs, and any retrofit should keep that intent.
- **Absence is asserted frozen** in world instances (`src/world_instances.js:108-111`). The MoL and Paradise campaign records (`src/book_world_mol_host.js:63`, `src/book_world_paradise_host.js:69`) and the carrier clocks (`src/book_world_paradise_carriers.js:30`, `src/feature_expansion_nested_carriers.js:31`) also write `absence:'freeze'`. The book-world campaigns also fix `bodyPolicy:'same_native_body'` and one `entryProfile` string.
- **Reputation regions are a closed set.** `add_reputation` throws on an unknown region (`src/reputation.js:5-14`). Restoring a save throws on an unsupported region (`src/reputation_state.js:8-12`).
- **Shared-file weight.** `src/main.js` is 8433 lines with 246 imports. There are 59 `*_host.js` files. World footprints for Proto23, MoL, Paradise and the nested worlds are hand-listed in `src/main.js:1426`.
- **Save import validates a fixed list of optional top-level containers** (`src/save_files.js:146-147`). A new lineage or profile block needs a line there plus its own validator.

## Save layers (the place each carry lives)

| Layer | What it is | Survives | Today |
|---|---|---|---|
| L1 Life | The current run save (`save data`) | This life only | All gameplay state |
| L2 Lineage | A block inside the save that the heir or successor builder copies forward | Heirs, successors, rebirths within one save | `life_record`, `npc_lives`, `options`, one grave |
| L3 World | World instance state (sites, facts, claims, people) that outlives the character living there | Lives within one save, if the builder keeps it | Wiped by the heir builder |
| L4 Profile | A key outside any save (KA5, M EO1) | New games; hard reset only if Weibao decides (NW1) | Does not exist |
| L5 Player | Weibao's own memory | Everything | No state; the codex in CL7 serves it |

Default: each carry names its layer. Dial: per world, a carry can move up or down a layer (a family vault in L2, or in L3 if it is a building the world keeps).
