## 2. Save strategy and compatibility

SHOWN current format: `src/main.js:4935-4967,5178-5197` serializes native component owners plus `fork_schema:1`, independently versioned expansion and optional domains. JSON is stored directly; export is `YAIR-UTF8-1:` plus base64 UTF-8 (`src/save_files.js:158-182`). The decoder supports older unmarked Latin-1 and qualifying upstream UTF-8 layouts, then validates. Base64 is encoding, not compression or secrecy.

SHOWN guarded path: `src/main.js:414-438` stages life/NPC observations and calls `writeGuardedSave` at line 421 before publishing those observations. The ordinary wrapper is not itself full-envelope validation. Expansion persistence calls `validateSaveEnvelope` before the wrapper (`src/main.js:921-922`). Writer ownership uses a Web Lock per live/dev key (`:588-596`). Import structurally decodes, runs the real loader preflight, then writes (`src/save_files.js:185-190`); the probe has a 60-second timeout and rejects loader warnings (`src/import_probe.js:1-57`). Failed storage does not authorize another writer or deletion.

SHOWN application budget: `src/save_files.js:194-216` counts `serialized.length * 2`, key text, and every other origin key against **4 MiB**. It also reports UTF-8 bytes and catches browser quota errors. STATED browser reference: [MDN storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) describes up to 5 MiB localStorage per origin; this is not a measured capacity promise for this device. Backups, dev saves, display settings and other keys all compete with the primary in the application's guard. Export size and storage occupancy use different units.

SHOWN measurement: existing generated early Village fixture `docs/gm/dispatch/foundation-adoption-next-2026-10-13/rounds/r15/g1/fixture/fa07-base-new-game-export.txt`, identified by sibling `generate.mjs:1-12` as a new-game elder-met export, is **61,612 file bytes**, **46,200 decoded/compact UTF-8 bytes**, **92,392 estimated compact UTF-16 storage bytes**. Two equal JSON copies would occupy 184,784 bytes plus keys, not counting other origin data. **UNKNOWN:** current native fresh-save size and typical medium/long campaign distribution. This older fixture is a sample, not a new browser creation or real-loader check.

Default additive policy: absence remains absent/unknown and inert until explicit compatible enrollment. New fields need validation and lossless serializer support, even if no outer schema bump is chosen. Existing migrations (`src/save_migration.js:1-26`, `src/save_compatibility.js:1-57`, `src/expansion_engine.js:258-269`) preserve biography/kits/retired content or migrate supported older expansion state; none is a generic migration for these proposed stores. New authoritative semantics require a supported schema/feature marker that prevents older readers silently dropping them. Old saves may load forward; backward import is not promised.
