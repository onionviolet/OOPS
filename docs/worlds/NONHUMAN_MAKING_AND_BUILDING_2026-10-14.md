## Recipe methods and slots

**INFERRED default:** describe an intended product/process separately from its
executor. A method states roles such as hold, cut, heat, mix, position, bind and
inspect. One body may fill several roles if it has real simultaneous means;
several bodies can cooperate when their shared task is supported. **Dial:** exact
ritual recipe, functional substitute, self-producing organ, borrowed apparatus
or complete source-specific exception. **Reasonably:** each method keeps real
inputs, product properties, expertise and permissions. No new method grants the
old recipe's unlock or changes an existing save's recipe silently.

Five proposed adapter shapes suffice for this palette. G codes are local to this
report. They describe behavior, not five required new JavaScript classes.

| Code | Job shape | Reuse and needed extension |
|---|---|---|
| G1 Body production | Organ/source + supported interval/input → owned batch; collection transfers it once | Use E2/E5 functions and existing stock/job seams. Add typed production yield/reserve/collection, including explicit source conversion. An empty-material ItemRecipe must not mean unlimited gland output. |
| G2 Process conversion | Exact selected batches + apparatus + ordered procedure → usable product and declared residues | Extend MF1/MF2 or a timed simulation command.
