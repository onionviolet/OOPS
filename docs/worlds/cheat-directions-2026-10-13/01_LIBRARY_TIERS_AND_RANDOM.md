# Cheat library, tiers, types and random generation

2026-10-13. Research and design proposal for Weibao's request. This lane changes documentation only. No gameplay, bundle, schema or private save was changed, and no runtime or browser result is claimed.

## Authority and scope

Read live [PROJECT.md](../../../PROJECT.md), [User vision](../../USER_VISION.md), [cheat library](../../CHEAT_LIBRARY.md) and [cheat cosmology](../../CHEAT_COSMOLOGY.md). Existing direction supports suspenseful random starts, canon-first book worlds with easy AU variants, wide design and implementation in playable slices. One realm and one prestige layer remain the first delivery milestone. Desktop/laptop is primary if these proposals later gain UI; mobile is deferred.

**F1:** the existing library describes 49 overlapping families, reusable placement cards, NPC holders, items, places, fragments and genre-changing gameplay. This pass extends that owner rather than creating a replacement taxonomy.

**F2:** [the cosmology correction](../../CHEAT_COSMOLOGY.md#where-the-no-universal-rank-idea-came-from) explicitly retracts an invented ban on universal ranks. Weibao welcomed a fun ranking, and verse equalization is an available dial. Multiple axes are recommended for useful decisions; single rankings and power ladders remain valid options with declared assumptions.

## L1: Three libraries with different purposes

| Layer | What it holds | Who sees it | Why it exists |
|---|---|---|---|
| Authoring registry | Full definitions, true mechanisms, world compatibility and sealed fields | Designers and engine | Consistent rules and reusable content |
| Life notebook | Rumors, witnessed effects, experiments, owned abilities, disputed names | This character | Discovery and practical planning |
| Cross-life collection | What the actual continuity mechanism preserves | Player or continuing identity, as the selected mode allows | Replay, preparation and comparison |

An entry in the collection need not unlock ownership. Knowing that a resurrection relic exists does not put one in your inventory. A discovered blueprint could unlock a crafting route, while a surviving soul-memory could retain practical knowledge. These are different rewards.

The character notebook needs confidence and provenance: witnessed, reproduced, told by someone, inferred, disproved. Player-facing filters use known information. The authoring registry's true grade, hidden clauses and selected secrets stay sealed. Accessibility, readable text, export and save controls remain ordinary player facilities unless a specific fictional analogue is chosen.

Library browsing can itself be fictional content: school catalogues, collectors, restricted archives, competing rankings, counterfeit descriptions, research societies or a hub exchange. It does not require a universal cosmic shop or a being handing out everything.

## L2: Types describe several things at once

Do not make artifact, multiversal, legendary and simulator mutually exclusive types. A legendary artifact can contain a simulator that works across worlds.

| Classification | Examples | Practical question |
|---|---|---|
| Effect family | Copy, multiply, analyze, revive, create, conceal, travel, command | What rule can it change? |
| Carrier/backing | Body, soul, artifact, place, law, knowledge, system, relationship, patron, concept | What keeps it functioning? |
| Acquisition route | Birth, discovery, study, manufacture, bargain, inheritance, ordeal | How can this life obtain it? |
| Gameplay form | Quiet passive, action, resource loop, controller, whole subsystem | What does the player actually do? |
| Control | Automatic, commanded, conditional, negotiated, autonomous | Who chooses the effect? |
| Social arrangement | Private, shared, public infrastructure, jointly owned, stolen access | Who can use, revoke or contest it? |
| Continuity | Per use, temporary, this body, this life, transferable, cross-life | What survives change or death? |
| Compatibility | Native, translated, fuel-dependent, restricted, blocked | What happens away from home? |

Some cheats are procedures rather than objects: a self-written reincarnation ritual, an ecosystem engineered to generate rare materials, a legal loophole made enforceable, or a training method that compresses years. Some are relationships: linked minds, distributed memories or reciprocal growth. Others are institutions. A library should allow a workshop or collective to own a cheat without pretending it is a personal stat.

## L3: Tiers without losing the distinctions

A tier can be useful shorthand when its meaning is explicit. Prefer several separately named measures over one unexplained rarity color.

| Measure | Example labels | What it must not silently imply |
|---|---|---|
| Rarity in this distribution | Common, scarce, unique, unknown | Stronger, or morally better |
| Current development | Dormant, awakened, practiced, expanded, transformed | A fixed universal sequence for every cheat |
| Effect scale | One object, room, city, world, linked worlds | Victory over every smaller-scale effect |
| Rule authority | Permission, exception, override, rewrite | Omnipotence in unrelated domains |
| Reliability | Experimental, conditional, repeatable, exact | Unlimited uses or free operation |
| Portability | Home-only, carried, adaptable, cross-world | Range, damage or death survival |
| Growth potential | Fixed, trainable, modular, generative, open-ended | Its current strength |
| Custody | Loaned, licensed, owned, integrated, self-sustaining | Legal or social legitimacy |

A local absolute effect can defeat a broadly powerful opponent under its conditions. A multiversal translator can be harmless in a fight yet essential to every future life. A mass-produced teaching system may be common and transformative. A unique curse might be undesirable. A perfect one-item duplicator can change an economy without ever damaging a city.

An optional overall ranking should state the scenario: best first-life survival, best research partner, best resale value, strongest duel at specified preparation, or greatest demonstrated reach. NPC institutions can use inconsistent grades. The game can offer a comparison with uncertainty without promoting institutional opinion into physical law.

**Proposal:** retain existing Knack/Gift/Golden finger/Fate-class/Origin-class vocabulary where it fits, plus native source-world grades. Avoid forcing every character to climb the same labels. If a world deliberately has an objective system tier, use it as that world's real rule.

## L4: Curated foundations, generated instances

Start from authored mechanisms and compose compatible aspects. Random generation should vary a runnable rule, not merely produce an impressive name.

Four levels can coexist: an exact source-supported card; an authored AU sibling; an original modular variant; and a deeply procedural instance. Each stores its derivation. An AU instance is not evidence about the source original.

The generated recipe needs an invariant, trigger, valid targets, input/fuel, observable output, ownership, persistence, interaction rules and one useful early application. Optional drawbacks are local design choices. A cheat does not need an arbitrary punishment to justify being powerful. Limited scope, opportunity cost, acquisition difficulty or world consequences may already produce interesting decisions; some starts can intentionally be overwhelmingly strong.

**Example recipe:** a memory recorder preserves practiced procedures. Artifact variant: a notebook records work written into it. Body variant: deliberate rehearsal consolidates motion. Soul variant: demonstrated skills survive rebirth. Shared variant: apprentices can retrieve the founder's demonstrations. The shared family is coherent, while custody, reach and continuity produce different lives.

## L5: Random cheat pipeline

1. **Choose the campaign envelope.** Canon-grounded, declared AU, crossover or sandbox determines eligible mechanisms and spoiler handling. The world instance and start-point matter, not only the franchise label.
2. **Select coherent circumstances.** World, era, role, body, location and institutions condition routes and eligibility. Joint templates avoid independent rolls producing an inaccessible artifact or impossible fuel requirement accidentally.
3. **Draw mechanism and opportunity.** Birth possession, dormant potential, a nearby lead and a later invitation are distinct outcomes. Guaranteed access to one early opportunity is an optional cheat-focused mode, not a universal starting rule.
4. **Validate and retain provenance.** Check valid targets, reachable activation, world compatibility, executable hooks and a useful first action. Record the seed, table revision, eligible set and chosen definition. Intentional impossible or cursed starts need an explicit mode; accidental unusable results need a deterministic fallback.
5. **Reveal through play.** The player gets what this character can observe. Experiments, witnesses and study reveal more. Persist the selected instance and acquisition receipt so ordinary reload is not a new lottery.

Randomness can occur at several moments: which life you enter, which opportunity you meet, which variant is made, which activation succeeds, or which evolution branch becomes possible. Decide the commitment point for each. A reroll can be a player setting, a sandbox feature or a fictional cheat with its own rules; these should not silently consume the same resource.

Offer purposeful random modes: unrestricted surprise, mystery within a chosen family, a tailored random draw for a chosen life goal, drafted offers, and fully chosen sandbox. Let the player choose uncertainty about the identity without necessarily accepting uncertainty about whether the run has anything useful to do.

Weights need population meaning. A one-percent starter draw is not automatically one-percent of all people in the world. Define whether the table models unusual protagonists, the general population, a faction's selection or a specific artifact lottery. NPC distribution can differ for a reason, while mechanisms remain consistent.

## L6: Worked original instances

| Card | First useful action | How it develops | What makes the case different |
|---|---|---|---|
| Threadkeeper needle | Record a verified sequence of stitches | Add repairs, patterns and teaching demonstrations | Quiet craft cheat; ordinary raw materials still matter |
| Borrowed sunrise | Reserve one uninterrupted hour in a carried practice chamber | Add users, environments or supply links | Time is available; knowledge and practice quality remain separate |
| Concordance lens | Compare two witnessed procedures and identify a shared dependency | Build mappings across systems | Translation needs evidence; cross-world utility is not combat supremacy |
| Unfinished inheritance | Decode a workshop left by your previous life | Restore its instruments and improve its blueprint | Library discovery is not immediate ownership; continuity needs an actual surviving carrier |
| Common miracle network | Share one learned recovery technique among consenting members | Add nodes, improve transmission, survive a founder's death | Institutional cheat with distributed custody and successors |

These examples are original proposals, not hidden world content or claimed source-book facts.

## L7: Further questions with gameplay consequences

| Consideration | What to decide |
|---|---|
| Fusion | Is it additive, transformative or a negotiated interaction? Preserve ingredients and identity history rather than assuming higher rarity wins. |
| Fragmentation | Does a fragment retain a narrow complete effect, incomplete instructions or a dependence on the whole? |
| Multiplication | Does copying duplicate custody, the underlying connection, or only a vessel? Can copied copies function? |
| Loss | Learned skill, world changes and relationships may remain after losing the grant. Removal needs a defined effect on ongoing jobs and stored outputs. |
| Identity | Two instances of one card may share mechanics but have different ownership and growth. A reincarnated holder is not automatically the same authorized user. |
| Preparation | A blueprint for the next life needs a carrier, delivery route and target conditions. A promise by a being is one route, not the default. |
| Historical versions | Preserve which AU, edition, source coverage and rule revision produced the instance. Older saves cannot silently adopt changed premises. |
| Automation | Quiet passives and queued practice can support idle play; autonomous cheats need authority, stop conditions and truthful result reports. |
| Economy | If cheats can be sold or copied, institutions, prices and access change. Universal rarity does not justify a fixed global price. |
| Information | Appraisal may detect an effect without revealing ownership, provenance or all clauses. Library completeness is not omniscience. |
| Power fantasy | A deliberately dominant cheat can shift play toward invention, exploration and social choice. Do not automatically restore equal combat difficulty. |
| Evaluation | Track which entries produce distinct useful choices, not just how many entries exist. A large catalogue of unreachable mechanisms is not playable breadth. |

## L8: Implementation seams and bounded evidence

Source-read in this pass: [`createContentRegistry`](../../../src/expansion_engine.js) registers capabilities, sources, actions, roll tables and techniques with stable IDs. Its roll tables validate revisions and effects; action evaluation computes distributions and contributors. Source effects record acquisition time, receipt, origin, world and revision. These are useful seams. They do not prove arbitrary per-cheat state, every proposed hook, generation, library UI or native acquisition already works.

[`buildLifeHeirSave`](../../../src/life_experience_host.js) currently builds an heir continuation from validated ended-life state and leftovers. It is not a general reincarnation or multiverse delivery controller. Reusing it requires an explicit continuity and save-compatibility decision; current heir behavior does not restrict future design.

A future first slice could use one authored card, two authored acquisition routes and several validated variants in one selected world instance. Demonstrate an earned first use and one distinction in tier or backing before expanding catalogue size. This is a proposal, not an implementation assignment or new gate over the existing milestone.

Later verification must include rebuilt browser play from a fresh origin at the desktop/laptop target, meaningful acquisition/use/decline, persisted identity and seed, save/reload/literal import, plus version compatibility. Exact UI placement, world roster, probabilities, first card, tier names, reroll policy, procedural depth and cross-life collection rules remain unselected.

## L9: Deepening the library into an authoring system

A family groups related play, while an effect contract identifies executable behavior. Two “copy” cards can differ fundamentally: copying an observed procedure, duplicating a source, imitating an output and acquiring permission must reference different contracts. A library count should track these distinctions rather than treating renamed cards as new mechanics.

For each family, author at least one concrete useful application, acquisition form, native-world behavior and state change. Expand to variants only where a parameter or rule changes actual use. Development should distinguish numerical refinement, newly executable modes, changed backing and genuinely transformed mechanics; a higher grade alone does not deliver a new verb.

Generation has two tasks: establish a coherent instance and give this start something meaningful to do. Those need separate checks. An intentional inaccessible inheritance can be a mystery start; an accidentally impossible activation is a content defect. Profile selection decides which experience is intended. See the [possibility grammar](07_POSSIBILITY_GRAMMAR_AND_AUTHORING.md) for the proposed authoring representation and [coverage method](09_COVERAGE_VALIDATION_AND_IMPLEMENTATION_ORDER.md) for delivery states.
