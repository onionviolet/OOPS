## C1. Cover the possibility space through a lattice

A long list of cheat names cannot establish coverage. A reusable operation and a
concrete authored instance cover different things. Track the selected intersections
of these axes rather than claiming every possible combination is scripted.

| Axis | Representative distinctions | Evidence to retain |
|---|---|---|
| Function | Observe, infer, record, teach, copy, transfer, generate, edit, reset, grant | Actual output and its consumer; family name alone is insufficient |
| Acquisition | Birth, salvage, craft, research, purchase, inheritance, direct grant | What exists before acquisition, what changes, and actual ownership/control |
| Holder | Player, NPC, artifact, location, institution, independent intelligence | Instance, controller and available knowledge/support |
| World mode | Source-grounded canon, original character, named AU, crossover, sandbox | Source profile, represented era, divergence and explicitly changed rules |
| Continuity | Same life, successor, rebirth, branch, rewind, travel | Carrier, recipient, surviving fields and restored/recreated domains |
| Interaction | Independent, chained, fused, suppressed, translated, stolen, conflicting | Selected resolver, ordering and constituent consequences |

An authoring record can state: "salvaged artifact, recording function, NPC or
player holder, original AU, physical inheritance, independent operation." That
is one defined intersection. Adding a soul-bound sibling changes continuity;
it does not automatically implement soul travel or every identity collision.

The most useful coverage unit is an **observable journey**: obtain means, make a
choice, perform a function, receive a useful result, retain or lose it according
to the selected rules. Track reusable pieces alongside such journeys.

## C2. Name the evidence state accurately

| State | What it establishes | What remains unproven |
|---|---|---|
| Enumerated | An idea, family or variant is recorded | Coherent mechanism or executable behavior |
| Defined | Prerequisites, output, holders, continuity and relevant interactions are specified | Engine support and playable integration |
| Executable | Selected engine operations can resolve the defined behavior in a checked path | Natural acquisition, interface, native consumer and persistence |
| Playable | Rebuilt native play can acquire/use it and see an actual useful consequence | Untested branches, migration and broader world fidelity |
| Verified for a named slice | Declared source and browser/persistence gates have passed | Every combination, the whole world or human acceptance |

These states can differ by route and consumer. Crafting may be verified while
purchase is only defined. An effect can work for simulated actors without a
native player adapter. A power can work in its home world while travel remains
unsupported. Record that granularity instead of assigning a single green label.

Human fiction/layout acceptance, packaging, installation, commits and deployment
remain separate when applicable. Reusing old proof requires the relevant current
path to be unchanged; a documentation entry is not proof of that condition.

## C3. Script primitives, authored content and exceptions together

Use reusable operations when the meaning matches. Put world-specific targets,
methods, eligibility, growth, supported outputs and wording in authored content.
Use a narrow authored exception when a special premise requires behavior the
selected primitives cannot honestly express.

For example, copy-observed-movement and transfer-an-actual-source should not share
one "copy" effect that grants ownership indiscriminately. A future-writing artifact
may need an explicit conditional forecast object; granting a knowledge flag does
not make it predict changing futures. Resurrection after erasure requires a
declared surviving identity/carrier and reconstruction operation. A restored HP
number alone does not implement it.

When a required primitive is unsupported:

1. **U1:** mark that intersection defined-but-unsupported and name the missing
   operation/consumer. Do not silently substitute a weaker mechanic.
2. **U2:** implement a bounded specific adapter or authored exception if the
   selected playable slice needs it. Preserve the exact special rule in its owner.
3. **U3:** generalize only after another actual use establishes shared semantics.
   One special power does not justify a universal cosmology compiler.

A natural-language authoring assistant can propose definitions and clarify unknown
fields. It cannot invent arbitrary executable effects by generating descriptions.
Content compilation must return supported operations or a precise unsupported
result, never a convincing name attached to no gameplay.

## C4. Finite authoring acceptance checks

Each selected card/journey needs a compact acceptance record. Empty costs are
valid. Unknown private properties stay unknown to the player. Only relevant
interactions are required; a quiet passive need not have a combat counter.

| Check | Required evidence |
|---|---|
| Meaning | Mechanism, exact output, source instance and actual consuming action/panel/world effect |
| Acquisition | Natural route changes actual means; discovery or library rendering alone grants nothing |
| Source/AU fidelity | Each sourced claim has a locator/status; selected version and era are explicit; AU changes are distinct from canon |
| Causality | Declared preconditions, commitments, optional costs, effects, observer updates and aftermath resolve in their chosen order |
| Information | Preview/search/counts/log/tooltips disclose only supported knowledge; exact detectors reveal what their actual premise permits |
| Randomness | Sampling moment, stream/key, table revision and settled instance are explicit; reload does not silently reroll |
| Persistence | Pending and completed state, lineage, ownership, useful output and selected carrier survive Save/reload/Export/literal Import |
| Evolution | Changes preserve existing instances/pending commitments or use an explicit migration; no global table rewrite silently changes acquired powers |

There must be a genuine useful output consumer. A pattern should enable a declared
procedure, an implement should affect a supported task, and a transmitted power
should be used by its recipient. A "cheat acquired" log and new panel can accompany
this evidence, but cannot replace it.

## C5. Broad coverage without combinatorial exhaustion

Testing every product of six axes quickly becomes impossible and produces mostly
duplicate evidence. Use three layers of coverage:

- **V1: Representative journeys.** Exercise a useful route for each selected
  operation/carrier/world profile and distinguish genuinely different semantics.
- **V2: Pairwise joins.** Cover relevant pairs such as acquisition × custody,
  holder × knowledge, world mode × compatibility, continuity × carrier and
  interaction × output. This catches wiring mistakes without proving all triples.
- **V3: Critical multi-axis collisions.** Add targeted cases where several
  authorities meet: source transfer during an interrupted commitment; rewind plus
  generated artifact identity; soul retention plus possession; perfect detection
  plus sealed projection; definition migration plus pending randomized output.

Use both a positive journey and a meaningful negative/control where it changes
the conclusion. Check a stronger variant on the same supported task when selected;
do not contrive a weak variant's victory. Test an absolute or deterministic mode
without inserting unrelated dice/costs. Avoid tests that merely duplicate data.

Pairwise coverage cannot prove source fidelity, complex ordering or every future
campaign. Mark uncovered selected intersections explicitly. Dormant catalog ideas
are a design horizon, not mandatory gates for delivering a useful current slice.

## C6. RNG, state and migration deserve critical coverage

Different unknowns have different settlement points, as recorded in lane 06.
Save the actual result, not just a seed whose meaning changes when content tables
change. A genuinely noisy repeat experiment may draw again; repeatedly appraising
one settled artifact should not recreate its identity.

Current source contains shared action RNG, derived event-check seeds, source
registry references and finite-number validation. Independent procedural-instance
streams, generated-definition persistence and symbolic unlimited values need
explicit selected implementation. Until then do not describe them as existing.

Selected persistence checks should include pending/completed jobs, repeated
settlement, interruption, stale target/source, source suppression/restoration and
failed persistence before publication where inputs/results change. Save failures
must not grant a second reward or spend the same inputs again on recovery.

Migration needs a declared choice for each changed definition: pin old behavior,
upgrade with retained lineage, convert with recorded consequences, or reject with
a readable supported recovery route. Distinguish old card definitions from actual
acquired instances and existing player's knowledge of them.

## S1-S3. Three staged useful slices

| Stage | Playable result | Coverage gained | Deferred scope |
|---|---|---|---|
| S1: Learn and make | Acquire one recording artifact through one natural route, learn one supported pattern, produce an implement and use it | Discovery, ownership/control, authored learning or timed work, a real output consumer and exact local persistence | General generation, travel, future-life delivery and world economy |
| S2: Meaningful variant | Add one source-profiled sibling with a genuinely different function, one seeded property if appropriate, and an independently equipped NPC | Family versus source, random-instance stability, particular observation/compatibility and simple interaction | Arbitrary free-text cheats, universal autonomous policy and every family |
| S3: Prepare and deliver | Preserve one actual pattern/implement through one selected carrier and let a later supported recipient obtain and use it | Continuity, recipient identity, custody, retained versus lost knowledge and useful inherited output | General reincarnation/multiverse transitions, second prestige layer and all reset collisions |

Each stage ends with useful play and its own declared gate. If S3 lacks an actual
supported native continuity route, it is blocked on that precise adapter; placing
a capsule in a cache is only preparation. The existing one-realm/one-prestige
milestone remains applicable unless Weibao changes it.

For UI integration, record 1366×768 laptop as the proposed target with useful
actions/results in existing independent panels. Rebuild and play from a fresh
origin; perform required persistence/import checks on the changed route. Mobile
and unselected worlds cannot become substitute acceptance gates.
