# UI rules

Standing rules for every agent that adds or changes player-facing UI. The look itself (identity, what every feature UI meets, the per-world contract) is owned by [DESIGN.md](../DESIGN.md), DSG1-DSG19; these rules are its mechanics. Weibao, 2026-10-15: "save logical rules to address these and more so similar mistakes wount be made again?" Each rule names the mistake it prevents. Accepted direction lives in [PROJECT](../PROJECT.md#standing-priorities-and-document-authority) and [USER_VISION](USER_VISION.md#format-portraits-and-view-decisions-2026-10-14); detail lives in the owners linked below. These rules are defaults with reasons; a world or feature can propose an exception, but it has to say why.

**Reading order (tiering, Weibao 2026-10-30; no rule text changed, [audit](audits/RULES_RECONCILIATION_AUDIT_2026-10-30.md) L1).** Read first, for every UI task: the checklist, the bounded-journey section, Descriptions, Before you build, While you build, Before you call it done, Getting anywhere and For coordinators (the sections from here to "Proportions"). Read by trigger: Proportions, Structural parity and Contextual navigation when layout or hierarchy changes; the Discord reference guide (UR59-UR64) when a design follows a reference; Craft 1 evidence for crafting surfaces; Scene and report rules (SUI, RPT) for scenes, travel, choices or Reports lines. What the 2026-11-10 rulebooks need on screen (UR83–UR88) when a feature shows knowledge, a coming loss, a readout, an unchosen act, other lives or notices. Open forms (UR89–UR92) when a feature needs a new kind of surface, shows progression, adds an effect or sound, or shows how something changed. Distinct, reactive and pleasing surfaces (UR93–UR99) for any new surface or redesign. The element sheet (UR100–UR127) for every element added or changed. Default: a lane reads the first tier plus its triggers. Dial: a coordinator or a full UI audit reads the whole file. Reason: most of the file applies only on a trigger, so reading it all on every task costs about 5,000 words.

## Applying the existing rules to a bounded journey, 2026-10-25

This is a routing aid, not another rule set or a selected redesign. In the
existing task packet, link the affected owner, shared component and a working
consumer/example; name the changed player outcome and relevant states. Use:

- UR35/42/47/52 for discovery-aware inspection, known prerequisites and distinct
  unknown, empty, filtered and unavailable states. A failure message explains
  only what the observer can know; disabled controls need not reveal secrets.
- UR10/55/61/63 for target, actual cost/duration/units, commitment, progress and
  settled/cancelled/interrupted outcomes. Read those from existing owners;
  presentation does not decide settlement or duplicate preview math.
- UR21–33/41/43/51–58 for navigation, keyboard/focus, return, larger text and
  recovery without lost work or moving targets. Exercise relevant empty/error
  and changed-state cases, not just a populated opening screenshot.
- UR6/12/34/37–39/49/60/62/64/65–69 for shared vocabulary/components, quiet
  hierarchy, world-specific expression, stable layout and bounded feedback.
  Text and static meaning remain usable without motion, sound or color alone.

Use the current desktop/text targets below with disposable test fixtures, not
private player saves. Follow AD36 for the changed risk and evidence reuse;
unchanged content rows do not each require another full UI matrix. Required
changed native behavior and affected persistence need agent-side evidence. Human
visual/feel review is optional feedback under AD42 and stays separate. A screenshot, row count or absence of overflow alone establishes none
of the later verification states. A settled UI fix does not need a new prototype; use the
existing mockup workflow only when the design question is actually unsettled.

### Navigation scope in ordinary play, 2026-10-26

Application of UR41/43/52/53, not a new universal layout rule: choose the smallest
navigation scope that serves the current task. Opening a local disclosure such
as More actions keeps that task and its context; a larger view is a separate
deliberate action through the existing controller. Preserve source identity,
pending choices and a clear return. This applies to services, people, effects,
list controls, reports and settings as well as items. Full tasks may deliberately
reflow, and UR69 still permits stable-moment space lending. Check meaningful
context and controls rather than universal pixel immobility.

## UI prose and subtle-detail reconciliation, 2026-11-04

[Weibao accepted updating these defaults](USER_VISION.md#ui-and-prose-defaults-subtle-details-and-whimsy-2026-11-04) with world/scene/player dials and future improvement. Apply existing UR53/57/60/62/64/66/70–74 and DESIGN DSG3/5/13: task composition, distinct editorial roles, paced expression, usable small details and truthful consequences. Interface/narrator/flavor whimsy is separate from a character's personality, motives, knowledge and behavior. Decorative pleasure needs no invented stat effect; real effect claims still read their owners. Existing statuses of UR76–UR82/UIV and unrelated design proposals are unchanged.

Prose-first interaction clarification (DSG5, UR35/57/61/70): [Weibao’s clarification](USER_VISION.md#prose-first-visuals-and-hall-interaction-2026-11-04) makes a prose illustration optional. Default: choose hierarchy, direct well-labelled actions, truthful quote/work feedback and readable results first. A caption/drawing that repeats the passage can be omitted. Deliberate spatial/reading treatments remain a world/task dial; an action or progress display should answer an actual question. A job with only remaining time and no frozen admitted total does not justify an invented completion percentage. Keep the time-left text or an honestly labelled supported measure.

For changed buttons, sample ready, hovered/focused, started, blocked, interrupted and settled behavior where relevant under AD36. Geometry and semantic role remain stable through hover/focus; focus follows the same job after activation or a stable task/result when it ends. A navigation label stays non-mutating; a direct action has an explicit verb and the native quote/revalidation path. Acknowledgement means started, not completed. Use the existing status channel for meaningful command feedback without announcing every simulation tick. This applies existing UR35/53/57/62/70–74, not a new all-widget checklist or bespoke feedback engine.

Editorial application, 2026-11-04 (UR70/73/74, RPT3/8/10): compare intent, in-flight status and settled receipt, then follow the same record into its Notebook/Reports consumers. On reload, check what each owner actually retains: remembered observations and ephemeral scrollback have different lifetimes (RPT8/9); avoid replaying a report merely to refill a cleared log. New wording belongs to its owning content/event; previously saved observations retain their historical wording unless an explicit, scoped compatibility repair is made. A prose edit does not silently rewrite history or change the event’s mechanics.

Default creative review: prefer details particular to the subject and source, verbs that carry the action, and rhythm suited to the scene. Question generic mood-padding, repeated sentence templates, tidy moral conclusions, stock rhetorical contrasts, forced jokes and unnecessary defensive caveats when they weaken the passage. These are editing prompts, not evidence of AI authorship, a banned-word list, or grounds for stripping a character’s established speech. Preserve meaningful uncertainty and actual commitments. Dial: a world may be spare, lyrical, eerie, comic or deliberately repetitive; richer prose belongs where the player has room to read it. Reason: interesting writing comes from fitting detail and voice, not a universal literary or corporate style. A short story quotation can be used deliberately under SUI1/RPT10 after verifying its wording, context and attribution; it is optional, and quotation does not repair a false game-state claim.


Source context and the exact adoption map live in [UI audit round 29](audits/UI_DESIGN_CORE_AUDIT.md#round-29-2026-11-04-adopted-ui-prose-defaults-and-character-separation), reusing the held Proto23/YAIR/Discord findings and qualified online guidance. A Reddit preference, old developer draft or external guideline is not a universal rule. AD36/AD43 remain the verification policy, not a new checklist or conformance target.

## Task layers and long-running work, 2026-11-04

Accepted application of UR41–43/46/49/52/57/61/63/70–74 and MR18/29, from
[Weibao's instruction](USER_VISION.md#task-appropriate-ui-layers-and-crafting-follow-through-2026-11-04).
These defaults apply to crafting, trade, services, research, travel, projects
and other tasks; they do not impose one form or new mechanics.

- **Choose the task layer before choosing fields (UR41–43/71).** Browse,
  inspect/compare, configure/review, commit, running work/settlement and reference
  are roles, not compulsory pages. Combine them for a short task. Keep the
  current commitment's known decision facts together: purpose, relevant effects,
  exact means, cost, uncertainty and output. Special calculations and long
  history use a labelled path. Dial by frequency, stakes and space; fewer rows
  do not justify repeated inspection to make one decision.
- **Keep display depth, execution depth and knowledge separate (UR42/72,
  MR18/31).** More detail need not switch quick work into guided/deep execution,
  and no disclosure level grants unknown facts. Reuse authoritative observer
  projections across surfaces; shared controls/meaning do not require identical
  layouts or one resolver. Patterns, parts, composition and alteration show the
  relations their actual mechanisms consume. World/task differences explain
  the form; a familiar skin cannot substitute for usable composition.
- **Condense repetition, not meaningful distinctions (UR46/64/71/74).** Keep
  exact selected holdings, comparison baseline, units and relevant ranges.
  Consolidate repeated costs and omit inapplicable filler; distinguish unknown
  from unavailable and not applicable. A forecast, a starting acknowledgement
  and a settled receipt are different claims. Reuse the result's actual supplier,
  including supported bonuses, rather than duplicating its formulas in UI.
- **Long work keeps its identity and terms (UR52/53/61/63).** A routine or
  project shows actual stage/remaining work, held versus spent means, useful
  output and the owner's stop/interruption/collection terms where relevant.
  Closing inspection does not cancel work. Preserve selection, draft, focus and
  return across navigation and refresh; requote changed conditions before a
  consequential command. Attempts differ from successes and useful outputs;
  remaining time alone supplies no completion percentage. Saved intent, active
  work and historical results retain their actual, separately stated lifetimes.
  Dial by the operation's real lifecycle, not a universal refund/resume policy.
- **Check a representative different consumer (UR49/57, AD36).** When changing
  a shared projection or interaction, choose relevant cases by actual model and
  task differences: fixed result, configurable parts, unknown experiment, staged
  or altered-object work. Exercise the selected decision through changed state
  and return. One screenshot or renderer test does not certify all consumers;
  a narrow change does not require an all-world matrix.

Crafting examples and source/adoption boundaries live in the
[comparison round 2](reviews/crafting-reference-2026-11-04/REPORT.md#round-2-source-adoption-ui-layers-and-other-making-2026-11-04),

## Descriptions explain the experience and effect, 2026-10-25

Weibao requested rules for more narrative UI descriptions, especially traits,
while retaining calculations. [Direction](USER_VISION.md#effect-first-ui-descriptions-2026-10-25)
and [source comparison, examples and verification](reviews/ui-descriptions-2026-10-25/REPORT.md).
These apply to stats, traits, skills, items, conditions, actions and other
inspectable subjects, alongside UR40/42/43/47 and AD6–AD8.

| Code | Rule | Mistake it prevents |
| --- | --- | --- |
| UR70 | **Lead with meaning and practical effect.** Default to one or two short sentences explaining what the subject represents and what it changes for the character. A trait may describe how it manifests in the body, habits or experience; a stat explains what increasing it helps. Use concrete verbs and restrained world-appropriate voice. Longer narrative belongs in a deliberate reading surface. Default editorial roles: atmosphere establishes perceived place/situation, action labels state commitments, inspection explains effects, Reports records aftermath, and dialogue expresses its speaker. Default: a current-task summary keeps the admitted action’s relevant explanation, known uncertainty and quote together before commitment; a label and price do not substitute for what is being attempted. Distinguish intended action from settled outcome, and do not import later-stage explanations into the current choice. Running work may replace instruction prose with its actual status. Dial: reuse a concise explanation or a nearby inspect route according to density and stakes. Reason: a useful summary must preserve the decision’s meaning (2026-11-04, LOTM editorial continuation). Dial: length and narrative richness follow the task, novelty and stakes rather than a universal sentence quota. Reason: expressive prose and quick repeated decisions need different treatment (2026-11-04, AD40). | A tooltip opening with “Native current-player attribute” or atmosphere that never explains what the trait does |
| UR71 | **Give mechanics a supporting layer.** Follow the description with relevant current effects, conditions, costs, drawbacks or duration, then a labelled calculation/source breakdown when useful. Retain exact useful numbers and formulas through UR42/43 disclosure; short descriptions need not reproduce the entire calculation. Spell out unfamiliar ratings and distinguish power, damage and target-specific chances under UR40. Keep a quote's target/payer, units/clock, requested amount and useful output distinct where relevant; attempts, yield chance and expected completion are different claims. An inventory count or comparison baseline is shown when it changes the decision, through its current owner. This applies the qualified YAIR/Discord lessons rather than assuming universal resumability, guaranteed yield or one rarity scale (2026-11-04, AD40). | A formula replacing the explanation, or narrative removing the information needed to choose |
| UR72 | **Describe actual behavior with its conditions.** Trace effect wording to the owning consumer and observer-permitted state. Distinguish present effects, dormant or conditional effects, uncertain knowledge and unimplemented uses in player terms. Narrative can express the character's known belief, clearly qualified; it cannot establish an effect or reveal a sealed truth. Default: sensory specificity and decorative metaphor may enrich UI/flavor without a numerical reward or new gameplay consumer. Dial: a character's belief and speech may be mistaken or figurative with their perspective clear. Reason: ornament is not a gameplay claim, while a statement about safety, healing, trust or power must not silently invent one. UI whimsy does not change the character's traits or supported actions (2026-11-04, AD40). | Copying a source's magic claim into a stat with no working magic consumer, or describing an inactive trait as already helping |
| UR73 | **Write for the player, with useful detail density.** Default to familiar names and meaningful comparisons. Internal source categories, stored-field caveats, pipeline terminology and tracing notes belong in developer documentation unless they explain a concrete player consequence. Omit repetitive neutral rows and empty-modifier messages by default; retain an explicit value or neutral comparison when it helps the current question. A command that should show while locked gives its rule a `reason` naming the missing thing. Default: UI/flavor can be whimsical while known costs, commitment terms and recovery stay understandable. Distinguish unknown, unavailable, invalid input, changed quote, partial result and technical failure; preserve relevant entered choices when recovery permits it. Dial: fictional setbacks can retain world voice, but character dialogue follows that character. Reason: a helpful next move and a fitting tone depend on what actually failed; corporate plain-language advice does not ban metaphor in fiction (2026-11-04, AD40). | Repeating Unit/points/Base/Before multipliers/×1 on every hover, or exposing implementation warnings as flavor text |
| UR74 | **Keep one meaning across surfaces and check the words against play.** Reuse the owning subject's description and public effect projection across hover, pinned inspection, lists and reference views; shorten by disclosure rather than writing conflicting copies. For changed copy, check the active case and a relevant conditional, inactive or unknown case. Runtime delivery follows AD36 with rebuilt desktop evidence; document-only rules do not establish rewritten or playable tooltips. Check complete messages and full known names at the relevant reading size, including a longer string/plural or supported locale when affected, while retaining selection and reading position. Current inspection and a historical event keep their respective baselines/knowledge. These are risk-scaled applications, not a new localization project or blanket copy rewrite (2026-11-04, AD40). | A trait card, tooltip and effect list disagreeing, or a prose rule being reported as a shipped UI repair |
| UR75 | **Explain terms and comparisons where they affect a choice.** Default to a short explanation of unfamiliar ratings or specialized terms in the current inspection. Say what higher/lower changes, which target or baseline matters, and distinguish a percent change from percentage points when relevant. Use warnings for the current subject and circumstances; keep deeper definitions available through an existing reference route when one exists. Reuse the owning numbers rather than adding display-side mechanics. | An unexplained AP bonus, “less damage” with no baseline, or a warning about a requirement that does not apply here |

trait with no numerical contribution is not thereby inactive (UR72). The

### Small-detail tokens, 2026-10-22

Weibao: "creating base rules for every little thing to make development easier? ... Yes do spacing but consider more as well." Small details belong in tokens and the contract test, so builders get them right by default without reading more prose. The [UI design core audit](audits/UI_DESIGN_CORE_AUDIT.md) holds the measurements, Discord-derived lessons and remaining proposals. A [one-screen card](ui/UI_RULES_CARD.md) summarizes every rule; this file stays the authority.

| Code | Rule | Mistake it prevents |
| --- | --- | --- |
| UR65 | **Spacing comes from the scale.** Padding, margin and gap use `--ui-space-1` to `--ui-space-7` (2, 4, 6, 8, 12, 16, 24 px at 14 px text), `--ui-space-hairline` for 1 px seams and `--ui-space-panel` for the player's panel-spacing setting. Steps scale with the panel's own text size (UR33) and round to whole pixels for the bitmap Gothic strikes. Zero, `auto` and percentages need no token. An off-scale value is kept as an exact entry in `tests/ui_contract_allowlist.json` with a `reason` field. ## Distinct, reactive and pleasing surfaces

Working defaults 2026-11-10 under AD56, adjustable. Requested by Weibao: "ALso making Uis disctinct and more? since alot of the UI work and implementations, for stuff like rituals and stuff and more turned into sets of circles and stuff, thoughts? How to have nuanced, interesting, reactive, and comprehensive, and pleasing ui?" ([log](gm/USER_VISION_LOG_2026-11.md#distinct-reactive-and-pleasing-ui-2026-11-10)). [UI audit round 39](audits/UI_DESIGN_CORE_AUDIT.md#round-39-2026-11-10-why-surfaces-look-alike-and-how-to-make-them-distinct) holds the diagnosis and per-system examples. Read this section for any new surface or a redesign. The shared rules (UR6, UR7, UR79) still hold; these say what they do not mean.

| Code | Rule (default, dial, reason) | Mistake it prevents |
| --- | --- | --- |
| UR93 | **Form follows the mechanism.** Default: a surface's layout encodes the real structure of what it shows, read from the owning data: a ritual's ordered steps, placements, offerings and invocation; a formation's nodes and flows; a mixture's ingredients, stages and heat; a contract's clauses and parties; a fight's positions; a divination's question, method and answer. A shape that encodes nothing (a ring of identical circles, a row of identical chips) is decoration, welcome on top (DSG3) and never a stand-in for the structure. Dial: per world and task. Reason: Weibao, 2026-11-10, on rituals and other systems turning into "sets of circles"; a form that mirrors the mechanism teaches it without reading. | Every system drawn with the same generic markers, so a ritual looks like an inventory |
| UR94 | **Shared grammar, distinct composition.** Default: what is shared is the grammar: tokens (UR6), controls and focus (UR7, UR53), back and return (UR9, UR22), information roles such as ledger, timeline and note (UR79), and wording (UR70–UR75). What differs is composition: the mechanism's form (UR93), the world's materials, ornament and motion (DSG12–DSG17), and its diegetic surfaces where ready (DSG18). Check with two tests on screenshots: with labels covered, can a reader tell which system it is; with the world's name covered, which world. Dial: how far a world departs, per world. Reason: UR6, UR7 and UR79 were read as "every system is the same rows"; they are meant to make distinct screens cheap, not to make them alike. | One template filled with different nouns |
| UR95 | **Surfaces react before and after commit.** Default: a surface shows the effect of a pending choice on its own form before commit (hovering an ingredient shows where it goes and what it changes; a ritual's risk builds on the altar as steps are added; a route redraws as stops are chosen), read from the real quote (UIV4); after commit the form changes to show what happened (UR91), and the world's state colours it (time, weather, place, standing). Changes land at stable moments (UR52, UR69). Dial: how much reacts, per surface; reduced motion keeps the change as a static mark. Reason: a form that does not move when the player thinks reads as a form to fill, not a thing to work. | Static forms where the player learns the result only from a log line |
| UR96 | **Comprehensive by layers, not by length.** Default: every fact a decision needs is reachable inside the surface, through the glance form, a pinned detail and a full reference, each complete for its layer (UR42, UR43); a fact the decision does not need stays one step away. Dial: layer depth per task and frequency. Reason: comprehensive and readable conflict only when everything is shown at once. | Either a sparse form that hides needed facts, or a wall of rows |
| UR97 | **Pleasing is craft, checked.** Default: a new or redesigned surface gets a craft pass before it is called done: one focal point, alignment and rhythm on the spacing scale (UR65), contrast that follows importance (UR37, UR46), the world's material, a settle motion (UR91), and its empty, full, warning and running states; compare it with one reference from the source's genre (UR59–UR64) and record the two UR94 tests. Dial: depth by how often the surface is used. Reason: taste stays Weibao's (AD42), and a recorded pass lets him judge craft instead of finding defects. | Screens that work and pass tests but feel like spreadsheets |
| UR98 | **Six levels; distinctness lives in the upper three.** Default: L0 tokens (UR6); L1 marks (pip, bar, slot, edge, label, glyph); L2 layouts (today chain, tree, wheel, web, ring, track and list in `src/ui/figure.js` and `figure_graph.js`; grid, map, timeline, flow, vessel, board and body outline are welcome additions) are shared. L3 mechanism forms (the altar, the vessel, the meridian chart, the case board) are per mechanism: they compose layouts and may add their own drawn parts. L4 world dress (a motif pack: material, glyph set, ornament, motion signature, sound) is per world through `data-world` (DSG12, MDL6). L5 diegetic frames (a newspaper, a status window, a jade slip) come per world or cheat after its basic kit (DSG18). Text form, the knowledge filter (MDL4, UR80), effects (UR91) and interaction (`figure_interact.js`) cut across every level. An adapter maps domain data to an L3 form, not straight to L2 geometry; MDL2's "never kind-specific drawing code" now reads as no kind-specific tokens or marks, with kind-specific composition and parts expected at L3. Dial: how far each mechanism and world departs. Reason: the figure primitive's rings, slots and pips became the look of rites, webs and lives across its 21 consumers; Weibao, 2026-11-10: "turned into sets of circles". | Every mechanism drawn as the same ring of pips |
| UR99 | **Cheap materials first.** Default: build distinctness from what the stack does well: typography and glyphs (DSG4, UR68 roles), hand-written or seeded SVG symbols and sigils keyed by the subject's id (the same rite always draws the same sigil), SVG filters and gradients for paper, ink, brass, jade and steel, CSS and Web Animations motion that settles (UR91), sound words, voices in Reports (DSG13), and canvas for ambient layers (`particles.js`). Check in the app he plays (UR16), since its web view can differ from headless Chromium. Dial: a library (a tween, a shape morph, a hand-drawn renderer) where it saves real work, with its size and gain noted in the task record; raster or generated art where a surface benefits from it, with its source noted per asset (Weibao opened both, 2026-11-10: LLR33 for libraries, LLR32 for art). Starting budgets, estimates until measured in the app (dials, loosened per surface once measured): about 400 drawn children per figure, figures redrawn on settled events and not on ticks, SVG texture filters baked once with only opacity or transform animated, about 10 running animations on screen, and ambient motion paused when the window is hidden ([R3](reviews/ui-distinct-forms-2026-11-10/R3_ACCESSIBILITY_AND_COST.md#budget-suggestions-all-estimates-adjust-after-section-d)). Reason: these means are cheap and need no art pipeline; heavier means are welcome when they buy something. | Waiting on art that does not exist, or a heavy library for what SVG already does |
