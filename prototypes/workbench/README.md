# YAIR mockup workbench

The standing workflow, extension protocol and limitations live in
[docs/MOCKUP_SYSTEM.md](../../docs/MOCKUP_SYSTEM.md).

```sh
node prototypes/workbench/build.mjs
node prototypes/workbench/serve.mjs
```

Open the fresh loopback URL printed by the server. The default is the populated
native character study: current OOPS shell/controllers, baseline and two proposed
CSS treatments. Switch Layout on the same running state. Task & limits names
fixture prerequisites and exclusions. Fit preview is scaled; uncheck it for
actual-size inspection. The native study uses isolated fixture storage and a
manual clock on this disposable origin; personal gameplay profiles stay untouched.

Native simultaneous command mirroring is unavailable, so that checkbox is disabled.
[The matched screenshot gallery](evidence/native-character-2026-10-26/gallery.html)
shows the baseline and treatments alongside. Recipe/launch history stays archived,
and the older reduced character study stays labelled a sketch. Earlier recipe
adapters used in-memory state without game startup; that is not the native route.
The always-visible banner rechecks declared input/output identity on focus, study
change and every 15 seconds. Matching bytes do not certify visual fidelity.

For scoped browser checks, pass that URL to `node prototypes/workbench/check.cjs`.
See [REPORT.md](REPORT.md) for the delivered state and remaining gates.

For the native route run `node prototypes/workbench/check-native-character.mjs <fresh-origin>/`
and `node prototypes/workbench/check-native-effects.mjs <fresh-origin>/` after building.
[UIC15–UIC22](../../docs/reviews/UI_CHARACTER_DIRECTION_2026-10-26.md#uic15uic22-faithful-current-shell-rerun-2026-10-26)
own the source map, fixture provenance, captured bundle and proposal limits.
