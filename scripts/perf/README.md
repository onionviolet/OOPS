# Perf gate

Standing performance gate for YAIRPG (audit D6 and T10 in
[the browser testing and engine perf audit](../../docs/research/BROWSER_TESTING_AND_ENGINE_PERF_AUDIT_2026-10-14.md);
PF1-PF2 in [the runtime performance considerations](../../docs/ENGINE_RUNTIME_PERFORMANCE_AND_STACK_CONSIDERATIONS_2026-10-14.md)).
Every perf lane runs it to prove its gain and byte-identical determinism.

```bash
node scripts/perf/gate.mjs --base <commit>
```

Exit 0 = PASS, 1 = a budget or det check failed, 2 = the gate itself broke.
Options: `--fixtures fresh,mid` `--idle 15` (seconds measured) `--det-minutes 8`
`--budgets <file>` `--out <report.json>` `--keep` (keep the temp builds).
Run it on a quiet host; one gate at a time.

## What it does

1. Copies the working tree (tracked and untracked, unignored files) and the
   base commit (`git archive`) into an OS temp dir, builds both there with
   `build.js`, and serves both on OS-assigned free ports. Tracked `dist/` and
   `index.html` are never written.
2. **Node tick**: per fixture, best of 15 one-minute `advanceSimulation` calls
   after 3 warmups on the loaded expansion state (head source,
   `expeditionRegistry`); the median is reported too.
3. **Browser idle** (head build, system Chrome headless, 1366x768): seed the
   fixture into a fresh origin, PLAY, warm 4 s, then a 15 s window of CDP
   `Performance.getMetrics` deltas, `longtask` entries and a `Storage.setItem`
   counter. Method ported from
   [baseline.cjs](../../docs/gm/dispatch/engine-perf-2026-10-14/tools/baseline.cjs).
4. **det**: base and head each load the fixture and capture the first durable
   save at fixture minute + N; the two must match byte for byte minus
   `saved_at` and `total_playtime`. Method from
   [det.cjs](../../docs/gm/dispatch/engine-perf-2026-10-14/tools/det.cjs).
   On a mismatch both saves are dumped to the OS temp dir and listed.
5. Prints a table against [budgets.json](budgets.json) and writes a JSON report.

Set `YAIRPG_PERF_VIEWPORT=1920x1080` to change the browser viewport (default 1366x768).

Playwright resolves from `YAIRPG_PLAYWRIGHT`, then `playwright`, then the Codex
runtime copy; Chrome from `YAIRPG_CHROME`, then `/Applications/Google Chrome.app`,
then Playwright's bundled Chromium.

## Fixtures

Committed in [tests/fixtures/perf/](../../tests/fixtures/perf/), regenerated by
`node scripts/perf/gen_fixtures.mjs` (about 25 s). No personal save is read;
every fixture starts from a fresh origin of the working-tree build.

| Fixture | Bytes | Expansion clock | Actors | Built by |
| --- | --- | --- | --- | --- |
| fresh | 47,654 | 0 | 1 | New game, PLAY, save |
| mid | 60,817 | 10 | 4 | fresh + native elder greeting and the systems workshop opening (quest, commission, claim, method, lease, upgrade, teaching) through real buttons |
| crowded | 279,175 | 22 | 68 | mid + engine APIs in Node: 64 hired route helpers run and collected, 512 settled history claims, every ordinary material template in the inventory |

`crowded` uses one fixture-only grant (`knowledge.player.workbench`), as
`engine_profile.cjs` always did. `saved_at` and `total_playtime` are fixed, and
`last_rewarded_export` is 0 so the export-reward state never flips with wall
time. Regeneration is not byte-identical (a new game rolls its own RNG seed);
the committed bytes are the fixture.
Regenerate after a save-format change, then rerun the gate twice and re-set
budgets: fixtures and budgets move together.

`scripts/engine_profile.cjs` and `scripts/scheduler_profile.mjs` now default
to `tests/fixtures/perf/mid.json` (override with `YAIRPG_PROFILE_SEED`).

## Budgets (proposal)

See [budgets.json](budgets.json): ceilings, not targets, set from three runs on
a loaded host at about max x 1.25. They catch regressions; a lane
that lands a gain should rerun twice and ratchet its fixture down. The audit's
acceptance ratios (for example D1: developed idle JS-busy at most 0.4x) are
checked by comparing two gate reports, not by these ceilings.

Measured on head 8abd3882 against base 7f8b8567, 2026-10-14, 18-core arm64
Mac shared with other lanes (1-min load 30-125, so not a quiet host). Ranges
over the four final runs; every run det-identical with no page errors:

| Fixture | Node tick ms (best of 15) | Task busy % | Script busy % | Layouts/s | Long tasks / 15 s | Max long task ms |
| --- | --- | --- | --- | --- | --- | --- |
| fresh | 0.23-0.36 | 7.3-11.1 | 3.4-5.0 | 70-74 | 0-1 | 0-51 |
| mid | 5.9-7.4 | 37-49 | 34-44 | 49-55 | 9-11 | 483-795 |
| crowded | 9.1-10.6 | 50-63 | 46-59 | 131-155 | 7-9 | 810-1208 |

Noise: busy % about +-12% relative, layouts/s +-8%, long tasks +-2, Node tick
best-of-15 +-15%; max long task is too noisy to budget and is only reported.
det identity and page errors are exact. A run takes 113-140 s. When 1-min load
exceeds the core count the gate prints a warning: rerun on a quiet host before
acting on a FAIL. The budgets were never tuned on a quiet host; a quiet rerun
should land well under them and is the right time to ratchet.

mid reproduces the audit's developed-save effect (about 5x fresh idle busy)
from clock 10. The other lanes' developed fixture (the workshop proof's
natural-final-save, clock 66) is not committed; mid is the committed stand-in.
